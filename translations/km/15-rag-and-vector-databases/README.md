# ការបង្កើតដោយបន្ថែមការទាញយក (RAG) និងមូលដ្ឋានទិន្នន័យវ៉ិចទ័រ

ក្នុងមេរៀនកម្មវិធីស្វែងរក យើងបានរំពឹងខ្លីពីរបៀបបញ្ចូលទិន្នន័យរបស់អ្នកទៅក្នុងគំរូភាសាធំ (LLMs)។ ក្នុងមេរៀននេះ យើងនឹងស្រាលជ្រៅទៅលើគំនិតនៃការដាំបđenប្រភពទិន្នន័យរបស់អ្នកក្នុងកម្មវិធី LLM របស់អ្នក ព្រមទាំងមេកានិកនៃដំណើរការ និងវិធីសាស្រ្តសំរាប់ផ្ទុកទិន្នន័យ រួមទាំង embeddings និងអត្ថបទ។

## ការណែនាំ

ក្នុងមេរៀននេះ យើងនឹងគ្របដណ្ដប់ដូចខាងក្រោម:

- ការណែនាំអំពី RAG វាជាអ្វី និងហេតុអ្វីបានជាវាត្រូវបានប្រើនៅក្នុង AI (បញ្ញាសិប្បនិម្មិត)។

- យល់ដឹងអំពីមូលដ្ឋានទិន្នន័យវ៉ិចទ័រ និងបង្កើតមូលដ្ឋានមួយសម្រាប់កម្មវិធីរបស់យើង។

- ឧទាហរណ៍អនុវត្តន៍ពីរបៀបបញ្ចូល RAG ទៅក្នុងកម្មវិធីមួយ។

## គោលបំណងសិក្សា

បន្ទាប់ពីបញ្ចប់មេរៀននេះ អ្នកនឹងអាច:

- ពន្យល់ពីសារៈសំខាន់របស់ RAG ក្នុងការទាញយក និងដំណើរការទិន្នន័យ។

- កំណត់កម្មវិធី RAG និងដាំបđen LLM ជាមួយទិន្នន័យរបស់អ្នក

- បញ្ចូល RAG និងមូលដ្ឋានទិន្នន័យវ៉ិចទ័រយ៉ាងមានប្រសិទ្ធភាពនៅក្នុងកម្មវិធី LLM។

## ស្ថានភាពរបស់យើង៖ បង្កើនសមត្ថភាព LLMs របស់យើងជាមួយទិន្នន័យផ្ទាល់ខ្លួន

សម្រាប់មេរៀននេះ យើងចង់បញ្ចូលកំណត់ត្រារបស់យើងទៅក្នុងស្តាតអាប់ការអប់រំ ដែលអនុញ្ញាតឲ្យ chatbot ទទួលបានព័ត៌មានបន្ថែមអំពីមុខវិជ្ជាពីរបៀបផ្សេងៗ។ ដោយប្រើកំណត់ត្រាដែលយើងមាន អ្នករៀននឹងអាចរៀនបានល្អជាងមុន និងយល់ដឹងអំពីប្រធានបទនានា បង្កើតភាពងាយស្រួលសម្រាប់ការត្រៀមប្រឡង។ ដើម្បីបង្កើតស្ថានភាពរបស់យើង យើងនឹងប្រើ:

- `Azure OpenAI:` LLM ដែលយើងនឹងប្រើដើម្បីបង្កើត chatbot របស់យើង

- `AI for beginners' lesson on Neural Networks`៖ នេះគឺជាទិន្នន័យដែលយើងដាំបđen LLM របស់យើងលើវា

- `Azure AI Search` និង `Azure Cosmos DB:` មូលដ្ឋានទិន្នន័យវ៉ិចទ័រសម្រាប់ផ្ទុកទិន្នន័យ និងបង្កើតសន្ទស្សន៍ស្វែងរក

អ្នកប្រើនឹងអាចបង្កើតសំណួរប្រឡងហាត់ប្រាណ និងកាដូផ្ដល់ការសង្ខេបពីកំណត់ត្រារបស់ពួកគេ និងសង្ខេបកំណត់ត្រាទាំងនោះទៅជាសេចក្ដីសង្ខេបខ្លី។ ដើម្បីចាប់ផ្តើម យើងមើលទៅ RAG ជាមុន និងរបៀបវាដំណើរការ៖

## ការបង្កើតដោយបន្ថែមការទាញយក (RAG)

chatbot ដែលដឹកនាំដោយ LLM ដំណើរការលើការបញ្ចូលប្រើប្រាស់របស់អ្នកដើម្បីបង្កើតចម្លើយ។ វាត្រូវបានរចនាឡើងដើម្បីមានបញ្ហាសកម្មភាព និងមានការចូលរួមជាមួយអ្នកប្រើនៅលើប្រធានបទចម្រុះ។ ទោះយ៉ាងណា ចម្លើយរបស់វាមានកំណត់នៅក្នុងបរិបទដែលផ្តល់ជូន និងទិន្នន័យបណ្តុំនាយជាលក្ខណៈមូលដ្ឋាន។ ឧទាហរណ៍ បំណុលចំណេះដឹង GPT-4 គឺនៅកម្រិតខែសីហា ២០២១ មានន័យថា វាបាត់បង់ចំណេះដឹងអំពីព្រឹត្តិការណ៍ដែលបានកើតឡើងបន្ទាប់ពីរយៈពេលនេះ។ បន្ថែមពីនេះ ទិន្នន័យដែលប្រើសម្រាប់បណ្តុំនាយ LLM មិនរួមបញ្ចូលព័ត៌មានសម្ងាត់ដូចជា កំណត់ត្រាផ្ទាល់ខ្លួនឬសៀវភៅណែនាំផលិតផលរបស់ក្រុមហ៊ុន។

### របៀបដំណើរការរបស់ RAG (ការបង្កើតដោយបន្ថែមការទាញយក)

![ដំនើរការបង្ហាញរបៀប RAG ដំណើរការ](../../../translated_images/km/how-rag-works.f5d0ff63942bd3a6.webp?WT.mc_id=academic-105485-koreyst)

សន្និដ្ឋានថាអ្នកចង់ដាក់ប្រើ chatbot ដែលបង្កើតសំណួរប្រឡងពីកំណត់ត្រារបស់អ្នក អ្នកនឹងត្រូវការតំណខ្សែការតភ្ជាប់ទៅមូលដ្ឋានចំណេះដឹង។ នេះគឺជាកន្លែងដែល RAG ជួយសង្គ្រោះ។ RAG ដំណើរការដូចតទៅ៖

- **មូលដ្ឋានចំណេះដឹង៖** មុនការទាញយក ឯកសារទាំងនេះត្រូវតែត្រូវបានដំណើរការជាមុន ជាទូទៅជាការចែកឯកសារធំនៅជាច្រើនជាតំណក់តូចៗ បម្លែងវាទៅជាអត្ថបទ embedding ហើយផ្ទុកវានៅក្នុងមូលដ្ឋានទិន្នន័យ។

- **សំណួរអ្នកប្រើ៖** អ្នកប្រើសួរចម្ងល់មួយ

- **ការទាញយក៖** ពេលអ្នកប្រើសួរចម្ងល់ ម៉ូដែល embedding នឹងទាញយកព័ត៌មានពាក់ព័ន្ធពីមូលដ្ឋានចំណេះដឹងរបស់យើង ដើម្បីផ្តល់បរិបទបន្ថែមដែលនឹងត្រូវបញ្ចូលទៅក្នុងការទាក់ទង។

- **ការបង្កើតបន្ថែម៖** LLM បង្កើនចម្លើយរបស់វាតាមព្រឹត្តិការណ៍ដែលបានទាញយក។ វាអនុញ្ញាតឲ្យចម្លើយដែលបង្កើតមិនត្រឹមតែផ្អែកលើទិន្នន័យដែលបានបណ្តុំនាយទេ តែមានព័ត៌មានពាក់ព័ន្ធពីបរិបទបន្ថែម។ ទិន្នន័យដែលបានទាញយកត្រូវបានប្រើដើម្បីបង្កើតចម្លើយក្នុង LLM។ LLM បន្ទាប់មកផ្តល់ចម្លើយទៅសំណួររបស់អ្នកប្រើ។

![គំនូរបង្ហាញស្ថាបត្យកម្ម RAG](../../../translated_images/km/encoder-decode.f2658c25d0eadee2.webp?WT.mc_id=academic-105485-koreyst)

RAG បញ្ចូល retriever ជាមួយ generator៖ សំណួរត្រូវបានបម្លែងជាវ៉ិចទ័រក្នុងបំណែកនៃសំណួរ ប្រៀបធៀបនឹងសន្ទស្សន៍ឯកសារដើម្បីស្វែងរកអត្ថបទលំអិតដែលពាក់ព័ន្ធ ហើយអត្ថបទនោះត្រូវបានផ្ដល់ជាបរិបទទៅ LLM ដែលបង្កើតចម្លើយ។ retriever និង generator អាចប្រើម៉ូដែលខុសៗគ្នា; RAG មិនតម្រូវឲ្យប្រើ encoder-decoder transformer ទេ។

វិធីសាស្រ្តពីរនាក់នៅពេលអនុវត្ត RAG ដោយតម្រូវនៅក្នុងកាសែតផ្តល់ណែនាំ៖ [Retrieval-Augmented Generation for Knowledge intensive NLP (natural language processing software) Tasks](https://arxiv.org/pdf/2005.11401.pdf?WT.mc_id=academic-105485-koreyst) គឺមាន៖

- **_RAG-Sequence_** ប្រើឯកសារដែលបានទាញដើម្បីប៉ាន់អោយចម្លើយល្អបំផុតដល់សំណួររបស់អ្នកប្រើ

- **RAG-Token** ប្រើឯកសារក្នុងការបង្កើតតួអក្សរបន្ទាប់ បន្ទាប់មកទាញយកពួកវាដើម្បីឆ្លើយសំណួររបស់អ្នកប្រើ

### ហេតុអ្វីអ្នកត្រូវប្រើ RAGs? 

- **ពហុភាពព័ត៌មាន:** ប្រាកដថាចម្លើយអត្ថបទមានភាពទាន់សម័យ និងបច្ចុប្បន្ន។ ដូច្នេះ វាបង្កើនសមត្ថភាពលើកិច្ចការเฉพาะខ្លោងដោយចូលដល់មូលដ្ឋានចំណេះដឹងខាងក្នុង។

- កាត់បន្ថយការបង្កប់ដោយប្រើ **ទិន្នន័យដែលអាចបញ្ជាក់បាន** ក្នុងមូលដ្ឋានចំណេះដឹងដើម្បីផ្តល់បរិបទដល់សំណួរអ្នកប្រើ។

- វា **សន្សំសំចៃថ្លៃថ្មី** ព្រោះវាមានតម្លៃតិចជាងការបង្រៀនលម្អិតទៅលើ LLM

## បង្កើតមូលដ្ឋានចំណេះដឹង

### ពីអត្ថបទទៅ embeddings

មុនពេលយើងផ្ទុកទិន្នន័យរបស់យើង យើងត្រូវបម្លែងវាទៅជាវ៉ិចទ័រ embeddings មុនពេលវាត្រូវបានផ្ទុកនៅក្នុងមូលដ្ឋានទិន្នន័យ។ បើអ្នកកំពុងវាយតម្លៃឯកសារធំ ឬអត្ថបទវែង អ្នកអាចបំបែកវាទៅជាជំពូកៗដោយផ្អែកលើយ៉ាងក្រោយទំនងនៃសំណួរដែលអ្នករំពឹងទុក។ ការបំបែក chunk អាចធ្វើនៅកម្រិតប្រយោគ ឬកម្រិតកថាខណ្ឌ។ ព្រោះ chunking ទទួលបានអត្ថន័យពីពាក្យទៀតនៅជុំវិញវា អ្នកអាចបន្ថែមបរិបទបន្ថែមទៅ chunk ដូចជា ការបញ្ចូលចំណងជើងឯកសារ ឬអត្ថបទមួយចំនួនមុន ឬក្រោយ chunk។ អ្នកអាចបំបែកទិន្នន័យដូចខាងក្រោម៖

```python
def split_text(text, max_length, min_length):
    words = text.split()
    chunks = []
    current_chunk = []

    for word in words:
        current_chunk.append(word)
        if len(' '.join(current_chunk)) < max_length and len(' '.join(current_chunk)) > min_length:
            chunks.append(' '.join(current_chunk))
            current_chunk = []

    # If the last chunk didn't reach the minimum length, add it anyway
    if current_chunk:
        chunks.append(' '.join(current_chunk))

    return chunks
```

បន្ទាប់ពីបានបំបែក chunk, យើងអាច embed អត្ថបទដោយប្រើម៉ូដែល embedding ផ្សេងៗ។ ម៉ូដែលមួយចំនួនដែលអ្នកអាចប្រើបាន មាន word2vec, ada-002 ដោយ OpenAI, Azure Computer Vision និងច្រើនទៀត។ ការជ្រើសម៉ូដែលសម្រាប់ប្រើ នឹងអាស្រ័យលើភាសាដែលអ្នកប្រើ ប្រភេទមាតិកា (អត្ថបទ/រូបភាព/សម្លេង) ទំហំចូលដែលវាអាច encode និងប្រវែងនៃការបញ្ចេញ embedding ។

### ភាពស្រដៀងវ៉ិចទ័រ

retriever នឹងស្វែងរកក្នុងមូលដ្ឋានចំណេះដឹងសម្រាប់ embeddings ដែលនៅជិតគ្នា — ជាដើមដែលជាភាគីជិតដ៏ខ្លាំង — ពីព្រោះពួកវាតំណាងឲ្យអត្ថបទដែលស្រដៀងគ្នា។ ក្នុងស្ថានភាពនេះ ពេលអ្នកប្រើដាក់សំណួរ វាត្រូវបាន embed ជាមុន ហើយបន្ទាប់មកប្រៀបធៀបជាមួយ embeddings ស្រដៀងគ្នា។ វិធីវាស់ផ្សេងទៀតដែលយើងអាចប្រើបានរួមមាន Euclidean distance ដែលជារបៀបវាស់បន្ទាត់ត្រង់រវាងចំណុចចុងវ៉ិចទ័រ និង dot product ដែលវាស់ផលបូកគុណនៃធាតុស្របគ្នា​ពីរ​ខាង​ក្នុងវ៉ិចទ័រ។

### សន្ទស្សន៍ស្វែងរក

ពេលធ្វើការទាញយក យើងត្រូវកសាងសន្ទស្សន៍ស្វែងរកសម្រាប់មូលដ្ឋានចំណេះដឹងរបស់យើង មុនពេលធ្វើការស្វែងរក។ សន្ទស្សន៍នឹងផ្ទុក embeddings របស់យើង ហើយអាចយក chunk ដែលស្រដៀងបំផុតចេញបានយ៉ាងរហ័ស ទោះជាមូលដ្ឋានធំប៉ុនណាក៏ដោយ។ យើងអាចបង្កើតសន្ទស្សន៍នៅក្នុងកន្លែងបុគ្គល ដោយប្រើ៖

```python
from sklearn.neighbors import NearestNeighbors

embeddings = flattened_df['embeddings'].to_list()

# Create the search index
nbrs = NearestNeighbors(n_neighbors=5, algorithm='ball_tree').fit(embeddings)

# To query the index, you can use the kneighbors method
distances, indices = nbrs.kneighbors(embeddings)
```

### ការរៀបចំឡើងវិញ

បន្ទាប់ពីលោកអ្នកបានសួរទិន្នន័យពីមូលដ្ឋាន អ្នកអាចត្រូវតែចាត់ថ្នាក់លទ្ធផលពីស្រដៀងបំផុត។ LLM reranking ប្រើបច្ចេកវិទ្យា Machine Learning ដើម្បីបង្កើនភាពពេញចិត្តនៃលទ្ធផលស្វែងរក ដោយរៀបចំវាពីពេញចិត្តបំផុត។ ប្រើ Azure AI Search, ការរៀបចំឡើងវិញត្រូវបានបំពេញដោយស្វ័យប្រវត្តិ ដោយប្រើ semantic reranker។ ឧទាហរណ៍ពីរបៀប reranking បានធ្វើ ដោយប្រើ nearest neighbours៖

```python
# Find the most similar documents
distances, indices = nbrs.kneighbors([query_vector])

# Print the three most similar documents with their distance to the question
for distance, index in zip(distances[0][:3], indices[0][:3]):
    print(flattened_df['chunks'].iloc[index])
    print(flattened_df['path'].iloc[index])

```

ជំហានចុងក្រោយ គឺបន្ថែម LLM របស់យើងចូលក្នុងប្រព័ន្ធ ដើម្បីអាចទទួលបានចម្លើយដែលបានដាំបđenលើទិន្នន័យរបស់យើង។ យើងអាចអនុវត្តវាជារបៀបដូចខាងក្រោម៖

```python
user_input = "what is a perceptron?"

def chatbot(user_input):
    # Convert the question to a query vector
    query_vector = create_embeddings(user_input)

    # Find the most similar documents
    distances, indices = nbrs.kneighbors([query_vector])

    # add documents to query  to provide context
    history = []
    for index in indices[0]:
        history.append(flattened_df['chunks'].iloc[index])

    # combine the history and the user input
    history.append(user_input)

    # create a message object
    messages=[
        {"role": "system", "content": "You are an AI assistant that helps with AI questions."},
        {"role": "user", "content": "\n\n".join(history) }
    ]

    # use the Responses API to generate a response
    response = client.responses.create(
        model="gpt-5-mini",
        max_output_tokens=800,
        input=messages,
        store=False,
    )

    return response.output_text

chatbot(user_input)
```

- ភាពពាក់ព័ន្ធ៖ វាយតម្លៃថាចម្លើយផ្គូរផ្គង និងពាក់ព័ន្ធនឹងសំណួរសួរឬអត់

## ករណីប្រើប្រាស់សម្រាប់ប្រើ RAG (ការបង្កើតដោយបន្ថែមការទាញយក) និងមូលដ្ឋានទិន្នន័យវ៉ិចទ័រ

មានករណីប្រើប្រាស់ជាច្រើនដែល RAG អាចធ្វើឲ្យកម្មវិធីរបស់អ្នកកាន់តែប្រសើរ ដូចជា៖

- សំនួរ និងការឆ្លើយសំណួរ៖ ដាំបđenទិន្នន័យក្រុមហ៊ុនទៅ chatbot ដែលអាចប្រើប្រាស់ដោយបុគ្គលិកក្នុងការសួរសំណួរ។

- ប្រព័ន្ធផ្នែកណែនាំ៖ ដែលអ្នកអាចបង្កើតប្រព័ន្ធផ្សំដោយតម្លៃស្រដៀងគ្នាដូចជាការចាក់ផ្សាយភាពយន្ត ភោជនីយដ្ឋាន និងច្រើនទៀត។

- សេវាកម្ម chatbot៖ អ្នកអាចផ្ទុកប្រវត្តិជជែក និងប្ដូរជជែកឲ្យផ្ទាល់ខ្លួនដោយផ្អែកលើទិន្នន័យអ្នកប្រើ។

- ស្វែងរករូបភាពដោយផ្អែកលើវ៉ិចទ័រដែលបានបញ្ចូល ដែលមានប្រយោជន៍ពេលធ្វើការទទួលស្គាល់រូបភាព និងបញ្ជាក់អាសន្នភាព។

## សេចក្ដីសង្ខេប

យើងបានគ្របដណ្ដប់តំបន់មូលដ្ឋាននៃ RAG ចាប់ពីការបញ្ចូលទិន្នន័យទៅក្នុងកម្មវិធី សំណួរអ្នកប្រើ និងលទ្ធផល។ ដើម្បីសម្រុកសម្រួលការបង្កើត RAG អ្នកអាចប្រើស៊េមវើកដូចជា Semantic Kernel, LangChain ឬ AutoGen។
