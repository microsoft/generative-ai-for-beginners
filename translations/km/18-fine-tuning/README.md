# ការតំណកម៉ូដែលធំរបស់អ្នក

ការប្រើម៉ូដែលភាសាធំដើម្បីសាងសង់កម្មវិធី AI កាន់តែច្នៃប្រឌិតមានបញ្ហាថ្មីៗ។ បញ្ហាសំខាន់មួយគឺការធានាគុណភាពនៃមតិយោបល់ (ភាពត្រឹមត្រូវ និងទាក់ទង) ក្នុងមាតិកាដែលម៉ូដែលបង្កើតសម្រាប់សំណើរបស់អ្នកប្រើប្រាស់មួយ។ នៅក្នុងមេរៀនមុនៗ យើងបានពិភាក្សាអំពីបច្ចេកវិទ្យាដូចជា វិស្វកម្មសំណើ និងការបង្កើតបន្ថែមដោយយកព័ត៌មានវិញ ដែលព្យាយាមដោះស្រាយបញ្ហាសម្រាំងដោយ _កែប្រែការបញ្ចូលសំណើ_ ទៅម៉ូដែលដែលមានរួច។

នៅក្នុងមេរៀនថ្ងៃនេះ យើងនឹងពិភាក្សាអំពីបច្ចេកវិទ្យាទីបី គឺ **ការតំណកម៉ូដែល** ដែលព្យាយាមដោះស្រាយបញ្ហាដោយ _បណ្តុះបណ្តាលម៉ូដែលឡើងវិញ_ ជាមួយទិន្នន័យបន្ថែម។ មកចូលរួមទៅក្នុងព័ត៌មានលម្អិត។

## គោលបំណងរៀន

មេរៀននេះណែនាំគំនិតនៃការតំណកសម្រាប់ម៉ូដែលភាសាដែលបានបណ្តុះបណ្តាលរួចហើយ អាចមើលឃើញអត្ថប្រយោជន៍ និងបញ្ហារបស់វិធីសាស្ត្រនេះ ហើយផ្តល់មគ្គុទេសក៍ពីពេលណា និងរបៀបទៅប្រើការតំណក ដើម្បីធ្វើឲ្យចំណុចរស់រវើកនៃម៉ូដែល AI របស់អ្នកកាន់តែល្អប្រសើរ។

នៅចុងបញ្ចប់មេរៀននេះ អ្នកគួរតែអាចបញ្ជាក់ចម្លើយសំណួរខាងក្រោមបាន៖

- តើការតំណកសម្រាប់ម៉ូដែលភាសាជាអ្វី?
- ពេលណា និងហេតុអ្វីបានជាការតំណកមានប្រយោជន៍?
- តើខ្ញុំអាចតំណកម៉ូដែលដែលបានបណ្តុះបណ្តាលរួចជាថ្មីបានយ៉ាងដូចម្តេច?
- តើមានកម្លាំងចិត្តអ្វីខ្លះក្នុងការតំណក?

ត្រៀមខ្លួនរួចហើយ? យើងចាប់ផ្តើមទៅ។

## មេរៀនរៀបរាប់ដោយរូបភាព

ចង់យល់កាន់តែច្បាស់ពីអ្វីដែលយើងនឹងគ្របដណ្តប់មុនធ្វើការចូលជ្រៅ? សូមមើលមេរៀនរៀបរាប់​នេះដែលពិពណ៌នាដំណើរការរៀនសម្រាប់មេរៀននេះ - ពីការសិក្សាគន្លងគោលនយោបាយ និងមេគោលចំណង់ចំណូលចិត្តក្នុងការតំណក ដល់ការយល់ដឹងដំណើរការនិងអនុវត្តន៍ល្អបំផុតសម្រាប់ការធ្វើការតំណក។ នេះជាប្រធានបទដែលគួរឲ្យចាប់អារម្មណ៍សម្រាប់ការស្វែងយល់ ដូច្នេះកុំភ្លេចមើលទំព័រ [ធនធាន](./RESOURCES.md?WT.mc_id=academic-105485-koreyst) សម្រាប់តំណភ្ជាប់បន្ថែមដើម្បីគាំទ្រដំណើរការរៀនដោយខ្លួនឯងរបស់អ្នក!

## តើការតំណកសម្រាប់ម៉ូដែលភាសាជាអ្វី?

ដោយនិយមន័យ ម៉ូដែលភាសាធំគឺជា _ម៉ូដែលដែលបានបណ្តុះបណ្តាលរួច_ លើចំនួនតំណាងអក្សរទីតាំងច្រើនពីប្រភពផ្សេងៗជារួមមានអ៊ីនធឺណិត។ ដូចដែលយើងបានរៀននៅមេរៀនមុនៗ យើងត្រូវការបច្ចេកវិទ្យាដូចជា _វិស្វកម្មសំណើ_ និង _ការបង្កើតបន្ថែមដោយយកព័ត៌មានវិញ_ ដើម្បីធ្វើឲ្យគុណភាពនៃការឆ្លើយតបរបស់ម៉ូដែលទៅនឹងសំណួររបស់អ្នកប្រើសម្រួលបានល្អ។

បច្ចេកទេសវិស្វកម្មសំណើពេញនិយមមួយជាបញ្ចូលការណែនាំបន្ថែមឲ្យម៉ូដែលអំពីអ្វីដែលគួរត្រូវបានរងចាំក្នុងការឆ្លើយតប ដោយផ្តល់ _ការណែនាំ_ (ការណែនាំច្បាស់លាស់) ឬ_ផ្តល់ឧទាហរណ៍ពីរបី_ (ការណែនាំប៉ុណ្ណោះ)។ វាត្រូវបានហៅថា _ការរៀនពីរបី_ ប៉ុន្តែវាមានកម្លាំងចិត្តពីរមុខគឺ៖

- កំណត់ចំនួនតួអក្សរម៉ូដែលអាចទទួលបាន ប្រែទៅកំណត់ចំនួនឧទាហរណ៍ដែលអ្នកអាចផ្តល់ និងកំណត់ប្រសិទ្ធិភាព។
- ចំណាយតួអក្សររបស់ម៉ូដែលអាចធ្វើឲ្យថ្លៃសូម្បីតែបន្ថែមឧទាហរណ៍ទៅក្នុងសំណើរ​នីមួយៗ ហើយកំណត់ភាពបត់បែន។

ការតំណកគឺជាបច្ចេកទេសទូទៅក្នុងប្រព័ន្ធសិក្សា ម៉ាស៊ីន ដែលយើងយកម៉ូដែលដែលបានបណ្តុះបណ្តាលរួចម្តងហើយ បណ្តុះបណ្តាលឡើងវិញជាមួយទិន្នន័យថ្មី ដើម្បីធ្វើឱ្យវាធ្វើការជាក់លាក់ល្អក្នុងបេសកកម្មជាក់លាក់មួយ។ ក្នុងបរិបទម៉ូដែលភាសា យើងអាចតំណកម៉ូដែលដែលបានបណ្តុះបណ្តាលរួច _ជាមួយជម្រើសឧទាហរណ៍ដែលបានរៀបចំសម្រាប់បេសកកម្មឬដែនការដែលបានកំណត់មួយ_ ដើម្បីបង្កើត **ម៉ូដែលប្ដូរតាមតម្រូវការ** ដែលមានភាពត្រឹមត្រូវ និងទាក់ទងច្រើនសម្រាប់បេសកកម្មឬដែនការនោះ។ អត្ថប្រយោជន៍បន្ថែមមួយនៃការតំណកគឺ វាអាចកាត់បន្ថយចំនួនឧទាហរណ៍ដែលត្រូវការដើម្បីរៀនពីរបី - កាត់បន្ថយការប្រើប្រាស់តួអក្សរនិងចំណាយដែលពាក់ព័ន្ធ។

## ពេលណានិងហេតុអ្វីយើងគួរតែតំណកម៉ូដែល?

នៅក្នុងបរិបទនេះ ពេលពិភាក្សាអំពីការតំណកយើងមានន័យទៅលើ **ការតំណកក្នុងការគ្រប់គ្រង** ដែលការបណ្តុះបណ្តាលឡើងវិញត្រូវបន្ថែមទិន្នន័យថ្មី ដែលមិនមែនជាផ្នែកនៃទិន្នន័យបណ្តុះបណ្តាលដើម។ វាផ្សេងពីវិធីសាស្ត្រតំណកមិនគ្រប់គ្រងដែលម៉ូដែលត្រូវបានបណ្តុះបណ្តាលឡើងវិញលើទិន្នន័យដើម ប៉ុន្តែជាមួយប៉ារ៉ាម៉ែត្រប្រតិបត្តិការផ្សេងៗ។

រឿងសំខាន់មួយដែលត្រូវចងចាំ គឺ ការតំណកគឺជាបច្ចេកទេសកម្រិតខ្ពស់ដែលត្រូវការជំនាញជាក់លាក់ ដើម្បីទទួលបានលទ្ធផលដែលចង់បាន។ ប្រសិនបើធ្វើខុស វាអាចមិនផ្តល់ការកែលម្អដូចដែលរំពឹងទុក ទៅទាំងអាចបន្ថយសមត្ថភាពរបស់ម៉ូដែលសម្រាប់ដែនការគោលដៅរបស់អ្នក។

ដូច្នេះ មុនពេលអ្នករៀនថា "របៀប" តំណកម៉ូដែលភាសា អ្នកត្រូវតែដឹង "ហេតុអ្វី" អ្នកគួរតែជ្រើសរើសវិធីនេះ ហើយ "ពេលណា" ចាប់ផ្តើមដំណើរការតំណក។ ចាប់ផ្តើមដោយសួរខ្លួនឯងសំណួរទាំងនេះ៖

- **ករណីប្រើប្រាស់**៖ តើ _ករណីប្រើប្រាស់_ របស់អ្នកសម្រាប់ការតំណកជាអ្វី? តើអ្វីជាផ្នែកនៃម៉ូដែលដែលបានបណ្តុះបណ្តាលរួចដែលអ្នកចង់កែលម្អ?
- **ជម្រើសផ្សេងទៀត**៖ តើអ្នកបានសាកល្បង _បច្ចេកទេសផ្សេងៗ_ ដើម្បីឈានដល់លទ្ធផលចង់បានហើយឬនៅ? ប្រើវា ដើម្បីបង្កើតមូលដ្ឋានសម្រាប់ការប្រៀបធៀប។
  - វិស្វកម្មសំណើ៖ សាកល្បងបច្ចេកទេសដូចជា few-shot prompting ជាមួយឧទាហរណ៍នៃការឆ្លើយតបដ៏ទាក់ទង។ ប្រមាសគុណភាពនៃការឆ្លើយតប។
  - ការបង្កើតបន្ថែមដោយយកព័ត៌មានវិញ៖ សាកល្បងបន្ថែមសំណើជាមួយលទ្ធផលស្វែងរកដោយស្វែងរកទិន្នន័យ។ ប្រមាសគុណភាពនៃការឆ្លើយតប។

- **រៀបចំទិន្នន័យត្រឹមត្រូវ។** ឯកសារបណ្តុះបណ្តាល និងផ្ទៀងផ្ទាត់ត្រូវជាទ្រង់ទ្រាយ JSONL, UTF-8 **ជាមួយ BOM**, មិនលើស ៥១២ មេកាបៃ, ប្រើរូបមន្តសារ chat-completions។ តែងតែមានឯកសារត្រួតពិនិត្យគុណភាព ដើម្បីត្រួតពិនិត្យមើលការរឹងប៉ិនពេក។
- **រក្សាសារ prompt ប្រព័ន្ធនៅពេលដំណើរការ inference។** ប្រើសារព្រមានដូចគ្នា ខណៈពេលហៅម៉ូដែលដូចដែលបានប្រើក្នុងការបណ្តុះបណ្តាល។
- **វាយតម្លៃកន្លែងផ្អែក - មិនត្រូវបំបែកចេញទៅចោលកន្លែងចុងក្រោយ។** Foundry រក្សាកន្លែងផ្អែកបញ្ចប់បីចុងក្រោយសម្រាប់ចេញផ្សាយ; ជ្រើសកន្លែងដែលធ្វើបានល្អបំផុតតាមការត្រួតពិនិត្យ `train_loss` / `valid_loss` និងភាពត្រឹមត្រូវតួអក្សរ។
- **វាស់ចំណាយតួអក្សររួមជាមួយគុណភាព** នៅពេលប្រៀបធៀបម៉ូដែលតំណកនិងមូលដ្ឋាន។
- **ធ្វើដំណើរការដោយបន្តទៅវិញទៅមកជាមួយ Fine-Tuning រហូតបន្ត** អ្នកអាចតំណកម៉ូដែលដែលបានតំណករួចលើទិន្នន័យថ្មី (គាំទ្រ OpenAI)។
- **ផ្តល់ចំណាយផ្នែកផ្ទុកមេត្តា។** ម៉ូដែលដែលបានប្ដូរត្រូវគិតថ្លៃរៀងរាល់ម៉ោង ហើយការផ្ទុកដែលមិនប្រើប្រាស់នឹងត្រូវលុបបាត់បន្ទាប់ពី ១៥ ថ្ងៃ - សម្អាតអ្វីដែលអ្នកមិនត្រូវការ។
