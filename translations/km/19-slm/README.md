SLM ត្រូវបានបត់បែនសម្រាប់ការសម្តែងលើប្រធានបទជាក់លាក់ទាំងបង្ហាញជាការពិសេសខ្ពស់ ប៉ុន្តែក៏អាចមានកំណត់នៅក្នុងការផ្តល់នូវការយល់ដឹងទូលំទូលាយលើផ្នែកច្រើននៃចំណេះដឹង។ ផ្ទុយពីនេះ LLM បំណងត្រូវបានបង្កើតឡើងដើម្បីច្បាស់លាស់ក្នុងវិញ្ញាសាបញ្ញាមនុស្សនៅកម្រិតទូលំទូលាយ។ ត្រូវបានហ្វឹកហាត់លើបរិមាណទិន្នន័យធំ និងចម្រុះ គេរាប់ថាអាចបំពេញបានល្អលើមុខងារផ្សេងៗ ដូចជាការធ្វើដំណើរការភាសាធម្មជាតិ និងកម្មវិធីប្រព័ន្ធ។

**វិស្វកម្មគណនា**

ការហ្វឹកហាត់ និងប្រើប្រាស់ LLM តម្រូវឲ្យមានធនធានធំ ដូចជាគណនាគ្រឿងកុំព្យូទ័រល្បឿនខ្ពស់ (GPU) ជាច្រើន។ ឧទាហរណ៍ ការហ្វឹកហាត់ម៉ូដែលដូចជា ChatGPT ចាប់ពីដំបូង ត្រូវការឧបករណ៍ GPU ជាច្រើននៅរយះពេលវែង។ ផ្ទុយមកវិញ SLM ដែលមានប៉ារ៉ាម៉ែត្រតិចជាង មានភាពងាយស្រួលក្នុងការប្រើប្រាស់ធនធានគណនា។ ម៉ូដែលដូចជា Mistral 7B អាចហ្វឹកហាត់ និងដំណើរការលើកុំព្យូទ័រផ្ទាល់ខ្លួនដែលមានសមត្ថភាព GPU មធ្យម ទោះបីការហ្វឹកហាត់ត្រូវការពេលវេលាច្រើនរយៈម៉ោងជាច្រើនលើ GPU ច្រើន។

**ការតំរូវការពណ៌នា**

ការប៉ុនប៉ងបាតឋិតិមាននៅ LLM ជារឿងធ្លាប់កើតឡើង ដោយសារតែធម្មជាតិទិន្នន័យហ្វឹកហាត់។ ម៉ូដែលទាំងនេះភាគច្រើនប្រើទិន្នន័យដើមដែលមានប្រយោជន៍ពីអ៊ីនធឺណិត ដែលអាចស្តិតស្ទង់ឬផ្សំស្តិត លើជនពលរដ្ឋមួយចំនួន, បង្កើតស្លាកខុសឬបញ្ចេញសង្ស័យភាសា ដែលសំលេងពីលក្ខណៈភាសាបានផ្លាស់ប្តូរតំបន់, ភាសាតំបន់។ លក្ខណៈស្មុគស្មាញនៃស្ថាបត្យកម្ម LLM អាចបង្កការពន្យារពេលបាតឋិតិ ដែលអាចមិនត្រូវបានចាប់អារម្មណ៍ ដោយមិនមានការកែលម្អយ៉ាងហ្មត់ចត់។ ផ្ទុយទៅវិញ SLM ដែលហ្វឹកហាត់លើទិន្នន័យជាគោលដៅច្បាស់ តិចជាងក្នុងការតំរូវបាតឋិតិទាំងនេះ ប៉ុន្តែវាមិនមែនជាការពិចារណាទៀតទេ។

**ការបញ្ជាក់ផល**

ទំហំតូចរបស់ SLM ផ្តល់អត្ថប្រយោជន៍យ៉ាងខ្លាំងក្នុងល្បឿនការបញ្ចេញទិន្នន័យ ឲ្យវាអាចបង្កើតចេញបានលឿនលើឧបករណ៍ក្នុងម៉ាស៊ីនដោយមិនត្រូវការប្រើបច្ចេកវិទ្យាគណនាច្រើនជាបណ្តោះអាសន្ន។ ផ្ទុយពីនេះ LLM គឺមកពីទំហំ និងស្មុគស្មាញខ្ពស់ ដែលតម្រូវឲ្យមានធនធានគណនា​ញឹកញាប់សម្រាប់ការបង្ហាញលទ្ធផលក្នុងរយៈពេលជាសមរម្យ។ ការមានអ្នកប្រើប្រាស់ជាច្រើនក្នុងពេលតែមួយក៍ធ្វើឲ្យពេលបញ្ចេញលទ្ធផលរបស់ LLM ធយ៉ាងខ្លាំង ពិសេសពេលដាក់ប្រើប្រាស់លើវិស័យធំនី។

សង្ខេបមក LLM និង SLM ទាំងពីរត្រូវបានបង្កើតលើមូលដ្ឋាននៃការសិក្សាម៉ាស៊ីន ប៉ុន្តែពួកវាមានភាពខុសគ្នាច្បាស់លាស់ក្នុងទំហំម៉ូដែល ការត្រូវការធនធាន ការយល់ដឹងទូលំទូលាយ ភាពងាយរងបាតឋិតិ និងល្បឿននៃការបញ្ចេញលទ្ធផល។ ភាពខុសគ្នារបស់ពួកវាបង្ហាញពីភាពសាកសមសម្រាប់ការប្រើប្រាស់លើករណីផ្សេងៗ ដោយ LLM មានប្រសិទ្ធភាព និងប្រើធនធានច្រើន ខណៈ SLM ផ្តល់ប្រសិទ្ធភាពលើវិស័យជាក់លាក់ជាមួយការត្រូវការផ្នែកគណនាតិចជាង។

***ចំណាំ៖ ក្នុងមេរៀននេះ យើងនឹងណែនាំ SLM ដោយប្រើ Microsoft Phi-3 / 3.5 ជាឧទាហរណ៍។***

### Phi-3 / 3.5 សម្រាប់ការណែនាំ

**Phi-3-mini**

ម៉ូដែលភាសា 3.8B មានស្រាប់នៅលើ Microsoft Foundry, Hugging Face, និង Ollama។ ម៉ូដែល Phi-3 ភាគច្រើនលើសម៉ូដែលភាសាទំហំដូចគ្នា និងធំជាងនៅលើកម្រិតសាកល្បងចម្បងៗ (មើលចំនួនសាកល្បងខាងក្រោម, ចំនួនខ្ពស់ជាងមានលទ្ធផលល្អជាង)។ Phi-3-mini មានលទ្ធផលលើសម៉ូដែលទំហំទ្វេដងរបស់វា ខណៈ Phi-3-small និង Phi-3-medium លើសម៉ូដែលធំៗរួមមាន GPT-3.5។

**ONNX Runtime សម្រាប់ GenAI**

[ONNX Runtime](https://github.com/microsoft/onnxruntime-genai?WT.mc_id=academic-105485-koreyst) គឺជាគម្រោងបន្សំម៉ូដែល និងបញ្ចេញការរំពឹងទុករបស់ម៉ាស៊ីនរៀននៅលើវេទិកាផ្សេងៗ។ ONNX Runtime សម្រាប់ Generative AI (GENAI) គឺជាឧបករណ៍ដ៏មានប្រសិទ្ធភាពដែលជួយឲ្យអ្នកដំណើរការម៉ូដែល AI បង្កើតអត្ថបទបានលឿនលើវេទិកាផ្សេងៗ។

## ONNX Runtime ជាអ្វី?
ONNX Runtime ជាគម្រោងកូដដើមបើកដែលអនុញ្ញាតឱ្យមានការបញ្ចេញលទ្ធផលគំរូម៉ាស៊ីនរៀនលឿន។ វាគាំទ្រម៉ូដែលក្នុងទ្រង់ទ្រាយ Open Neural Network Exchange (ONNX) ដែលជាស្តង់ដាសម្រាប់តំណាងម៉ូដែលម៉ាស៊ីនរៀន។ ការបញ្ចេញលទ្ធផល ONNX Runtime អាចធ្វើឲ្យបទពិសោធន៍អ្នកប្រើលឿន និងកាត់បន្ថយថ្លៃដើម ដោយគាំទ្រម៉ូដែលមកពីបណ្ដុំរៀនជ្រៅដូចជា PyTorch និង TensorFlow/Keras រួមទាំងបណ្ដុំម៉ាស៊ីនរៀនបែបចាស់ដូចជា scikit-learn, LightGBM, XGBoost, ល។ ONNX Runtime អាចប្រើបានជាមួយហ្រ្វេវ័រ, ដ្រាយវ័រ និងប្រព័ន្ធប្រតិបត្តិការផ្សេងៗ ហើយផ្តល់នូវសមត្ថភាពល្អបំផុតដោយប្រើហ្រ្វេវ័រទំនើប និងអនុវត្តបំលែងក្រាហ្វ។

## Generative AI ជាអ្វី?
Generative AI មានន័យថារបៀបប្រព័ន្ធ AI ដែលអាចបង្កើតមាតិកាថ្មីដូចជា អត្ថបទ រូបភាព ឬតន្ត្រី ដោយផ្អែកលើទិន្នន័យដែលវាបានបណ្តុះបណ្តាល។ ឧទាហរណ៍រួមមានម៉ូដែលភាសាដូចជា GPT-3 និងម៉ូដែលបង្កើតរូបភាពដូចជា Stable Diffusion។ បណ្ណាល័យ ONNX Runtime សម្រាប់ GenAI ផ្តល់រោងចក្របង្កើតអត្ថបទសម្រាប់ម៉ូដែល ONNX រួមមានការបញ្ចេញលទ្ធផលជាមួយ ONNX Runtime, ការត្រួតពិនិត្យ logits, ការស្វែងរក និងការដំឡើងគំរូ, និងការគ្រប់គ្រងម៉ាស៊ីនផ្ទុក KV cache។

## ONNX Runtime សម្រាប់ GENAI
ONNX Runtime សម្រាប់ GENAI ពង្រីកសមត្ថភាពរបស់ ONNX Runtime ដើម្បីគាំទ្រម៉ូដែល AI បង្កើតអត្ថបទ។ នេះជាគុណលក្ខណៈសំខាន់ៗ៖

- **គាំទ្រវេទិកាច្រើនមុខ:** វាដំណើរការលើវេទិកាផ្សេងៗ រួមទាំង Windows, Linux, macOS, Android និង iOS។
- **គាំទ្រម៉ូដែល:** វាគាំទ្រម៉ូដែល AI បង្កើតជាប្រភេទពេញនិយមជាច្រើន ដូចជា LLaMA, GPT-Neo, BLOOM និងផ្សេងៗទៀត។
- **បច្ចេកវិទ្យាផ្ទាល់ខ្លួនបង្ហាញល្បឿន:** វាមានការបំលែងជាច្រើនសម្រាប់ហ្រ្វេវ័រម៉ាស៊ីនដូចជា NVIDIA GPUs, AMD GPUs និងផ្សេងៗ។
- **ភាពងាយស្រួលប្រើ:** វាបំពេញ API សម្រាប់ការតំណភ្ជាប់សាមញ្ញទៅកម្មវិធី, អនុញ្ញាតឱ្យអ្នកបង្កើតអត្ថបទ រូបភាព និងមាតិកាផ្សេងៗការបានដោយកូដតិច។
- អ្នកប្រើប្រាស់អាចហៅវិធាន high level generate() ឬរត់មួយម្តងមួយនៃម៉ូដែលក្នុងលំហូរ ដើម្បីបង្កើតសញ្ញានិទេសមួយ និងបន្ទាន់សម័យប៉ារ៉ាម៉ែត្របង្កើតក្នុងលំហូរ។
- ONNX runtime ក៏គាំទ្រការស្វែងរក greedy/beam និង TopP, TopK ដើម្បីបង្កើតលំដាប់សញ្ញា និងមានការគ្រប់គ្រង logits ដូចជាការដាក់ពិនន័យទទេឡើងវិញ។ អ្នកអាចបញ្ចូលការវាយតម្លៃផ្ទាល់ខ្លួនបានយ៉ាងងាយស្រួលផងដែរ។

```Python
import onnxruntime_genai as og

model = og.Model('path_to_your_model.onnx')

tokenizer = og.Tokenizer(model)

input_text = "Hello, how are you?"

input_tokens = tokenizer.encode(input_text)

output_tokens = model.generate(input_tokens)

output_text = tokenizer.decode(output_tokens)

print(output_text) 
```
### សាកល្បង: ប្រើ ONNX Runtime GenAI ដើម្បីហៅ Phi-3.5-Vision


```python

import onnxruntime_genai as og

model_path = './Your Phi-3.5-vision-instruct ONNX Path'

img_path = './Your Image Path'

model = og.Model(model_path)

processor = model.create_multimodal_processor()

tokenizer_stream = processor.create_stream()

text = "Your Prompt"

prompt = "<|user|>\n"

prompt += "<|image_1|>\n"

prompt += f"{text}<|end|>\n"

prompt += "<|assistant|>\n"

image = og.Images.open(img_path)

inputs = processor(prompt, images=image)

params = og.GeneratorParams(model)

params.set_inputs(inputs)

params.set_search_options(max_length=3072)

generator = og.Generator(model, params)

while not generator.is_done():

    generator.compute_logits()
    
    generator.generate_next_token()

    new_token = generator.get_next_tokens()[0]
    
    output = tokenizer_stream.decode(new_token)
    
    print(tokenizer_stream.decode(new_token), end='', flush=True)

```
