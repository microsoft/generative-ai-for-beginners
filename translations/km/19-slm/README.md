# ចំណាំដល់ម៉ូដែលភាសាខ្នាតតូចសម្រាប់ AI បង្កើតសម្រាប់អ្នកចាប់ផ្តើម
AI បង្កើតគឺជាផ្នែកគួរឱ្យចាប់អារម្មណ៍នៃបញ្ញាស مصنوع ដែលផ្តោតលើការបង្កើតប្រព័ន្ធដែលអាចបង្កើតមាតិកាថ្មីៗ។ មាតិកានេះអាចមានចេលពីអត្ថបទ និងរូបភាព ទៅតន្ត្រី និងបរិដ្ឋានវេរជាផ្នែកទាំងមូលក៏បាន។ មួយក្នុងចំណោមការអនុវត្តសប្បាយប្រកបដោយសារសំខាន់នៃ AI បង្កើតគឺនៅក្នុងដែននៃម៉ូដែលភាសា។

## ម៉ូដែលភាសាខ្នាតតូចគឺជាអ្វី?

ម៉ូដែលភាសាខ្នាតតូច (SLM) តំណាងឲ្យមួយជាជម្រើសតូចជាងម៉ូដែលភាសាធំ (LLM) ដែលប្រើប្រាស់គោលការណ៍សំណុំបែបបទនិងបច្ចេកទេសជាច្រើនរបស់ LLM ខណៈពួកវាបង្ហាញពីការប្រើប្រាស់កុំព្យូទ័រតិចជាងយ៉ាងហោចណាស់។

SLM គឺជាតំបន់តិចតួចនៃម៉ូដែលភាសាដែលបានរចនាមកសម្រាប់បង្កើតអត្ថបទដូចជាមនុស្ស។ ផ្សេងពីម៉ូដែលធំៗដូចជា GPT-4, SLM មានទំហំតូច និងមានប្រសិទ្ធភាពខ្ពស់ជាង ដែលធ្វើឲ្យវា ល្អបំផុតសម្រាប់កម្មវិធីដែលមានធនធានកុំព្យូទ័រពិបាកប្រើប្រាស់។ ទោះបីជាមានទំហំតូច តែវានៅតែអាចអនុវត្តគប្បីកិច្ចការផ្សេងៗបាន។ ភាគច្រើន SLM ត្រូវបានបង្កើតឡើងដោយការសម្រុក ឬបញ្ជាទុកដោយការបញ្ចី LLM ដើម្បីរក្សាភាគច្រើននៃមុខងារ និងសមត្ថភាពភាសាដើម។ ការបន្ថយទំហំម៉ូដែលនេះធ្វើឱ្យកម្រិតកត្តាជាន់ខ្ពស់តិចជាង ធ្វើឲ្យ SLM មានប្រសិទ្ធភាពបន្ថែមទៀតហើយដោយផ្នែកចងចាំ និងតំរូវការកុំព្យូទ័រតិចជាង។ ទោះជាយ៉ាងនេះ ប៉ុន្តែ SLM នៅតែអាចអនុវត្តបាននូវកិច្ចការខុសៗគ្នានៃការបកស្រាយភាសាធម្មជាតិ (NLP)៖

- ការបង្កើតអត្ថបទ៖ បង្កើតឃ្លា ឬវាគ្រាបែបដែលមានលំនាំ និងផ្គូផ្គងតាមបរិបទ។
- ការបញ្ចប់អត្ថបទ៖ ការទស្សន៍ទាយ និងបញ្ចប់ឃ្លាដោយផ្អែកលើបរិបទដែលបានផ្តល់។
- ការប្រែសម្រួល៖ បម្លែងអត្ថបទពីភាសាមួយទៅភាសាមួយទៀត។
- ការសង្កេតសង្ខេប៖ កាត់ចុះអត្ថបទវែងៗទៅជាសង្ខេបខ្លី និងងាយស្រូបយក។

បើទោះបីជាមានការប្រែប្រួលខ្លះនៅក្នុងការអនុវត្តឬជម្រះជ្រៅនៃការយល់ដូចជាម៉ូដែលធំៗ។

## តើម៉ូដែលភាសាខ្នាតតូចដំណើរការ​យ៉ាងដូចម្តេច?

- ការប្រមូលទិន្នន័យ៖ ស្វែងរកឃ្លាំងទិន្នន័យអត្ថបទធំនេះពីប្រភពជាច្រើន។
- ការពុម្ពអក្សរ៖ សម្អាត និងរៀបចំទិន្នន័យឲ្យ សមស្រូបសម្រាប់ការបណ្តុះបណ្តាល។
- ការបណ្តុះបណ្តាល៖ ប្រើវិធីសាស្រ្តម៉ាស៊ីនរៀនដើម្បីបង្រៀនម៉ូដែលរបៀបយល់ និងបង្កើតអត្ថបទ។
- ការកំណត់ឱ្យប្រសើរ៖ កែសំរួលម៉ូដែលឲ្យប្រសើរឡើងនៅលើកិច្ចការពិសេសៗ។

ការអភិវឌ្ឍន៍ SLM ស្របទៅនឹងការតម្រូវកាន់តែច្រើនសម្រាប់ម៉ូដែលដែលអាចដាក់ប្រើនៅលើបរិយាកាសកាត់ទុនធនធាន ដូចជា ឧបករណ៍ចល័ត ឬវេទិកាក្នុងរយៈដែនខាងចុង (edge computing) ដែលមាន LLM ដែលគ្រប់គ្រងធនធានយ៉ាងធ្ងន់ធ្ងរ មិនអាច​ប្រើបាន។ ដោយផ្តោតលើការបង្កើតប្រសិទ្ធភាព SLM ប្រមាញ់តុល្យភាពរវាងការអនុវត្ត និងសមត្ថភាពចូលដំណើរការ តំណាងឲ្យការអភិវឌ្ឍន៍ដែលទូលំទូលាយក្នុងវិស័យផ្សេងៗ។

## ភាពខុសគ្នារវាងម៉ូដែលភាសាធំ (LLMs) និងម៉ូដែលភាសាខ្នាតតូច (SLMs)

ទាំង LLM និង SLM ត្រូវបានបង្កើតលើគោលការណ៍ស្វ័យប្រវត្តិមោទនភាពនៃម៉ាស៊ីនរៀន ដោយអនុវត្តវិធីសាស្រ្តស្រដៀងគ្នានៅលើការរចនា ដំណើរការបណ្តុះបណ្តាល ការបង្កើតទិន្នន័យ និងវិធីសាស្រ្តវាយតម្លៃម៉ូដែល។ ប៉ុន្តែ មានកត្តាសំខាន់ជាច្រើនដែលធ្វើឱ្យម៉ូដែលទាំងពីរប្រែប្រួលគ្នា។

## ការប្រើប្រាស់ម៉ូដែលភាសាខ្នាតតូច

SLM មានការអនុវត្តច្រើនដូចជា៖

- ប្រព័ន្ធចម្លើយសំណួរ (Chatbots): ផ្ដល់សេវាពិគ្រោះ និងធ្វើអន្តរកម្មជាមួយអ្នកប្រើប្រាស់ដោយរបៀបសន្ទនា។
- ការបង្កើតមាតិកា៖ ជួយអ្នកនិពន្ធក្នុងការបង្កើតគំនិត ឬសរសេរអត្ថបទពេញលេញ។
- ការអប់រំ៖ ជួយសិស្សក្នុងការសរសេរងារផ្ញើរ ឬរៀនភាសាថ្មីៗ។
- ការចូលរួមបានយ៉ាងងាយស្រួល៖ បង្កើតឧបករណ៍សម្រាប់មនុស្សពិការដូចជាប្រព័ន្ធបម្លែងអត្ថបទទៅសំលេង។

**ទំហំ**

### Phi-3.5-MoE

***Mixture of Experts (MoE)*** អនុញ្ញាតឲ្យម៉ូដែលត្រូវបានបណ្តុះបណ្តាលដោយតម្រូវការគណនា​តិចជាងនេះ ដែលមានន័យថាអ្នកអាចពង្រីកទំហំម៉ូដែល ឬទិន្នន័យតាមបរិមាណបានច្រើនជាងដោយទំនេរគណនាដូចម៉ូដែលដង់ស្តង់។ ជាពិសេស ម៉ូដែល MoE គួរត្រូវបានបណ្តុះលឿនជាងម៉ូដែលដង់ស្តង់ក្នុងដំណាក់កាលបណ្តុះបណ្តាល។

Phi-3.5-MoE មានរួមបញ្ចូលម៉ូឌុលជំនាញត្រូវបានបង្កប់ចំនួន 16x3.8B។ Phi-3.5-MoE ដែលមានត្រឹមតែ 6.6B ពារ៉ាម៉ែត្រសកម្ម ដល់កម្រិតនៃការវិភាគ ការយល់ភាសា និងគណិតវិទ្យាស្មើនឹងម៉ូដែលធំៗជាច្រើន។

យើងអាចប្រើម៉ូដែលគ្រួសារ Phi-3/3.5 ដោយផ្អែកលើសេណារីយ៉ូផ្សេងៗ។ ផ្ទុយពី LLM អ្នកអាចចាក់នៅ Phi-3/3.5-mini ឬ Phi-3/3.5-Vision នៅលើឧបករណ៍អេដច។

### ការរត់ Phi-3/3.5 ពីលើឧបករណ៍ក្នុងតំបន់
ការបញ្ចេញទាន (Inference) នៅទាក់ទងនឹង Phi-3 ឬគំរូភាសាណាមួយដូចជា GPT-3 បញ្ជាក់ពីដំណើរការផលិតចម្លើយ ឬការទស្សន៍ទាយផ្អែកលើការបញ្ចូលដែលវារៀបចំ។ នៅពេលអ្នកផ្ដល់សំណួរ ឬឈ្នាន់ឆ្លើយទៅ Phi-3 វាប្រើបណ្តាញប្រសាទដែលបានបណ្តុះបណ្តាលរួច ដើម្បីបង្ហាញចម្លើយដែលមានសក្តានុពល និងទាក់ទងដោយវិភាគលំហាត់និងទំនាក់ទំនងក្នុងទិន្នន័យដែលវាត្រូវបានបណ្តុះបណ្តាល។

**Hugging Face Transformer**
Hugging Face Transformers គឺជាបណ្ណាល័យមានថាមពល ដែលរចនាសម្រាប់បណ្តាញភាសាស្រស់ (NLP) និងបេសកកម្មរៀនម៉ាស៊ីនផ្សេងៗ។ ខាងក្រោមជាចំណុចសំខាន់ខ្លះៗអំពីវា៖

1. **គំរូដែលបានបណ្តុះបណ្តាលរួច**៖ វាបើកផ្តល់គំរូរាប់ពាន់ដែលបានបណ្តុះបណ្តាលរួចដែលអាចប្រើសម្រាប់បេសកកម្មផ្សេងៗ ដូចជា ការបែងចែកអត្ថបទ ការទាន់ចិត្តសារណាមួយ ការឆ្លើយសំណួរ ការសង្ខេប ការប្រែសម្រួល និងការបង្កើតអត្ថបទ។

2. **ការភ្ជាប់ជាមួយသម្ព៌គំរូផ្សេងៗ**៖ បណ្ណាល័យគាំទ្រតំបន់រៀនជម្រៅច្រើន ដូចជា PyTorch, TensorFlow, និង JAX។ នេះអាចឲ្យអ្នកបណ្តុះបណ្តាលគំរូក្នុងបណ្ដុំមួយ ហើយប្រើវានៅក្នុងបណ្ដុំផ្សេងទៀតបាន។

## ONNX Runtime ជាអ្វី?
ONNX Runtime គឺជាគម្រោងមូលដ្ឋានបើកចំហ ដែលអនុញ្ញាតឲ្យមានការបញ្ចេញទានមានប្រសិទ្ធភាពខ្ពស់សម្រាប់គំរូម៉ាស៊ីនរៀន។ វាគាំទ្រគំរូក្នុងទ្រង់ទ្រាយ Open Neural Network Exchange (ONNX) ដែលជាមាត្រដ្ឋានមួយសម្រាប់តំណាងគំរូម៉ាស៊ីនរៀន ។ ONNX Runtime អាចធ្វើដោយលឿនក្នុងការផ្តល់បទពិសោធន៍អ្នកប្រើ និងថវិកាបញ្ចុះ តាមគំរូទាំងពីរពីបណ្ដុំរៀនជម្រៅដូចជា PyTorch និង TensorFlow/Keras ដូចជាបណ្ណាល័យម៉ាស៊ីនរៀនបុរាណដូចជា scikit-learn, LightGBM, XGBoost ជាដើម។ ONNX Runtime លើកដៃគាំទ្រឧបករណ៍ hardware, ដ្រាយវើរ និងប្រព័ន្ធប្រតិបត្តិការ ខុសៗគ្នា និងផ្តល់ការសម្របសម្រួលខ្ពស់តាមរៀងទុកនូវ hardware accelerator ដែលអាចប្រើបាន ជាមួយការបង្ហាញការ graph ប្រែប្រួលនានា។

### រត់គំរូ៖ ឧទាហរណ៍ខាងមុខនេះសាមញ្ញក្នុង Python:
```Python
import onnxruntime_genai as og

model = og.Model('path_to_your_model.onnx')

tokenizer = og.Tokenizer(model)

input_text = "Hello, how are you?"

input_tokens = tokenizer.encode(input_text)

output_tokens = model.generate(input_tokens)

output_text = tokenizer.decode(output_tokens)

print(output_text) 
```
### សំណួរបង្ហាញ៖ ការប្រើ ONNX Runtime GenAI ដើម្បីហៅ Phi-3.5-Vision


```python

import onnxruntime_genai as og

model_path = './Your Phi-3.5-vision-instruct ONNX Path'

img_path = './Your Image Path'

model = og.Model(model_path)

processor = model.create_multimodal_processor()

tokenizer_stream = processor.create_stream()

text = "Your Prompt"

prompt = "<|user|>\n"

prompt += "<|image_1|>\n"

prompt += f"{text}<|end|>\n"

prompt += "<|assistant|>\n"

image = og.Images.open(img_path)

inputs = processor(prompt, images=image)

params = og.GeneratorParams(model)

params.set_inputs(inputs)

params.set_search_options(max_length=3072)

generator = og.Generator(model, params)

while not generator.is_done():

    generator.compute_logits()
    
    generator.generate_next_token()

    new_token = generator.get_next_tokens()[0]
    
    output = tokenizer_stream.decode(new_token)
    
    print(tokenizer_stream.decode(new_token), end='', flush=True)

```

លើសពីវិធីសាស្រ្តយោង ONNX Runtime, Ollama, និង Foundry Local រាងខាងលើ ក៏អាចបញ្ចប់ការយោងគំរូបរិមាណ ដោយផ្អែកលើវិធីសាស្រ្តយោងគំរូដែលផ្ដល់ដោយក្រុមហ៊ុនផលិតផ្សេងៗ។ ឧ. Apple MLX framework ជាមួយ Apple Metal, Qualcomm QNN ជាមួយ NPU, Intel OpenVINO ជាមួយ CPU/GPU ល. អ្នកអាចទទួលបានមាតិកាបន្ថែមពី [Phi-3 Cookbook](https://github.com/microsoft/phi-3cookbook?WT.mc_id=academic-105485-koreyst)។
