# Εισαγωγή στα Μικρά Γλωσσικά Μοντέλα για Γενετική Τεχνητή Νοημοσύνη για Αρχάριους
Η Γενετική Τεχνητή Νοημοσύνη είναι ένας συναρπαστικός τομέας της τεχνητής νοημοσύνης που εστιάζει στη δημιουργία συστημάτων ικανών να παράγουν νέο περιεχόμενο. Αυτό το περιεχόμενο μπορεί να ποικίλει από κείμενο και εικόνες μέχρι μουσική και ακόμη και ολόκληρα εικονικά περιβάλλοντα. Μία από τις πιο συναρπαστικές εφαρμογές της γενετικής τεχνητής νοημοσύνης είναι στον τομέα των γλωσσικών μοντέλων.

## Τι Είναι τα Μικρά Γλωσσικά Μοντέλα;

Ένα Μικρό Γλωσσικό Μοντέλο (SLM) αποτελεί μια μειωμένη παραλλαγή ενός μεγάλου γλωσσικού μοντέλου (LLM), αξιοποιώντας πολλές από τις αρχιτεκτονικές αρχές και τεχνικές των LLM, ενώ παρουσιάζει σημαντικά μειωμένο υπολογιστικό αποτύπωμα.

Τα SLM είναι ένα υποσύνολο γλωσσικών μοντέλων σχεδιασμένων να παράγουν κείμενο που μοιάζει με ανθρώπινο. Σε αντίθεση με τους μεγαλύτερους ομολόγους τους, όπως το GPT-4, τα SLM είναι πιο συμπαγή και αποδοτικά, καθιστώντας τα ιδανικά για εφαρμογές όπου οι υπολογιστικοί πόροι είναι περιορισμένοι. Παρά το μικρό τους μέγεθος, μπορούν να εκτελέσουν ποικίλες εργασίες. Συνήθως, τα SLM κατασκευάζονται με συμπίεση ή απόσταξη των LLM, με στόχο τη διατήρηση σημαντικού μέρους της λειτουργικότητας και των γλωσσικών ικανοτήτων του αρχικού μοντέλου. Αυτή η μείωση στο μέγεθος του μοντέλου μειώνει τη συνολική πολυπλοκότητα, καθιστώντας τα SLM πιο αποδοτικά τόσο σε όρους χρήσης μνήμης όσο και υπολογιστικών απαιτήσεων. Παρά αυτές τις βελτιστοποιήσεις, τα SLM μπορούν να εκτελέσουν ένα ευρύ φάσμα εργασιών επεξεργασίας φυσικής γλώσσας (NLP):

- Δημιουργία Κειμένου: Δημιουργία συνεκτικών και σχετικά σχετικών προτάσεων ή παραγράφων.
- Ολοκλήρωση Κειμένου: Πρόβλεψη και ολοκλήρωση προτάσεων βάσει ενός δεδομένου ερωτήματος.
- Μετάφραση: Μετατροπή κειμένου από μια γλώσσα σε άλλη.
- Περίληψη: Συμπύκνωση μεγάλων κειμένων σε συντομότερες, πιο ευκολοχώνευτες περιλήψεις.

Αν και με κάποιους συμβιβασμούς στην απόδοση ή στο βάθος κατανόησης σε σύγκριση με τους μεγαλύτερους ομολόγους τους.

## Πώς Λειτουργούν τα Μικρά Γλωσσικά Μοντέλα;
Τα SLM εκπαιδεύονται σε τεράστια ποσά δεδομένων κειμένου. Κατά την εκπαίδευση, μαθαίνουν τα μοτίβα και τις δομές της γλώσσας, επιτρέποντάς τους να παράγουν κείμενο που είναι τόσο γραμματικά σωστό όσο και κατάλληλο στο πλαίσιο. Η διαδικασία εκπαίδευσης περιλαμβάνει:

- Συλλογή Δεδομένων: Συγκέντρωση μεγάλων συνόλων δεδομένων κειμένου από διάφορες πηγές.
- Προεπεξεργασία: Καθαρισμός και οργάνωση των δεδομένων για να είναι κατάλληλα για εκπαίδευση.
- Εκπαίδευση: Χρήση αλγορίθμων μηχανικής μάθησης για να εκπαιδευτεί το μοντέλο να κατανοεί και να παράγει κείμενο.
- Λεπτομερής Προσαρμογή: Ρύθμιση του μοντέλου για βελτίωση της απόδοσής του σε συγκεκριμένες εργασίες.

Η ανάπτυξη των SLM ευθυγραμμίζεται με την αυξανόμενη ανάγκη για μοντέλα που μπορούν να αναπτυχθούν σε περιβάλλοντα με περιορισμένους πόρους, όπως κινητές συσκευές ή πλατφόρμες edge computing, όπου τα πλήρους κλίμακας LLM μπορεί να είναι μη πρακτικά λόγω των μεγάλων απαιτήσεων πόρων. Εστιάζοντας στην αποδοτικότητα, τα SLM εξισορροπούν την απόδοση με την προσβασιμότητα, επιτρέποντας ευρύτερη εφαρμογή σε διάφορους τομείς.

## Οι Διαφορές μεταξύ Μεγάλων Γλωσσικών Μοντέλων (LLMs) και Μικρών Γλωσσικών Μοντέλων (SLMs)

Τόσο τα LLM όσο και τα SLM βασίζονται σε θεμελιώδεις αρχές πιθανοκρατικής μηχανικής μάθησης, ακολουθώντας παρόμοιες προσεγγίσεις στον αρχιτεκτονικό σχεδιασμό, τις μεθοδολογίες εκπαίδευσης, τις διαδικασίες παραγωγής δεδομένων και τις τεχνικές αξιολόγησης μοντέλου. Ωστόσο, αρκετοί βασικοί παράγοντες διακρίνουν αυτούς τους δύο τύπους μοντέλων.

## Εφαρμογές των Μικρών Γλωσσικών Μοντέλων

Τα SLM έχουν ευρύ φάσμα εφαρμογών, συμπεριλαμβανομένων:

- Chatbots: Παροχή υποστήριξης πελατών και αλληλεπίδραση με χρήστες με συνομιλιακό τρόπο.
- Δημιουργία Περιεχομένου: Βοηθώντας συγγραφείς με τη δημιουργία ιδεών ή ακόμη και προσχέδιο ολόκληρων άρθρων.
- Εκπαίδευση: Βοηθώντας μαθητές με εργασίες γραφής ή εκμάθηση νέων γλωσσών.
- Προσβασιμότητα: Δημιουργία εργαλείων για άτομα με αναπηρίες, όπως συστήματα μετατροπής κειμένου σε ομιλία.

**Μέγεθος**
  
Μία βασική διαφορά μεταξύ LLM και SLM είναι το μέγεθος των μοντέλων. Τα LLM, όπως το ChatGPT (GPT-4), μπορούν να περιλαμβάνουν περίπου 1,76 τρισεκατομμύρια παραμέτρους, ενώ τα ανοιχτού κώδικα SLM όπως το Mistral 7B έχουν σχεδιαστεί με σημαντικά λιγότερες παραμέτρους—περίπου 7 δισεκατομμύρια. Αυτή η διαφορά οφείλεται κυρίως στις διαφορές στην αρχιτεκτονική και τις διαδικασίες εκπαίδευσης. Για παράδειγμα, το ChatGPT χρησιμοποιεί μηχανισμό αυτό-προσοχής μέσα σε ένα πλαίσιο κωδικοποιητή-αποκωδικοποιητή, ενώ το Mistral 7B χρησιμοποιεί μηχανισμό προσοχής με κινητό παράθυρο, που επιτρέπει πιο αποδοτική εκπαίδευση μέσα σε ένα αποκωδικοποιητή μόνο μοντέλο. Αυτή η αρχιτεκτονική διαφορά έχει σημαντικές επιπτώσεις στην πολυπλοκότητα και την απόδοση αυτών των μοντέλων.

**Κατανόηση**

Τα SLM είναι συνήθως βελτιστοποιημένα για απόδοση σε συγκεκριμένα πεδία, κάνοντάς τα πολύ εξειδικευμένα αλλά ενδεχομένως περιορισμένα στην ικανότητά τους να παρέχουν ευρεία κατανόηση πλαισίου σε πολλούς τομείς γνώσης. Αντιθέτως, τα LLM στοχεύουν να προσομοιώσουν ανθρώπινη νοημοσύνη σε πιο ολοκληρωμένο επίπεδο. Εκπαιδευόμενα σε τεράστια, ποικίλα σύνολα δεδομένων, τα LLM σχεδιάζονται ώστε να αποδίδουν καλά σε ποικίλους τομείς, προσφέροντας μεγαλύτερη ευελιξία και προσαρμοστικότητα. Κατά συνέπεια, τα LLM είναι πιο κατάλληλα για ευρύτερο φάσμα αποστολών, όπως η επεξεργασία φυσικής γλώσσας και ο προγραμματισμός.

**Υπολογιστική Ισχύς**

Η εκπαίδευση και η ανάπτυξη των LLM είναι διαδικασίες που απαιτούν πολλούς πόρους, συχνά απαιτώντας σημαντική υπολογιστική υποδομή, συμπεριλαμβανομένων μεγάλων συστοιχιών GPU. Για παράδειγμα, η εκπαίδευση ενός μοντέλου όπως το ChatGPT από την αρχή μπορεί να απαιτεί χιλιάδες GPUs για εκτεταμένες χρονικές περιόδους. Αντιθέτως, τα SLM, με τον μικρότερο αριθμό παραμέτρων, είναι πιο προσβάσιμα όσον αφορά τους υπολογιστικούς πόρους. Μοντέλα όπως το Mistral 7B μπορούν να εκπαιδευτούν και να τρέξουν σε τοπικά μηχανήματα με μέτριες δυνατότητες GPU, αν και η εκπαίδευση εξακολουθεί να απαιτεί αρκετές ώρες σε πολλαπλές GPUs.

**Μεροληψία**

Η μεροληψία είναι ένα γνωστό ζήτημα στα LLM, κυρίως λόγω της φύσης των δεδομένων εκπαίδευσης. Αυτά τα μοντέλα συχνά βασίζονται σε ακατέργαστα, δημόσια διαθέσιμα δεδομένα από το διαδίκτυο, τα οποία μπορεί να υποεκπροσωπούν ή να παραποιούν ορισμένες ομάδες, να εισάγουν λανθασμένες ετικέτες ή να αντικατοπτρίζουν γλωσσικές μεροληψίες επηρεασμένες από διάλεκτο, γεωγραφικές παραλλαγές και γραμματικούς κανόνες. Επιπλέον, η πολυπλοκότητα των αρχιτεκτονικών LLM μπορεί ακούσια να επιδεινώσει τη μεροληψία, η οποία μπορεί να παραμείνει αόρατη χωρίς προσεκτική λεπτή ρύθμιση. Αντιθέτως, τα SLM, εκπαιδευόμενα σε πιο περιορισμένα, τομεακά-ειδικά σύνολα δεδομένων, είναι εγγενώς λιγότερο επιρρεπή σε τέτοιες μεροληψίες, αν και δεν είναι αλώβητα από αυτές.

**Inference**

Το μειωμένο μέγεθος των SLM τους παρέχει σημαντικό πλεονέκτημα όσον αφορά την ταχύτητα inference, επιτρέποντάς τους να παράγουν εξόδους αποδοτικά σε τοπικό εξοπλισμό χωρίς την ανάγκη ευρείας παράλληλης επεξεργασίας. Αντίθετα, τα LLM, λόγω του μεγέθους και της πολυπλοκότητάς τους, συχνά απαιτούν σημαντικούς παράλληλους υπολογιστικούς πόρους για να επιτύχουν αποδεκτούς χρόνους inference. Η παρουσία πολλών ταυτόχρονων χρηστών επιβραδύνει περαιτέρω τους χρόνους ανταπόκρισης των LLM, ειδικά όταν λειτουργούν σε μεγάλη κλίμακα.

Συνοψίζοντας, ενώ τόσο τα LLM όσο και τα SLM μοιράζονται θεμελιώδη βάση στη μηχανική μάθηση, διαφέρουν σημαντικά όσον αφορά το μέγεθος του μοντέλου, τις απαιτήσεις πόρων, την κατανόηση πλαισίου, την ευπάθεια στη μεροληψία και την ταχύτητα inference. Αυτές οι διαφορές αντανακλούν την καταλληλότητά τους για διαφορετικές χρήσεις, με τα LLM να είναι πιο ευέλικτα αλλά απαιτητικά σε πόρους, και τα SLM να προσφέρουν πιο εξειδικευμένη αποδοτικότητα με μειωμένες υπολογιστικές απαιτήσεις.

## Παρουσίαση της Οικογένειας Phi-3 / Phi-3.5

Η οικογένεια Phi-3 / 3.5 απευθύνεται κυρίως σε σενάρια εφαρμογών κειμένου, όρασης και Agent (MoE):

### Phi-3 / 3.5 Instruct

Κυρίως για δημιουργία κειμένου, ολοκλήρωση συνομιλίας και εξαγωγή πληροφοριών περιεχομένου, κ.ά.

**Phi-3-mini**

Το γλωσσικό μοντέλο 3.8B είναι διαθέσιμο στο Microsoft Foundry, Hugging Face και Ollama. Τα μοντέλα Phi-3 υπερέχουν σημαντικά των γλωσσικών μοντέλων ίδιου και μεγαλύτερου μεγέθους σε βασικά benchmarks (βλ. αριθμούς benchmark παρακάτω, όπου μεγαλύτεροι αριθμοί σημαίνουν καλύτερα αποτελέσματα). Το Phi-3-mini υπερέχει μοντέλων διπλάσιου μεγέθους, ενώ τα Phi-3-small και Phi-3-medium υπερέχουν μεγαλύτερων μοντέλων, συμπεριλαμβανομένου του GPT-3.5.

**Phi-3-small & medium**

Με μόλις 7B παραμέτρους, το Phi-3-small νικά το GPT-3.5T σε μια ποικιλία γλωσσικών, λογικών, προγραμματιστικών και μαθηματικών benchmarks.

Το Phi-3-medium με 14B παραμέτρους συνεχίζει αυτή την τάση και υπερέχει του Gemini 1.0 Pro.

**Phi-3.5-mini**

Μπορούμε να το θεωρήσουμε ως αναβάθμιση του Phi-3-mini. Ενώ οι παράμετροι παραμένουν αμετάβλητες, βελτιώνει την ικανότητα υποστήριξης πολλαπλών γλωσσών (υποστηρίζει 20+ γλώσσες: Αραβικά, Κινέζικα, Τσέχικα, Δανικά, Ολλανδικά, Αγγλικά, Φινλανδικά, Γαλλικά, Γερμανικά, Εβραϊκά, Ουγγρικά, Ιταλικά, Ιαπωνικά, Κορεάτικα, Νορβηγικά, Πολωνικά, Πορτογαλικά, Ρωσικά, Ισπανικά, Σουηδικά, Ταϊλανδικά, Τουρκικά, Ουκρανικά) και προσθέτει ισχυρότερη υποστήριξη για μεγάλο πλαίσιο συμφραζομένων.

Το Phi-3.5-mini με 3.8B παραμέτρους υπερέχει των γλωσσικών μοντέλων ίδιου μεγέθους και είναι ισάξιο με μοντέλα διπλάσιου μεγέθους.

### Phi-3 / 3.5 Vision

Μπορούμε να θεωρήσουμε το Instruct μοντέλο του Phi-3/3.5 ως την ικανότητα του Phi να κατανοεί, ενώ το Vision είναι αυτό που δίνει στον Phi μάτια για να κατανοεί τον κόσμο.


**Phi-3-Vision**

Το Phi-3-vision, με μόλις 4.2B παραμέτρους, συνεχίζει αυτή την τάση και υπερέχει μεγαλύτερων μοντέλων όπως Claude-3 Haiku και Gemini 1.0 Pro V σε γενικά καθήκοντα οπτικής λογικής, OCR, και κατανόησης πινάκων και διαγραμμάτων.


**Phi-3.5-Vision**

Το Phi-3.5-Vision είναι επίσης μια αναβάθμιση του Phi-3-Vision, προσθέτοντας υποστήριξη για πολλαπλές εικόνες. Μπορείτε να το θεωρήσετε ως βελτίωση στην όραση, όχι μόνο βλέπετε εικόνες, αλλά και βίντεο.

Το Phi-3.5-vision υπερέχει μεγαλύτερων μοντέλων όπως Claude-3.5 Sonnet και Gemini 1.5 Flash στα καθήκοντα OCR, της κατανόησης πινάκων και γραφημάτων και είναι ισάξιο στα καθήκοντα γενικής οπτικής γνώσης και λογικής. Υποστηρίζει εισόδους με πολλαπλά καρέ, δηλαδή μπορεί να εκτελέσει αποκωδικοποίηση σε πολλαπλές εισερχόμενες εικόνες.


### Phi-3.5-MoE

***Mixture of Experts(MoE)*** επιτρέπει στα μοντέλα να προ-εκπαιδεύονται με πολύ λιγότερη υπολογιστική ισχύ, που σημαίνει ότι μπορείτε να κλιμακώσετε δραματικά το μέγεθος του μοντέλου ή των δεδομένων με τον ίδιο υπολογιστικό προϋπολογισμό σαν ένα πυκνό μοντέλο. Συγκεκριμένα, ένα μοντέλο MoE θα πρέπει να επιτυγχάνει την ίδια ποιότητα με τον πυκνό ομόλογό του πολύ πιο γρήγορα κατά την προ-εκπαίδευση.

Το Phi-3.5-MoE αποτελείται από 16x3.8B εξειδικευμένες μονάδες. Το Phi-3.5-MoE με μόλις 6.6B ενεργές παραμέτρους επιτυγχάνει παρόμοιο επίπεδο λογικής, γλωσσικής κατανόησης και μαθηματικών όπως πολύ μεγαλύτερα μοντέλα.

Μπορούμε να χρησιμοποιήσουμε το μοντέλο της οικογένειας Phi-3/3.5 βάσει διαφορετικών σεναρίων. Σε αντίθεση με τα LLM, μπορείτε να αναπτύξετε το Phi-3/3.5-mini ή το Phi-3/3.5-Vision σε συσκευές edge.

Το Hugging Face Transformers είναι μια ισχυρή βιβλιοθήκη σχεδιασμένη για επεξεργασία φυσικής γλώσσας (NLP) και άλλες εργασίες μηχανικής μάθησης. Εδώ είναι μερικά βασικά σημεία για αυτήν:

1. **Προεκπαιδευμένα Μοντέλα:** Παρέχει χιλιάδες προεκπαιδευμένα μοντέλα που μπορούν να χρησιμοποιηθούν για διάφορες εργασίες όπως ταξινόμηση κειμένου, αναγνώριση οντοτήτων, απάντηση σε ερωτήσεις, σύνοψη, μετάφραση και παραγωγή κειμένου.

3. **Πολυμορφικές Ικανότητες:** Εκτός από το NLP, το Hugging Face Transformers υποστηρίζει επίσης εργασίες στην υπολογιστική όραση (π.χ. ταξινόμηση εικόνας, ανίχνευση αντικειμένων) και επεξεργασία ήχου (π.χ. αναγνώριση ομιλίας, ταξινόμηση ήχου).

4. **Ευκολία Χρήσης:** Η βιβλιοθήκη προσφέρει APIs και εργαλεία για εύκολη λήψη και προσαρμογή μοντέλων, καθιστώντας την προσβάσιμη τόσο για αρχάριους όσο και για ειδικούς.

5. **Κοινότητα και Πόροι:** Το Hugging Face διαθέτει ζωντανή κοινότητα και εκτενή τεκμηρίωση, μαθήματα και οδηγούς για να βοηθήσει τους χρήστες να ξεκινήσουν και να αξιοποιήσουν στο έπακρο τη βιβλιοθήκη.

**ONNX Runtime για GenAI**

Το [ONNX Runtime](https://github.com/microsoft/onnxruntime-genai?WT.mc_id=academic-105485-koreyst) είναι ένας επιταχυντής μηχανικής μάθησης για επαγωγή και εκπαίδευση πολλαπλών πλατφορμών. Το ONNX Runtime για Generative AI (GENAI) είναι ένα ισχυρό εργαλείο που βοηθά στην αποτελεσματική εκτέλεση μοντέλων γεννητικής AI σε διάφορες πλατφόρμες.

## Τι είναι το ONNX Runtime;
Το ONNX Runtime είναι ένα έργο ανοικτού κώδικα που επιτρέπει υψηλής απόδοσης επαγωγή μοντέλων μηχανικής μάθησης. Υποστηρίζει μοντέλα στη μορφή Open Neural Network Exchange (ONNX), που είναι πρότυπο αναπαράστασης μοντέλων μηχανικής μάθησης. Η επαγωγή με ONNX Runtime μπορεί να επιταχύνει τις εμπειρίες των πελατών και να μειώσει το κόστος, υποστηρίζοντας μοντέλα από πλαίσια βαθιάς μάθησης όπως PyTorch και TensorFlow/Keras καθώς και κλασικές βιβλιοθήκες μηχανικής μάθησης όπως scikit-learn, LightGBM, XGBoost, κ.ά. Το ONNX Runtime είναι συμβατό με διαφορετικό υλικό, οδηγούς και λειτουργικά συστήματα, και παρέχει βέλτιστη απόδοση αξιοποιώντας επιταχυντές υλικού όταν είναι διαθέσιμοι, παράλληλα με βελτιστοποιήσεις και μετασχηματισμούς γραφημάτων.

## Τι είναι η Γεννητική Τεχνητή Νοημοσύνη;
Η γεννητική τεχνητή νοημοσύνη αναφέρεται σε συστήματα AI που μπορούν να δημιουργούν νέο περιεχόμενο, όπως κείμενο, εικόνες ή μουσική, βασισμένα στα δεδομένα στα οποία έχουν εκπαιδευτεί. Παραδείγματα είναι γλωσσικά μοντέλα όπως το GPT-3 και μοντέλα παραγωγής εικόνων όπως το Stable Diffusion. Η βιβλιοθήκη ONNX Runtime για GenAI παρέχει τον κύκλο γεννητικής AI για μοντέλα ONNX, συμπεριλαμβανομένης της επαγωγής με ONNX Runtime, της επεξεργασίας logits, της αναζήτησης και δειγματοληψίας, καθώς και της διαχείρισης προσωρινής μνήμης KV.

## ONNX Runtime για GENAI
Το ONNX Runtime για GENAI επεκτείνει τις δυνατότητες του ONNX Runtime για να υποστηρίξει μοντέλα γεννητικής AI. Εδώ είναι μερικά βασικά χαρακτηριστικά:

- **Ευρεία Υποστήριξη Πλατφορμών:** Λειτουργεί σε διάφορες πλατφόρμες, όπως Windows, Linux, macOS, Android και iOS.
- **Υποστήριξη Μοντέλων:** Υποστηρίζει πολλά δημοφιλή μοντέλα γεννητικής AI, όπως LLaMA, GPT-Neo, BLOOM και άλλα.
- **Βελτιστοποίηση Απόδοσης:** Περιλαμβάνει βελτιστοποιήσεις για διαφορετικούς επιταχυντές υλικού όπως NVIDIA GPUs, AMD GPUs και άλλα2.
- **Ευκολία Χρήσης:** Παρέχει APIs για εύκολη ενσωμάτωση σε εφαρμογές, επιτρέποντάς σας να δημιουργείτε κείμενο, εικόνες και άλλο περιεχόμενο με ελάχιστο κώδικα.
- Οι χρήστες μπορούν να καλέσουν μια υψηλού επιπέδου μέθοδο generate(), ή να εκτελέσουν κάθε επανάληψη του μοντέλου σε βρόχο, δημιουργώντας ένα token τη φορά, και προαιρετικά ενημερώνοντας παραμέτρους γεννήσεων μέσα στον βρόχο.
- Το ONNX runtime υποστηρίζει επίσης greedy/beam search και δειγματοληψία TopP, TopK για την παραγωγή ακολουθιών token καθώς και ενσωματωμένη επεξεργασία logits όπως ποινές επανάληψης. Μπορείτε επίσης εύκολα να προσθέσετε προσαρμοσμένη βαθμολόγηση.

```Python
import onnxruntime_genai as og

model = og.Model('path_to_your_model.onnx')

tokenizer = og.Tokenizer(model)

input_text = "Hello, how are you?"

input_tokens = tokenizer.encode(input_text)

output_tokens = model.generate(input_tokens)

output_text = tokenizer.decode(output_tokens)

print(output_text) 
```
### Παράδειγμα: Χρήση ONNX Runtime GenAI για κλήση Phi-3.5-Vision


```python

import onnxruntime_genai as og

model_path = './Your Phi-3.5-vision-instruct ONNX Path'

img_path = './Your Image Path'

model = og.Model(model_path)

processor = model.create_multimodal_processor()

tokenizer_stream = processor.create_stream()

text = "Your Prompt"

prompt = "<|user|>\n"

prompt += "<|image_1|>\n"

prompt += f"{text}<|end|>\n"

prompt += "<|assistant|>\n"

image = og.Images.open(img_path)

inputs = processor(prompt, images=image)

params = og.GeneratorParams(model)

params.set_inputs(inputs)

params.set_search_options(max_length=3072)

generator = og.Generator(model, params)

while not generator.is_done():

    generator.compute_logits()
    
    generator.generate_next_token()

    new_token = generator.get_next_tokens()[0]
    
    output = tokenizer_stream.decode(new_token)
    
    print(tokenizer_stream.decode(new_token), end='', flush=True)

```
