# Εισαγωγή στα Μικρά Γλωσσικά Μοντέλα για Γεννητική Τεχνητή Νοημοσύνη για Αρχάριους  
Η Γεννητική Τεχνητή Νοημοσύνη είναι ένας συναρπαστικός τομέας της τεχνητής νοημοσύνης που εστιάζει στη δημιουργία συστημάτων ικανών να παράγουν νέο περιεχόμενο. Αυτό το περιεχόμενο μπορεί να περιλαμβάνει κείμενο και εικόνες έως μουσική και ακόμη πλήρη εικονικά περιβάλλοντα. Μία από τις πιο συναρπαστικές εφαρμογές της γεννητικής τεχνητής νοημοσύνης είναι στον τομέα των γλωσσικών μοντέλων.  

## Τι Είναι τα Μικρά Γλωσσικά Μοντέλα;  

Ένα Μικρό Γλωσσικό Μοντέλο (SLM) αντιπροσωπεύει μια μειωμένη σε κλίμακα παραλλαγή ενός μεγάλου γλωσσικού μοντέλου (LLM), αξιοποιώντας πολλές από τις αρχιτεκτονικές αρχές και τεχνικές των LLM, ενώ παρουσιάζει σημαντικά μειωμένο υπολογιστικό αποτύπωμα.  

Τα SLM είναι ένα υποσύνολο γλωσσικών μοντέλων σχεδιασμένα να δημιουργούν κείμενο που μοιάζει ανθρώπινο. Σε αντίθεση με τους μεγαλύτερους ομολόγους τους, όπως το GPT-4, τα SLM είναι πιο συμπαγή και αποδοτικά, καθιστώντας τα ιδανικά για εφαρμογές όπου οι υπολογιστικοί πόροι είναι περιορισμένοι. Παρόλο που είναι μικρότερα, μπορούν να εκτελέσουν μια ποικιλία από εργασίες. Συνήθως, τα SLM κατασκευάζονται μέσω συμπίεσης ή απόσταξης των LLM, με στόχο να διατηρούν σημαντικό μέρος της λειτουργικότητας και των γλωσσικών ικανοτήτων του αρχικού μοντέλου. Αυτή η μείωση στο μέγεθος του μοντέλου μειώνει τη συνολική πολυπλοκότητα, καθιστώντας τα SLM πιο αποδοτικά σε όρους χρήσης μνήμης και υπολογιστικών απαιτήσεων. Παρά αυτές τις βελτιστοποιήσεις, τα SLM μπορούν ακόμα να εκτελέσουν ευρύ φάσμα εργασιών επεξεργασίας φυσικής γλώσσας (NLP):  

- Δημιουργία Κειμένου: Δημιουργία συνεκτικών και ουσιαστικά σχετικών προτάσεων ή παραγράφων.  
- Ολοκλήρωση Κειμένου: Πρόβλεψη και ολοκλήρωση προτάσεων βάσει μιας δοθείσας υπόδειξης.  
- Μετάφραση: Μετατροπή κειμένου από μια γλώσσα σε άλλη.  
- Περίληψη: Συμπύκνωση μεγάλων κειμένων σε πιο σύντομες και εύπεπτες περιλήψεις.  

Ενώ υπάρχουν κάποια ανταλλάγματα σε απόδοση ή βάθος κατανόησης σε σύγκριση με τους μεγαλύτερους ομολόγους τους.  

## Πώς Λειτουργούν τα Μικρά Γλωσσικά Μοντέλα;  
Τα SLM εκπαιδεύονται σε τεράστιες ποσότητες δεδομένων κειμένου. Κατά την εκπαίδευση, μαθαίνουν τα πρότυπα και τις δομές της γλώσσας, επιτρέποντάς τους να δημιουργούν κείμενο που είναι τόσο γραμματικά σωστό όσο και συμφραζόμενα κατάλληλο. Η διαδικασία εκπαίδευσης περιλαμβάνει:  

- Συλλογή Δεδομένων: Συγκέντρωση μεγάλων συνόλων δεδομένων κειμένου από διάφορες πηγές.  
- Προεπεξεργασία: Καθαρισμός και οργάνωση των δεδομένων ώστε να είναι κατάλληλα για εκπαίδευση.  
- Εκπαίδευση: Χρήση αλγορίθμων μηχανικής μάθησης για να διδάξουν το μοντέλο πώς να κατανοεί και να παράγει κείμενο.  
- Λεπτομερής Ρύθμιση: Προσαρμογή του μοντέλου για βελτίωση της απόδοσής του σε συγκεκριμένες εργασίες.  

Η ανάπτυξη των SLM ευθυγραμμίζεται με την αυξημένη ανάγκη για μοντέλα που μπορούν να αναπτυχθούν σε περιβάλλοντα με περιορισμένους πόρους, όπως φορητές συσκευές ή πλατφόρμες edge computing, όπου τα πλήρους κλίμακας LLM μπορεί να είναι πρακτικά ανεφάρμοστα λόγω των βαρέων απαιτήσεών τους σε πόρους. Επικεντρώνοντας την προσοχή στην αποδοτικότητα, τα SLM ισορροπούν την απόδοση με την προσβασιμότητα, επιτρέποντας ευρύτερη εφαρμογή σε διάφορους τομείς.

## Οι Διαφορές μεταξύ Μεγάλων Γλωσσικών Μοντέλων (LLMs) και Μικρών Γλωσσικών Μοντέλων (SLMs)  

Τα LLM και SLM βασίζονται σε θεμελιώδεις αρχές πιθανοκρατικής μηχανικής μάθησης, ακολουθώντας παρόμοιες προσεγγίσεις στο αρχιτεκτονικό τους σχεδιασμό, τις μεθοδολογίες εκπαίδευσης, τις διαδικασίες παραγωγής δεδομένων και τις τεχνικές αξιολόγησης μοντέλων. Ωστόσο, αρκετοί βασικοί παράγοντες διαφοροποιούν αυτούς τους δύο τύπους μοντέλων.  

## Εφαρμογές των Μικρών Γλωσσικών Μοντέλων  

Τα SLM έχουν ευρύ φάσμα εφαρμογών, όπως:  

- Chatbots: Παροχή υποστήριξης πελατών και αλληλεπίδραση με τους χρήστες με συνομιλιακό τρόπο.  
- Δημιουργία Περιεχομένου: Βοήθεια σε συγγραφείς με τη δημιουργία ιδεών ή ακόμα και τη σύνταξη ολόκληρων άρθρων.  
- Εκπαίδευση: Βοήθεια σε μαθητές με εργασίες γραφής ή εκμάθηση νέων γλωσσών.  
- Προσβασιμότητα: Δημιουργία εργαλείων για άτομα με αναπηρίες, όπως συστήματα μετατροπής κειμένου σε ομιλία.  

**Μέγεθος**  
  
Ένας βασικός διαχωρισμός μεταξύ LLM και SLM έγκειται στην κλίμακα των μοντέλων. Τα LLM, όπως το ChatGPT (GPT-4), μπορούν να περιλαμβάνουν περίπου 1.76 τρισεκατομμύρια παραμέτρους, ενώ ανοιχτού κώδικα SLM όπως το Mistral 7B είναι σχεδιασμένα με σημαντικά λιγότερες παραμέτρους — περίπου 7 δισεκατομμύρια. Αυτή η διαφορά οφείλεται κυρίως σε διαφορές στην αρχιτεκτονική του μοντέλου και τις διαδικασίες εκπαίδευσης. Για παράδειγμα, το ChatGPT χρησιμοποιεί μηχανισμό αυτο-προσοχής εντός πλαισίου κωδικοποιητή-αποκωδικοποιητή, ενώ το Mistral 7B χρησιμοποιεί προσαρμοζόμενη προσοχή παραθύρου, που επιτρέπει πιο αποδοτική εκπαίδευση εντός αποκωδικοποιητή μόνο. Αυτή η αρχιτεκτονική διαφορά έχει βαθιές επιπτώσεις στην πολυπλοκότητα και την απόδοση αυτών των μοντέλων.  

**Κατανόηση**  

Τα SLM συνήθως βελτιστοποιούνται για απόδοση εντός συγκεκριμένων τομέων, καθιστώντας τα ιδιαίτερα εξειδικευμένα αλλά ενδεχομένως περιορισμένα στην ικανότητά τους να παρέχουν ευρεία κατανόηση συμφραζομένων σε πολλούς τομείς γνώσης. Αντίθετα, τα LLM επιδιώκουν να προσομοιώσουν ανθρώπινη νοημοσύνη σε πιο ολοκληρωμένο επίπεδο. Εκπαιδευμένα σε τεράστια, ποικίλα σύνολα δεδομένων, τα LLM έχουν σχεδιαστεί για να αποδίδουν καλά σε ποικίλους τομείς, προσφέροντας μεγαλύτερη ευελιξία και προσαρμοστικότητα. Κατά συνέπεια, τα LLM είναι πιο κατάλληλα για ευρύτερο φάσμα εργασιών, όπως η επεξεργασία φυσικής γλώσσας και ο προγραμματισμός.  

**Υπολογιστική Ισχύς**  

Η εκπαίδευση και η ανάπτυξη των LLM είναι διαδικασίες που απαιτούν πολλούς πόρους, συχνά απαιτώντας σημαντική υποδομή υπολογιστών, συμπεριλαμβανομένων μεγάλων συστάδων GPU. Για παράδειγμα, η εκπαίδευση ενός μοντέλου όπως το ChatGPT από το μηδέν μπορεί να χρειαστεί χιλιάδες GPU για μεγάλο χρονικό διάστημα. Αντίθετα, τα SLM, με τους μικρότερους αριθμούς παραμέτρων τους, είναι πιο προσβάσιμα από πλευράς υπολογιστικών πόρων. Μοντέλα όπως το Mistral 7B μπορούν να εκπαιδευτούν και να λειτουργήσουν σε τοπικούς υπολογιστές με μέτριες δυνατότητες GPU, αν και η εκπαίδευση εξακολουθεί να απαιτεί αρκετές ώρες σε πολλαπλές GPU.  

**Μεροληψία**  

Η μεροληψία αποτελεί γνωστό πρόβλημα στα LLM, κυρίως λόγω της φύσης των δεδομένων εκπαίδευσης. Αυτά τα μοντέλα συχνά βασίζονται σε ακατέργαστα, ανοιχτά δεδομένα από το διαδίκτυο, τα οποία μπορεί να υποεκπροσωπούν ή να παραποιούν ορισμένες ομάδες, να εισάγουν λανθασμένη επισήμανση ή να αντανακλούν γλωσσικές μεροληψίες που επηρεάζονται από διάλεκτο, γεωγραφικές διαφορές και γραμματικούς κανόνες. Επιπλέον, η πολυπλοκότητα των αρχιτεκτονικών των LLM μπορεί αθέλητα να επιδεινώνει τη μεροληψία, η οποία μπορεί να παραμείνει απαρατήρητη χωρίς προσεκτική λεπτομερή ρύθμιση. Από την άλλη πλευρά, τα SLM, εκπαιδευμένα σε πιο περιορισμένα, ειδικά σε τομείς σύνολα δεδομένων, είναι εκ φύσεως λιγότερο επιρρεπή σε τέτοιες μεροληψίες, αν και δεν είναι αμόλυντα από αυτές.  

**Συμπέρασμα**  

Το μικρό μέγεθος των SLM τους προσφέρει σημαντικό πλεονέκτημα σε όρους ταχύτητας συμπερασμάτων, επιτρέποντάς τους να παράγουν αποτελέσματα αποδοτικά σε τοπικό υλικό χωρίς την ανάγκη εκτεταμένης παράλληλης επεξεργασίας. Αντίθετα, τα LLM, λόγω του μεγέθους και της πολυπλοκότητάς τους, συχνά απαιτούν σημαντικούς παράλληλους υπολογιστικούς πόρους για να επιτύχουν αποδεκτούς χρόνους συμπερασμάτων. Η παρουσία πολλών ταυτόχρονων χρηστών επιβραδύνει περαιτέρω τους χρόνους απόκρισης των LLM, ειδικά όταν αναπτύσσονται σε μεγάλη κλίμακα.  

Συνοψίζοντας, ενώ και τα LLM και τα SLM μοιράζονται μια θεμελιώδη βάση στη μηχανική μάθηση, διαφέρουν σημαντικά όσον αφορά το μέγεθος μοντέλου, τις απαιτήσεις πόρων, την κατανόηση των συμφραζομένων, την ευαισθησία στη μεροληψία και την ταχύτητα συμπεράσματος. Αυτές οι διαφορές αντικατοπτρίζουν την αντίστοιχη καταλληλότητά τους για διαφορετικές χρήσεις, με τα LLM να είναι πιο ευέλικτα αλλά βαριά σε πόρους, και τα SLM να προσφέρουν μεγαλύτερη αποδοτικότητα μείωσης πόρων ειδικά γι' αυτούς τους τομείς.

## Παρουσίαση της οικογένειας Phi-3 / Phi-3.5  

Η οικογένεια Phi-3 / 3.5 απευθύνεται κυρίως σε σενάρια εφαρμογών κειμένου, όρασης και Agent (MoE):  

### Phi-3 / 3.5 Instruct  

Κυρίως για δημιουργία κειμένου, ολοκλήρωση συνομιλίας και εξαγωγή πληροφοριών περιεχομένου κ.ά.  

**Phi-3-mini**  

Το γλωσσικό μοντέλο 3.8B είναι διαθέσιμο στο Microsoft Foundry, Hugging Face και Ollama. Τα μοντέλα Phi-3 υπερέχουν σημαντικά σε σχέση με γλωσσικά μοντέλα ίδιου ή μεγαλύτερου μεγέθους σε βασικά benchmark (δείτε τους αριθμούς benchmark παρακάτω, υψηλότεροι αριθμοί είναι καλύτεροι). Το Phi-3-mini υπερέχει των μοντέλων διπλάσιου μεγέθους, ενώ τα Phi-3-small και Phi-3-medium υπερέχουν ακόμα και από μεγαλύτερα μοντέλα, συμπεριλαμβανομένου του GPT-3.5.  

**Phi-3-small & medium**  

Με μόλις 7 δισεκατομμύρια παραμέτρους, το Phi-3-small ξεπερνά το GPT-3.5T σε διάφορα benchmark γλώσσας, λογικής, κωδικοποίησης και μαθηματικών.  

Το Phi-3-medium με 14 δισεκατομμύρια παραμέτρους συνεχίζει αυτή την τάση και ξεπερνά το Gemini 1.0 Pro.  

**Phi-3.5-mini**  

Μπορεί να θεωρηθεί ως αναβάθμιση του Phi-3-mini. Ενώ οι παράμετροι παραμένουν αμετάβλητες, βελτιώνει την ικανότητα υποστήριξης πολλαπλών γλωσσών (υποστηρίζει πάνω από 20 γλώσσες: Αραβικά, Κινέζικα, Τσέχικα, Δανέζικα, Ολλανδικά, Αγγλικά, Φινλανδικά, Γαλλικά, Γερμανικά, Εβραϊκά, Ουγγρικά, Ιταλικά, Ιαπωνικά, Κορεατικά, Νορβηγικά, Πολωνικά, Πορτογαλικά, Ρωσικά, Ισπανικά, Σουηδικά, Ταϊλανδέζικα, Τουρκικά, Ουκρανικά) και προσθέτει ισχυρότερη υποστήριξη για μεγάλα συμφραζόμενα.  

Το Phi-3.5-mini με 3.8 δισεκατομμύρια παραμέτρους υπερέχει των γλωσσικών μοντέλων ίδιας κλίμακας και είναι ισοδύναμο με μοντέλα διπλάσιου μεγέθους.  

### Phi-3 / 3.5 Όραση  

Μπορούμε να θεωρήσουμε το μοντέλο Instruct του Phi-3/3.5 ως την ικανότητα του Phi να κατανοεί, ενώ η Όραση δίνει στο Phi "μάτια" για να κατανοεί τον κόσμο.  


**Phi-3-Vision**  

Το Phi-3-vision, με μόλις 4.2B παραμέτρους, συνεχίζει αυτή την τάση και υπερέχει από μεγαλύτερα μοντέλα όπως Claude-3 Haiku και Gemini 1.0 Pro V σε γενικές εργασίες οπτικής λογικής, OCR και κατανόησης πινάκων και διαγραμμάτων.  


**Phi-3.5-Vision**  

Το Phi-3.5-Vision είναι επίσης μια αναβάθμιση του Phi-3-Vision, προσθέτοντας υποστήριξη για πολλαπλές εικόνες. Μπορεί να θεωρηθεί ως βελτίωση στην όραση, όπου δεν βλέπετε μόνο εικόνες, αλλά και βίντεο.  

Το Phi-3.5-vision υπερέχει σε μεγαλύτερα μοντέλα όπως Claude-3.5 Sonnet και Gemini 1.5 Flash σε εργασίες OCR, κατανόησης πινάκων και διαγραμμάτων, και είναι ισοδύναμο σε γενικές εργασίες οπτικής λογικής. Υποστηρίζει είσοδο πολλαπλών καρέ, δηλαδή μπορεί να εκτελεί λογική σε πολλαπλές εισερχόμενες εικόνες.  


### Phi-3.5-MoE  

***Mixture of Experts (MoE)*** επιτρέπει στα μοντέλα να προ-εκπαιδεύονται με πολύ λιγότερη υπολογιστική ισχύ, που σημαίνει ότι μπορείτε να κλιμακώσετε δραματικά το μέγεθος του μοντέλου ή το σύνολο δεδομένων με τον ίδιο προϋπολογισμό υπολογισμών όπως ένα πυκνό μοντέλο. Ειδικότερα, ένα μοντέλο MoE θα πρέπει να επιτυγχάνει την ίδια ποιότητα με το πυκνό αντίστοιχό του πολύ πιο γρήγορα κατά την προεκπαίδευση.  

Το Phi-3.5-MoE αποτελείται από 16x3.8B expert modules. Το Phi-3.5-MoE με μόλις 6.6B ενεργές παραμέτρους επιτυγχάνει παρόμοιο επίπεδο λογικής, κατανόησης γλώσσας και μαθηματικών με πολύ μεγαλύτερα μοντέλα.  

Μπορούμε να χρησιμοποιήσουμε το μοντέλο της οικογένειας Phi-3/3.5 βάσει διαφορετικών σεναρίων. Σε αντίθεση με τα LLM, μπορείτε να αναπτύξετε το Phi-3/3.5-mini ή το Phi-3/3.5-Vision σε περιφερειακές συσκευές.

**NVIDIA NIM**  

Επιπλέον του κατάλογου Microsoft Foundry Models στο cloud, μπορείτε επίσης να χρησιμοποιήσετε το [NVIDIA NIM](https://developer.nvidia.com/nim?WT.mc_id=academic-105485-koreyst) για να ολοκληρώσετε σχετικές κλήσεις. Μπορείτε να επισκεφτείτε το NVIDIA NIM για να ολοκληρώσετε τις κλήσεις API της οικογένειας Phi-3/3.5. Το NVIDIA NIM (NVIDIA Inference Microservices) είναι ένα σύνολο επιταχυνόμενων μικροϋπηρεσιών συμπερασμάτων σχεδιασμένο να βοηθάει προγραμματιστές να αναπτύσσουν AI μοντέλα αποδοτικά σε διάφορα περιβάλλοντα, συμπεριλαμβανομένων cloud, κέντρων δεδομένων και σταθμών εργασίας.  

Ορισμένα βασικά χαρακτηριστικά του NVIDIA NIM είναι:  

- **Ευκολία Ανάπτυξης:** Το NIM επιτρέπει την ανάπτυξη μοντέλων AI με μία εντολή, καθιστώντας το απλό να ενσωματωθεί σε υπάρχουσες ροές εργασίας.
- **Βελτιστοποιημένη Απόδοση:** Αξιοποιεί τις προ-βελτιστοποιημένες μηχανές ανάλυσης της NVIDIA, όπως TensorRT και TensorRT-LLM, για να διασφαλίσει χαμηλή καθυστέρηση και υψηλή απόδοση.
- **Κλιμάκωση:** Το NIM υποστηρίζει αυτόματη κλιμάκωση στο Kubernetes, επιτρέποντάς του να διαχειρίζεται αποτελεσματικά ποικίλα φορτία εργασίας.
- **Ασφάλεια και Έλεγχος:** Οι οργανισμοί μπορούν να διατηρούν έλεγχο στα δεδομένα και τις εφαρμογές τους φιλοξενώντας οι ίδιοι τις υπηρεσίες microservices του NIM στην ίδια τη διαχειριζόμενη υποδομή τους.
- **Τυπικά API:** Το NIM παρέχει API βιομηχανικού προτύπου, καθιστώντας εύκολη την κατασκευή και ενσωμάτωση εφαρμογών AI όπως chatbots, βοηθούς AI, και άλλα.

Το NIM αποτελεί μέρος του NVIDIA AI Enterprise, το οποίο στοχεύει στην απλοποίηση της ανάπτυξης και λειτουργίας μοντέλων AI, διασφαλίζοντας ότι εκτελούνται αποδοτικά σε GPUs της NVIDIA.

**Hugging Face Transformer**
Το Hugging Face Transformers είναι μια ισχυρή βιβλιοθήκη σχεδιασμένη για επεξεργασία φυσικής γλώσσας (NLP) και άλλες εργασίες μηχανικής μάθησης. Ιδού μερικά βασικά σημεία σχετικά με αυτήν:

1. **Προ-εκπαιδευμένα Μοντέλα**: Παρέχει χιλιάδες προ-εκπαιδευμένα μοντέλα που μπορούν να χρησιμοποιηθούν για διάφορες εργασίες όπως ταξινόμηση κειμένου, αναγνώριση οντοτήτων, απαντήσεις σε ερωτήσεις, συνοψίσεις, μετάφραση και δημιουργία κειμένου.

2. **Διαλειτουργικότητα Πλαισίων Εργασίας:** Η βιβλιοθήκη υποστηρίζει πολλαπλά πλαίσια βαθιάς μάθησης, όπως PyTorch, TensorFlow και JAX. Αυτό σας επιτρέπει να εκπαιδεύσετε ένα μοντέλο σε ένα πλαίσιο και να το χρησιμοποιήσετε σε άλλο.

3. **Πολλαπλές Δυνατότητες:** Εκτός από το NLP, το Hugging Face Transformers υποστηρίζει εργασίες στην υπολογιστική όραση (π.χ. ταξινόμηση εικόνας, εντοπισμός αντικειμένων) και επεξεργασία ήχου (π.χ. αναγνώριση ομιλίας, ταξινόμηση ήχου).

4. **Ευκολία Χρήσης:** Η βιβλιοθήκη προσφέρει API και εργαλεία για εύκολη λήψη και λεπτομερή προσαρμογή μοντέλων, κάνοντάς την προσβάσιμη τόσο σε αρχάριους όσο και σε ειδικούς.

5. **Κοινότητα και Πόροι:** Το Hugging Face διαθέτει μια ζωντανή κοινότητα και εκτενή τεκμηρίωση, σεμινάρια και οδηγούς για να βοηθήσει τους χρήστες να ξεκινήσουν και να αξιοποιήσουν στο έπακρο τη βιβλιοθήκη.
[επίσημη τεκμηρίωση](https://huggingface.co/docs/transformers/index?WT.mc_id=academic-105485-koreyst) ή το [αποθετήριο τους στο GitHub](https://github.com/huggingface/transformers?WT.mc_id=academic-105485-koreyst).

Αυτή είναι η πιο συχνά χρησιμοποιούμενη μέθοδος, αλλά απαιτεί επίσης επιτάχυνση GPU. Άλλωστε, σενάρια όπως το Vision και MoE απαιτούν πολλούς υπολογισμούς, που θα είναι πολύ αργοί σε CPU αν δεν ποσοτικοποιηθούν.

**ONNX Runtime για GenAI**

[ONNX Runtime](https://github.com/microsoft/onnxruntime-genai?WT.mc_id=academic-105485-koreyst) είναι ένας επιταχυντής μηχανικής μάθησης για ανάλυση και εκπαίδευση πολλαπλών πλατφορμών. Το ONNX Runtime για Generative AI (GENAI) είναι ένα ισχυρό εργαλείο που βοηθά στην αποτελεσματική εκτέλεση γεννητικών μοντέλων AI σε διάφορες πλατφόρμες.

## Τι είναι το ONNX Runtime;
Το ONNX Runtime είναι ένα έργο ανοικτού κώδικα που επιτρέπει υψηλής απόδοσης ανάλυση μοντέλων μηχανικής μάθησης. Υποστηρίζει μοντέλα στη μορφή Open Neural Network Exchange (ONNX), που είναι ένα πρότυπο για την αναπαράσταση μοντέλων μηχανικής μάθησης. Το ONNX Runtime μπορεί να επιταχύνει τις εμπειρίες πελατών και να μειώσει τα κόστη, υποστηρίζοντας μοντέλα από πλαίσια βαθιάς μάθησης όπως PyTorch και TensorFlow/Keras, καθώς και κλασικές βιβλιοθήκες μηχανικής μάθησης όπως scikit-learn, LightGBM, XGBoost κ.α. Το ONNX Runtime είναι συμβατό με διάφορα υλικά, οδηγούς και λειτουργικά συστήματα και παρέχει βέλτιστη απόδοση αξιοποιώντας επιταχυντές υλικού όπου είναι εφικτό μαζί με βελτιστοποιήσεις και μετασχηματισμούς γραφήματος.

## Τι είναι η Γεννητική AI;
Η γεννητική AI αναφέρεται σε συστήματα τεχνητής νοημοσύνης που μπορούν να παράγουν νέο περιεχόμενο, όπως κείμενο, εικόνες ή μουσική, βασισμένα στα δεδομένα με τα οποία έχουν εκπαιδευτεί. Παραδείγματα περιλαμβάνουν μοντέλα γλώσσας όπως το GPT-3 και μοντέλα παραγωγής εικόνων όπως το Stable Diffusion. Η βιβλιοθήκη ONNX Runtime για GenAI παρέχει τον γεννητικό βρόχο AI για μοντέλα ONNX, συμπεριλαμβανομένης της ανάλυσης με ONNX Runtime, της επεξεργασίας λογίτων, της αναζήτησης και δειγματοληψίας, καθώς και της διαχείρισης KV cache.

## ONNX Runtime για GENAI
Το ONNX Runtime για GENAI επεκτείνει τις δυνατότητες του ONNX Runtime ώστε να υποστηρίζει γεννητικά μοντέλα AI. Ιδού μερικά βασικά χαρακτηριστικά:

- **Ευρεία Υποστήριξη Πλατφόρμας:** Λειτουργεί σε διάφορες πλατφόρμες, όπως Windows, Linux, macOS, Android και iOS.
- **Υποστήριξη Μοντέλων:** Υποστηρίζει πολλά δημοφιλή γεννητικά μοντέλα AI, όπως LLaMA, GPT-Neo, BLOOM, και άλλα.
- **Βελτιστοποίηση Απόδοσης:** Περιλαμβάνει βελτιστοποιήσεις για διάφορους επιταχυντές υλικού όπως NVIDIA GPUs, AMD GPUs, κ.ά.
- **Ευκολία Χρήσης:** Παρέχει API για εύκολη ενσωμάτωση σε εφαρμογές, επιτρέποντάς σας να παράγετε κείμενο, εικόνες και άλλο περιεχόμενο με ελάχιστο κώδικα
- Οι χρήστες μπορούν να καλέσουν μια μέθοδο generate() υψηλού επιπέδου, ή να τρέξουν κάθε επανάληψη του μοντέλου σε βρόχο, παράγοντας ένα token κάθε φορά, και προαιρετικά ενημερώνοντας παραμέτρους παραγωγής μέσα στον βρόχο.
- Το ONNX runtime έχει επίσης υποστήριξη για greedy/beam search και δειγματοληψία TopP, TopK για την παραγωγή ακολουθιών token, καθώς και ενσωματωμένη επεξεργασία λογίτων όπως ποινές επανάληψης. Μπορείτε επίσης εύκολα να προσθέσετε προσαρμοσμένη βαθμολόγηση.

### Εκτέλεση μοντέλου: Εδώ είναι ένα απλό παράδειγμα σε Python:
```Python
import onnxruntime_genai as og

model = og.Model('path_to_your_model.onnx')

tokenizer = og.Tokenizer(model)

input_text = "Hello, how are you?"

input_tokens = tokenizer.encode(input_text)

output_tokens = model.generate(input_tokens)

output_text = tokenizer.decode(output_tokens)

print(output_text) 
```
### Demo: Χρήση ONNX Runtime GenAI για κλήση Phi-3.5-Vision


```python

import onnxruntime_genai as og

model_path = './Your Phi-3.5-vision-instruct ONNX Path'

img_path = './Your Image Path'

model = og.Model(model_path)

processor = model.create_multimodal_processor()

tokenizer_stream = processor.create_stream()

text = "Your Prompt"

prompt = "<|user|>\n"

prompt += "<|image_1|>\n"

prompt += f"{text}<|end|>\n"

prompt += "<|assistant|>\n"

image = og.Images.open(img_path)

inputs = processor(prompt, images=image)

params = og.GeneratorParams(model)

params.set_inputs(inputs)

params.set_search_options(max_length=3072)

generator = og.Generator(model, params)

while not generator.is_done():

    generator.compute_logits()
    
    generator.generate_next_token()

    new_token = generator.get_next_tokens()[0]
    
    output = tokenizer_stream.decode(new_token)
    
    print(tokenizer_stream.decode(new_token), end='', flush=True)

```
