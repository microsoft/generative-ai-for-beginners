# Внесение вклада

Этот проект приветствует вклады и предложения. Большинство вкладов требуют, чтобы вы
согласились с Лицензионным соглашением для участников (CLA), в котором заявляете, что имеете право
и фактически предоставляете нам права использовать ваш вклад. Для подробностей посетите
<https://cla.microsoft.com>.

> Важно: при переводе текста в этом репозитории, пожалуйста, убедитесь, что не используете машинный перевод. Мы будем проверять переводы через сообщество, поэтому добровольно принимайте участие в переводах только на тех языках, которыми вы владеете.

При отправке pull-запроса CLA-бот автоматически определит, нужно ли вам
предоставить CLA и соответствующим образом отметит PR (например, ярлыком или комментарием). Просто следуйте
инструкциям бота. Это потребуется сделать только один раз во всех репозиториях, использующих наш CLA.

## Опечатки, проблемы, ошибки и вклады

При отправке любых изменений в репозиторий Generative AI for Beginners, пожалуйста, следуйте этим рекомендациям.

* Всегда форкайте репозиторий в свой аккаунт перед внесением изменений
* Не объединяйте несколько изменений в один pull-запрос. Например, отправляйте исправления ошибок и обновления документации в отдельных PR
* Если в вашем pull-запросе есть конфликты слияния, убедитесь, что вы обновили локальную ветку main так, чтобы она соответствовала основной ветке репозитория перед внесением изменений
* Если вы отправляете перевод, пожалуйста, создайте один PR для всех переведённых файлов, так как частичные переводы содержимого не принимаются
* Если вы отправляете исправление опечатки или документации, вы можете объединить изменения в одном PR, если это уместно

## Общие рекомендации по написанию

- Убедитесь, что все ваши URL заключены в квадратные скобки с последующими круглыми скобками без лишних пробелов вокруг или внутри них `[]()`.
- Убедитесь, что любой относительный линк (то есть ссылки на другие файлы и папки в репозитории) начинается с `./`, указывающего на файл или папку в текущем рабочем каталоге или `../`, указывающего на файл или папку в родительском каталоге.
- Убедитесь, что любой относительный линк (то есть ссылки на другие файлы и папки в репозитории) имеет трекинг ID (то есть `?` или `&` затем `wt.mc_id=` или `WT.mc_id=`) в конце.
- Убедитесь, что любой URL из следующих доменов _github.com, microsoft.com, visualstudio.com, aka.ms, и azure.com_ имеет трекинг ID (то есть `?` или `&` затем `wt.mc_id=` или `WT.mc_id=`) в конце.
- Убедитесь, что ваши ссылки не содержат локализацию, специфичную для страны (например, `/en-us/` или `/en/`).
- Убедитесь, что все изображения хранятся в папке `./images`.
- Убедитесь, что изображения имеют описательные имена, используя английские символы, цифры и дефисы в имени файла.

## Рабочие процессы GitHub

При отправке pull-запроса будут запущены четыре различных рабочих процесса для проверки соблюдения правил.
Просто следуйте инструкциям, перечисленным здесь, чтобы пройти проверки рабочего процесса.

- [Проверка сломанных относительных путей](#check-broken-relative-paths)
- [Проверка наличия трекинга в путях](#check-paths-have-tracking)
- [Проверка наличия трекинга в URL](#check-urls-have-tracking)
- [Проверка отсутствия локализации в URL](#check-urls-dont-have-locale)

### Проверка сломанных относительных путей

Этот рабочий процесс гарантирует, что любой относительный путь в ваших файлах работает.
Этот репозиторий развернут на GitHub pages, поэтому вам нужно очень внимательно вводить ссылки, скрепляющие всё, чтобы не перенаправлять никуда неправильно.

Чтобы убедиться, что ваши ссылки работают правильно, просто используйте VS Code для проверки.

Например, когда вы наведёте курсор на любую ссылку в ваших файлах, вам будет предложено перейти по ссылке, нажав **ctrl + клик**

![Скриншот VS Code, предлагающий перейти по ссылке при наведении курсора](../../translated_images/ru/vscode-follow-link.85520ab6a1237adc.webp?WT.mc_id=academic-105485-koreyst "Скриншот подсказки VS Code о переходе по ссылке при наведении курсора.")

Если вы кликните по ссылке, и она не работает локально, тогда это обязательно вызовет срабатывание рабочего процесса и не будет работать на GitHub.

Чтобы исправить эту проблему, попробуйте ввести ссылку с помощью VS Code.

Когда вы вводите `./` или `../`, VS Code предложит выбрать из доступных вариантов в зависимости от того, что вы набрали.

![Скриншот VS Code с выбором относительного пути из всплывающего списка](../../translated_images/ru/vscode-select-relative-path.3804eb73c3a9e5f2.webp?WT.mc_id=academic-105485-koreyst "Скриншот подсказки VS Code с выбором относительного пути из всплывающего списка.")

Следуйте по пути, кликнув на нужный файл или папку, и вы будете уверены, что ваш путь не сломан.

После того, как вы добавите правильный относительный путь, сохраните и отправьте изменения — рабочий процесс снова запустится для проверки ваших изменений.
Если вы пройдёте проверку, значит, всё в порядке.

### Проверка наличия трекинга в путях

Этот рабочий процесс проверяет, что любой относительный путь содержит трекинг.
Этот репозиторий развернут на GitHub pages, поэтому нам нужно отслеживать перемещения между разными файлами и папками.

Чтобы убедиться, что ваши относительные пути содержат трекинг, просто проверьте наличие текста `?wt.mc_id=` в конце пути.
Если это добавлено к вашим относительным путям, то вы пройдёте эту проверку.

В противном случае вы можете получить следующую ошибку.

![GitHub check paths missing tracking comment screenshot](../../translated_images/ru/github-check-paths-missing-tracking-comment.880d4afe03e898ff.webp?WT.mc_id=academic-105485-koreyst "Скриншот из комментария github, который показывает отсутствие отслеживания в относительных путях")

Чтобы исправить эту проблему, попробуйте открыть путь к файлу, который подсветил рабочий процесс, и добавить идентификатор отслеживания в конец относительных путей.

После того как вы добавите идентификатор отслеживания, сохраните и отправьте изменения, рабочий процесс будет запущен снова для проверки ваших изменений.
Если вы пройдёте проверку, значит всё готово к работе.

### Проверка наличия отслеживания в URL

Этот рабочий процесс гарантирует, что любой веб-URL содержит отслеживание.
Этот репозиторий доступен для всех, поэтому вам нужно убедиться, что доступ отслеживается, чтобы знать, откуда идёт трафик.

Чтобы убедиться, что в ваших URL есть отслеживание, просто проверьте, есть ли в конце URL следующий текст `?wt.mc_id=`.
Если он добавлен к вашим URL, то вы пройдёте проверку.

В противном случае вы можете получить следующую ошибку.

![GitHub check urls missing tracking comment screenshot](../../translated_images/ru/github-check-urls-missing-tracking-comment.1bd00d20b24a1e2e.webp?WT.mc_id=academic-105485-koreyst "Скриншот из комментария github, показывающий отсутствие отслеживания в URL")

Чтобы исправить эту проблему, попробуйте открыть путь к файлу, который подсветил рабочий процесс, и добавить идентификатор отслеживания в конец URL.

После того как вы добавите идентификатор отслеживания, сохраните и отправьте изменения, рабочий процесс будет запущен снова для проверки ваших изменений.
Если вы пройдёте проверку, значит всё готово к работе.

### Проверка отсутствия локали в URL

Этот рабочий процесс гарантирует, что любой веб-URL не содержит локаль, специфичную для страны.
Этот репозиторий доступен для всех по всему миру, поэтому необходимо убедиться, что локаль вашей страны не включена в URL.

Чтобы убедиться, что в ваших URL нет локали страны, просто проверьте наличие следующих текстов `/en-us/` или `/en/` или любой другой языковой локали в любом месте URL.
Если их нет в ваших URL, тогда вы пройдёте проверку.

В противном случае вы можете получить следующую ошибку.

![GitHub check country locale comment screenshot](../../translated_images/ru/github-check-country-locale-comment.2f4fe93228161dee.webp?WT.mc_id=academic-105485-koreyst "Скриншот из комментария github, показывающий добавленную локаль страны в URL")

Чтобы исправить эту проблему, попробуйте открыть путь к файлу, который подсветил рабочий процесс, и удалить локаль страны из URL.

После удаления локали страны сохраните и отправьте изменения, рабочий процесс будет запущен снова для проверки ваших изменений.
Если вы пройдёте проверку, значит всё готово к работе.
