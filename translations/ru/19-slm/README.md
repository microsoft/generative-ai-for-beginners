# Введение в небольшие языковые модели для генеративного ИИ для начинающих
Генеративный ИИ — это увлекательная область искусственного интеллекта, которая сосредоточена на создании систем, способных генерировать новый контент. Этот контент может варьироваться от текста и изображений до музыки и даже целых виртуальных окружений. Одним из самых захватывающих применений генеративного ИИ является область языковых моделей.

## Что такое небольшие языковые модели?

Небольшая языковая модель (SLM) представляет собой уменьшенный вариант большой языковой модели (LLM), использующий многие архитектурные принципы и техники LLM, при этом значительно уменьшенный по вычислительной нагрузке.

SLM — это подмножество языковых моделей, предназначенных для генерации текста, похожего на человеческий. В отличие от своих более крупных аналогов, таких как GPT-4, SLM более компактны и эффективны, что делает их идеальными для приложений с ограниченными вычислительными ресурсами. Несмотря на меньший размер, они всё ещё могут выполнять различные задачи. Обычно SLM создаются сжатием или дистилляцией LLM с целью сохранить значительную часть функциональности и лингвистических возможностей исходной модели. Такое уменьшение размера модели снижает общую сложность, делая SLM более эффективными как с точки зрения использования памяти, так и с точки зрения вычислительных требований. Несмотря на эти оптимизации, SLM всё ещё способны выполнять широкий спектр задач обработки естественного языка (NLP):

- Генерация текста: создание связных и контекстуально релевантных предложений или абзацев.
- Дополнение текста: предсказание и дополнение предложений на основе заданного запроса.
- Перевод: преобразование текста с одного языка на другой.
- Резюмирование: сокращение длинных текстов до кратких и удобоваримых сводок.

Хотя с некоторыми компромиссами в производительности или глубине понимания по сравнению с их более крупными аналогами.

## Как работают небольшие языковые модели?
SLM обучаются на огромных объемах текстовых данных. Во время обучения они изучают закономерности и структуры языка, что позволяет им генерировать текст, который грамматически корректен и контекстуально уместен. Процесс обучения включает:

- Сбор данных: сбор больших наборов текстов из различных источников.
- Предобработка: очистка и организация данных для подготовки к обучению.
- Обучение: использование алгоритмов машинного обучения для обучения модели понимать и генерировать текст.
- Тонкая настройка: корректировка модели для улучшения её производительности по конкретным задачам.

Разработка SLM соответствует растущей потребности в моделях, которые могут быть развернуты в средах с ограниченными ресурсами, таких как мобильные устройства или периферийные вычислительные платформы, где полноразмерные LLM могут быть непрактичны из-за их высокой требовательности к ресурсам. Фокусируясь на эффективности, SLM балансируют производительность и доступность, обеспечивая более широкое применение в различных областях.

## Отличия больших языковых моделей (LLM) и небольших языковых моделей (SLM)

И LLM, и SLM строятся на базовых принципах вероятностного машинного обучения, следуя схожим подходам в архитектурном дизайне, методах обучения, процессах генерации данных и методах оценки моделей. Однако есть несколько ключевых факторов, которые отличают эти два типа моделей.

## Применения небольших языковых моделей

SLM используются в широком спектре задач, включая:

- Чат-боты: предоставление поддержки клиентам и взаимодействие с пользователями в виде диалогов.
- Создание контента: помощь писателям в генерации идей или даже создании целых статей.
- Образование: помощь студентам с письменными заданиями или изучением новых языков.
- Доступность: создание инструментов для людей с ограниченными возможностями, таких как системы синтеза речи.

**Размер**
  
Основное отличие между LLM и SLM заключается в масштабе моделей. LLM, такие как ChatGPT (GPT-4), могут содержать примерно 1,76 триллиона параметров, в то время как открытые SLM, например Mistral 7B, разработаны с значительно меньшим количеством параметров — около 7 миллиардов. Эта разница обусловлена различиями в архитектуре модели и процессах обучения. Например, ChatGPT использует механизм самовнимания в рамках архитектуры энкодер-декодер, тогда как Mistral 7B применяет скользящее окно внимания, что позволяет более эффективно обучать модель только с декодером. Такое различие в архитектуре имеет важные последствия для сложности и производительности моделей.

**Понимание**

SLM обычно оптимизированы для работы в конкретных областях, что делает их высокоспециализированными, но с потенциально ограниченными возможностями предоставления широкого контекстного понимания в различных областях знаний. Напротив, LLM стремятся имитировать человеческий интеллект на более всеобъемлющем уровне. Обученные на огромных, разнообразных наборах данных, они предназначены для хорошей работы в разных областях, предлагая большую универсальность и адаптивность. Следовательно, LLM лучше подходят для более широкого спектра задач, таких как обработка естественного языка и программирование.

**Вычислительные ресурсы**

Обучение и развёртывание LLM требует значительных ресурсов, часто включая крупномасштабные GPU-кластеры. Например, обучение модели вроде ChatGPT с нуля может занимать тысячи GPU в течение долгого времени. В отличие от них, SLM с меньшим количеством параметров более доступны по вычислительным ресурсам. Такие модели, как Mistral 7B, можно обучать и запускать на локальных машинах с умеренными возможностями GPU, хотя обучение все же требует нескольких часов и использования нескольких GPU.

**Смещения (предвзятость)**

Смещения — известная проблема LLM, вызванная природой обучающих данных. Эти модели часто используют необработанные открытые данные из интернета, которые могут недопредставлять или искажать информацию о некоторых группах, содержать ошибочные метки или отражать лингвистические предрассудки, обусловленные диалектами, географическими вариациями и грамматическими правилами. Кроме того, сложность архитектуры LLM может непреднамеренно усиливать смещения, которые могут остаться незамеченными без тщательной тонкой настройки. В свою очередь, SLM, обучаемые на более ограниченных, специализированных наборах данных, менее подвержены таким смещениям, хотя и не полностью защищены от них.

**Инференс (вывод)**

Уменьшенный размер SLM даёт им значительное преимущество по скорости вывода, позволяя эффективно генерировать результаты на локальном оборудовании без необходимости обширной параллельной обработки. В то время как LLM из-за своих размеров и сложности часто требуют значительных параллельных вычислительных ресурсов для достижения приемлемого времени ответа. Наличие множества одновременных пользователей дополнительно замедляет время отклика LLM, особенно при их масштабном развёртывании.

В итоге, несмотря на то, что LLM и SLM основаны на схожих принципах машинного обучения, они значительно отличаются по размеру моделей, требованиям к ресурсам, уровню контекстного понимания, подверженности смещениям и скорости вывода. Эти различия отражают их соответствующую пригодность для различных вариантов использования: LLM более универсальны, но требуют больше ресурсов, а SLM предлагают более узконаправленную эффективность при сниженных вычислительных затратах.

## Представление семейства Phi-3 / Phi-3.5

Семейство Phi-3 / 3.5 главным образом ориентировано на текстовые, визуальные и агентные (MoE) сценарии применения:

### Phi-3 / 3.5 Instruct

В основном для генерации текста, дополнения в чатах и извлечения информации из контента и др.

**Phi-3-mini**

Языковая модель с 3,8 миллиарда параметров доступна на Microsoft Foundry, Hugging Face и Ollama. Модели Phi-3 значительно превосходят языковые модели равного или большего размера по ключевым бенчмаркам (см. показатели бенчмарков ниже, где выше — лучше). Phi-3-mini превосходит модели вдвое большего размера, а Phi-3-small и Phi-3-medium превосходят более крупные модели, включая GPT-3.5.

**Phi-3-small & medium**

При всего 7 миллиардах параметров Phi-3-small превосходит GPT-3.5T по ряду бенчмарков в области языка, рассуждений, программирования и математики.

Phi-3-medium с 14 миллиардами параметров продолжает эту тенденцию и превосходит Gemini 1.0 Pro.

**Phi-3.5-mini**

Его можно считать обновленной версией Phi-3-mini. Хотя количество параметров осталось неизменным, улучшилась поддержка множества языков (поддерживается 20+ языков: арабский, китайский, чешский, датский, голландский, английский, финский, французский, немецкий, иврит, венгерский, итальянский, японский, корейский, норвежский, польский, португальский, русский, испанский, шведский, тайский, турецкий, украинский) и добавлена усиленная поддержка длинного контекста.

Phi-3.5-mini с 3,8 миллиарда параметров превосходит языковые модели аналогичного размера и сопоставима с моделями вдвое большего размера.

### Phi-3 / 3.5 Vision

Модель Instruct Phi-3/3.5 можно рассматривать как способность Phi к пониманию, а Vision — это «глаза» Phi для восприятия мира.


**Phi-3-Vision**

Phi-3-vision, всего с 4,2 миллиарда параметров, продолжает эту тенденцию и превосходит более крупные модели, такие как Claude-3 Haiku и Gemini 1.0 Pro V, в задачах общего визуального рассуждения, оптического распознавания символов (OCR), а также понимания таблиц и диаграмм.


**Phi-3.5-Vision**

Phi-3.5-Vision является также обновлением Phi-3-Vision, добавляя поддержку нескольких изображений одновременно. Можно рассматривать это как улучшение зрения: теперь не только изображения, но и видео доступны для понимания.

Phi-3.5-vision превосходит более крупные модели, такие как Claude-3.5 Sonnet и Gemini 1.5 Flash, в задачах OCR, понимания таблиц и диаграмм и сопоставима с ними в задачах общего визуального рассуждения. Поддерживает многокадровый ввод, то есть способность рассуждать на основе нескольких изображений.


### Phi-3.5-MoE

***Mixture of Experts (MoE)*** позволяет моделям проходить предварительное обучение с гораздо меньшими вычислительными затратами, что означает, что вы можете значительно увеличить размер модели или набора данных при том же бюджете вычислений, что и у плотных моделей. В частности, MoE модель должна достигать того же качества, что и её плотный аналог, намного быстрее в процессе предварительного обучения.

Phi-3.5-MoE состоит из 16 модулей-экспертов по 3,8 миллиарда параметров каждый. Phi-3.5-MoE с всего 6,6 миллиардами активных параметров достигает схожего уровня рассуждений, понимания языка и математики, что и гораздо большие модели.

Мы можем использовать модель из семейства Phi-3/3.5 для разных сценариев. В отличие от LLM, Phi-3/3.5-mini или Phi-3/3.5-Vision можно развернуть на периферийных устройствах.

### Локальный запуск Phi-3/3.5
Инференс в отношении Phi-3, или любой языковой модели, подобной GPT-3, — это процесс генерации ответов или предсказаний на основе вводимых данных. При подаче запроса или вопроса модели Phi-3 она использует свою обученную нейронную сеть, чтобы вывести наиболее вероятный и релевантный ответ, анализируя закономерности и взаимосвязи в обучающих данных.

**Hugging Face Transformer**
Библиотека Hugging Face Transformers — мощный инструмент для задач обработки естественного языка (НЛП) и других задач машинного обучения. Вот несколько ключевых моментов:

1. **Предобученные модели**: Предоставляет тысячи предобученных моделей, которые можно использовать для различных задач, таких как классификация текста, распознавание именованных сущностей, ответы на вопросы, суммирование, перевод и генерация текста.

2. **Совместимость с фреймворками**: Поддерживает несколько фреймворков глубокого обучения, включая PyTorch, TensorFlow и JAX. Это позволяет обучать модель в одном фреймворке и использовать её в другом.

3. **Мультимодальные возможности**: Кроме задач НЛП, Hugging Face Transformers поддерживает задачи компьютерного зрения (например, классификация изображений, обнаружение объектов) и обработки аудио (например, распознавание речи, классификация аудио).

4. **Простота использования**: Библиотека предоставляет API и инструменты для легкой загрузки и дообучения моделей, делая ее доступной как для новичков, так и для экспертов.

**ONNX Runtime для GenAI**

[ONNX Runtime](https://github.com/microsoft/onnxruntime-genai?WT.mc_id=academic-105485-koreyst) — это кроссплатформенный ускоритель инеренса и обучения моделей машинного обучения. ONNX Runtime для Generative AI (GENAI) — мощный инструмент, позволяющий эффективно запускать генеративные ИИ-модели на разных платформах.

## Что такое ONNX Runtime?
ONNX Runtime — это проект с открытым исходным кодом, обеспечивающий высокопроизводительный инференс моделей машинного обучения. Он поддерживает модели в формате Open Neural Network Exchange (ONNX), который является стандартом для представления моделей машинного обучения. Инференс ONNX Runtime может ускорить взаимодействие с клиентом и снизить затраты, поддерживая модели из фреймворков глубокого обучения, таких как PyTorch и TensorFlow/Keras, а также классические библиотеки машинного обучения, такие как scikit-learn, LightGBM, XGBoost и др. ONNX Runtime совместим с разным оборудованием, драйверами и операционными системами, обеспечивая оптимальную производительность через использование аппаратных ускорителей, а также за счет оптимизаций и трансформаций графа вычислений.

## Что такое генеративный ИИ?
Генеративный ИИ — это системы ИИ, которые могут создавать новый контент, такой как текст, изображения или музыка, на основе данных, на которых они были обучены. Примеры включают языковые модели, такие как GPT-3, и модели генерации изображений, например Stable Diffusion. Библиотека ONNX Runtime для GenAI обеспечивает цикл генеративного ИИ для моделей ONNX, включая инференс с ONNX Runtime, обработку логитов, поиск и выборку, а также управление кешем KV.

## ONNX Runtime для GENAI
ONNX Runtime для GENAI расширяет возможности ONNX Runtime, поддерживая генеративные ИИ-модели. Вот некоторые ключевые функции:

- **Широкая поддержка платформ:** Работает на различных платформах, включая Windows, Linux, macOS, Android и iOS.
- **Поддержка моделей:** Поддерживает множество популярных генеративных ИИ-моделей, таких как LLaMA, GPT-Neo, BLOOM и другие.
- **Оптимизация производительности:** Включает оптимизации для различных аппаратных ускорителей, таких как GPU NVIDIA, GPU AMD и другие.
- **Простота использования:** Предоставляет API для легкой интеграции в приложения, позволяя генерировать текст, изображения и другой контент с минимальным количеством кода.
- Пользователи могут вызвать высокоуровневый метод generate() или запускать модель по итерациям в цикле, генерируя по одному токену за раз и при необходимости обновляя параметры генерации внутри цикла.
- ONNX Runtime также поддерживает жадный поиск/beam search и семплирование TopP, TopK для генерации последовательностей токенов, а также встроенную обработку логитов, такую как штрафы за повторения. Вы также легко можете добавить собственную оценку.

### Запустите модель: Простой пример на Python:
```Python
import onnxruntime_genai as og

model = og.Model('path_to_your_model.onnx')

tokenizer = og.Tokenizer(model)

input_text = "Hello, how are you?"

input_tokens = tokenizer.encode(input_text)

output_tokens = model.generate(input_tokens)

output_text = tokenizer.decode(output_tokens)

print(output_text) 
```
### Демонстрация: Использование ONNX Runtime GenAI для вызова Phi-3.5-Vision


```python

import onnxruntime_genai as og

model_path = './Your Phi-3.5-vision-instruct ONNX Path'

img_path = './Your Image Path'

model = og.Model(model_path)

processor = model.create_multimodal_processor()

tokenizer_stream = processor.create_stream()

text = "Your Prompt"

prompt = "<|user|>\n"

prompt += "<|image_1|>\n"

prompt += f"{text}<|end|>\n"

prompt += "<|assistant|>\n"

image = og.Images.open(img_path)

inputs = processor(prompt, images=image)

params = og.GeneratorParams(model)

params.set_inputs(inputs)

params.set_search_options(max_length=3072)

generator = og.Generator(model, params)

while not generator.is_done():

    generator.compute_logits()
    
    generator.generate_next_token()

    new_token = generator.get_next_tokens()[0]
    
    output = tokenizer_stream.decode(new_token)
    
    print(tokenizer_stream.decode(new_token), end='', flush=True)

```
