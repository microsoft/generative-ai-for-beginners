# Введение в маленькие языковые модели для генеративного ИИ для начинающих
Генеративный ИИ — это увлекательное направление искусственного интеллекта, которое сосредоточено на создании систем, способных генерировать новый контент. Этот контент может включать текст, изображения, музыку и даже целые виртуальные среды. Одно из самых захватывающих применений генеративного ИИ связано с языковыми моделями.

## Что такое маленькие языковые модели?

Маленькая языковая модель (SLM) представляет собой уменьшенную версию большой языковой модели (LLM), использующую многие архитектурные принципы и техники LLM, но при этом имеющую значительно меньшие вычислительные требования. 

SLM — это подмножество языковых моделей, предназначенных для генерации текста, подобного человеческому. В отличие от более крупных моделей, таких как GPT-4, SLM более компактны и эффективны, что делает их идеальными для приложений с ограниченными вычислительными ресурсами. Несмотря на меньший размер, они могут выполнять разнообразные задачи. Обычно SLM создаются путём сжатия или дистилляции LLM с целью сохранить большую часть функциональности и языковых способностей исходной модели. Сокращение размера модели снижает общую сложность, делая SLM более эффективными как по использованию памяти, так и по вычислительным затратам. Несмотря на эти оптимизации, SLM способны выполнять широкий спектр задач обработки естественного языка (NLP):

- Генерация текста: создание связных и контекстуально уместных предложений или абзацев.
- Дополнение текста: прогнозирование и завершение предложений на основе заданного запроса.
- Перевод: преобразование текста с одного языка на другой.
- Суммирование: сокращение длинных текстов до более коротких и удобных для восприятия резюме.

Хотя при этом присутствуют определённые компромиссы в производительности или глубине понимания по сравнению с большими моделями. 

## Как работают маленькие языковые модели?
SLM обучаются на огромных объёмах текстовых данных. Во время обучения они изучают паттерны и структуры языка, что позволяет генерировать текст, грамматически правильный и соответствующий контексту. Процесс обучения включает:

- Сбор данных: сбор больших наборов текстов из различных источников.
- Предварительная обработка: очистка и организация данных для их подготовки к обучению.
- Обучение: использование алгоритмов машинного обучения для обучения модели пониманию и генерации текста.
- Тонкая настройка: корректировка модели для улучшения её работы по конкретным задачам.

Разработка SLM отвечает растущей потребности моделей, которые можно развернуть в условиях ограниченных ресурсов, например, на мобильных устройствах или платформах edge computing, где использование полноценных LLM может быть непрактично из-за больших требований к ресурсам. Фокусируясь на эффективности, SLM балансируют между производительностью и доступностью, позволяя расширить применение в различных областях.

## Отличия больших языковых моделей (LLM) и маленьких языковых моделей (SLM)

И LLM, и SLM основаны на фундаментальных принципах вероятностного машинного обучения, используя схожие подходы в архитектурном дизайне, методах обучения, процессах генерации данных и оценке моделей. Однако существует несколько ключевых факторов, которые отличают эти два типа моделей.

## Применение маленьких языковых моделей

SLM находят широкое применение, включая:

- Чатботы: предоставление поддержки клиентам и взаимодействие с пользователями в формате диалога.
- Создание контента: помощь авторам в генерации идей или даже написании целых статей.
- Образование: помощь студентам с письменными заданиями или изучением новых языков.
- Доступность: создание инструментов для лиц с ограниченными возможностями, например, систем преобразования текста в речь.

**Размер**
  
Главное отличие LLM и SLM заключается в масштабе моделей. LLM, такие как ChatGPT (GPT-4), могут содержать около 1,76 триллиона параметров, в то время как открытые SLM, такие как Mistral 7B, проектируются с гораздо меньшим количеством параметров — примерно 7 миллиардов. Эта разница связана с архитектурой и процессами обучения. Например, ChatGPT использует механизм самовнимания в рамках энкодер-декодерной архитектуры, тогда как Mistral 7B применяет скользящее окно внимания, что обеспечивает более эффективное обучение в модели только с декодером. Эта архитектурная особенность существенно влияет на сложность и производительность моделей.

**Понимание**

SLM обычно оптимизируются для работы в конкретных доменах, что делает их высокоспециализированными, но потенциально ограниченными в способности обеспечивать широкое контекстное понимание в разных областях знаний. В противоположность им, LLM стремятся моделировать интеллект, похожий на человеческий, на более комплексном уровне. Обученные на больших и разнообразных наборах данных, LLM предназначены для успешной работы в разных областях, обеспечивая большую универсальность и адаптивность. Поэтому LLM более подходят для широкого круга задач, таких как обработка естественного языка и программирование.

**Вычисления**

Обучение и развёртывание LLM требуют значительных ресурсов, часто включая крупномасштабные GPU-кластеры. Например, обучение модели типа ChatGPT с нуля может занять тысячи GPU и длительное время. В отличие от этого, SLM, с меньшим количеством параметров, требуют меньших вычислительных ресурсов. Модели, подобные Mistral 7B, можно обучать и запускать на локальных машинах с умеренными возможностями GPU, хотя обучение по-прежнему занимает несколько часов на нескольких GPU.

**Смещение**

Смещение является известной проблемой у LLM, главным образом из-за характера обучающих данных. Эти модели часто обучаются на необработанных, общедоступных данных из интернета, которые могут недооценивать или искажать представление о некоторых группах, содержать ошибочную маркировку или отражать лингвистические предубеждения, связанные с диалектами, географическими вариациями и грамматическими правилами. Кроме того, сложность архитектуры LLM может усугублять смещение, которое может оставаться незамеченным без тщательной тонкой настройки. С другой стороны, SLM, обучаемые на более ограниченных, специфичных наборах данных, по своей природе менее подвержены таким смещениям, хотя полностью от них не застрахованы.

**Инференс**

Меньший размер SLM даёт им значительное преимущество в скорости инференса, позволяя эффективно генерировать результаты на локальном оборудовании без необходимости масштабных параллельных вычислений. В противоположность этому, LLM из-за своего размера и сложности требуют значительных параллельных вычислительных ресурсов для обеспечения приемлемого времени отклика. Наличие множества одновременно работающих пользователей дополнительно замедляет ответ LLM, особенно при масштабированном развёртывании.

В итоге, несмотря на общую основу в машинном обучении, LLM и SLM существенно различаются по размеру модели, требованиям к ресурсам, уровню контекстного понимания, подверженности смещению и скорости инференса. Эти различия отражают их пригодность для разных случаев использования: LLM более универсальны, но требуют больше ресурсов, а SLM обеспечивают более эффективную узкоспециализированную работу с меньшими вычислительными затратами.

## Введение в семейство Phi-3 / Phi-3.5

Семейство Phi-3 / 3.5 в основном ориентировано на использование в текстовых, визуальных и Agent (MoE) сценариях:

### Phi-3 / 3.5 Instruct

В основном для генерации текста, дополнения диалогов и извлечения информации из контента.

**Phi-3-mini**

Языковая модель с 3.8 млрд параметров доступна на Microsoft Foundry, Hugging Face и Ollama. Модели Phi-3 значительно превосходят языковые модели равного и большего размера по ключевым бенчмаркам (см. показатели ниже, чем выше — тем лучше). Phi-3-mini превосходит модели вдвое большего размера, в то время как Phi-3-small и Phi-3-medium превосходят более крупные модели, включая GPT-3.5.

**Phi-3-small и medium**

При всего 7 млрд параметров Phi-3-small обходит GPT-3.5T по различным языковым, логическим, кодировочным и математическим бенчмаркам.

Phi-3-medium с 14 млрд параметров продолжает эту тенденцию и превосходит Gemini 1.0 Pro.

**Phi-3.5-mini**

Можно рассматривать её как улучшение Phi-3-mini. Параметры остаются неизменными, но модель улучшает поддержку множества языков (поддержка более 20 языков: арабский, китайский, чешский, датский, нидерландский, английский, финский, французский, немецкий, иврит, венгерский, итальянский, японский, корейский, норвежский, польский, португальский, русский, испанский, шведский, тайский, турецкий, украинский) и добавляет более сильную поддержку длинного контекста.

Phi-3.5-mini с 3.8 млрд параметров превосходит языковые модели того же размера и сопоставима с моделями вдвое большего размера.

### Phi-3 / 3.5 Vision

Можно считать, что Instruct-модель Phi-3/3.5 отвечает за способность Phi понимать, а Vision даёт Phi глаза для понимания мира.


**Phi-3-Vision**

Phi-3-vision с 4.2 млрд параметров продолжает тенденцию и превосходит более крупные модели, такие как Claude-3 Haiku и Gemini 1.0 Pro V, в общих задачах визуального рассуждения, OCR и понимания таблиц и диаграмм.


**Phi-3.5-Vision**

Phi-3.5-Vision — это обновление Phi-3-Vision, добавляющее поддержку множества изображений. Можно рассматривать это как улучшение зрения: теперь модель способна не только видеть картинки, но и видео.

Phi-3.5-vision превосходит более крупные модели, такие как Claude-3.5 Sonnet и Gemini 1.5 Flash, по задачам OCR, понимания таблиц и диаграмм и сопоставима в общих задачах визуальных знаний. Поддерживается ввод нескольких кадров, то есть рассуждение на основе нескольких входных изображений.


### Phi-3.5-MoE

***Mixture of Experts (MoE)*** позволяет моделям предварительно обучаться с гораздо меньшими вычислительными затратами, что означает, что можно значительно увеличить размер модели или набора данных при том же бюджете вычислений, что и у плотной модели. В частности, MoE-модель должна достигать того же качества, что и её плотный аналог, гораздо быстрее в процессе предварительного обучения.

Phi-3.5-MoE состоит из 16 экспертных модулей по 3.8 млрд параметров. Phi-3.5-MoE с только 6.6 млрд активных параметров достигает сопоставимого уровня рассуждений, понимания языка и математики с гораздо более крупными моделями.

Мы можем использовать модели семейства Phi-3/3.5 в различных сценариях. В отличие от LLM, Phi-3/3.5-mini или Phi-3/3.5-Vision можно развернуть на edge-устройствах.

### Запуск Phi-3/3.5 локально
Инференс в отношении Phi-3, или любой языковой модели, такой как GPT-3, означает процесс генерации ответов или предсказаний на основе полученных входных данных. Когда вы предоставляете запрос или вопрос Phi-3, она использует свою обученную нейронную сеть для вывода наиболее вероятного и релевантного ответа, анализируя паттерны и взаимосвязи в данных, на которых она была обучена.

**Hugging Face Transformer**
Hugging Face Transformers — мощная библиотека, предназначенная для обработки естественного языка (NLP) и других задач машинного обучения. Вот несколько ключевых моментов о ней:

1. **Предобученные модели**: Предоставляет тысячи предобученных моделей, которые могут использоваться для различных задач, таких как классификация текста, распознавание именованных сущностей, ответы на вопросы, суммирование, перевод и генерация текста.

2. **Совместимость с фреймворками**: Библиотека поддерживает несколько фреймворков глубокого обучения, включая PyTorch, TensorFlow и JAX. Это позволяет обучать модель в одном фреймворке и использовать её в другом.

3. **Мультимодальные возможности**: Помимо NLP, Hugging Face Transformers поддерживает задачи компьютерного зрения (например, классификация изображений, обнаружение объектов) и обработки аудио (например, распознавание речи, классификация аудио).

4. **Простота использования**: Библиотека предлагает API и инструменты для легкой загрузки и дообучения моделей, делая её доступной как для новичков, так и для экспертов.

5. **Сообщество и ресурсы**: Hugging Face обладает активным сообществом и обширной документацией, учебниками и руководствами, которые помогают пользователям начать работу и максимально эффективно использовать библиотеку.

**ONNX Runtime для GenAI**

[ONNX Runtime](https://github.com/microsoft/onnxruntime-genai?WT.mc_id=academic-105485-koreyst) — кроссплатформенный ускоритель инференса и обучения моделей машинного обучения. ONNX Runtime for Generative AI (GENAI) — мощный инструмент, помогающий эффективно запускать генеративные AI-модели на различных платформах. 

## Что такое ONNX Runtime?
ONNX Runtime — проект с открытым исходным кодом, обеспечивающий высокопроизводительный инференс моделей машинного обучения. Он поддерживает модели в формате Open Neural Network Exchange (ONNX), который является стандартом представления моделей машинного обучения. Инференс с помощью ONNX Runtime позволяет ускорить взаимодействие с пользователем и снизить затраты, поддерживая модели из фреймворков глубокого обучения, таких как PyTorch и TensorFlow/Keras, а также классические библиотеки машинного обучения, такие как scikit-learn, LightGBM, XGBoost и др. ONNX Runtime совместим с различным оборудованием, драйверами и операционными системами, обеспечивая оптимальную производительность за счёт использования аппаратных ускорителей, где это возможно, в сочетании с оптимизациями и трансформациями графа.

## Что такое генеративный AI?
Генеративный AI — это системы искусственного интеллекта, способные создавать новый контент, такой как текст, изображения или музыка, на основе данных, на которых они были обучены. Примеры включают языковые модели, такие как GPT-3, и модели генерации изображений, такие как Stable Diffusion. Библиотека ONNX Runtime для GenAI предоставляет цикл генеративного AI для моделей ONNX, включая инференс с ONNX Runtime, обработку логитов, поиск и сэмплинг, а также управление кэшем KV.

## ONNX Runtime для GENAI
ONNX Runtime для GENAI расширяет возможности ONNX Runtime, поддерживая генеративные AI-модели. Вот некоторые ключевые функции:

- **Широкая поддержка платформ:** Работает на различных платформах, включая Windows, Linux, macOS, Android и iOS.
- **Поддержка моделей:** Поддерживает многие популярные генеративные AI-модели, такие как LLaMA, GPT-Neo, BLOOM и другие.
- **Оптимизация производительности:** Включает оптимизации для различных аппаратных ускорителей, таких как GPU NVIDIA, GPU AMD и др.
- **Простота использования:** Предоставляет API для легкой интеграции в приложения, обеспечивая генерацию текста, изображений и другого контента с минимальным написанием кода.
- Пользователи могут использовать высокоуровневый метод generate() или запускать каждую итерацию модели в цикле, генерируя по одному токену за раз и при желании обновляя параметры генерации внутри цикла.
- ONNX Runtime также поддерживает жадный/лучевой поиск и сэмплирование TopP, TopK для генерации последовательностей токенов и встроенную обработку логитов, такую как штрафы за повторения. Вы также можете легко добавить собственную функцию оценки.

## Начало работы
Чтобы начать работу с ONNX Runtime для GENAI, выполните следующие шаги:

### Установка ONNX Runtime:
```Python
pip install onnxruntime
```
### Установка расширений Generative AI:
```Python

```

### Запуск модели: простой пример на Python:
```Python
import onnxruntime_genai as og

model = og.Model('path_to_your_model.onnx')

tokenizer = og.Tokenizer(model)

input_text = "Hello, how are you?"

input_tokens = tokenizer.encode(input_text)

output_tokens = model.generate(input_tokens)

output_text = tokenizer.decode(output_tokens)

print(output_text) 
```
### Демонстрация: Использование ONNX Runtime GenAI для вызова Phi-3.5-Vision


```python

import onnxruntime_genai as og

model_path = './Your Phi-3.5-vision-instruct ONNX Path'

img_path = './Your Image Path'

model = og.Model(model_path)

processor = model.create_multimodal_processor()

tokenizer_stream = processor.create_stream()

text = "Your Prompt"

prompt = "<|user|>\n"

prompt += "<|image_1|>\n"

prompt += f"{text}<|end|>\n"

prompt += "<|assistant|>\n"

image = og.Images.open(img_path)

inputs = processor(prompt, images=image)

params = og.GeneratorParams(model)

params.set_inputs(inputs)

params.set_search_options(max_length=3072)

generator = og.Generator(model, params)

while not generator.is_done():

    generator.compute_logits()
    
    generator.generate_next_token()

    new_token = generator.get_next_tokens()[0]
    
    output = tokenizer_stream.decode(new_token)
    
    print(tokenizer_stream.decode(new_token), end='', flush=True)

```
