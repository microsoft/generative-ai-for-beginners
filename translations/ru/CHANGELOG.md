# Журнал изменений

Все заметные изменения в учебной программе "Генеративный ИИ для начинающих" документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Поскольку это
учебная программа, а не версия программного обеспечения, записи сгруппированы по дате.

## [2026-07-16] — Проверка контента + Графика для урока 09

### Изменено

- **Урок 10 (приложения ИИ с низким кодом):** обновлены две устаревшие `docs.microsoft.com/powerapps/...` ссылки Dataverse
  на текущие `learn.microsoft.com/power-apps/maker/data-platform/data-platform-intro`
  (проверено вживую).
- **Урок 17 (агенты ИИ):** модернизирован устаревший пример модели (`GPT-3.5, GPT-4, Llama-2` →

  (`my-gpt-4o-deployment` → `my-gpt-5-mini-deployment`).
- **Корень `README.md`:** добавлен недостающий идентификатор отслеживания `?WT.mc_id=academic-105485-koreyst` в
  ссылку *Microsoft for Startups*.
- **Графические активы урока 09** переработаны с использованием модели `gpt-image`: `images/generated-image.png`,
  `images/sunlit_lounge.png`, `images/mask.png`, `images/sunlit_lounge_result.png` и
  `images/startup.png` (пара до/после из примера редактирования была получена через реальный
  вызов `client.images.edit` с созданной маской).

- Проведён аудит README для уроков 01, 03, 05, 12, 14 и 16 — все актуальны (корректные имена и ссылки Microsoft Foundry);
  изменений не требуется.
- Выполнена полная проверка markdown во всех 41 markdown-файлах репозитория (без переводов) на
  устаревшие пути документации, локали Microsoft `/en-us/`, устаревшие названия продуктов/моделей, отсутствие идентификаторов отслеживания

  все остальные предупреждения оказались ложными срабатываниями (автоматические ссылки переводов,
  закомментированные заглушки и сторонние структурные URL `/en/`).

## [2026-07-15] — Переписывание урока 09 (Приложения для работы с изображениями) для моделей GPT Image

### Изменено

- **Переписан урок 09 «Создание приложений генерации изображений»** вокруг текущей **`gpt-image`**
  семейство моделей (по умолчанию **`gpt-image-2`**; `gpt-image-1.5` / `gpt-image-1-mini` также GA), заменяющее
  устаревший контент DALL·E 2/3. Основные исправления:
  - модели `gpt-image` возвращают изображение в виде **base64 (`b64_json`)**, а не URL. Все примеры обновлены для
    `base64.b64decode(...)` вместо скачивания `url` с `requests`.
  - Версия API изображений повышена до `2025-04-01-preview`.
  - Удалён выдуманный раздел "temperature" (модели изображений не принимают `temperature`) и
    контент вариаций изображений только для DALL·E-2 заменён разделом об **редактировании изображений** (маска/доделка).
  - Обновлены `README.md`, `python/aoai-app.py`, `python/oai-app.py`, `python/aoai-solution.py`, как
    тетради заданий (`aoai-assignment.ipynb`, `oai-assignment.ipynb`),
    `typescript/image-generation-app` (`main.ts`, `.env-sample`), и .NET тетрадь `.dib`.

### Удалено

- Удалены устаревшие примеры `python/aoai-app-variation.py` и `python/oai-app-variation.py`
  (`images.create_variation` предназначен только для DALL·E-2 и не поддерживается `gpt-image`).
- Удалены 4 неиспользуемых графических файла, связанные с удалённым разделом сравнения температур
  (`v1-generated-image.png`, `v2-generated-image.png`, `v1-temp-generated-image.png`,
  `v2-temp-generated-image.png`).
- Исключена ненужная зависимость `requests` из примеров на Python и требований урока.

### Проверено

- Запущен end-to-end тест `aoai-app.py` на развернутой модели `gpt-image-1.5`, подтвердив что декодирование/сохранение base64
  выдаёт PNG. Тетради подтверждены как валидный JSON.

## [2026-07-14] — Обновление модели по умолчанию + руководство по модели рассуждений

### Изменено

- **Модель чата по умолчанию `gpt-4o-mini` → `gpt-5-mini`** во всех рабочих примерах,
  документации и конфигурации учебного курса. Это вызвано статусом жизненного цикла модели: в Microsoft Foundry,
  `gpt-4o-mini` (выводится из эксплуатации 2026-10-01), а также всё семейство `gpt-4.1` (`gpt-4.1`, `gpt-4.1-mini`,
  `gpt-4.1-nano`, снятие с поддержки 2026-10-14) являются **устаревающими**, тогда как **семейство GPT-5
  (`gpt-5-mini`, `gpt-5`, `gpt-5-nano`) является Общедоступным** (снятие с поддержки 2027-02-06). Обновлено:
  - `.env.copy`, `00-course-setup/03-providers.md` (рекомендуемое развертывание и команды `az cognitiveservices`
    deploy), а также README для уроков 04, 06, 07 и 15.
  - Примеры на Python в уроке 06 (`oai-app.py`, `oai-app-recipe.py`, `oai-history-bot.py`,
    `oai-study-buddy.py`, `githubmodels-app.py`) и скрипты урока 08.
  - Примеры на TypeScript / JavaScript в уроках 06, 07 и 11, а также ноутбуки `.dib` .NET для
    уроков 06 и 07.
  - Ноутбуки с заданиями в уроках 04, 06, 07 и 11 (кодовые ячейки), плюс примеры строк документации `shared/python/api_utils.py`.

- **Руководство по параметрам reasoning-модели (новое).** `gpt-5-mini` — это *reasoning* модель: она **не**
  поддерживает `temperature`/`top_p` и использует `max_completion_tokens` (чат-завершения) /
  `max_output_tokens` (API ответов) вместо `max_tokens`. Соответственно:
  - Удалены `temperature`/`top_p`/`max_tokens` из примеров, которые теперь по умолчанию используют `gpt-5-mini`
    (`githubmodels-app.py`, `aoai-app-recipe.py`, `oai-app-recipe.py`, README урока 15 RAG).
  - Добавлена **примечание "Reasoning-модели не используют `temperature`"** к уроку 06, объясняющая, что
    reasoning-модели управляются с помощью **промпт-инжиниринга + контролей reasoning**, а не
    настроек сэмплирования, в то время как `temperature`/`top_p` остаются актуальными для не-reasoning моделей
    (GPT-4.x, Mistral, Llama, Phi, открытые модели).
- **`gpt-5-mini` не используется в уроке по дообучению методом тонкой настройки (урок 18).** GPT-5 поддерживает
  только дообучение с подкреплением (RFT); в прохождении урока 18 по контролируемому дообучению (SFT)
  сохраняется `gpt-4.1-mini`, который поддерживает SFT/DPO.
- **Демонстрации температуры используют модель Llama.** Чтобы продолжать обучение `temperature` (которое модели рассуждений
  отвергают), используется модель `Llama-3.3-70B-Instruct` через конечную точку Foundry Models. Добавлена новая
  переменная `AZURE_INFERENCE_CHAT_MODEL` в `.env.copy`; тетради урока 04/06 `githubmodels` и
  пример `06` `js-githubmodels` прочитайте его (с возвратом к `Llama-3.3-70B-Instruct`) и сохраните их
  демонстрации `temperature`/`top_p`/`max_tokens`.
- **Образцы JS / .NET обновлены для GPT-5.** Удалено `temperature`/`top_p`/`max_tokens` из GPT-5
  образцы (`06` `recipe-app` TypeScript, `06` `.dib` .NET — что также вызывает `MaxOutputTokenCount`
  так что вывод рассуждений не обрезается). Образец `06` `js-githubmodels` теперь использует Llama для сохранения демо температуры.
  В `.dib` отмечается, что `Azure.AI.Inference` + модель Llama — это способ
  продемонстрировать `Temperature` в .NET.
- Слева `gpt-4o-mini` / `gpt-5-mini` оставлены там, где они остаются точными: ссылки на кодирование токенов `tiktoken`,
  списки доступности каталога моделей и модели речи из урока 02 (`gpt-4o-transcribe`).
- Образцы уроков 20 (Mistral) и 21 (Meta) сохраняют `temperature`/`max_tokens`, так как они нацелены на
  модели Mistral/Llama, которые поддерживают эти параметры.

## [2026-07-06] — Обновление модернизации контента

Широкое обновление для поддержания актуальности учебной программы на 2026 год: современные API, текущие наименования продуктов и
моделей, обновленные рекомендации поставщиков и новые инструменты для опыта разработчиков.

### Добавлено

- раздел **Microsoft Agent Framework** в уроке `17-ai-agents`, охватывающий однопользовательские чат-агенты,
  инструменты/вызов функций, конфигурацию Azure OpenAI (Microsoft Foundry) и мультиагентные
  оркестрация рабочих процессов (`SequentialBuilder` / `ConcurrentBuilder`).
- **Foundry Local** задокументирован как офлайн / локальный провайдер (вместе с Ollama) в
  `00-course-setup/03-providers.md` и уроке `19-slm`.
- **Рабочие процессы непрерывной интеграции**:
  - `.github/workflows/code-quality.yml` — Ruff + Black (применяется к поддерживаемому модулю `shared/`,
    рекомендован для остального учебного материала), проверка ESLint и задача pytest.
  - `.github/workflows/security.yml` — анализ CodeQL (Python + JavaScript/TypeScript) и
    проверка зависимостей в pull-реквестах.
- **Набор тестов** под `tests/` — 41 тест pytest, охватывающий общий вспомогательный модуль.
- **Навык миграции Azure OpenAI → Responses API** под
  `.github/skills/azure-openai-to-responses/`, используемый для управления миграцией API.

### Изменено

- **Chat Completions API → Responses API** во всех примерах чатов на Python и TypeScript
  (`client.responses.create(...)` → `response.output_text`), включая уроки 04, 06, 07, 11,
  15 и 18, а также их README.
- **GitHub Models → Microsoft Foundry Models** во всем тексте, ссылках и примерах. GitHub Models
  будет выведен из эксплуатации в конце июля 2026 года; примеры теперь используют каталог моделей Microsoft Foundry и применяют
  переменные окружения `AZURE_INFERENCE_ENDPOINT` / `AZURE_INFERENCE_CREDENTIAL`.
- **`.env.copy`, `AGENTS.md` и документация провайдера** обновлены, чтобы отразить, что Azure OpenAI теперь часть
  Microsoft Foundry, а версия API по умолчанию повышена до `2024-10-21`.
- **Примеры на TypeScript** (уроки 06, 07, 08, 11) мигрировали с устаревшего бета-SDK `@azure/openai`
  на пакет `openai` (чат-приложения используют Responses API; поисковое приложение использует
  embeddings client).
- **.NET ноутбуки** (`dotnet/*.dib`) стандартизированы на `Azure.AI.OpenAI` версии **2.1.0**: уроки 06 и 07
  используют API `ChatClient`, урок 08 использует `EmbeddingClient` (`GenerateEmbedding` / `ToFloats`), и
  урок 09 использует `ImageClient` (`GenerateImage`) с `gpt-image-1`, заменяя устаревшие
  `OpenAIClient` / `GetEmbeddingsAsync` / `GetImageGenerationsAsync` из `1.0.0-beta.9`.
- **Обновление названий продуктов**: "Azure AI Studio" / "Azure AI Foundry" → **Microsoft Foundry**
  (уроки 14, 16, 17) и "Bing" → **Microsoft Copilot** (урок 12), в тех случаях, где упоминались
  текущие продукты.
- **DevContainer** (`.devcontainer/`) теперь включает расширения Pylance, Black, Ruff, ESLint, Prettier и Copilot,
  активирует форматирование при сохранении и устанавливает `ruff`, `black`, `mypy` и `pytest` для
  возможности воспроизведения проверок CI локально.
- **Генерация изображений** (урок 09) рекомендует `gpt-image-1` для Azure (в каталоге Azure убран
  `dall-e-3`).
- **`docs/ENHANCED_FEATURES_ROADMAP.md`** обновлено с учетом выполненных работ (миграция API, CI,  
  DevContainer, тесты) и текущих фактов (переводы создаются автоматически с помощью  
  Azure Co-op Translator; API Ассистентов заменен на API Ответов).  

### Исправлено  

- **`shared/python/input_validation.py`** — `validate_text_input(allow_empty=True)` теперь возвращает  
  пустую строку для входных данных, содержащих только пробелы, вместо того, чтобы вызывать ошибку «слишком короткий ввод» (что согласуется  
  с случаем `None`). Найдено и покрыто новым набором тестов.  
- **Примеры изображений к уроку 09** — исправлены реальные ошибки: `InvalidRequestError` → `BadRequestError`,  
  `images.create` → `images.generate`, `Image.create_variation` → `client.images.create_variation`,  
  а также переменная, затенявшая модуль `openai`.  
- **Блокнот RAG урока 15** — восстановлена настройка клиента, заменен удалённый `DataFrame.append`  
  на `pd.concat`, и модернизировано использование устаревшего SDK.  
- Устаревшие / выведенные из эксплуатации имена моделей (`gpt-3.5-turbo`, `gpt-35-turbo`) заменены на `gpt-4o-mini`  
  в активных примерах; исторические данные дообучения в уроке 18 сохранены и аннотированы,  
  а не переписаны.  

### Устаревшее / Заметки  

- **Примеры моделей Microsoft Foundry**, использующие `azure-ai-inference` / `@azure-rest/ai-inference`  
  SDK (`client.complete()`) — примеры и уроки `githubmodels-*` и `js-githubmodels`, а также 19, 20,
  и 21 — остаются на Model Inference API, который **не** поддерживает Responses API. Они
  намеренно оставлены на этом SDK.
- `AzureOpenAI()` намеренно сохранён там, где это еще уместно (встраивания и генерация изображений),
  так как эти рабочие процессы не входят в миграцию на Responses API.
- `text-embedding-ada-002` ссылки сохранены там, где на них зависит предварительно вычисленный индекс встраивания.
