## Генерација обогаћена претрагом (RAG)

Чатбот на бази LLM обрађује упите корисника да генерише одговоре. Дизајниран је да буде интерактиван и да се бави широким спектром тема. Међутим, његови одговори су ограничени на обезбеђени контекст и основне податке коришћене у тренингу. На пример, GPT-4 има датум завршетка знања у септембру 2021, што значи да нема знање о догађајима који су се десили после тог периода. Поред тога, подаци коришћени за тренирање LLM-ова искључују поверљиве информације попут личних белешки или упутстава за производ компаније.

### Како RAG (генерација обогаћена претрагом) функционише

![цртеж који показује како RAG функционише](../../../translated_images/sr/how-rag-works.f5d0ff63942bd3a6.webp?WT.mc_id=academic-105485-koreyst)

Рецимо да желите да поставите чатбот који креира квизове из ваших белешки, биће вам потребна веза са базом знања. Ту RAG долази као помоћ. RAG функционише на следећи начин:

- **База знања:** Пре претраге, документи се морају унети и претпрограмски обрадити, обично разбијајући велике документе у мање делове, претварајући их у текстуалне уграђене векторе и чувајући их у бази података.

- **Кориснички упит:** корисник поставља питање

- **Претрага:** Када корисник постави питање, модел за уграђивање прибавља релевантне информације из наше базе знања да пружи више контекста који ће бити укључен у упит.

- **Обогаћена генерација:** LLM побољшава свој одговор на основу прибављених података. Ово омогућава да одговор који се генерише није заснован само на претходно тренираним подацима већ и на релевантним информацијама из додатног контекста. Прибављени подаци се користе за обогаћивање одговора LLM-а. Zатим LLM враћа одговор на корисничко питање.

![Дијаграм који приказује архитектуру RAG](../../../translated_images/sr/encoder-decode.f2658c25d0eadee2.webp?WT.mc_id=academic-105485-koreyst)

RAG комбинује претраживач са генератором: упит се претвара у вектор, упоређује са индексом докумената да би пронашао релевантне делове текста, и ти делови се достављају као контекст LLM-у који генерише одговор. Претраживач и генератор могу користити различите моделе; RAG не захтева енкодер-декодер трансформер.

Постоје два приступа при имплементацији RAG према предложеном раду: [Генерација обогаћена претрагом за интензивне NLP (обрада природног језика) задатке](https://arxiv.org/pdf/2005.11401.pdf?WT.mc_id=academic-105485-koreyst):

- **_RAG-Sequence_** користи прибављене документе за предвиђање најбољег могућег одговора на кориснички упит

- **RAG-Token** користи документе за генерисање следећег тока, потом их пребацује да одговори на кориснички упит

### Зашто користити RAG? 

- **Богатство информација:** обезбеђује да текстуални одговори буду ажурни и актуелни. На тај начин побољшава перформансе на специјализованим задацима приступајући интерној бази знања.

- Смањује измишљене информације коришћењем **проверљивих података** из базе знања за пружање контекста корисничким упитима.

- Је **исплатив** јер је економичнији у поређењу са подешавањем (фина подешавања) LLM-а.

### Векторске базе података

Векторска база података, за разлику од традиционалних база, је специјализована база дизајнирана за чување, управљање и претрагу уграђених вектора. Она чува нумеричке репрезентације докумената. Разлагање података на нумеричке уграђене векторе олакшава нашем AI систему разумевање и обраду података.

Пошто LLM има ограничење броја улазних токена, разлажемо документе у делове пре него што их уградимо. Када корисник постави питање, уграђени вектори који су најсличнији упиту идентификују релевантне делове текста, који се враћају са упитом. Разлагање такође смањује број токена који се прослеђују LLM-у и стога може смањити трошкове.

Неки популарни векторски бази података укључују Azure Cosmos DB, Clarifyai, Pinecone, Chromadb, ScaNN, Qdrant и DeepLake. Можете креирати модел Azure Cosmos DB користећи Azure CLI са следећом командом:

```bash
az cosmosdb create -n <cosmos-db-name> -r <resource-group-name>
az cosmosdb list-keys -n <cosmos-db-name> -g <resource-group-name>
```

### Од текста до уграђених вектора

Пре него што сачувамо наше податке, морамо их претворити у векторске уграђене репрезентације пре него што буду сачувани у бази. Ако радите са великим документима или дугим текстовима, можете их разложити у делове на основу упита које очекујете. Разлагање може бити на нивоу реченице или параграфа. Пошто се значење делова изводи из речи које их окружују, можете додати неки други контекст деловима, на пример додавањем наслова документа или укључивањем неког текста пре или после дела. Податке можете разложити на следећи начин:

```python
def split_text(text, max_length, min_length):
    words = text.split()
    chunks = []
    current_chunk = []

    for word in words:
        current_chunk.append(word)
        if len(' '.join(current_chunk)) < max_length and len(' '.join(current_chunk)) > min_length:
            chunks.append(' '.join(current_chunk))
            current_chunk = []

    # If the last chunk didn't reach the minimum length, add it anyway
    if current_chunk:
        chunks.append(' '.join(current_chunk))

    return chunks
```

Једном када су делови састављени, можемо уњегово текст користећи различите моделе уграђивања. Неки модели које можете користити укључују: word2vec, ada-002 компаније OpenAI, Azure Computer Vision и многе друге. Избор модела зависиће од језика који користите, типа садржаја који се кодира (текст/слике/звучни сигнали), величине улаза који може да кодира и дужине излаза уграђеног вектора.

## Претраживање и векторска претрага

Када корисник постави питање, претраживач га претвара у вектор користећи енкодер упита, затим претражује индекс докумената да пронађе релевантне векторе у документу који су повезани са уносом. Када заврши, претвара и улазни вектор и векторе докумената у текст и прослеђује их LLM-у.

### Претрага

Претрага се дешава када систем покушава брзо да пронађе документе из индекса који задовољавају критеријуме претраге. Циљ претраживача је да добије документе који ће се користити за пружање контекста и основе LLM-а на вашим подацима.

Постоји неколико начина за претраживање у бази података као што су:

- **Претрага кључним речима** - користи се за претраге текста

- **Векторска претрага** - претвара документе из текста у векторске репрезентације користећи моделе уграђивања, омогућавајући **семантичку претрагу** користећи значење речи. Претрага се врши упитивањем докумената чије су векторске репрезентације најближе питању корисника.

- **Хибридна** - комбинација претраге кључним речима и векторске претраге.

Изазов претраге настаје када у бази нема сличног одговора на упит, систем ће вратити најбоље могуће информације, међутим, можете користити тактике као што је подешавање максималне удаљености за релевантност или користити хибридну претрагу која комбинује обе методе. У овој лекцији ћемо користити хибридну претрагу, комбинацију векторске и претраге кључним речима. Чуваћемо наше податке у dataframe-у са колонама које садрже делове као и уграђене векторе.

### Векторска сличност

Претраживач ће претраживати базу знања за уграђеним векторима који су блиски - најближи суседи - јер они представљају сличне текстове. У овом сценарију, када корисник достави упит, он се прво уграђује и затим упоређује са сличним уграђеним векторима. Најчешћа мера која се користи за поређење сличности вектора је косинусна сличност, која се базира на углу између два вектора.

Друге мере које можемо користити за мерење сличности укључују Евклидијеву удаљеност, која представља директну линију између крајњих тачака вектора, и скаларни производ, који мери збир производа одговарајућих елемената у два вектора.

### Претражни индекс

Приликом претраге, потребно је изградити претражни индекс за нашу базу знања пре извођења претраге. Индекс ће чувати наше уграђене векторе и може брзо пронаћи најсличније делове чак и у великој бази података. Индекс можемо креирати локално користећи:

```python
from sklearn.neighbors import NearestNeighbors

embeddings = flattened_df['embeddings'].to_list()

# Create the search index
nbrs = NearestNeighbors(n_neighbors=5, algorithm='ball_tree').fit(embeddings)

# To query the index, you can use the kneighbors method
distances, indices = nbrs.kneighbors(embeddings)
```

### Ре-ранкинг

Када унесете упит у базу, можда ћете морати да сортирате резултате по релевантности. Ре-ранкинг LLM користи машинско учење да побољша релевантност резултата претраге тако што их уређује од најрелевантнијих. Коришћењем Azure AI Search, ре-ранкинг се аутоматски изводи помоћу семантичког ре-ранкера. Пример како ре-ранкинг функционише помоћу најближих суседа:

```python
# Find the most similar documents
distances, indices = nbrs.kneighbors([query_vector])

# Print the three most similar documents with their distance to the question
for distance, index in zip(distances[0][:3], indices[0][:3]):
    print(flattened_df['chunks'].iloc[index])
    print(flattened_df['path'].iloc[index])
    print(distance)
```

## Обједињавање

Последњи корак је додавање нашег LLM у процес да би добили одговоре који су засновани на нашим подацима. Можемо га имплементирати на следећи начин:

```python
user_input = "what is a perceptron?"

def chatbot(user_input):
    # Convert the question to a query vector
    query_vector = create_embeddings(user_input)

    # Find the most similar documents
    distances, indices = nbrs.kneighbors([query_vector])

    # add documents to query  to provide context
    history = []
    for index in indices[0]:
        history.append(flattened_df['chunks'].iloc[index])

    # combine the history and the user input
    history.append(user_input)

    # create a message object
    messages=[
        {"role": "system", "content": "You are an AI assistant that helps with AI questions."},
        {"role": "user", "content": "\n\n".join(history) }
    ]

    # use the Responses API to generate a response
    response = client.responses.create(
        model="gpt-5-mini",
        max_output_tokens=800,
        input=messages,
        store=False,
    )

    return response.output_text

chatbot(user_input)
```

## Евалуација наше апликације

### Метрике евалуације

- Квалитет достављених одговора обезбеђујући да звуче природно, течно и људски

- Основаност података: евалуација да ли одговор потиче из достављених докумената

- Релевантност: евалуација да ли одговор одговара и повезан је са постављеним питањем

- Течност - да ли одговор има граматички смисла

## Примена RAG (Генерација обогаћена претрагом) и векторских база података

Постоји много различитих примена где RAG може побољшати вашу апликацију, као што су:

- Питања и одговори: основање података ваше компаније у чат који могу користити запослени за постављање питања.

- Системи препорука: где можете креирати систем који упоређује најсличније вредности, нпр. филмове, ресторане и још много тога.

- Чатбот услуге: можете чувати историју ћаскања и персонализовати разговор на основу корисничких података.

- Претрага слика на основу уграђених вектора, корисно при препознавању слика и детекцији аномалија.
