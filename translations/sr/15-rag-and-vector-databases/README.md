## Ретривал Аугментед Генератион (RAG)

ЛЛМ-погонски чатбот обрађује корисничке упите да генерише одговоре. Дизајниран је да буде интерактиван и да комуницира са корисницима о широком спектру тема. Међутим, његови одговори су ограничени на контекст који је обезбеђен и основне тренинг податке. На пример, GPT-4 има прекид знања у септембру 2021, што значи да нема знања о догађајима након тог периода. Поред тога, подаци који се користе за тренинг LLM искључују поверљиве информације као што су личне белешке или упутства за производ компаније.

### Како RAG функционише (Ретривал Аугментед Генератион)

![цртеж који показује како RAG функционише](../../../translated_images/sr/how-rag-works.f5d0ff63942bd3a6.webp?WT.mc_id=academic-105485-koreyst)

Претпоставимо да желите да примените чатбот који прави квизове из ваших бележака, биће вам потребна веза са базом знања. Овде RAG улази у помоћ. RAG функционише на следећи начин:

- **База знања:** Пре претраживања, ови документи морају бити унети и претходно обрађени, обично делењем великих докумената на мање делове, трансформисањем у текстуалне уградње и чувањем у базу података.

- **Кориснички упит:** корисник поставља питање

- **Претраживање:** Када корисник постави питање, модел уградње извлачи релевантне информације из наше базе знања како би пружио више контекста који ће бити укључен у упит.

- **Аугментед Генератион:** LLM побољшава свој одговор на основу података који су пронађени. Ово омогућава да одговор који генерише буде не само заснован на претходно обученим подацима него и на релевантним информацијама из додатног контекста. Проналазни подаци се користе за побољшање одговора LLM-а. LLM затим враћа одговор на питање корисника.

![Дијаграм који показује RAG архитектуру](../../../translated_images/sr/encoder-decode.f2658c25d0eadee2.webp?WT.mc_id=academic-105485-koreyst)

RAG комбинује ретеривер и генератор: упит се претвара у вектор, упоређује са индекском докумената да се пронађу релевантни делови текста, који се потом користе као контекст за LLM, који генерише одговор. Ретеривер и генератор могу користити различите моделе; RAG не захтева енкодер-декодер трансформер.

Два приступа при имплементацији RAG-а према предложеном раду: [Retrieval-Augmented Generation for Knowledge intensive NLP (natural language processing software) Tasks](https://arxiv.org/pdf/2005.11401.pdf?WT.mc_id=academic-105485-koreyst) су:

- **_RAG-Sequence_** користи враћене документе за предвиђање најбољег могућег одговора на кориснички упит

- **RAG-Token** користи документе за креирање следећег токена, а затим их враћа да одговори на кориснички упит

### Зашто бисте користили RAG? 

- **Богатство информација:** обезбеђује да текстуални одговори буду ажурни и тренутни. Самим тим унапређује перформансе на специфичним задацима приступајући унутрашњој бази знања.

- Смањује измишљање користећи **проверљиве податке** у бази знања да би пружио контекст корисничким упитима.

- Профитабилно је јер је економичније у односу на фино подешавање великог језичког модела (LLM)

## Креирање базе знања

Наша апликација је заснована на нашим личним подацима, тј. лекцији о неуронским мрежама из курикулума Вештачка интелигенција за почетнике.

### Векторске базе података

Векторска база података, за разлику од традиционалних база, је специјализована база дизајнирана за складиштење, управљање и претрагу уграђених вектора. Она чува нумеричке репрезентације докумената. Разлагање података у нумеричке уградње олакшава нашем AI систему да разуме и обради податке.

Пошто LLM има ограничење броја улазних токена, документе делео на делове пре уграђивања. Када корисник постави питање, уградње које су најсличније упиту идентификују релевантне делове текста, који се враћају са упитом. Деловање такође смањује број токена прослеђених LLM-у и тиме може смањити трошкове.

Неке популарне векторске базе укључују Azure Cosmos DB, Clarifyai, Pinecone, Chromadb, ScaNN, Qdrant и DeepLake. Можете креирати модел Azure Cosmos DB користећи Azure CLI са следећом командом:

```bash
az login
az group create -n <resource-group-name> -l <location>
az cosmosdb create -n <cosmos-db-name> -r <resource-group-name>
az cosmosdb list-keys -n <cosmos-db-name> -g <resource-group-name>
```

### Од текста до уградњи

Пре него што сачувамо наше податке, морамо их претворити у векторске уградње пре складиштења у бази. Ако радите са великим документима или дугачким текстовима, можете их поделити на делове у зависности од очекиваних упита. Деловање може бити на нивоу реченица или пасуса. Пошто деловање изводи значења из речи око њих, можете додати додатни контекст делу, на пример, додавањем наслова документа или укључивањем текста пре или после дела. Податке можете поделити како следи:

```python
def split_text(text, max_length, min_length):
    words = text.split()
    chunks = []
    current_chunk = []

    for word in words:
        current_chunk.append(word)
        if len(' '.join(current_chunk)) < max_length and len(' '.join(current_chunk)) > min_length:
            chunks.append(' '.join(current_chunk))
            current_chunk = []

    # If the last chunk didn't reach the minimum length, add it anyway
    if current_chunk:
        chunks.append(' '.join(current_chunk))

    return chunks
```

Када се поделе, текст можемо уградити користећи различите моделе уградње. Неки модели које можете користити укључују: word2vec, ada-002 од OpenAI, Azure Computer Vision и многе друге. Избор модела зависи од језика који користите, типа садржаја који се кодира (текст/слике/аудио), величине улаза који може да кодира и дужине излаза уградње.

## Претрага и претраживање вектора

Када корисник постави питање, претраживач га трансформише у вектор користећи енкодер упита, затим претражује индекс докумената за релевантне векторе који су повезани са уносом. Када се заврши, претвара и улазни вектор и векторе докумената у текст и прослеђује их LLM-у.

### Претрага

Претрага се дешава када систем покушава брзо да нађе документе из индекса који задовољавају критеријуме претраге. Циљ претраживача је да добије документе који ће се користити за пружање контекста и ослањање LLM-а на ваше податке.

Постоји неколико начина за претрагу базе података као што су:

- **Претрага по кључним речима** - користи се за претрагу текста

- **Претрага вектора** - претвара документе из текста у векторске репрезентације користећи моделе уградње, омогућавајући **семантичку претрагу** коришћењем значења речи. Претрага се врши коришћењем докумената чије су векторске репрезентације најближе корисничком питању.

- **Хибридна** - комбинација претраге по кључним речима и претраге вектора.

Изазов са претрагом долази када у бази не постоји сличан одговор на упит, систем ће онда вратити најбоље доступне информације, међутим, можете користити тактике као што је постављање максималне удаљености за релевантност или користити хибридну претрагу која комбинује претрагу по кључним речима и претрагу вектора. У овој лекцији користићемо хибридну претрагу, комбинацију претраге вектора и кључних речи. Чуваћемо наше податке у dataframe-у са колонама које садрже делове текста као и уградње.

### Сличност вектора

Претраживач ће претраживати базу знања за уградње које су близу једна другој—најближе комшије—јер представљају сличне текстове. У овом сценарију, када корисник поднесе упит, прво се уграђује, а затим упоређује са сличним уградњама. Најчешће мерење за упоређивање сличности вектора је косинусна сличност, која се заснива на углу између два вектора.

Друге мере које можемо користити за мерење сличности укључују Еуклидску удаљеност, која је права линија између крајева вектора, и скаларни производ, који мери зброј производа одговарајућих елемената два вектора.

### Индекс претраге

При обављању претраге, биће нам потребно да изградимо индекс претраге за нашу базу знања пре него што извршимо претрагу. Индекс ће чувати наше уградње и може брзо пронаћи најсличније делове чак и у великој бази података. Наш индекс можемо креирати локално коришћењем:

```python
from sklearn.neighbors import NearestNeighbors

embeddings = flattened_df['embeddings'].to_list()

# Create the search index
nbrs = NearestNeighbors(n_neighbors=5, algorithm='ball_tree').fit(embeddings)

# To query the index, you can use the kneighbors method
distances, indices = nbrs.kneighbors(embeddings)
```

### Поновно рангирање

Када упитате базу, можда ћете морати да сортирате резултате од најрелевантнијих. LLM за поновно рангирање користи машинско учење за побољшање релевантности резултата претраге поређајући их од најрелевантнијих. Коришћењем Azure AI претраге, поновно рангирање се аутоматски ради помоћу семантичког рангирача. Пример како поновно рангирање функционише коришћењем најближих комшија:

```python
# Find the most similar documents
distances, indices = nbrs.kneighbors([query_vector])

index = []
# Print the most similar documents
for i in range(3):
    index = indices[0][i]
    for index in indices[0]:
        print(flattened_df['chunks'].iloc[index])
        print(flattened_df['path'].iloc[index])
        print(flattened_df['distances'].iloc[index])
    else:
        print(f"Index {index} not found in DataFrame")
```

## Све заједно

Последњи корак је додавање нашег LLM у комбинацију да бисмо могли добити одговоре који се ослањају на наше податке. То можемо имплементирати како следи:

```python
user_input = "what is a perceptron?"

def chatbot(user_input):
    # Convert the question to a query vector
    query_vector = create_embeddings(user_input)

    # Find the most similar documents
    distances, indices = nbrs.kneighbors([query_vector])

    history = []

        {"role": "system", "content": "You are an AI assistant that helps with AI questions."},
        {"role": "user", "content": "\n\n".join(history) }
    ]

    # use the Responses API to generate a response
    response = client.responses.create(
        model="gpt-5-mini",

    )

    return response.output_text

chatbot(user_input)
```

## Процена наше апликације

### Метрике евалуације

- Квалитет одговора, водећи рачуна да звуче природно, течно и људски

- Основаност на подацима: процена да ли је одговор потекао из приложених докумената

- Релевантност: процена да ли одговор одговара и односи се на постављено питање

- Течност - да ли одговор има смисла граматички

## Употребни случајеви за коришћење RAG (Retrieval Augmented Generation) и векторских база података

Постоје бројни случајеви где RAG може побољшати вашу апликацију, као што су:

- Питања и одговори: ослањање на податке компаније у разговору који могу користити запослени за постављање питања.

- Системи препорука: где можете креирати систем који упоређује најсличније вредности, нпр. филмове, ресторане и многе друге.

- Услуге четбота: можете чувати историју разговора и персонализовати разговор на основу података корисника.

- Претрага слика заснована на векторским уградњама, корисна за препознавање слика и детекцију аномалија.
