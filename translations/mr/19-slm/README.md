# सुरुवातीसाठी लहान भाषा मॉडेल्ससाठी जनरेटिव्ह AI परिचय
जनरेटिव्ह AI हा कृत्रिम बुद्धिमत्तेचा एक आकर्षक क्षेत्र आहे जे नवीन सामग्री तयार करण्यास सक्षम सिस्टम्स तयार करण्यावर लक्ष केंद्रित करते. ही सामग्री मजकूर आणि प्रतिमा पासून ते संगीत आणि संपूर्ण आभासी वातावरणांपर्यंत असू शकते. जनरेटिव्ह AI चा एक सर्वात रोमांचक अनुप्रयोग भाषा मॉडेल्सच्या क्षेत्रात आहे.

## लहान भाषा मॉडेल्स म्हणजे काय?

लहान भाषा मॉडेल (SLM) म्हणजे मोठ्या भाषा मॉडेल (LLM) चा एक संकुचित प्रकार, जो LLM च्या अनेक स्थापत्य तत्त्वे आणि तंत्र वापरतो, परंतु लक्षणीयरीत्या कमी संगणकीय अवकाश असलेला.

SLMs हे भाषा मॉडेल्सचा एक उपसमूह आहेत जे मानवी सारखा मजकूर निर्माण करण्यासाठी डिझाइन केलेले आहेत. GPT-4 सारख्या त्यांच्या मोठ्या मॉडेल्सच्या उलट, SLMs अधिक कॉम्पॅक्ट आणि कार्यक्षम असतात, जे संगणकीय संसाधने मर्यादित असलेल्या अनुप्रयोगांसाठी आदर्श आहेत. त्यांच्या आकाराच्या छोटेपणानुसारही, ते विविध कार्ये पार पाडू शकतात. सहसा, SLMs LLMs चा संपीडन किंवा सुव्यवस्थापन करून तयार केले जातात, ज्याचा उद्देश मूळ मॉडेलच्या कार्यक्षमता आणि भाषिक क्षमतांचा मोठा भाग राखणे असतो. मॉडेलच्या आकारातील ही घट संपूर्ण गुंतागुंती कमी करून, SLMs अधिक कार्यक्षम बनवते, ज्यामुळे स्मृती वापर व संगणकीय गरजा दोन्ही कमी होतात. या सुधारणांनंतरही, SLMs नैसर्गिक भाषा प्रक्रिया (NLP) चे विविध कार्ये पार पाडू शकतात:

- मजकूर निर्मिती: सुसंगत आणि संदर्भानुरूप वाक्ये किंवा परिच्छेद तयार करणे.
- मजकूर पूर्ण करणे: दिलेल्या प्रम्प्टवर आधारित वाक्ये भाकीत करणे आणि पूर्ण करणे.
- अनुवाद: एका भाषेतील मजकूर दुसऱ्या भाषेत रूपांतरित करणे.
- सारांश: लांब मजकूर भाग संक्षिप्त, अधिक सोप्या सारांशात रूपांतरित करणे.

त्यांच्या मोठ्या मॉडेल्सच्या तुलनेत काही कामगिरी किंवा समजुतीच्या खोलीतील फेरफारांसह.

## लहान भाषा मॉडेल्स कसे कार्य करतात?
SLMs प्रचंड प्रमाणात मजकूर डेटावर प्रशिक्षित केले जातात. प्रशिक्षणादरम्यान, ते भाषा संरचना आणि नमुने शिकतात, ज्यामुळे ते व्याकरणिकदृष्ट्या बरोबर आणि संदर्भानुसार योग्य मजकूर तयार करू शकतात. प्रशिक्षण प्रक्रियेमध्ये समाविष्ट आहे:

- डेटा संकलन: विविध स्त्रोतांमधून मोठ्या मजकूर डेटासेट्स गोळा करणे.
- पूर्वतयारी: डेटाला स्वच्छ आणि प्रशिक्षणासाठी योग्य प्रकारे आयोजित करणे.
- प्रशिक्षण: मशीन लर्निंग अल्गोरिदमचा वापर करून मॉडेलला मजकूर समजून घेण्याचे आणि निर्माण करण्याचे प्रशिक्षण देणे.
- फाइन-ट्यूनिंग: विशिष्ट कार्यांवरील कार्यक्षमता सुधारण्यासाठी मॉडेल समायोजित करणे.

SLMs चा विकास संसाधन-मर्यादित वातावरणांमध्ये तैनात करण्याच्या गरजेनुसार झाला आहे, जसे की मोबाईल डिव्हाइसेस किंवा एज संगणन प्लॅटफॉर्म्स, जिथे पूर्ण-स्तरीय LLMs त्यांच्या जड संसाधन गरजांमुळे वापरणे अव्यवहार्य ठरू शकते. कार्यक्षमतेवर लक्ष केंद्रित करून, SLMs कार्यक्षमता आणि उपलब्धता यांच्यात संतुलन साधतात, ज्यामुळे विविध क्षेत्रांमध्ये अधिक मोठ्या प्रमाणावर अनुप्रयोग शक्य होतो.

## मोठ्या भाषा मॉडेल्स (LLMs) आणि लहान भाषा मॉडेल्स (SLMs) मधील फरक

LLMs आणि SLMs दोन्ही संभाव्य मशीन लर्निंगच्या मूलभूत तत्त्वांवर आधारित आहेत, त्यांची स्थापत्य रचना, प्रशिक्षण पद्धती, डेटा निर्मिती प्रक्रिया, आणि मॉडेल मूल्यांकन तंत्रे सारखीच आहेत. मात्र, काही महत्त्वाचे घटक या दोन्ही प्रकारच्या मॉडेल्समध्ये फरक करतात.

## लहान भाषा मॉडेल्सचे अनुप्रयोग

SLMs चे विविध वापर आहेत, ज्यामध्ये समाविष्ट आहेत:

- चैटबॉट्स: ग्राहक सेवा प्रदान करणे आणि वापरकर्त्यांशी संवादात्मक पद्धतीने संवाद साधणे.
- सामग्री निर्मिती: लेखकांना कल्पना निर्माण करण्यात मदत करणे किंवा संपूर्ण लेख तयार करणे.
- शिक्षण: विद्यार्थ्यांना लेखन कामात किंवा नवीन भाषा शिकण्यात मदत करणे.
- सुलभता: अपंगत्व असलेल्या लोकांसाठी उपकरणे तयार करणे, उदा. मजकूर-ते-वाद वळण्याची प्रणाली.

**आकार**
  
LLMs आणि SLMs मधील मुख्य फरक म्हणजे मॉडेल्सचा परिमाण. उदाहरणार्थ, ChatGPT (GPT-4) मध्ये अंदाजे 1.76 ट्रिलियन पॅरामीटर्स असू शकतात, तर मुक्त स्रोत SLMs जसे Mistral 7B मध्ये सुमारे 7 अब्ज पॅरामीटर्स असतात. हा फरक मुख्यतः मॉडेल स्थापत्य आणि प्रशिक्षण प्रक्रियेतील भिन्नतेमुळे असतो. उदाहरणादाखल, ChatGPT एक्सकोडर-डेकोडर फ्रेमवर्कमध्ये सेल्फ-अटेंशन मेकॅनिझम वापरतो, तर Mistral 7B स्लाइडिंग विंडो अटेंशन वापरतो, जे डेकोडर-ओन्ली मॉडेलमध्ये अधिक कार्यक्षम प्रशिक्षण सक्षम करते. या स्थापत्य भिन्नतेचे या मॉडेल्सच्या गुंतागुंती आणि कार्यक्षमतेवर मोठे परिणाम होतात.

**समज**

SLMs सहसा विशिष्ट क्षेत्रांमध्ये चांगली कार्यक्षमता देण्यासाठी अनुकूलित केले जातात, त्यामुळे ते फारसे व्यापक संदर्भात्मक समज देण्यात मर्यादित असू शकतात. उलट, LLMs मानवी सारख्या बुद्धिमत्तेचे यथार्थ अनुकरण करण्याचा उद्देश ठेवतात. प्रचंड आणि विविध डेटासेट्सवर प्रशिक्षित, LLMs विविध क्षेत्रांत चांगली कामगिरी करण्यासाठी डिझाइन केलेले आहेत, ज्यामुळे त्यांना अधिक लवचीकता आणि अनुकूलता मिळते. परिणामी, LLMs नैसर्गिक भाषा प्रक्रिया आणि प्रोग्रॅमिंगसारख्या विविध कार्यांसाठी अधिक योग्य ठरतात.

**संगणकीय क्षमता**

LLMs चे प्रशिक्षण व तैनाती संसाधन-गहन प्रक्रिया आहे, ज्यासाठी बहुधा मोठ्या प्रमाणावर संगणकीय अंतर्गत रचना आवश्यक असते, ज्यात मोठ्या प्रमाणात GPU क्लस्टर समाविष्ट आहेत. उदाहरणार्थ, ChatGPT सारख्या मॉडेलचे सुरुवातीपासून प्रशिक्षण करणे हजारो GPU वापरून अनेक वेळा लागू शकते. याउलट, SLMs, त्यांच्या छोट्या पॅरामीटर संख्येमुळे, संगणकीय संसाधनांच्या दृष्टीने अधिक प्रवेशयोग्य आहेत. Mistral 7B सारखे मॉडेल स्थानिक संगणकांवर मध्यम GPU क्षमता वापरून प्रशिक्षण आणि चालवले जाऊ शकतात, जरी प्रशिक्षण अनेक GPUs मध्ये काही तास लागतात.

**पूर्वग्रह**

LLMs मध्ये पूर्वग्रह ही एक ज्ञात समस्या आहे, मुख्यतः प्रशिक्षण डेटाच्या स्वरूपामुळे. या मॉडेल्स सहसा इंटरनेटवरील खुले डेटावर अवलंबून असतात, जे काही गटांचे अपर्याप्त किंवा अयोग्य प्रतिनिधित्त्व करते, चुकीचे लेबलिंग करते, किंवा बोलीभाषा, भौगोलिक फरक आणि व्याकरण नियमांमुळे भाषिक पूर्वग्रह प्रतिबिंबित करते. शिवाय, LLM च्या स्थापत्यातील गुंतागुंत अनवधानाने पूर्वग्रह वाढवू शकते, ज्यावर काळजीपूर्वक फाइन-ट्यूनिंग शिवाय लक्ष दिले जात नाही. दुसरीकडे, SLMs मर्यादित, क्षेत्रविशेष डेटासेट्सवर आधारित असल्याने अशा पूर्वग्रहांपासून तुलनेने कमी प्रभावित होतात, तरीही ते पूर्णपणे मोकळे नाहीत.

**अनुमान**

SLMs चा कमी आकार त्यांना अनुमान गतीमध्ये मोठा फायदा देतो, ज्यामुळे ते स्थानिक हार्डवेअरवर कार्यक्षमता वाढवून आउटपुट निर्माण करू शकतात, ज्यासाठी मोठ्या प्रमाणात समांतर प्रक्रिया आवश्यक नसते. विरुद्ध, LLMs च्या आकार आणि जटिलतेमुळे स्वीकारार्ह अनुमान वेळ मिळवण्यासाठी मोठ्या प्रमाणावर समांतर संगणकीय संसाधनांची गरज भासते. अनेक वापरकर्त्यांच्या एकाच वेळी उपस्थितीमुळे LLMs ची प्रतिसाद वेळ अजूनही हळू होते, विशेषत: वेगळ्या प्रमाणावर तैनात केल्यावर.

एकूणच, जरी LLMs आणि SLMs मशीन लर्निंगच्या मूलभूत तत्त्वांवर आधारित असले तरी, ते मॉडेल आकार, संसाधन आवश्यकता, संदर्भात्मक समज, पूर्वग्रहाची संवेदनशीलता, आणि अनुमान गतीच्या बाबतीत लक्षणीय फरक दाखवतात. हे फरक त्यांच्या वेगळ्या वापरासाठी अनुकूलतेचे प्रतिबिंब आहेत, ज्यामध्ये LLMs अधिक बहुमुखी पण जड असतात आणि SLMs कमी संगणकीय मागण्यांसह क्षेत्रविशेष कार्यक्षमतेसाठी योग्य ठरतात.

## Phi-3 / Phi-3.5 कुटुंबाची ओळख

Phi-3 / 3.5 कुटुंब मुख्यतः मजकूर, दृष्टी, आणि एजंट (MoE) वापराच्या परिस्थितींवर लक्ष केंद्रित करते:

### Phi-3 / 3.5 इंस्ट्रक्ट

मुख्यतः मजकूर निर्मिती, चॅट पूर्ण करणे, आणि सामग्री माहिती काढणे इत्यादीसाठी.

**Phi-3-mini**

3.8B भाषा मॉडेल Microsoft Foundry, Hugging Face, आणि Ollama वर उपलब्ध आहे. Phi-3 मॉडेल्स समान आणि मोठ्या आकाराच्या भाषा मॉडेल्सच्या मुख्य बेंचमार्कवर (खाली दिलेल्या बेंचमार्क संख्यांकडे पहा, जास्त संख्या चांगली असते) लक्षणीयरीत्या उच्च कार्यक्षमता दर्शवतात. Phi-3-mini दोनपट आकाराच्या मॉडेल्सपेक्षा अधिक चांगले आहे, तर Phi-3-small आणि Phi-3-medium जास्त मोठ्या मॉडेल्ससहीत, GPT-3.5 दृष्टीलाच चांगले कामगिरी करतात.

**Phi-3-small & medium**

फक्त 7B पॅरामीटर्ससह, Phi-3-small विविध भाषा, तार्किक, कोडिंग, आणि गणित बेंचमार्कमध्ये GPT-3.5T ला मात देतो.

14B पॅरामीटर्ससह Phi-3-medium या प्रवृत्तीस चालना देतो आणि Gemini 1.0 Pro पेक्षा उत्कृष्ट कामगिरी करतो.

**Phi-3.5-mini**

आपण याला Phi-3-mini चे एक उन्नत आवृत्ती समजू शकतो. पॅरामीटर्स अपरिवर्तित राहिले तरी, हे अनेक भाषा (20+ भाषा समर्थन: अरबी, चीनी, चेक, डॅनिश, डच, इंग्रजी, फिनिश, फ्रेंच, जर्मन, हिब्रू, हंगेरीयन, इटालियन, जपानी, कोरियन, नॉर्वेजियन, पोलिश, पोर्तुगीज, रशियन, स्पॅनिश, स्वीडिश, थाई, टर्किश, युक्रेनियन) समर्थन सुधारणा करते आणि लांब संदर्भाचा मजबूत आधार देते.

3.8B पॅरामीटर्ससह Phi-3.5-mini समान आकाराच्या भाषा मॉडेल्सना मात देतो आणि दोनपट आकाराच्या मॉडेल्ससह तुल्यकारक असतो.

### Phi-3 / 3.5 दृष्टी

आपण Phi-3/3.5 च्या इंस्ट्रक्ट मॉडेलला Phi च्या समजण्याच्या क्षमतेसारखे समजू शकतो, आणि दृष्टी म्हणजे Phi ला जग समजण्याची दृष्टी देणारे आहे.


**Phi-3-Vision**

फक्त 4.2B पॅरामीटर्ससह Phi-3-विजन या प्रवृत्तीस सुरू ठेवतो आणि सामान्य दृश्यात्मक तार्किक कार्ये, OCR, तक्ता आणि आकृती समजणे अशा कार्यांमध्ये Claude-3 Haiku आणि Gemini 1.0 Pro V सारख्या मोठ्या मॉडेल्सला मागे टाकतो.


**Phi-3.5-Vision**

Phi-3.5-विजन हा Phi-3-विजनचा ही एक उन्नत आवृत्ती आहे, ज्यात अनेक प्रतिमांसाठी समर्थन समाविष्ट आहे. आपण हे एक दृष्टिकोनातील सुधारणा म्हणून पाहू शकता, जेथे आपण फक्त चित्रे नाही तर व्हिडिओही पाहू शकता.

Phi-3.5-विजन OCR, तक्ता व तक्ता समजण्यासाठी आणि सामान्य दृश्य ज्ञान तार्किक कार्यांमध्ये Claude-3.5 Sonnet आणि Gemini 1.5 Flash सारख्या मोठ्या मॉडेल्सला मागे टाकतो. मल्टिफ्रेम इनपुट समर्थन, म्हणजे अनेक इनपुट प्रतिमांवर तार्किक कार्य करणे शक्य.


### Phi-3.5-MoE

***तज्ञांचा मिश्रण (MoE)*** मॉडेल्सना खूप कमी संगणकीय खर्चात पूर्वप्रशिक्षित होण्यास सक्षम करते, ज्याचा अर्थ असा की आपण समान संगणकीय बजेटमध्ये मॉडेल किंवा डेटासेटचा आकार मोठ्या प्रमाणात वाढवू शकता. विशेषतः, MoE मॉडेल आपला घन मॉडेलसारखी गुणवत्ता पूर्वप्रशिक्षणात खूप जलद गाठते.

Phi-3.5-MoE मध्ये 16x3.8B तज्ञ मॉड्यूल्स असतात. फक्त 6.6B सक्रिय पॅरामीटर्ससह Phi-3.5-MoE खूप मोठ्या मॉडेल्ससारखी तार्किक क्षमता, भाषा समज आणि गणित गुणवत्ता प्राप्त करते.

- **सुरक्षा आणि नियंत्रण:** संस्था त्यांच्या डेटा आणि अनुप्रयोगांवर स्वयं-होस्टिंग NIM सूक्ष्मसेवांचे नियंत्रण राखू शकतात त्यांच्या स्वत: च्या व्यवस्थापित अवसंरचनेवर.

**Hugging Face Transformer**
Hugging Face Transformers हा एक शक्तिशाली ग्रंथालय आहे जो नॅचरल लँग्वेज प्रोसेसिंग (NLP) आणि इतर मशीन लर्निंग कार्यांसाठी डिझाइन केला आहे. येथे याबद्दल काही महत्त्वाचे मुद्दे आहेत:

1. **पूर्व-प्रशिक्षित मॉडेल:** हे विविध कार्यांसाठी हजारो पूर्व-प्रशिक्षित मॉडेल प्रदान करतात, जसे मजकूर वर्गीकरण, नामांकित घटक ओळख, प्रश्न उत्तरे, सारांश, अनुवाद आणि मजकूर निर्मिती.

2. **फ्रेमवर्क इंटरऑपरेबिलिटी:** हे ग्रंथालय PyTorch, TensorFlow, आणि JAX सारख्या अनेक डीप लर्निंग फ्रेमवर्कसाठी समर्थन करते. यामुळे आपण एका फ्रेमवर्कमध्ये मॉडेल प्रशिक्षण घेऊ शकता आणि दुसर्‍यामध्ये वापरू शकता.

3. **मल्टिमोडल क्षमता:** NLP शिवाय, Hugging Face Transformers संगणक दृश्यमानता (उदा., प्रतिमा वर्गीकरण, ऑब्जेक्ट डिटेक्शन) आणि ऑडिओ प्रक्रिया (उदा., भाषण ओळख, ऑडिओ वर्गीकरण) मध्येही कार्यांसाठी समर्थन करतो.

4. **सोपे वापर:** ग्रंथालय सुलभ डाउनलोड आणि फाइन-ट्यूनिंगसाठी API आणि साधने देते, ज्यामुळे ते नवीन आणि तज्ञ दोघांसाठी सहज प्रवेशयोग्य बनतो.

5. **समुदाय आणि संसाधने:** Hugging Face कडे सक्रिय समुदाय आणि विस्तृत दस्तऐवज, ट्यूटोरियल्स, आणि मार्गदर्शक आहेत जे वापरकर्त्यांना सुरू करण्यात आणि ग्रंथालयाचा जास्तीत जास्त फायदा घेण्यात मदत करतात.
[अधिकृत दस्तऐवज](https://huggingface.co/docs/transformers/index?WT.mc_id=academic-105485-koreyst) किंवा त्यांच्या [GitHub रिपॉझिटरी](https://github.com/huggingface/transformers?WT.mc_id=academic-105485-koreyst).

## ONNX Runtime म्हणजे काय?
ONNX Runtime हा एक मुक्त स्त्रोत प्रकल्प आहे जो मशीन लर्निंग मॉडेल्सच्या उच्च-प्रदर्शन अंदाज करण्यास सक्षम करतो. हे Open Neural Network Exchange (ONNX) स्वरूपातील मॉडेल्सला समर्थन देतो, जे मशीन लर्निंग मॉडेल्सचे प्रतिनिधित्व करण्यासाठी एक मानक आहे. ONNX Runtime इन्फरन्स जलद ग्राहक अनुभव आणि कमी खर्च सक्षम करू शकतो, PyTorch आणि TensorFlow/Keras सारख्या डीप लर्निंग फ्रेमवर्कसह तसेच scikit-learn, LightGBM, XGBoost सारख्या पारंपरिक मशीन लर्निंग लायब्ररीजसाठी मॉडेल्सचे समर्थन करतो. ONNX Runtime विविध हार्डवेअर, ड्रायव्हर्स, आणि ऑपरेटिंग सिस्टमसाठी सुसंगत आहे, आणि हार्डवेअर त्वरेकारकांचा लाभ घेऊन तसेच ग्राफ ऑप्टिमायझेशन्स आणि ट्रान्सफॉर्म्ससह उत्कृष्ट कार्यक्षमतेची हमी देते.

## जनरेटिव्ह AI म्हणजे काय?
जनरेटिव्ह AI म्हणजे अशा AI प्रणाली ज्यात त्यांनी प्रशिक्षण घेतल्या डेटावर आधारित नवीन सामग्री निर्माण करण्याची क्षमता आहे, जसे की मजकूर, प्रतिमा, किंवा संगीत. उदाहरणार्थ भाषा मॉडेल्स जसे GPT-3 आणि प्रतिमा उत्पादन मॉडेल्स जसे Stable Diffusion. ONNX Runtime GenAI लायब्ररी ONNX मॉडेल्ससाठी जनरेटिव्ह AI लूप प्रदान करते, ज्यात ONNX Runtime सह इन्फरन्स, लाजिट्स प्रक्रिया, शोध आणि सॅम्पलिंग, तसेच KV कॅशे व्यवस्थापन समाविष्ट आहे.

## ONNX Runtime for GENAI
ONNX Runtime for GENAI ONNX Runtime च्या क्षमता वाढवते जेणेकरून जनरेटिव्ह AI मॉडेल्सना समर्थन करता येईल. येथे काही मुख्य वैशिष्ट्ये:

- **व्यापक प्लॅटफॉर्म समर्थन:** हे Windows, Linux, macOS, Android, आणि iOS यांसारख्या विविध प्लॅटफॉर्मवर कार्य करते.
- **मॉडेल समर्थन:** हे LLaMA, GPT-Neo, BLOOM, आणि अन्य लोकप्रिय जनरेटिव्ह AI मॉडेल्सना समर्थन करते.
- **कार्यक्षमता ऑप्टिमायझेशन:** यात NVIDIA GPUs, AMD GPUs आणि इत्यादी हार्डवेअर त्वरेकारकांसाठी भिन्न ऑप्टिमायझेशन्स समाविष्ट आहेत.
- **सोप्या वापरासाठी:** हे API प्रदान करते जे अनुप्रयोगांमध्ये सहज समाकलनास मदत करतात, ज्यामुळे किमान कोड वापरून तुम्ही मजकूर, प्रतिमा, आणि अन्य सामग्री निर्माण करू शकता.
- वापरकर्ते एक उच्च-स्तरीय generate() पद्धत कॉल करू शकतात, किंवा मॉडेलच्या प्रत्येक पुनरावृत्तीत लूपमध्ये चालवू शकतात, एका वेळेस एक टोकन निर्माण करून, आणि इच्छेनुसार लूपच्या आत जनरेशन पॅरामिटर्स अद्यतनित करू शकतात.
- ONNX runtime मध्ये greedy/beam शोध आणि TopP, TopK सॅम्पलिंगचा देखील समर्थन आहे ज्यामुळे टोकन सिक्वेन्स तयार होतात आणि पुनरावृत्ती दंडांसारखी अंगभूत लाजिट्स प्रक्रिया होते. आपण सहजपणे कस्टम स्कोअरिंग देखील जोडू शकता.


### मॉडेल चालवा: Python मधील एक सोपा उदाहरण:
```Python
import onnxruntime_genai as og

model = og.Model('path_to_your_model.onnx')

tokenizer = og.Tokenizer(model)

input_text = "Hello, how are you?"

input_tokens = tokenizer.encode(input_text)

output_tokens = model.generate(input_tokens)

output_text = tokenizer.decode(output_tokens)

print(output_text) 
```
### डेमो: ONNX Runtime GenAI वापरून Phi-3.5-Vision कॉल करणे


```python

import onnxruntime_genai as og

model_path = './Your Phi-3.5-vision-instruct ONNX Path'

img_path = './Your Image Path'

model = og.Model(model_path)

processor = model.create_multimodal_processor()

tokenizer_stream = processor.create_stream()

text = "Your Prompt"

prompt = "<|user|>\n"

prompt += "<|image_1|>\n"

prompt += f"{text}<|end|>\n"

prompt += "<|assistant|>\n"

image = og.Images.open(img_path)

inputs = processor(prompt, images=image)

params = og.GeneratorParams(model)

params.set_inputs(inputs)

params.set_search_options(max_length=3072)

generator = og.Generator(model, params)

while not generator.is_done():

    generator.compute_logits()
    
    generator.generate_next_token()

    new_token = generator.get_next_tokens()[0]
    
    output = tokenizer_stream.decode(new_token)
    
    print(tokenizer_stream.decode(new_token), end='', flush=True)

```
