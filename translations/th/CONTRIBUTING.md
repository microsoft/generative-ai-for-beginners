# การมีส่วนร่วม

โครงการนี้ยินดีต้อนรับการมีส่วนร่วมและข้อเสนอแนะ ส่วนใหญ่การมีส่วนร่วมจำเป็นต้องให้คุณ
ยอมรับข้อตกลงใบอนุญาตผู้ร่วมพัฒนา (CLA) ที่ระบุว่าคุณมีสิทธิ์,
และแท้จริงแล้วให้สิทธิ์แก่เราในการใช้การมีส่วนร่วมของคุณ สำหรับรายละเอียด โปรดไปที่
<https://cla.microsoft.com>.

> สำคัญ: เมื่อแปลข้อความในที่เก็บนี้ โปรดแน่ใจว่าคุณไม่ได้ใช้การแปลด้วยเครื่อง เราจะตรวจสอบการแปลผ่านชุมชน ดังนั้น โปรดอาสาทำการแปลในภาษาเท่านั้นที่คุณมีความชำนาญ

เมื่อคุณส่งคำขอดึง (pull request) CLA-bot จะตรวจสอบโดยอัตโนมัติว่าคุณต้อง
ให้ CLA หรือไม่ และประดับ PR อย่างเหมาะสม (เช่น ป้ายกำกับ ความเห็น) เพียงทำตาม
คำแนะนำที่บอทให้มา คุณจะต้องทำเช่นนี้เพียงครั้งเดียวสำหรับทุกที่เก็บที่ใช้ CLA ของเรา

## หลักปฏิบัติ

โครงการนี้ได้นำ [Microsoft Open Source Code of Conduct](https://opensource.microsoft.com/codeofconduct/?WT.mc_id=academic-105485-koreyst) มาใช้
สำหรับข้อมูลเพิ่มเติม โปรดอ่าน [Code of Conduct FAQ](https://opensource.microsoft.com/codeofconduct/faq/?WT.mc_id=academic-105485-koreyst) หรือ ติดต่อ [opencode@microsoft.com](mailto:opencode@microsoft.com) หากมีคำถามหรือความคิดเห็นเพิ่มเติม

## คำถามหรือปัญหา?

โปรดอย่าเปิดประเด็นใน GitHub สำหรับคำถามสนับสนุนทั่วไปเนื่องจากรายการใน GitHub ควรใช้สำหรับคำขอฟีเจอร์และรายงานบั๊ก วิธีนี้จะช่วยให้เราติดตามปัญหาหรือบั๊กที่แท้จริงจากโค้ดได้ง่ายขึ้นและแยกการอภิปรายทั่วไปออกจากโค้ดจริง

## การสะกดผิด ปัญหา บั๊ก และการมีส่วนร่วม

เมื่อใดก็ตามที่คุณส่งการเปลี่ยนแปลงใด ๆ ไปยังคลังข้อมูล Generative AI for Beginners โปรดปฏิบัติตามคำแนะนำเหล่านี้

* ควร fork คลังข้อมูลไปยังบัญชีของคุณเองก่อนทำการแก้ไขเสมอ
* อย่ารวมหลายการเปลี่ยนแปลงใน pull request เดียว เช่น ส่งการแก้ไขบั๊กและอัปเดตเอกสารแยกกันใน PR ต่างหาก
* หาก pull request ของคุณแสดงความขัดแย้งการ merge ให้แน่ใจว่าได้อัปเดต main ในเครื่องของคุณให้เป็นภาพสะท้อนของ main ที่อยู่ในคลังหลักก่อนทำการแก้ไข
* หากคุณส่งการแปล โปรดสร้าง PR เดียวสำหรับไฟล์ที่แปลทั้งหมดเนื่องจากเราไม่รับการแปลบางส่วนสำหรับเนื้อหา
* หากคุณส่งการแก้ไขการสะกดผิดหรือเอกสาร คุณสามารถรวมการแก้ไขใน PR เดียวได้ในกรณีที่เหมาะสม

## ขอบเขตการแก้ไขและผลิตภัณฑ์ของบุคคลที่สาม

หลักสูตรนี้เน้นเทคโนโลยีของ Microsoft และมาตรฐานเปิดที่เป็นกลางจากผู้จำหน่าย การมีส่วนร่วมควรมีวัตถุประสงค์เพื่อการศึกษาอย่างชัดเจนและไม่ควรมุ่งเน้นเพื่อแนะนำหรือส่งเสริมผลิตภัณฑ์เชิงพาณิชย์ บุคคลที่สาม บริการโฮสต์ เราเตอร์โมเดล SDK MCP เซิร์ฟเวอร์ หรือข้อเสนอเฉพาะของผู้จำหน่ายอื่น ๆ เป็นหลัก

ซอฟต์แวร์โอเพ่นซอร์สและการพึ่งพาบุคคลที่สามอาจถูกอ้างอิงเมื่อจำเป็นเพื่ออธิบายมาตรฐานเปิดหรือสถานการณ์ความเข้ากันได้ ถูกนำเสนออย่างเป็นกลาง และไม่เน้นไปที่ผลิตภัณฑ์หรือจุดเชื่อมต่อที่โฮสต์โดยผู้จำหน่าย หากการมีส่วนร่วมที่เสนอของคุณรวมถึงผลิตภัณฑ์หรือบริการเฉพาะของผู้จำหน่าย ให้เปิด issue และขออนุมัติจากผู้ดูแลก่อนส่ง pull request

ผู้มีส่วนร่วมต้องเปิดเผยการจ้างงาน ความเป็นเจ้าของ การสนับสนุน หรือความสัมพันธ์อื่น ๆ ที่เกี่ยวข้องกับผลิตภัณฑ์หรือบริการที่อ้างอิงในการมีส่วนร่วมของพวกเขา ห้ามรวมคำกล่าวอ้างราคาที่ไม่ได้รับการสนับสนุน ประสิทธิภาพ ความปลอดภัย ความเป็นส่วนตัว หรือการเปรียบเทียบ ตัวอย่างที่รันได้ต้องไม่ส่งข้อมูลผู้เรียนหรือดำเนินการสาธารณะผ่านบริการบุคคลที่สามภายนอกโดยค่าเริ่มต้น

## แนวทางทั่วไปสำหรับการเขียน

- ตรวจสอบให้แน่ใจว่า URL ทั้งหมดของคุณถูกครอบด้วยเครื่องหมายวงเล็บเหลี่ยม ตามด้วยวงเล็บปีกกาที่ไม่มีช่องว่างเพิ่มรอบ ๆ หรือภายใน `[]()`
- ตรวจสอบให้แน่ใจว่าลิงก์สัมพัทธ์ใด ๆ (เช่น ลิงก์ไปยังไฟล์และโฟลเดอร์อื่นในคลัง) เริ่มต้นด้วย `./` ที่อ้างถึงไฟล์หรือโฟลเดอร์ในไดเรกทอรีทำงานปัจจุบัน หรือ `../` ที่อ้างถึงไฟล์หรือโฟลเดอร์ในไดเรกทอรีทำงานเหนือขึ้นไป
- ตรวจสอบให้แน่ใจว่าลิงก์สัมพัทธ์ใด ๆ (เช่น ลิงก์ไปยังไฟล์และโฟลเดอร์อื่นในคลัง) มี ID ติดตาม (เช่น `?` หรือ `&` ตามด้วย `wt.mc_id=` หรือ `WT.mc_id=`) ที่ท้ายลิงก์
- ตรวจสอบให้แน่ใจว่า URL ใด ๆ จากโดเมนต่อไปนี้ _github.com, microsoft.com, visualstudio.com, aka.ms, และ azure.com_ มี ID ติดตาม (เช่น `?` หรือ `&` ตามด้วย `wt.mc_id=` หรือ `WT.mc_id=`) ที่ท้าย URL
- ตรวจสอบให้แน่ใจว่า ลิงก์ของคุณไม่มีโลเคลเฉพาะประเทศ (เช่น `/en-us/` หรือ `/en/`).
- ตรวจสอบให้แน่ใจว่ารูปภาพทั้งหมดถูกเก็บไว้ในโฟลเดอร์ `./images`.
- ตรวจสอบให้แน่ใจว่ารูปภาพมีชื่อที่บรรยายโดยใช้ตัวอักษรภาษาอังกฤษ ตัวเลข และขีดกลางในชื่อของรูปภาพของคุณ

## GitHub Workflows

เมื่อคุณส่งคำขอดึง (pull request) จะมีเวิร์กโฟลว์สี่ชุดที่ถูกเรียกใช้งานเพื่อยืนยันกฎก่อนหน้านี้
เพียงแค่ทำตามคำแนะนำที่ระบุไว้ที่นี่เพื่อผ่านการตรวจสอบเวิร์กโฟลว์

- [ตรวจสอบ Broken Relative Paths](#check-broken-relative-paths)
- [ตรวจสอบ Paths Have Tracking](#check-paths-have-tracking)
- [ตรวจสอบ URLs Have Tracking](#check-urls-have-tracking)
- [ตรวจสอบ URLs Don't Have Locale](#check-urls-dont-have-locale)

### ตรวจสอบ Broken Relative Paths

เวิร์กโฟลว์นี้จะยืนยันว่าทุกเส้นทางสัมพันธ์ในไฟล์ของคุณใช้งานได้
รีโพสิตอรีนี้ถูกนำเสนอไปยัง GitHub pages ดังนั้นคุณต้องระมัดระวังมากเมื่อพิมพ์ลิงก์ที่เชื่อมโยงทุกอย่างเข้าด้วยกันเพื่อไม่ให้ลิงก์พาใครไปยังที่ผิดพลาด

เพื่อให้แน่ใจว่าลิงก์ของคุณทำงานอย่างถูกต้อง ให้ใช้ VS code ตรวจสอบได้อย่างง่ายดาย

ตัวอย่างเช่น เมื่อคุณวางเมาส์เหนือใด ๆ ในไฟล์ของคุณ คุณจะได้รับแจ้งให้ติดตามลิงก์ด้วยการกด **ctrl + คลิก**

![VS code follow links screenshot](../../translated_images/th/vscode-follow-link.85520ab6a1237adc.webp?WT.mc_id=academic-105485-koreyst "ภาพหน้าจอจาก vs code แจ้งให้ติดตามลิงก์เมื่อคุณวางเมาส์เหนือลิงก์")

หากคุณคลิกที่ลิงก์และมันไม่ทำงานในเครื่องท้องถิ่น (local) แน่นอนมันจะทำให้เวิร์กโฟลว์ทำงานล้มเหลวและจะไม่ทำงานบน GitHub

เพื่อแก้ไขปัญหานี้ ลองพิมพ์ลิงก์โดยใช้ความช่วยเหลือของ VS code

เมื่อคุณพิมพ์ `./` หรือ `../` VS code จะเสนอทางเลือกให้คุณเลือกจากตัวเลือกที่มีตามสิ่งที่คุณพิมพ์

![VS code select relative path screenshot](../../translated_images/th/vscode-select-relative-path.3804eb73c3a9e5f2.webp?WT.mc_id=academic-105485-koreyst "ภาพหน้าจอจาก vs code แจ้งให้เลือกเส้นทางสัมพันธ์จากรายการป๊อปอัป")

ติดตามเส้นทางโดยคลิกไฟล์หรือโฟลเดอร์ที่ต้องการ และคุณจะมั่นใจได้ว่าเส้นทางของคุณไม่ขาดตอน

เมื่อคุณเพิ่มเส้นทางสัมพันธ์ที่ถูกต้อง บันทึก และผลักดันการเปลี่ยนแปลงของคุณ เวิร์กโฟลว์จะถูกเรียกใช้อีกครั้งเพื่อตรวจสอบการเปลี่ยนแปลงของคุณ
ถ้าคุณผ่านการตรวจสอบแล้ว คุณก็พร้อมใช้งานได้เลย

### ตรวจสอบ Paths Have Tracking

เวิร์กโฟลว์นี้จะยืนยันว่าเส้นทางสัมพันธ์ใด ๆ นั้นมีการติดตาม (tracking)
รีโพสิตอรีนี้ถูกนำเสนอไปยัง GitHub pages ดังนั้นเราต้องติดตามการเคลื่อนที่ระหว่างไฟล์และโฟลเดอร์ต่าง ๆ

เพื่อให้แน่ใจว่าเส้นทางสัมพันธ์ของคุณมีการติดตามในนั้น ให้ตรวจสอบข้อความ `?wt.mc_id=` ที่ท้ายเส้นทาง
หากเพิ่มลงในเส้นทางสัมพัทธ์ของคุณแล้ว คุณจะผ่านการตรวจสอบนี้

หากไม่ใช่ คุณอาจได้รับข้อผิดพลาดดังต่อไปนี้

![GitHub check paths missing tracking comment screenshot](../../translated_images/th/github-check-paths-missing-tracking-comment.880d4afe03e898ff.webp?WT.mc_id=academic-105485-koreyst "Screenshot from github comment that shows missing tracking from relative paths")

เพื่อแก้ไขปัญหานี้ ลองเปิดเส้นทางไฟล์ที่ workflow เน้นและเพิ่มรหัสติดตามไปที่ส่วนท้ายของเส้นทางสัมพัทธ์

เมื่อคุณเพิ่มรหัสติดตามแล้ว บันทึกและ push การเปลี่ยนแปลงของคุณ workflow จะถูกเรียกใช้งานอีกครั้งเพื่อตรวจสอบการเปลี่ยนแปลง
หากคุณผ่านการตรวจสอบ ก็พร้อมใช้งานได้เลย

### ตรวจสอบว่า URL มีการติดตาม

workflow นี้จะตรวจสอบว่า URL เว็บใด ๆ มีการติดตามอยู่ในนั้น
ที่เก็บนี้สามารถเข้าถึงได้สำหรับทุกคน ดังนั้นคุณต้องแน่ใจว่ามีการติดตามการเข้าถึงเพื่อรู้ว่าการเข้าชมนั้นมาจากที่ใด

เพื่อให้แน่ใจว่า URL ของคุณมีการติดตาม ให้ตรวจสอบข้อความต่อไปนี้ `?wt.mc_id=` ที่ส่วนท้ายของ URL
หากเพิ่มลงใน URL ของคุณแล้ว คุณจะผ่านการตรวจสอบนี้

หากไม่ใช่ คุณอาจได้รับข้อผิดพลาดดังต่อไปนี้

![GitHub check urls missing tracking comment screenshot](../../translated_images/th/github-check-urls-missing-tracking-comment.1bd00d20b24a1e2e.webp?WT.mc_id=academic-105485-koreyst "Screenshot from github comment that shows missing tracking from urls")

เพื่อแก้ไขปัญหานี้ ลองเปิดเส้นทางไฟล์ที่ workflow เน้นและเพิ่มรหัสติดตามไปที่ส่วนท้ายของ URL

เมื่อคุณเพิ่มรหัสติดตามแล้ว บันทึกและ push การเปลี่ยนแปลงของคุณ workflow จะถูกเรียกใช้งานอีกครั้งเพื่อตรวจสอบการเปลี่ยนแปลง
หากคุณผ่านการตรวจสอบ ก็พร้อมใช้งานได้เลย

### ตรวจสอบว่า URL ไม่มีโลเคลของประเทศ

workflow นี้จะตรวจสอบว่า URL เว็บใด ๆ ไม่มีโลเคลเฉพาะประเทศในนั้น
ที่เก็บนี้สามารถเข้าถึงได้สำหรับทุกคนทั่วโลก ดังนั้นคุณต้องแน่ใจว่าไม่มีการรวมโลเคลประเทศของคุณไว้ใน URL

เพื่อให้แน่ใจว่า URL ของคุณไม่มีโลเคลประเทศ ให้ตรวจสอบข้อความต่อไปนี้ `/en-us/` หรือ `/en/` หรือโลเคลภาษาอื่นใดใน URL ที่ใดก็ได้
หากไม่มีข้อความเหล่านี้ใน URL ของคุณ คุณจะผ่านการตรวจสอบนี้

หากไม่ใช่ คุณอาจได้รับข้อผิดพลาดดังต่อไปนี้

![GitHub check country locale comment screenshot](../../translated_images/th/github-check-country-locale-comment.2f4fe93228161dee.webp?WT.mc_id=academic-105485-koreyst "Screenshot from github comment that shows added country locale to urls")

เพื่อแก้ไขปัญหานี้ ลองเปิดเส้นทางไฟล์ที่ workflow เน้นและลบโลเคลประเทศออกจาก URL

เมื่อคุณลบโลเคลประเทศแล้ว บันทึกและ push การเปลี่ยนแปลงของคุณ workflow จะถูกเรียกใช้งานอีกครั้งเพื่อตรวจสอบการเปลี่ยนแปลง
หากคุณผ่านการตรวจสอบ ก็พร้อมใช้งานได้เลย
