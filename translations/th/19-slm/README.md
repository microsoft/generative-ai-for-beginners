# บทนำสู่โมเดลภาษาเล็กสำหรับปัญญาประดิษฐ์เชิงสร้างสรรค์สำหรับผู้เริ่มต้น
ปัญญาประดิษฐ์เชิงสร้างสรรค์เป็นสาขาที่น่าหลงใหลของปัญญาประดิษฐ์ซึ่งเน้นการสร้างระบบที่สามารถสร้างเนื้อหาใหม่ ๆ ได้ เนื้อหานี้อาจครอบคลุมตั้งแต่ข้อความและรูปภาพไปจนถึงดนตรีและแม้กระทั่งสภาพแวดล้อมเสมือนทั้งปวง หนึ่งในแอปพลิเคชันที่น่าตื่นเต้นที่สุดของปัญญาประดิษฐ์เชิงสร้างสรรค์คือในด้านของโมเดลภาษา

## โมเดลภาษาเล็กคืออะไร?

โมเดลภาษาเล็ก (SLM) เป็นตัวแปรที่ย่อขนาดลงของโมเดลภาษาใหญ่ (LLM) โดยใช้หลักการทางสถาปัตยกรรมและเทคนิคหลายอย่างของ LLM ในขณะที่มีการใช้ทรัพยากรการคำนวณที่น้อยลงอย่างมาก

SLM คือกลุ่มย่อยของโมเดลภาษาที่ออกแบบมาเพื่อสร้างข้อความที่คล้ายมนุษย์ แตกต่างจากโมเดลขนาดใหญ่ เช่น GPT-4 SLM มีขนาดกะทัดรัดและมีประสิทธิภาพมากกว่า เหมาะสำหรับแอปพลิเคชันที่มีทรัพยากรการคำนวณจำกัด แม้จะมีขนาดเล็ก แต่ก็สามารถทำงานได้หลากหลาย หนึ่งในวิธีการสร้าง SLM คือการบีบอัดหรือสกัดโมเดล LLM โดยมุ่งหวังที่จะรักษาฟังก์ชันการทำงานและความสามารถทางภาษาส่วนใหญ่ของโมเดลต้นฉบับ การลดขนาดโมเดลนี้ช่วยลดความซับซ้อนโดยรวม ทำให้ SLM มีประสิทธิภาพทั้งในแง่ของการใช้หน่วยความจำและความต้องการด้านคำนวณ แม้จะมีการปรับแต่งเหล่านี้ SLM ยังสามารถทำงานต่าง ๆ ในการประมวลผลภาษาธรรมชาติ (NLP) ได้ดังนี้:

- การสร้างข้อความ: สร้างประโยคหรือย่อหน้าที่สอดคล้องและเหมาะสมกับบริบท
- การเติมข้อความ: ทำนายและเติมประโยคตามคำกระตุ้นที่ให้มา
- การแปลภาษา: แปลงข้อความจากภาษาหนึ่งสู่อีกภาษา
- การสรุปเนื้อหา: ย่อข้อความยาวให้สั้นลงและเข้าใจง่ายขึ้น

แม้ว่าจะมีการแลกเปลี่ยนบางอย่างในเรื่องประสิทธิภาพหรือความลึกของความเข้าใจเมื่อเทียบกับโมเดลขนาดใหญ่

## โมเดลภาษาเล็กทำงานอย่างไร?
SLM ถูกฝึกด้วยข้อมูลข้อความจำนวนมาก ในระหว่างการฝึก ฝึกเรียนรู้รูปแบบและโครงสร้างของภาษา ทำให้สามารถสร้างข้อความที่ถูกต้องทางไวยากรณ์และเหมาะสมกับบริบท กระบวนการฝึกประกอบด้วย:

- การรวบรวมข้อมูล: รวบรวมชุดข้อมูลข้อความขนาดใหญ่จากแหล่งต่าง ๆ
- การเตรียมข้อมูล: ทำความสะอาดและจัดระเบียบข้อมูลให้อยู่ในรูปแบบที่เหมาะสมสำหรับการฝึก
- การฝึก: ใช้อัลกอริธึมการเรียนรู้ของเครื่องเพื่อสอนโมเดลให้เข้าใจและสร้างข้อความ
- การปรับแต่ง: ปรับโมเดลเพื่อเพิ่มประสิทธิภาพในงานเฉพาะต่าง ๆ

การพัฒนา SLM สอดคล้องกับความต้องการที่เพิ่มขึ้นสำหรับโมเดลที่สามารถนำไปใช้ในสภาพแวดล้อมที่มีทรัพยากรจำกัด เช่น อุปกรณ์มือถือหรือแพลตฟอร์มคอมพิวติ้งที่ปลายขอบ ซึ่ง LLM ขนาดเต็มอาจไม่เหมาะสมเนื่องจากต้องการทรัพยากรมาก การเน้นที่ประสิทธิภาพทำให้ SLM สามารถสมดุลประสิทธิภาพและการเข้าถึงได้ ส่งผลให้สามารถนำไปใช้ในหลากหลายโดเมนมากขึ้น

## ความแตกต่างระหว่างโมเดลภาษาใหญ่ (LLM) และโมเดลภาษาเล็ก (SLM)

ทั้ง LLM และ SLM สร้างขึ้นบนหลักการพื้นฐานของการเรียนรู้ของเครื่องแบบความน่าจะเป็น โดยใช้วิธีการที่คล้ายกันในสถาปัตยกรรมการออกแบบ กระบวนการฝึก การสร้างข้อมูล และเทคนิคการประเมินโมเดล อย่างไรก็ตาม มีปัจจัยสำคัญหลายประการที่ทำให้โมเดลสองประเภทนี้แตกต่างกัน

## การใช้งานของโมเดลภาษาเล็ก

SLM มีการใช้งานที่หลากหลาย รวมถึง:

- แชทบอท: ให้บริการลูกค้าและสื่อสารกับผู้ใช้ในรูปแบบการสนทนา
- การสร้างเนื้อหา: ช่วยนักเขียนโดยการสร้างไอเดียหรือร่างบทความทั้งหมด
- การศึกษา: ช่วยนักเรียนทำงานเขียนหรือติวภาษาใหม่
- ความช่วยเหลือ: สร้างเครื่องมือสำหรับบุคคลที่มีความสามารถจำกัด เช่น ระบบข้อความเป็นเสียง

**ขนาด**
  
ความแตกต่างหลักระหว่าง LLM และ SLM อยู่ที่ขนาดของโมเดล LLM เช่น ChatGPT (GPT-4) อาจมีพารามิเตอร์ประมาณ 1.76 ล้านล้าน ในขณะที่ SLM แบบโอเพนซอร์สอย่าง Mistral 7B ถูกออกแบบด้วยพารามิเตอร์ที่น้อยกว่าอย่างมาก ประมาณ 7 พันล้าน ความต่างนี้เป็นผลมาจากความแตกต่างในสถาปัตยกรรมและกระบวนการฝึก เช่น ChatGPT ใช้กลไก self-attention ภายในกรอบ encoder-decoder ในขณะที่ Mistral 7B ใช้ sliding window attention ซึ่งช่วยให้การฝึกเป็นไปอย่างมีประสิทธิภาพมากขึ้นในโมเดล decoder-only ความแตกต่างนี้ส่งผลอย่างลึกซึ้งต่อความซับซ้อนและประสิทธิภาพของโมเดลเหล่านี้

**ความเข้าใจ**

SLM มักถูกปรับแต่งเพื่อประสิทธิภาพในโดเมนเฉพาะ ทำให้มีความเชี่ยวชาญสูงแต่จำกัดในความสามารถเข้าใจบริบทกว้างในหลายสาขาความรู้ ในทางตรงกันข้าม LLM มีเป้าหมายที่จะเลียนแบบความฉลาดเหมือนมนุษย์ในระดับที่ครอบคลุมมากกว่า ฝึกด้วยชุดข้อมูลขนาดใหญ่และหลากหลาย LLM ถูกออกแบบมาเพื่อทำงานได้ดีในหลายโดเมน ให้ความยืดหยุ่นและการปรับตัวสูงกว่า ดังนั้น LLM เหมาะสำหรับงานลึกหลายประเภทเช่น การประมวลผลภาษาธรรมชาติและการเขียนโปรแกรม

**การคำนวณ**

การฝึกและปรับใช้ LLM เป็นกระบวนการที่ต้องใช้ทรัพยากรมาก ทั้งมักต้องใช้โครงสร้างพื้นฐานการคำนวณขนาดใหญ่ รวมถึงคลัสเตอร์ GPU กว้างขวาง เช่น การฝึกโมเดลอย่าง ChatGPT ตั้งแต่ต้นอาจต้องใช้ GPU หลายพันชุดในช่วงเวลานาน ในทางตรงกันข้าม SLM ด้วยพารามิเตอร์ที่น้อยกว่าจะเข้าถึงได้ง่ายกว่าในแง่ทรัพยากรการคำนวณ โมเดลอย่าง Mistral 7B สามารถฝึกและรันบนเครื่องท้องถิ่นที่มี GPU ประสิทธิภาพปานกลาง แม้ว่าการฝึกยังคงต้องใช้เวลาหลายชั่วโมงกับ GPU หลายชุด

**อคติ**

อคติเป็นปัญหาที่รู้จักใน LLM ส่วนใหญ่เกิดจากลักษณะของข้อมูลฝึกอบรม โมเดลเหล่านี้มักใช้ข้อมูลดิบที่เปิดเผยในอินเทอร์เน็ตซึ่งอาจเป็นตัวแทนข้อมูลในกลุ่มบางกลุ่มไม่ตรงหรือผิดเพี้ยน นอกจากนี้ยังอาจสะท้อนความลำเอียงทางภาษาเช่น ภาษาถิ่น ภูมิศาสตร์ และกฎไวยากรณ์ที่แตกต่าง ความซับซ้อนของสถาปัตยกรรม LLM อาจทำให้อคติเหล่านี้รุนแรงขึ้นโดยไม่รู้ตัวหากไม่มีการปรับแต่งอย่างละเอียด ในทางกลับกัน SLM ซึ่งฝึกด้วยชุดข้อมูลจำกัดที่เฉพาะเจาะจงต่อโดเมน มีแนวโน้มได้รับอคติน้อยกว่าแม้ว่าจะไม่ปลอดจากปัญหานี้

**การอนุมาน**

ขนาดที่เล็กลงของ SLM ช่วยให้มีข้อได้เปรียบสำคัญในด้านความเร็วของการอนุมาน ทำให้สามารถสร้างผลลัพธ์ได้อย่างมีประสิทธิภาพบนฮาร์ดแวร์ท้องถิ่นโดยไม่ต้องใช้กระบวนการขนานที่มากมาย ในทางตรงกันข้าม LLM เนื่องจากมีขนาดและความซับซ้อนมาก มักจะต้องใช้ทรัพยากรการคำนวณขนานอย่างมากเพื่อให้ได้เวลาตอบสนองที่ยอมรับได้ การมีผู้ใช้จำนวนมากพร้อมกันจะทำให้เวลาในการตอบสนองของ LLM ช้าลง โดยเฉพาะอย่างยิ่งเมื่อใช้งานในระดับใหญ่

สรุปคือ แม้ทั้ง LLM และ SLM จะมีฐานมาจากการเรียนรู้ของเครื่อง แต่ก็แตกต่างกันอย่างมากในด้านขนาดโมเดล ความต้องการทรัพยากร ความเข้าใจบริบท ความไวต่ออคติ และความเร็วในการอนุมาน ความแตกต่างเหล่านี้สะท้อนความเหมาะสมสำหรับกรณีใช้งานที่ต่างกัน โดย LLM มีความยืดหยุ่นมากกว่าแต่ต้องใช้ทรัพยากรมาก ขณะที่ SLM มุ่งเน้นประสิทธิภาพในโดเมนเฉพาะด้วยความต้องการคำนวณที่ลดลง

***หมายเหตุ: ในบทเรียนนี้ เราจะนำเสนอ SLM โดยใช้ Microsoft Phi-3 / 3.5 เป็นตัวอย่าง***

## แนะนำครอบครัว Phi-3 / Phi-3.5

ครอบครัว Phi-3 / 3.5 เน้นไปที่การประยุกต์ใช้ในข้อความ วิสัยทัศน์ และ Agent (MoE):

### Phi-3 / 3.5 Instruct

เน้นสำหรับการสร้างข้อความ การตอบแชท และการสกัดข้อมูลเนื้อหา เป็นต้น

**Phi-3-mini**

โมเดลภาษา 3.8B มีให้บน Microsoft Foundry, Hugging Face, และ Ollama โมเดล Phi-3 มีประสิทธิภาพสูงกว่ารุ่นที่มีขนาดเท่ากันและใหญ่กว่าในการทดสอบมาตรฐานหลัก (ดูตัวเลขการทดสอบด้านล่าง ตัวเลขที่สูงกว่าจะดีกว่า) Phi-3-mini ทำผลงานได้ดีกว่าโมเดลที่มีขนาดใหญ่กว่าสองเท่า ในขณะที่ Phi-3-small และ Phi-3-medium ดีกว่าโมเดลที่ใหญ่กว่าเช่น GPT-3.5

**Phi-3-small & medium**

ด้วยพารามิเตอร์แค่ 7B Phi-3-small ชนะ GPT-3.5T ในหลายการทดสอบทางภาษา ตรรกะ การเขียนโค้ด และคณิตศาสตร์

Phi-3-medium ที่มี 14B พารามิเตอร์ดำเนินแนวโน้มนี้ต่อเนื่องและทำผลงานดีกว่า Gemini 1.0 Pro

**Phi-3.5-mini**

เราสามารถมองว่าเป็นการอัปเกรดของ Phi-3-mini แม้ว่าพารามิเตอร์ยังคงไม่เปลี่ยนแปลง แต่เพิ่มความสามารถในการรองรับภาษาหลายภาษา (รองรับมากกว่า 20 ภาษา: อารบิก จีน เช็ก เดนมาร์ก ดัตช์ อังกฤษ ฟินแลนด์ ฝรั่งเศส เยอรมัน ฮีบรู ฮังการี อิตาลี ญี่ปุ่น เกาหลี นอร์เวย์ โปแลนด์ โปรตุเกส รัสเซีย สเปน สวีเดน ไทย ตุรกี ยูเครน) และเพิ่มการรองรับบริบทยาวๆ ที่แข็งแกร่งขึ้น

Phi-3.5-mini ด้วยพารามิเตอร์ 3.8B ทำผลงานได้ดีกว่าโมเดลขนาดเท่ากันและเทียบเท่ากับโมเดลที่มีขนาดสองเท่า

### Phi-3 / 3.5 Vision

เราสามารถมองโมเดล Instruct ของ Phi-3/3.5 เป็นความสามารถของ Phi ในการเข้าใจ ส่วน Vision คือสิ่งที่ทำให้ Phi มีตาเพื่อเข้าใจโลก


**Phi-3-Vision**

Phi-3-vision ที่มีพารามิเตอร์แค่ 4.2B ยังคงแนวโน้มนี้และทำได้ดีกว่าโมเดลใหญ่กว่าเช่น Claude-3 Haiku และ Gemini 1.0 Pro V ในงานตรรกะเชิงภาพทั่วไป OCR และความเข้าใจตารางและแผนภูมิ


**Phi-3.5-Vision**

Phi-3.5-Vision ก็เป็นการอัปเกรดของ Phi-3-Vision เพิ่มการรองรับภาพหลายภาพ คุณอาจมองว่าเป็นการพัฒนาด้านวิสัยทัศน์ ไม่เพียงแต่ดูภาพนิ่งได้ แต่ยังรวมถึงวิดีโอด้วย

Phi-3.5-vision ทำได้ดีกว่าโมเดลใหญ่กว่าเช่น Claude-3.5 Sonnet และ Gemini 1.5 Flash ในงาน OCR, การเข้าใจตารางและแผนภูมิ และเทียบเท่าในงานตรรกะเชิงภาพทั่วไป รองรับการป้อนข้อมูลหลายเฟรม คือสามารถทำตรรกะกับภาพป้อนเข้าหลายภาพพร้อมกัน


### Phi-3.5-MoE

***Mixture of Experts (MoE)*** ช่วยให้โมเดลฝึกล่วงหน้าด้วยการคำนวณที่น้อยลงอย่างมาก ซึ่งหมายความว่าคุณสามารถเพิ่มขนาดโมเดลหรือชุดข้อมูลอย่างมากด้วยงบประมาณคำนวณเท่าเดิมเมื่อเทียบกับโมเดลแบบหนาแน่น โดยเฉพาะโมเดล MoE ควรจะเข้าถึงคุณภาพเดียวกับโมเดลหนาแน่นในระยะเวลาการฝึกล่วงหน้าที่เร็วกว่า

Phi-3.5-MoE ประกอบด้วยโมดูลผู้เชี่ยวชาญ 16 ตัวขนาด 3.8B ตัว Phi-3.5-MoE ที่มีพารามิเตอร์ที่ใช้งานแค่ 6.6B ได้ระดับตรรกะ ความเข้าใจภาษา และคณิตศาสตร์ที่ใกล้เคียงกับโมเดลที่ใหญ่กว่ามาก

เราสามารถใช้โมเดลครอบครัว Phi-3/3.5 ในสถานการณ์ต่าง ๆ แตกต่างจาก LLM ที่คุณสามารถติดตั้ง Phi-3/3.5-mini หรือ Phi-3/3.5-Vision บนอุปกรณ์ขอบเครือข่ายได้

นอกจากแคตตาล็อก Microsoft Foundry Models บนคลาวด์แล้ว คุณยังสามารถใช้ [NVIDIA NIM](https://developer.nvidia.com/nim?WT.mc_id=academic-105485-koreyst) เพื่อทำการเรียกใช้ที่เกี่ยวข้องได้ คุณสามารถเยี่ยมชม NVIDIA NIM เพื่อทำการเรียก API ของครอบครัว Phi-3/3.5 NVIDIA NIM (NVIDIA Inference Microservices) คือชุดไมโครเซอร์วิสสำหรับการอนุมานแบบเร่งความเร็ว ที่ออกแบบมาเพื่อช่วยนักพัฒนาปรับใช้โมเดล AI อย่างมีประสิทธิภาพในหลากหลายสภาพแวดล้อม รวมถึงคลาวด์ ศูนย์ข้อมูล และเวิร์กสเตชัน

ต่อไปนี้เป็นคุณสมบัติหลักของ NVIDIA NIM:

- **ง่ายต่อการติดตั้ง:** NIM อนุญาตให้ติดตั้งโมเดล AI ด้วยคำสั่งเดียว ทำให้ง่ายต่อการผนวกเข้ากับเวิร์กโฟลว์เดิม
- **ประสิทธิภาพที่ปรับแต่งแล้ว:** ใช้เครื่องมืออนุมานที่ปรับแต่งล่วงหน้าของ NVIDIA เช่น TensorRT และ TensorRT-LLM เพื่อให้ได้ค่าความหน่วงต่ำและปริมาณงานสูง
- **รองรับการขยายตัว:** NIM รองรับการปรับขนาดอัตโนมัติบน Kubernetes เพื่อจัดการภาระงานที่หลากหลายได้อย่างมีประสิทธิภาพ
- **ความปลอดภัยและการควบคุม:** องค์กรสามารถควบคุมข้อมูลและแอปพลิเคชันของตนได้โดยโฮสต์ไมโครเซอร์วิส NIM บนโครงสร้างพื้นฐานที่จัดการเอง
- **Standard APIs:** NIM จัดเตรียม API มาตรฐานอุตสาหกรรม ทำให้ง่ายต่อการสร้างและรวมแอปพลิเคชัน AI เช่น แชทบอท ผู้ช่วย AI และอื่นๆ

NIM เป็นส่วนหนึ่งของ NVIDIA AI Enterprise ซึ่งมีเป้าหมายเพื่อทำให้ง่ายขึ้นในการปรับใช้และการปฏิบัติงานของโมเดล AI โดยมั่นใจว่าโมเดลเหล่านั้นทำงานได้อย่างมีประสิทธิภาพบน NVIDIA GPUs

**Hugging Face Transformer**
Hugging Face Transformers เป็นไลบรารีที่ทรงพลังสำหรับการประมวลผลภาษาธรรมชาติ (NLP) และงานแมชชีนเลิร์นนิงอื่นๆ ต่อไปนี้คือประเด็นสำคัญเกี่ยวกับไลบรารีนี้:

1. **โมเดลที่ผ่านการฝึกมาแล้ว:** มีโมเดลที่ฝึกมาแล้วนับพันๆ โมเดล ซึ่งสามารถใช้กับงานหลากหลาย เช่น การจัดหมวดหมู่ข้อความ การรู้จำชื่อเฉพาะ การตอบคำถาม การสรุปข้อความ การแปลภาษา และการสร้างข้อความ

2. **ความเข้ากันได้กับเฟรมเวิร์กหลายตัว:** ไลบรารีรองรับหลายเฟรมเวิร์กสำหรับการเรียนรู้เชิงลึก ได้แก่ PyTorch, TensorFlow และ JAX ทำให้คุณสามารถฝึกโมเดลในเฟรมเวิร์กหนึ่งแล้วใช้ในอีกเฟรมเวิร์กหนึ่งได้

3. **ความสามารถแบบมัลติโมดัล:** นอกจาก NLP แล้ว Hugging Face Transformers ยังรองรับงานด้านวิสัยทัศน์คอมพิวเตอร์ (เช่น การจัดหมวดหมู่ภาพ การตรวจจับวัตถุ) และการประมวลผลเสียง (เช่น การรู้จำเสียง การจัดหมวดหมู่เสียง)

4. **ใช้งานง่าย:** ไลบรารีมี API และเครื่องมือสำหรับดาวน์โหลดและปรับแต่งโมเดลอย่างง่าย ทำให้เข้าถึงได้ทั้งผู้เริ่มต้นและผู้เชี่ยวชาญ

5. **ชุมชนและทรัพยากร:** Hugging Face มีชุมชนที่คึกคักและเอกสาร คู่มือ และบทเรียนมากมายเพื่อช่วยให้ผู้ใช้เริ่มต้นและใช้ไลบรารีได้อย่างเต็มที่
[เอกสารอย่างเป็นทางการ](https://huggingface.co/docs/transformers/index?WT.mc_id=academic-105485-koreyst) หรือ [ที่เก็บ GitHub](https://github.com/huggingface/transformers?WT.mc_id=academic-105485-koreyst) ของพวกเขา

นี่คือวิธีที่ใช้กันมากที่สุด แต่ก็ต้องการการเร่งด้วย GPU เช่นกัน สถานการณ์อย่าง Vision และ MoE ต้องการการคำนวณมากซึ่งจะช้ามากบน CPU ถ้าไม่ได้มีการควิ้นไทซ์

**ONNX Runtime for GenAI**

[ONNX Runtime](https://github.com/microsoft/onnxruntime-genai?WT.mc_id=academic-105485-koreyst) คือเครื่องเร่งการฝึกและ inference แบบข้ามแพลตฟอร์มสำหรับแมชชีนเลิร์นนิง ONNX Runtime for Generative AI (GENAI) เป็นเครื่องมือทรงพลังที่ช่วยให้คุณรันโมเดล generative AI ได้อย่างมีประสิทธิภาพบนแพลตฟอร์มต่างๆ

## ONNX Runtime คืออะไร?
ONNX Runtime เป็นโปรเจกต์โอเพ่นซอร์สที่ช่วยให้การ inference โมเดลแมชชีนเลิร์นนิงทำได้อย่างมีประสิทธิภาพสูง มันรองรับโมเดลในฟอร์แมต Open Neural Network Exchange (ONNX) ซึ่งเป็นมาตรฐานสำหรับการแสดงโมเดลแมชชีนเลิร์นนิง ONNX Runtime ช่วยเพิ่มความเร็วของประสบการณ์ลูกค้าและลดต้นทุน รองรับโมเดลจากเฟรมเวิร์กการเรียนรู้ลึกอย่าง PyTorch และ TensorFlow/Keras รวมถึงไลบรารีแมชชีนเลิร์นนิงทั่วไปอย่าง scikit-learn, LightGBM, XGBoost เป็นต้น ONNX Runtime เข้ากันได้กับฮาร์ดแวร์ ไดรเวอร์ และระบบปฏิบัติการต่างๆ และให้ประสิทธิภาพที่ดีที่สุดด้วยการใช้เครื่องเร่งฮาร์ดแวร์พร้อมกับการปรับแต่งกราฟและการแปลง

## Generative AI คืออะไร?
Generative AI หมายถึงระบบ AI ที่สามารถสร้างเนื้อหาใหม่ๆ เช่น ข้อความ ภาพ หรือดนตรี ตามข้อมูลที่ได้รับการฝึกมา ตัวอย่างเช่น โมเดลภาษาอย่าง GPT-3 และโมเดลสร้างภาพอย่าง Stable Diffusion ไลบรารี ONNX Runtime สำหรับ GenAI ให้วงจร generative AI สำหรับโมเดล ONNX รวมถึงการทำ inference ด้วย ONNX Runtime การประมวลผล logits การค้นหาและการสุ่มตัวอย่าง และการจัดการแคช KV

## ONNX Runtime สำหรับ GENAI
ONNX Runtime สำหรับ GENAI ขยายขีดความสามารถของ ONNX Runtime เพื่อรองรับโมเดล generative AI ด้วยคุณสมบัติสำคัญดังนี้:

- **รองรับแพลตฟอร์มหลากหลาย:** ทำงานบนแพลตฟอร์มต่างๆ รวมถึง Windows, Linux, macOS, Android และ iOS
- **รองรับโมเดล:** รองรับโมเดล generative AI ยอดนิยมหลายรุ่น เช่น LLaMA, GPT-Neo, BLOOM และอื่นๆ
- **การเพิ่มประสิทธิภาพการทำงาน:** รวมการปรับแต่งสำหรับฮาร์ดแวร์เครื่องเร่งต่างๆ เช่น NVIDIA GPUs, AMD GPUs และอื่นๆ
- **ใช้งานง่าย:** ให้ API เพื่อการผนวกรวมเข้ากับแอปพลิเคชันได้ง่าย ช่วยให้สร้างข้อความ ภาพ และเนื้อหาอื่นๆ ด้วยโค้ดเพียงเล็กน้อย
- ผู้ใช้สามารถเรียกใช้เมธอดระดับสูง generate() หรือรันซ้ำแต่ละรอบของโมเดลเป็นลูป โดยสร้าง token ทีละตัว และปรับพารามิเตอร์การสร้างภายในลูปได้ตามต้องการ
- ONNX runtime ยังรองรับการค้นหาแบบ greedy/beam และการสุ่มแบบ TopP, TopK เพื่อสร้างลำดับ token พร้อมการประมวลผล logits ในตัวเช่น การลงโทษซ้ำซ้อน คุณยังสามารถเพิ่มการให้คะแนนแบบกำหนดเองได้ง่ายๆ

## การเริ่มต้นใช้งาน
เพื่อเริ่มต้นใช้งาน ONNX Runtime สำหรับ GENAI คุณสามารถทำตามขั้นตอนเหล่านี้:

### ติดตั้ง ONNX Runtime:
```Python
pip install onnxruntime
```
### ติดตั้ง Generative AI Extensions:
```Python
pip install onnxruntime-genai
```

### รันโมเดล: ตัวอย่างง่ายๆ ใน Python:
```Python
import onnxruntime_genai as og

model = og.Model('path_to_your_model.onnx')

tokenizer = og.Tokenizer(model)

input_text = "Hello, how are you?"

input_tokens = tokenizer.encode(input_text)

output_tokens = model.generate(input_tokens)

output_text = tokenizer.decode(output_tokens)

print(output_text) 
```
### ตัวอย่างสาธิต: ใช้ ONNX Runtime GenAI เพื่อเรียก Phi-3.5-Vision


```python

import onnxruntime_genai as og

model_path = './Your Phi-3.5-vision-instruct ONNX Path'

img_path = './Your Image Path'

model = og.Model(model_path)

processor = model.create_multimodal_processor()

tokenizer_stream = processor.create_stream()

text = "Your Prompt"

prompt = "<|user|>\n"

prompt += "<|image_1|>\n"

prompt += f"{text}<|end|>\n"

prompt += "<|assistant|>\n"

image = og.Images.open(img_path)

inputs = processor(prompt, images=image)

params = og.GeneratorParams(model)

params.set_inputs(inputs)

params.set_search_options(max_length=3072)

generator = og.Generator(model, params)

while not generator.is_done():

    generator.compute_logits()
    
    generator.generate_next_token()

    new_token = generator.get_next_tokens()[0]
    
    output = tokenizer_stream.decode(new_token)
    
    print(tokenizer_stream.decode(new_token), end='', flush=True)

```
