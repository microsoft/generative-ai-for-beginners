# தொடக்கவுரை புதியவர்களுக்கு உருவாக்கும் AI க்கான சிறிய மொழி மாதிரிகள்
உருவாக்கும் AI என்பது புதிய உள்ளடக்கங்களை உருவாக்க இயல்பான அமைப்புகளை உருவாக்கும் செயற்கை நுண்ணறிவின் ஒரு அதிசயத் துறை ஆகும். இந்த உள்ளடக்கம் உரை, படங்கள், இசை மற்றும் முழு மெய்நிகர் சூழல்களை உள்ளடக்க பலவகை இருக்கலாம். உருவாக்கும் AI இன் மிகவும் சுவாரஸ்யமான பயன்பாடுகளில் ஒன்று மொழி மாதிரிகள் என்பதாகும்.

## சிறிய மொழி மாதிரிகள் என்றால் என்ன?

சிறிய மொழி மாதிரி (SLM) என்பது பெரிய மொழி மாதிரியின் (LLM) குறைக்கப்பட்ட வடிவமாகும், LLM களின் கட்டமைப்பு 원ல்வையும் தொழில்நுட்பங்களையும் பயன்படுத்தி, மிகவும் குறைந்த கணினி செயல்திறன் இருப்பதை கொண்டுள்ளது.

SLM கள் மனிதன் போன்ற உரையை உருவாக்க வடிவமைக்கப்பட்டுள்ள மொழி மாதிரிகளின் ஒரு துணைக்குழுவாகும். GPT-4 போன்ற பெரிய மாதிரிகளுடன் ஒப்பிடும்போது, SLM கள் சிறியது மற்றும் அதிக திறமையானவை, கணினி வளங்கள் குறைந்தபோது பயன்பாட்டுக்கு மிகவும் பொருத்தமானது. குறைந்த அளவு இருப்பினும் பல பணிகளை செய்யக்கூடியவை. பொதுவாக, SLM கள் LLM களை பற்றாக்குறை செய்தல் அல்லது சுருக்குதல் மூலம் உருவாக்கப்படுகின்றன, இதன் மூலம் ஆரம்ப மாதிரியின் பல இயல்புகளை மற்றும் மொழி திறன்களை சேமிக்க முடியும். மாதிரி அளவு குறைவு சிக்கலான தன்மையை குறைத்து நினைவக மற்றும் கணினி தேவைகளில் திறமையை அதிகரிக்கிறது. இந்த மேம்பாடுகளால் கூட, SLM கள் பல இயற்கை மொழி செயலாக்க (NLP) பணிகளுக்கு திறன் பெற்றுள்ளன:

- உரை உருவாக்கல்: தொடர்புடைய மற்றும் இணக்கமான வாக்கியங்கள் அல்லது பத்திகளை உருவாக்குதல்.
- உரை நிறைவு: கொடுக்கப்பட்ட முன்மொழிவின் அடிப்படையில் வாக்கியங்களை கணித்து நிறைவு செய்தல்.
- மொழிபெயர்ப்பு: ஒரு மொழியிலிருந்து மற்றொரு மொழிக்கு உரை மாற்றுதல்.
- சுருக்கம்: நீண்ட உரைகளை சுருக்கமான, எளிதில் புரிந்து கொள்ளக்கூடிய சுருக்கங்களாக மாற்றுதல்.

பெரிய மாதிரிகளுடன் ஒப்பிடும்போது செயல்திறன் அல்லது ஆழமான புரிதலில் சில தார்மீகங்கள் உள்ளன.

## சிறிய மொழி மாதிரிகள் எப்படி செயல்படுகின்றன?
SLM கள் பெரிய அளவிலான உரை தரவுகள்மீது பயிற்சி பெறுகின்றன. பயிற்சி கிடைக்கும் போதும், மொழியின் அமைப்பு மற்றும் வடிவமைப்புகளை கற்றுக்கொண்டும், வரையறுக்கப்பட்ட மொழி மற்றும் சூழலுக்கு பொருத்தமான உரையை உருவாக்க உதவுகின்றன. பயிற்சி செயல்முறை:

- தரவு சேகரிப்பு: பல்வேறு மூலங்களிலிருந்து பெரிய உரை தரவுகளை சேகரித்தல்.
- முன் செயலாக்கம்: தரவை தூய்மையாக்கி, பயிற்சிக்கு ஏற்றவாறு ஒழுங்குபடுத்தல்.
- பயிற்சி: இயந்திரக் கற்றல் அல்காரிதங்கள் கொண்டு மாதிரிக்கு உரையை புரிந்து கொண்டு உருவாக்க கற்றல்.
- நுட்பமாய் சரிசெய்தல்: குறிப்பிட்ட பணிகளின் செயல்திறனை மேம்படுத்த மாதிரியை சரிசெய்தல்.

SLM களின் வளர்ச்சி கட்டமைப்பில் அதிக வளங்கள் தேவையான பெரும் LLM களை ஒப்பிடும்போது, குறைந்த வளங்கள் உள்ள சூழல்களில், உதாரணமாக கைப்பேசி சாதனங்கள் அல்லது எdge கணினி தளங்களில் பயன்படுத்த சிறந்ததாகும். திறமையை முன்னிட்டு, SLM கள் செயல்திறன் மற்றும் அணுகலை சமனோசிதமாக்குகின்றன, ஆகவே பல துறைபட்ட பயன்பாடுகள் விரிவடைகின்றன.

## பெரிய மொழி மாதிரிகள் (LLMs) மற்றும் சிறிய மொழி மாதிரிகள் (SLMs) இடையேயான வித்தியாசங்கள்

LLM களும் SLM களும் வாயிலாக வாயிலான இயந்திர கற்றல் அடிப்படையில் கட்டமைக்கப்பட்டுள்ளன, கட்டமைப்பு வடிவமைப்பு, பயிற்சி முறைகள், தரவு உருவாக்க செயல்முறைகள் மற்றும் மாதிரி மதிப்பீட்டு தொழில்நுட்பங்களில் சமமான அணுகுமுறைகளை பின்பற்றுகின்றன. இருப்பினும், சில முக்கிய காரணிகள் இந்த இரண்டு வகை மாதிரிகளுக்கு வேறுபாடு தருகின்றன.

## சிறிய மொழி மாதிரிகளின் பயன்பாடுகள்

SLM கள் பலவகை பயன்பாடுகளை கொண்டுள்ளன, அதாவது:

- சாட்போட்ஸ்: வாடிக்கையாளர் உதவியை வழங்கி பயனர்களுடன் உரையாடல் நடத்துதல்.
- உள்ளடக்கம் உருவாக்கல்: எழுத்தாளர்களுக்கு எண்ணங்களை உருவாக்க உதவுதல் அல்லது முழு கட்டுரைகள் வரை வரைபொருள்களை எழுதுதல்.
- கல்வி: மாணவர்களுக்கு எழுத்துப்பணிகளில் அல்லது புதிய மொழிகள் கற்றலிலும் உதவுதல்.
- அணுகல் வசதிகள்: மாற்றுத்திறனாளிகளுக்கான உரை-தொலைச்சார்பு போன்ற கருவிகளை உருவாக்குதல்.

**அளவு**
  
LLM களுக்கும் SLM களுக்கும் இடையேயான முதன்மை வித்தியாசம் மாதிரிகளின் அளவிலும் உள்ளது. ChatGPT (GPT-4) போன்ற LLM கள் சுமார் 1.76 டிரில்லியன் அளவீடுகளைக் கொண்டிருக்கலாம், ஆனால் திறந்த மூல SLM கான மாதிரிகள், உதாரணமாக Mistral 7B, சுமார் 7 பில்லியன் அளவீடுகளைக் கொண்டுள்ளன. இந்த வேறுபாடு மாதிரி கட்டமைப்பு மற்றும் பயிற்சி முறைகளின் வேறுபாடுகளால் ஏற்படுகிறது. உதாரணமாக, ChatGPT ஒரு encoder-decoder கட்டமைப்பில் சொந்த கவனக் கூறுகையை பயன்படுத்துகிறது, அதே சமயம் Mistral 7B ஒரு sliding window attention ஐ பயன்படுத்தி, decoder மட்டுமே கொண்ட மாதிரியில் மிக திறமையான பயிற்சியை வழங்குகிறது. இந்த கட்டமைப்பு வேறுபாடு இந்த மாதிரிகளின் சிக்கல் மற்றும் செயல்பாட்டில் முக்கிய தாக்கத்துடன் உள்ளது.

**புரிதல்**

SLM கள் பெரும்பாலும் குறிப்பிட்ட துறைகளுக்குள் சிறந்து செயல்படும் வகையில் சீரமைக்கப்பட்டுள்ளன, ஆகவே அவை பரவலான சூழல்களின் மேல் பரந்து விரிவான தரவுகளை நம்ப முடியாமல் இருக்கலாம். மாற்றாக, LLM கள் மனிதன் போன்ற அறிவை மறுபரியமைக்கும் நோக்கில் பயிற்சி பெறுகின்றன மற்றும் பரவலான தரவுத்தொகுப்புகளில் பயிற்சி பெற்று பல துறைகளில் சிறந்த அளவில் செயல்படுகின்றன, அதன்மூலம் பரபரப்பும் மற்றும் பொருத்தத்தன்மையும் அதிகரிக்கின்றன. எனவே, LLM கள் இயற்கை மொழி செயலாக்கம் மற்றும் நிரலாக்கம் போன்ற பல பணிகளுக்கு பொருத்தமானவை.

**கணினி திறன்**

LLM களின் பயிற்சி மற்றும் இயக்கம் பெரும் கணினி வளங்களை நாடுகின்றன, பெரும்பாலும் பெரிய GPU குழுக்களை எதிர்கொள்வது அவசியமாகும். உதாரணமாக, ChatGPT மாதிரியை ஆரம்பத்திலிருந்தே பயிற்சி கொள்ள, ஆயிரக்கணக்கான GPU கள் நீண்டநேரம் தேவைப்படுகிறது. அதற்குப் புறம்பாக, SLM கள் குறைந்த அளவு அளவீடுகளைக் கொண்டதால், கணினி வளங்களுக்குள் அதிக அணுகல் கிடைக்கிறது. Mistral 7B மாதிரி போன்றவை நடுத்தர திறன் கொண்ட GPU களை கொண்ட உள்ளூர் கணினிகளில் பயிற்சி பெற்று இயக்கலாம், எனினும் பயிற்சி பெரும்பாலும் பல மணி நேரம் மற்றும் பல GPU களை சார்ந்தது.

**பாகுபாடு (Bias)**

பாகுபாடு என்பது LLM களில் பொதுவான பிரச்சனை, இது பயிற்சி தரவின் தன்மைக்கு காரணமாக உள்ளது. இவை பொதுவாக இணையத்தில் இருக்கும் மூலதரவை பயன்படுத்துவதால் சில குழுக்களை குறைவாக பிரதிநிதித்துவம் செய்யலாம் அல்லது தவறான அடையாளத்தை கொடுக்கலாம், மேலும் மொழியியல் பாகுபாடுகளும் (மொழி கோளாறுகள், புவியியல் வேறுபாடுகள், இலக்கண விதிகள்) இதில் தாக்கமளிக்கலாம். கூடுதலாக, LLM கட்டமைப்பின் சிக்கல் பாகுபாட்டை பெருக்க வாய்ப்புள்ளது, இது நுட்பமாக சரிசெய்தல் இல்லாமல் காணாமல் போகலாம். அதே சமயத்தில், SLM கள் குறிப்பிட்ட துறைகளை கொண்டு சுருங்கிய தரவுகள்களில் பயிற்சி பெறுவதால் பாகுபாட்டுக்கு குறைந்த அளவில் பாதிக்கப்படுகின்றன, எனினும் பாகுபாட்டை முற்றிலும் விலக்க முடியாது.

**ஊகித்தல் (Inference)**

SLM களின் குறைக்கப்பட்ட அளவு அவற்றுக்கு ஊகித்தலின் வேகத்தில் முக்கிய முன்னிலை தருகிறது, ஆகவே அவை உள்ளூர் ஹார்ட்வேரில் விரைவாக வெளியீடுகளை உருவாக்க உதவுகின்றன, பரபல செயலாக்க தேவையற்றது. ஒப்பிடுகையில், LLM கள் குறைந்த ஊகித்தல் நேரம் பெற பெரும் பரபல கணினி வளங்களை நாடுகின்றன. பல பயனர்கள் ஒரே நேரத்தில் பயன்படுத்தும்போதும் LLM களின் பதில் நேரம் தாமதமடைகிறது, குறிப்பாக பெரிய அளவிலுள்ள போது.

சுருக்கமாக கூறினால், LLM களும் SLM களும் இயந்திரத் கற்றலில் அடிப்படையாக ஒன்று, ஆனால் மாதிரி அளவு, வள தேவைகள், சூழலியல் புரிதல், பாகுபாடு பற்றிய ஆற்றல் மற்றும் ஊகித்தல் வேகம் போன்ற காரியங்களில் பெரும் வேறுபாடுகள் உள்ளன. இவை அவற்றின் பிரயோக இடங்களில் தொடர்புடையவை, LLM கள் பரபரப்பானதாலும் வளம் பெரும்பாலும் தேவைபடும், மற்றும் SLM கள் குறிப்பிட்ட துறைகளுக்குள் திறமையானவை மற்றும் குறைந்த கணினி தேவைபடுகின்றன.

***குறிப்பு: இந்த பாடத்தில், நாம் Microsoft Phi-3 / 3.5 மாதிரியை எடுத்துக்காட்டாக SLM ஐ அறிமுகப்படுத்துவோம்.***

## Phi-3 / Phi-3.5 குடும்பத்தை அறிமுகப்படுத்தல்

Phi-3 / 3.5 குடும்பம் பெரும்பாலும் உரை, காட்சி மற்றும் முகவர் (MoE) பயன்பாட்டு சூழல்களை இலக்கு வைக்கின்றது:

### Phi-3 / 3.5 Instruct

முன்னேற்றப்பட்ட உரை உருவாக்கல், உரை நிறைவு, மற்றும் உள்ளடக்க தகவல் பிறிது பெறுதல் போன்ற பணிகளுக்கு.

**Phi-3-mini**

3.8B அளவுடைய மொழி மாதிரி Microsoft Foundry, Hugging Face மற்றும் Ollama இல் கிடைக்கக்கூடியது. Phi-3 மாதிரிகள், சமநிலை மற்றும் பெரிய அளவுள்ள மொழி மாதிரிகள் மீது முக்கியமான தரவுத்தாள்களில் (பின்வரும் தரவுத்தாள்கள் பொருளாதாரமாக உயரமான எண்ணிக்கைகள் கூடியவை) பெரும் முன்னேற்றம் காண்பிக்கின்றன. Phi-3-mini தனது அளவுக்கு இருட்டியான மாதிரிகளை மிஞ்சுகிறது, மற்றும் Phi-3-small மற்றும் Phi-3-medium GPT-3.5 உட்பட பெரிய மாதிரிகளையும் மிஞ்சுகின்றன.

**Phi-3-small & medium**

7B அளவில் Phi-3-small பல்வேறு மொழி, காரணம், நிரல் மற்றும் கணிதப் பரிசோதனைகளில் GPT-3.5T ஐ மேல் எடுக்கும்.

14B அளவு கொண்ட Phi-3-medium இந்த போக்கை தொடர்கிறது மற்றும் Gemini 1.0 Pro ஐ மிஞ்சுகிறது.

**Phi-3.5-mini**

இதனை Phi-3-mini இன் மேம்படுத்தப்பட்ட வடிவமாகக் கருதலாம். அளவீடுகள் ஒரே மாதிரி இருப்பினும், அது பல மொழிகளை ஆதரிக்க மேம்படுத்தப்பட்டுள்ளது (20+ மொழிகளை ஆதரிக்கிறது: அரபி, சீனி, செக், டேனிஷ், டச்சு, ஆங்கிலம், ஃபின்னிஷ், பிரெஞ்சு, ஜெர்மன், ஹீப்ரூ, ஹங்கேரியன், இத்தாலியன், ஜப்பானிய, கொரியன், நோர்வேஜியன், போலிஷ், போர்ச்சுகீஸ், ரஷியன், ஸ்பானிஷ், ஸ்வீடிஷ், தாய், துருக்கியன், உக்கிரைனியன்) மற்றும் நீண்ட சூழலை ஆதரிக்கும் திறனும் அதிகரித்துள்ளது.

3.8B அளவில் Phi-3.5-mini அதே அளவுள்ள மொழி மாதிரிகளைத் தாண்டி, இரட்டைப் பெரிய மாதிரிகளுக்கு சமமான திறன் காண்பிக்கிறது.

**Phi-3-Vision**

4.2B அளவுடைய Phi-3-vision இந்த போக்கை தொடர்கிறது மற்றும் Claude-3 Haiku மற்றும் Gemini 1.0 Pro V போன்ற பெரிய மாதிரிகளை பொதுவான காட்சி காரணிக்கான பணிகளில், OCR மற்றும் அட்டவணை மற்றும் வரைபட அறிதல் பணிகளில் தாண்டுகிறது.

### Phi-3.5-MoE

***Mixture of Experts (MoE)*** மாதிரிகள் மிகக் குறைவான கணினி வளங்களுடன் முன்பயிற்சி பெறும் திறனைக் கொண்டவை, இதனால் நீங்கள் ஒரு தடம் மாதிரி அல்லது தரவுத்தொகுப்பை இதே கணினி பணிக்கிடத்தில் பெரிதாக பெருக்க முடியும். குறிப்பாக, MoE மாதிரி அதன் திதுவான மாதிரிக்குக் கூடுதலாக விரைவாக இனிப்படுகிறது.

Phi-3.5-MoE 16x3.8B நிபுணர் தொகுதிகளைக் கொண்டுள்ளது. Phi-3.5-MoE 6.6B செயல்படும் அளவீடுகளுடன் கூட, பெரிய மாதிரிகளுக்கு இதே நிலைமான காரணித்தல், மொழிபிஷயம் மற்றும் கணித திறனைக் கொண்டுள்ளது.

வெவ்வேறு சூழல்களுக்கு அடிப்படையான Phi-3/3.5 குடும்ப மாதிரியைப் பயன்படுத்த முடியும். LLM கள் போல இல்லாமல், Phi-3/3.5-mini அல்லது Phi-3/3.5-Vision ஐ எdge சாதனங்களில் இயக்க முடியும்.

**ONNX Runtime for GenAI**

[ONNX Runtime](https://github.com/microsoft/onnxruntime-genai?WT.mc_id=academic-105485-koreyst) என்பது பல தளங்களில் இயங்கும் இறுக்கல் மற்றும் பயிற்சி மெஷின் லெர்னிங் வேகம் அதிகரிக்கும் கருவி. ONNX Runtime for Generative AI (GENAI) பல தளங்களில் சிருஷ்டிக்க AI மாதிரிகளை திறம்பட இயங்க உதவும் சக்திவாய்ந்த கருவி.

## ONNX Runtime என்பது என்ன?
ONNX Runtime என்பது மெஷின் லெர்னிங் மாதிரிகளின் உயர் செயல்திறன் இறுக்கலை இயற்றும் திறந்த மூல திட்டமாகும். இது Open Neural Network Exchange (ONNX) வடிவத்தில் உள்ள மாதிரிகளை ஆதரிக்கிறது, இது மெஷின் லெர்னிங் மாதிரிகளுக்கான ஒரு தரமாகும். ONNX Runtime inference வாடிக்கையாளர் அனுபவங்களை விரைவுபடுத்தவும் செலவுகளை குறைக்கவும் உதவும், PyTorch, TensorFlow/Keras போன்ற ஆழ்ந்த கற்றல் கட்டமைப்புகளிலும் scikit-learn, LightGBM, XGBoost போன்ற பாரம்பரிய மெஷின் லெர்னிங் நூலகங்களிலும் உள்ள மாதிரிகளை ஆதரிக்கிறது. ONNX Runtime பலவித ஹார்டுவேர், டிரைவர்கள் மற்றும் இயக்கமுறைமைகளுடன் இணக்கமாக செயல்படுகிறது, மேலும் உயர் செயல்திறனை வழங்க ஹார்டுவேரின் வேக்விருத்திகளை பயன்படுத்துகிறது மத்தியிலும் காட்சி மேம்பாடுகள் மற்றும் மாற்றங்களையும் பயன்படுத்துகிறது.

## Generative AI என்பது என்ன?
Generative AI என்பது பயிற்றளிக்கப்பட்ட தரவுகளின் அடிப்படையில் புதிய உள்ளடக்கங்களை உருவாக்கும் AI அமைப்புகளை குறிக்கும், உதாரணத்திற்கு உரை, படங்கள் அல்லது இசை போன்றவை. உதாரணமாக GPT-3 போன்ற மொழி மாதிரிகள் மற்றும் Stable Diffusion போன்ற படம் உருவாக்கும் மாதிரிகள் உள்ளன. ONNX Runtime for GenAI நூலகம் ONNX மாதிரிகளுக்கான generative AI சுற்றுப்பாதையையும் வழங்குகிறது, இதில் ONNX Runtime உடன் inference, logits செயலாக்கம், தேடல் மற்றும் எடுத்துக்காட்டு, KV காசே நிர்வாகம் அடங்கும்.

- **செயல்திறன் மேம்பாடு:** NVIDIA GPUகள், AMD GPUகள் போன்ற பல ஹார்டுவேர் வேகவிருத்திகளை உள்ளடக்கியது.
- **பயன்பாட்டிற்கான எளிதுதல்:** குறைந்த குறியீட்டில் உரை, படங்கள் மற்றும் பிற உள்ளடக்கங்களை உருவாக்க API களை வழங்குகிறது.
- பயனர்கள் ஒரு உயர் நிலை generate() முறையை அழைக்கலாம், அல்லது மாதிரியின் ஒவ்வொரு சுற்றத்தையும் சூழ்நிலையிலும் ஓடி ஒரு குறியீட்டினை ஒருமுறை உருவாக்கலாம் மற்றும் விருப்பப்பட்டால் சுற்றிலும் உருவாக்கும் அளவுருக்களை புதியதாக்கலாம்.
- ONNX runtime க்கு greedy/beam தேடல் மற்றும் TopP, TopK எடுத்துக்காட்டு உதவும் செயல்பாடுகள் மற்றும் மறுபடியும் தூண்டுதல் போன்ற logits செயலாக்கமும் உள்ளது. தனிப்பயன் மதிப்பீடுகளையும் எளிதில் சேர்க்க முடியும்.

## துவக்கம்
ONNX Runtime for GENAIயுடன் துவங்க நீங்கள் கீழ்காணும் படிகள் பின்பற்றலாம்:

### ONNX Runtime நிறுவுக:
```Python
pip install onnxruntime
```
### Generative AI நீட்சிகள் நிறுவுக:
```Python
pip install onnxruntime-genai
```

### மாதிரி ஓட்ட: Python இல் ஒரு எளிய எடுத்துக்காட்டு:
```Python
import onnxruntime_genai as og

model = og.Model('path_to_your_model.onnx')

tokenizer = og.Tokenizer(model)

input_text = "Hello, how are you?"

input_tokens = tokenizer.encode(input_text)

output_tokens = model.generate(input_tokens)

output_text = tokenizer.decode(output_tokens)

print(output_text) 
```
### மாதிரி: ONNX Runtime GenAI பயன்படுத்தி Phi-3.5-Vision ஐ அழைக்கும்


```python

import onnxruntime_genai as og

model_path = './Your Phi-3.5-vision-instruct ONNX Path'

img_path = './Your Image Path'

model = og.Model(model_path)

processor = model.create_multimodal_processor()

tokenizer_stream = processor.create_stream()

text = "Your Prompt"

prompt = "<|user|>\n"

prompt += "<|image_1|>\n"

prompt += f"{text}<|end|>\n"

prompt += "<|assistant|>\n"

image = og.Images.open(img_path)

inputs = processor(prompt, images=image)

params = og.GeneratorParams(model)

params.set_inputs(inputs)

params.set_search_options(max_length=3072)

generator = og.Generator(model, params)

while not generator.is_done():

    generator.compute_logits()
    
    generator.generate_next_token()

    new_token = generator.get_next_tokens()[0]
    
    output = tokenizer_stream.decode(new_token)
    
    print(tokenizer_stream.decode(new_token), end='', flush=True)

```
