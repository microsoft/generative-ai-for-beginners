## יצירת תוכן משודרג עם הושטת שליפה (RAG)

צ'אטבוט עם מנוע LLM מעבד בקשות משתמש ליצירת תגובות. הוא מיועד להיות אינטראקטיבי ומתנהל עם המשתמשים על מגוון נושאים רחב. עם זאת, התגובות מוגבלות להקשר שניתן והנתונים הבסיסיים שבהם הוכשר. לדוגמה, גבול הידע של GPT-4 הוא ספטמבר 2021, כלומר, אין לו מידע על אירועים שהתרחשו לאחר תקופה זו. בנוסף, הנתונים שבהם משתמשים לאימון LLM אינם כוללים מידע סודי כגון הערות אישיות או מדריך מוצר של חברה.

### איך RAGs (יצירת תוכן משודרג עם הושטת שליפה) פועלים

![איור שמראה איך RAGs פועלים](../../../translated_images/he/how-rag-works.f5d0ff63942bd3a6.webp?WT.mc_id=academic-105485-koreyst)

נניח שברצונך לפרוס צ'אטבוט שיוצר מבחנים מההערות שלך, תצטרך חיבור למאגר הידע. כאן RAG נכנס לתמונה. RAGs פועלים כך:

- **מאגר ידע:** לפני השליפה, יש צורך בקליטת המסמכים ועיבודם המוקדם, בדרך כלל פירוק מסמכים גדולים לחלקים קטנים יותר, המרתם לטקסט מוטמע ואחסונם במאגר.

- **שאילתת משתמש:** המשתמש שואל שאלה

- **שליפה:** כאשר משתמש שואל שאלה, מודל ההטמעה מושך מידע רלוונטי ממאגר הידע שלנו כדי לספק הקשר נוסף שיוכנס לתוך הבקשה.

- **יצירה משודרגת:** ה-LLM משפר את תגובתו על בסיס הנתונים שהושגו. זה מאפשר שהתשובה שתיווצר לא תהיה מבוססת רק על הנתונים המאומנים מראש אלא גם על מידע רלוונטי מההקשר שנוסף. הנתונים שהושגו משמשים להגדלת תגובות ה-LLM. לאחר מכן ה-LLM מחזיר תשובה לשאלת המשתמש.

![תרשים שמראה את מבנה RAG](../../../translated_images/he/encoder-decode.f2658c25d0eadee2.webp?WT.mc_id=academic-105485-koreyst)

RAG משלב בין מקבל ושלוף למוליד: השאילתה מומרת לוקטור, משווה לאינדקס המסמכים כדי למצוא חלקי טקסט רלוונטיים, והחלקים האלה מסופקים בהקשר ל-LLM, אשר מייצר את התגובה. המשלוף והמוליד עשויים להשתמש בדגמים שונים; ל-RAG אין צורך בממיר מקודד-מפענח.

שתי גישות בעת יישום RAG בהתאם למאמר המוצע: [Retrieval-Augmented Generation for Knowledge intensive NLP (software עיבוד שפה טבעית) Tasks](https://arxiv.org/pdf/2005.11401.pdf?WT.mc_id=academic-105485-koreyst) הן:

- **_RAG-Sequence_** משתמש במסמכים שנשלפו כדי לחזות את התשובה הטובה ביותר לשאלה של המשתמש

- **RAG-Token** משתמש במסמכים כדי לייצר את הטוקן הבא, ואז שולף אותם כדי לענות על שאלת המשתמש

### למה תשתמש ב-RAG?

- **עושר מידע:** מבטיח שתשובות הטקסט יהיו מעודכנות ועכשוויות. הדבר משפר את הביצועים במשימות ספציפיות לתחום על ידי גישה לבסיס ידע פנימי.

- מפחית המצאות על ידי שימוש ב**נתונים שניתנים לאימות** בבסיס הידע כדי לספק הקשר לשאלות המשתמש.

- זה **חסכוני** כי הוא זול יותר יחסית לכיול מחדש (fine-tuning) של LLM

### מטקסט להטמעות

לפני שנאחסן את הנתונים שלנו, נצטרך להמיר אותם להטמעות וקטוריות לפני שהם יאוחסנו במסד הנתונים. אם אתה עובד עם מסמכים גדולים או טקסטים ארוכים, תוכל לחלק אותם לפי שאילתות שאתה מצפה להן. הפיצול יכול להיעשות ברמת משפט או ברמת פסקה. מכיוון שהפיצול מפיק משמעות מהמילים שמסביב, תוכל להוסיף הקשר נוסף לקטע, למשל על ידי הוספת כותרת המסמך או הכללת טקסט לפני או אחרי הקטע. ניתן לפצל את הנתונים כך:

```python
def split_text(text, max_length, min_length):
    words = text.split()
    chunks = []
    current_chunk = []

    for word in words:
        current_chunk.append(word)
        if len(' '.join(current_chunk)) < max_length and len(' '.join(current_chunk)) > min_length:
            chunks.append(' '.join(current_chunk))
            current_chunk = []

    # If the last chunk didn't reach the minimum length, add it anyway
    if current_chunk:
        chunks.append(' '.join(current_chunk))

    return chunks
```

לאחר הפיצול, נוכל להטמיע את הטקסט שלנו באמצעות מודלים שונים להטמעה. כמה מודלים שניתן להשתמש בהם כוללים: word2vec, ada-002 של OpenAI, Azure Computer Vision ועוד רבים. בחירת מודל תלויה בשפות שבהן אתה משתמש, בסוג התוכן המקודד (טקסט/תמונות/אודיו), בגודל הקלט שניתן לקודד ואורך הפלט של ההטמעה.

## שליפה וחיפוש וקטורי

כשמשתמש שואל שאלה, המשלף ממיר אותה לוקטור בעזרת מקודד השאילתא, ואז מחפש דרך אינדקס החיפוש של המסמכים שלנו וקטורים רלוונטיים במסמך שקשורים לקלט. לאחר מכן הוא ממיר את וקטור הקלט ואת וקטורי המסמך לטקסט ומעביר אותם ל-LLM.

### שליפה

השליפה מתרחשת כשהמערכת מנסה למצוא במהירות את המסמכים מהאינדקס שעומדים בקריטריוני החיפוש. מטרת המשלף היא להשיג מסמכים שישמשו להענקת הקשר ויעמדו בקרקע ל-LLM על הנתונים שלך.

יש כמה דרכים לבצע חיפוש בתוך מסד הנתונים שלנו, כגון:

- **חיפוש לפי מילות מפתח** - משמש לחיפוש טקסט

- **חיפוש וקטורי** - ממיר מסמכים מטקסט לייצוגים וקטוריים באמצעות מודלים להטמעה, ומאפשר **חיפוש סמנטי** באמצעות משמעות המילים. השליפה תתבצע על ידי שאילתה למסמכים שייצוגי הוקטור שלהם הם הקרובים ביותר לשאלה של המשתמש.

- **היברידי** - שילוב של חיפוש לפי מילות מפתח וחיפוש וקטורי.

אתגר בשליפה מתעורר כאשר אין תשובה דומה לשאלה בבסיס הנתונים, המערכת תחזיר אז את המידע הטוב ביותר שהיא יכולה להשיג, אך ניתן להשתמש בטקטיקות כמו הגדרת מרחק מקסימלי לרלוונטיות או שימוש בחיפוש היברידי שמשלב מילות מפתח וחיפוש וקטורי. בשיעור זה נשתמש בחיפוש היברידי, שילוב של חיפוש וקטורי ומילות מפתח. אנו נאחסן את הנתונים שלנו במסגרת נתונים עם עמודות שמכילות את הקטעים וההטמעות.

### דמיון וקטורי

המשלף יחפש דרך מסד הידע הטמעות הקרובות זו לזו — השכנים הקרובים — מכיוון שהן מייצגות טקסטים דומים. בתרחיש זה, כאשר המשתמש מגיש שאילתה, היא מוטמעת תחילה ואז מותאמת להטמעות דומות. המדד הנפוץ ביותר להשוואת דמיון וקטורי הוא דמיון קוסינוס, המבוסס על הזווית בין שני וקטורים.

מדדים אחרים שניתן להשתמש בהם למדידת דמיון כוללים מרחק אוקלידי, שהוא הקו הישר בין נקודות הקצה של הוקטורים, ומכפלה סקלרית, שמודדת את סכום המכפלות של האלמנטים המתאימים בשני הוקטורים.

### אינדקס חיפוש

בעת ביצוע שליפה, נצטרך לבנות אינדקס חיפוש עבור בסיס הידע שלנו לפני ביצוע החיפוש. אינדקס יאחסן את ההטמעות שלנו ויכול להגיע במהירות לקטעים הדומים ביותר אפילו במסד נתונים גדול. נוכל ליצור את האינדקס מקומית באמצעות:

```python
from sklearn.neighbors import NearestNeighbors

embeddings = flattened_df['embeddings'].to_list()

# Create the search index
nbrs = NearestNeighbors(n_neighbors=5, algorithm='ball_tree').fit(embeddings)

# To query the index, you can use the kneighbors method
distances, indices = nbrs.kneighbors(embeddings)
```

### דירוג מחדש

לאחר שביצעת שאילתה למסד הנתונים, ייתכן שתצטרך למיין את התוצאות מהכי רלוונטיות. LLM לדירוג מחדש משתמש בלמידת מכונה לשיפור הרלוונטיות של תוצאות החיפוש על ידי סידורן מהכי רלוונטיות. באמצעות Azure AI Search, הדירוג מחדש מבוצע אוטומטית עבורך באמצעות ריראנקר סמנטי. דוגמה לדרך שבה דירוג מחדש פועל בעזרת השכנים הקרובים:

# Find the most similar documents
distances, indices = nbrs.kneighbors([query_vector])

for distance, index in zip(distances[0][:3], indices[0][:3]):

## הערכת היישום שלנו

### מדדי הערכה

- איכות התגובות המסופקות, הבטחה שהן נשמעות טבעיות, שוטפות ודמויות אדם

- הבסיסיות של הנתונים: הערכה האם התגובה הגיעה מהמסמכים שנמסרו

- רלוונטיות: הערכה שהתשובה מתאימה וקשורה לשאלה שנשאלה

- שוטפות - האם התגובה הגיונית מבחינה דקדוקית

## מקרים לשימוש ב-RAG (Retrieval Augmented Generation) ובסיסי נתונים וקטוריים

ישנם מקרים רבים שבהם RAG יכול לשפר את האפליקציה שלך, כגון:

- שאלות ותשובות: לגבי חיבור נתוני החברה שלך לצאט שניתן להשתמש בו על ידי עובדים לשאילת שאלות.

- מערכות המלצה: שבהן ניתן ליצור מערכת המתאימה את הערכים הדומים ביותר לדוגמה: סרטים, מסעדות ועוד.

- שירותי צ'אטבוט: ניתן לאחסן היסטוריית צ'אט ולהתאים אישית את השיחה בהתאם לנתוני המשתמש.

- חיפוש תמונות מבוסס הטמעות וקטוריות, שימושי לזיהוי תמונות וגילוי חריגות.

## סיכום

סקרנו את התחומים הבסיסיים של RAG מהוספת הנתונים שלנו לאפליקציה, דרך שאילתת המשתמש ועד הפלט. לפשט יצירת RAG, ניתן להשתמש במסגרת כמו Semantic Kernel, LangChain או AutoGen.

## משימה

להמשיך את לימודך ב-Retrieval Augmented Generation (RAG) תוכל לבנות:

- לבנות ממשק קדמי לאפליקציה באמצעות המסגרת שבחרת

- להשתמש במסגרת, בין אם LangChain או Semantic Kernel, וליצור מחדש את היישום שלך.
