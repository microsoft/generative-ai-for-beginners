# מבוא למודלים שפתיים קטנים ל-AI יצירתי למתחילים
AI יצירתי הוא תחום מרתק בבינה מלאכותית שמתמקד ביצירת מערכות המסוגלות לייצר תוכן חדש. תוכן זה יכול לנוע מטקסט ותמונות למוזיקה ואפילו סביבות וירטואליות שלמות. אחת היישומים המלהיבים ביותר של AI יצירתי היא בתחום המודלים השפתיים.

## מה הם מודלים שפתיים קטנים?

מודל שפה קטן (SLM) מייצג גרסה מוקטנת של מודל שפה גדול (LLM), המשתמש בדרכי בנייה וטכניקות רבות של LLMs, תוך הצגת טביעת חישובית מופחתת משמעותית.

SLMs הם תת-קבוצה של מודלים שפתיים שמטרתם לייצר טקסט הדומה לטקסט אנושי. בניגוד לעמיתיהם הגדולים יותר, כמו GPT-4, SLMs הם קומפקטיים ויעילים יותר, מה שהופך אותם לאידיאליים ליישומים שבהם משאבים חישוביים מוגבלים. למרות גודלם הקטן יותר, הם יכולים לבצע מגוון משימות. בדרך כלל, SLMs נבנים על ידי כיווץ או זיקוק של LLMs, מתוך מטרה לשמור על חלק משמעותי מפונקציונליות המודל המקורי וכישורי השפה שלו. הקטנה זו בגודל המודל מפחיתה את המורכבות הכוללת, מה שהופך את ה-SLMs ליעילים יותר מבחינת שימוש בזיכרון ודרישות חישוביות. למרות האופטימיזציות הללו, SLMs עדיין יכולים לבצע טווח רחב של משימות עיבוד שפה טבעית (NLP):

- יצירת טקסט: יצירת משפטים או פסקאות קוהרנטיים ורלוונטיים להקשר.
- השלמת טקסט: חיזוי והשלמת משפטים בהתבסס על טקסט נתון.
- תרגום: המרת טקסט משפה אחת לאחרת.
- סיכום: קיצור טקסטים ארוכים לסיכומים קצרים וקליטים יותר.

אם כי עם כמה פשרות בביצועים או עומק ההבנה לעומת עמיתיהם הגדולים יותר.

## איך מודלים שפתיים קטנים עובדים?
SLMs מאומנים על כמויות עצומות של נתוני טקסט. במהלך האימון, הם לומדים את הדפוסים והמבנים של השפה, מה שמאפשר להם לייצר טקסט שיהיה גם נכון מבחינה דקדוקית וגם מתאים להקשר. תהליך האימון כולל:

- איסוף נתונים: איסוף מאגרי נתונים גדולים של טקסט ממקורות שונים.
- עיבוד מוקדם: ניקוי וארגון הנתונים כדי שיהיו מתאימים לאימון.
- אימון: שימוש באלגוריתמים של למידת מכונה ללמד את המודל כיצד להבין וליצור טקסט.
- כיוונון עדין: התאמת המודל לשיפור ביצועים במשימות מסוימות.

פיתוח SLMs עולה בקנה אחד עם הצורך המתגבר במודלים שניתן לפרוס בסביבות מוגבלות במשאבים, כמו מכשירים ניידים או פלטפורמות מחשוב פריפריאליות, שבהן מודלים LLM מגודל מלא עשויים להיות לא פרקטיים בגלל דרישות המשאבים הכבדות שלהם. על ידי התמקדות ביעילות, SLMs מאזנים בין ביצועים לזמינות, ומאפשרים שימוש נרחב יותר בתחומים שונים.

## ההבדלים בין מודלים שפתיים גדולים (LLMs) ומודלים שפתיים קטנים (SLMs)

גם LLMs וגם SLMs מבוססים על עקרונות יסודיים של למידת מכונה הסתברותית, ופועלים בגישות דומות בעיצוב הארכיטקטוני, שיטות אימון, תהליכי יצירת נתונים וטכניקות הערכת מודל. עם זאת, מספר גורמים מרכזיים מבדילים בין שני סוגי המודלים.

## יישומים של מודלים שפתיים קטנים

ל-SLMs יש מגוון רחב של יישומים, כולל:

- צ׳אטבוטים: מתן תמיכה ללקוחות ומעורבות בשיחה עם משתמשים.
- יצירת תוכן: סיוע לכותבים ביצירת רעיונות או אפילו טיוטות של מאמרים שלמים.
- חינוך: עזרה לתלמידים במשימות כתיבה או בלימוד שפות חדשות.
- נגישות: יצירת כלים לאנשים עם מוגבלויות, כגון מערכות טקסט לדיבור.

**גודל**
  
בידול ראשי בין LLMs ל-SLMs טמון בקנה המידה של המודלים. LLMs, כמו ChatGPT (GPT-4), יכולים לכלול כ-1.76 טריליון פרמטרים, בעוד ש-SLMs בקוד פתוח כמו Mistral 7B מעוצבים עם מספר פרמטרים קטן בהרבה — כ-7 מיליארד. הבדל זה נובע בעיקר מהבדלים בארכיטקטורת המודל ותהליכי האימון. לדוגמה, ChatGPT משתמש במנגנון קשב עצמי במסגרת מקודד-פענח (encoder-decoder), בעוד Mistral 7B משתמש בקשב חלון מחליק, שמאפשר אימון יעיל יותר במסגרת מודל פענח בלבד. שונות ארכיטקטונית זו משפיעה עמוקות על המורכבות והביצועים של המודלים.

**הבנה**

SLMs מותאמים בדרך כלל לביצועים בתחום ספציפי, מה שהופך אותם למומחים מאוד אך עם מגבלה ביכולתם להעניק הבנה הקשרית רחבה במגוון תחומי ידע. בניגוד לכך, LLMs שואפים לדמות אינטליגנציה בדומה לבני אדם ברמה מקיפה יותר. מאומנים על מאגרי נתונים מגוונים וגדולים, LLMs מיועדים לביצועים טובים במגוון תחומים, עם גמישות והסתגלות גבוהה יותר. לכן, LLMs מתאימים יותר למשימות שונות במורד הזרם, כמו עיבוד שפה טבעית ותכנות.

**חישוב**

האימון וההפעלה של LLMs הם תהליכים עתירי משאבים, שדורשים לעיתים תשתיות חישוביות משמעותיות, כולל אשכולות GPU בקנה מידה גדול. לדוגמה, אימון מודל כמו ChatGPT מאפס עשוי לדרוש אלפי GPUs לפרקי זמן ארוכים. לעומת זאת, SLMs, עם מספר הפרמטרים הקטן יותר, נגישים יותר מבחינת משאבים חישוביים. מודלים כמו Mistral 7B ניתנים לאימון ולהפעלה במכונות מקומיות עם יכולות GPU בינוניות, אף שהאימון עדיין דורש מספר שעות על פני מספר GPUs.

**הטיה**

הטיה היא בעיה ידועה ב-LLMs, בעיקר בשל אופי נתוני האימון. מודלים אלה מסתמכים לעיתים קרובות על נתונים גלויים וזמינים ברשת, שעשויים לייצג באופן חלקי או מוטעה קבוצות מסוימות, להוסיף תיוג שגוי, או לשקף הטיות לשוניות המושפעות מניבים, שינויים גיאוגרפיים וכללי דקדוק. בנוסף, המורכבות של ארכיטקטורות LLM עשויה להחמיר את ההטיה, שעשויה להתפספס ללא כיוונון קפדני. מצד שני, SLMs, המאומנים על מאגרי נתונים מוגבלים ותחומיים יותר, פגיעים פחות להטיות כאלה, אם כי אינם חסינים מהן.

**חיזוי**

הגודל המופחת של SLMs מעניק להם יתרון משמעותי במהירות החיזוי, ומאפשר להם לייצר תוצאות ביעילות בחומרה מקומית בלי צורך בעיבוד מקביל נרחב. לעומת זאת, LLMs, בשל גודל ומורכבותם, דורשים לעיתים משאבים חישוביים מקביליים נרחבים להשגת זמני חיזוי מקובלים. הימצאות משתמשים מרובים במקביל גם מאיטה את זמני התגובה של LLMs, במיוחד כאשר מפעילים אותם בקנה מידה גדול.

לסיכום, בעוד ששני הסוגים מבוססים על יסודות למידת מכונה, הם שונים משמעותית בגודל המודל, דרישות המשאבים, הבנת ההקשר, פגיעות להטיה ומהירות החיזוי. הבדלים אלה משקפים את התאמתם לשימושים שונים, כאשר LLMs הם גמישים אך כבדי משאבים, ו-SLMs מציעים יעילות תחומית עם דרישות חישוב מופחתות.

***הערה: בשיעור זה, נציג SLM באמצעות Microsoft Phi-3 / 3.5 כדוגמה.***

## הצגת משפחת Phi-3 / Phi-3.5

משפחת Phi-3 / 3.5 מתמקדת בעיקר בתרחישי שימוש בטקסט, ראייה וסוכן (MoE):

### Phi-3 / 3.5 Instruct

בעיקר ליצירת טקסט, השלמת שיחות וחילוץ מידע מתוכן, ועוד.

**Phi-3-mini**

מודל השפה עם 3.8 מיליארד פרמטרים זמין ב-Microsoft Foundry, Hugging Face ו-Ollama. מודלים של Phi-3 מבצעים טוב בהרבה ממרכזי שפה בגודל שווה או גדול יותר בנקודות מדידה מרכזיות (ראה מספרי הבנצ'מרק למטה, מספרים גבוהים יותר הם טובים יותר). Phi-3-mini מציג ביצועים טובים יותר ממודלים כפולי גודל שלו, בעוד ש-Phi-3-small ו-Phi-3-medium עוקפים מודלים גדולים יותר, כולל GPT-3.5.

**Phi-3-small ו-medium**

עם רק 7 מיליארד פרמטרים, Phi-3-small עולה על GPT-3.5T במגוון מבחני שפה, הסקה, קידוד ומתמטיקה.

Phi-3-medium עם 14 מיליארד פרמטרים ממשיך את המגמה ומצטיין על Gemini 1.0 Pro.

**Phi-3.5-mini**

ניתן לחשוב עליו כשדרוג ל-Phi-3-mini. הפרמטרים לא השתנו, אך השיפור הוא ביכולת לתמוך בשפות מרובות (תומך ב-20+ שפות: ערבית, סינית, צ'כית, דנית, הולנדית, אנגלית, פינית, צרפתית, גרמנית, עברית, הונגרית, איטלקית, יפנית, קוריאנית, נורווגית, פולנית, פורטוגזית, רוסית, ספרדית, שוודית, תאילנדית, טורקית, אוקראינית) ומוסיף תמיכה חזקה יותר להקשרים ארוכים.

Phi-3.5-mini עם 3.8 מיליארד פרמטרים מבצע טוב יותר ממודלי שפה בגודל זהה ומשווה למודלים כפולי גודלו.

### Phi-3 / 3.5 Vision

ניתן לחשוב על מודל ה-Instruct של Phi-3/3.5 כליכולתו של Phi להבין, וחזון הוא מה שנותן ל-Phi עיניים להבין את העולם.


**Phi-3-Vision**

Phi-3-vision, עם רק 4.2 מיליארד פרמטרים, ממשיך מגמה זו ועוקף מודלים גדולים יותר כמו Claude-3 Haiku ו-Gemini 1.0 Pro V במשימות הסקה חזותית כללית, OCR, והבנת טבלאות ותרשימים.


**Phi-3.5-Vision**

Phi-3.5-Vision הוא גם שדרוג ל-Phi-3-Vision, המוסיף תמיכה לריבוי תמונות. ניתן לחשוב עליו כשיפור בראייה, לא רק ניתן לראות תמונות, אלא גם וידאו.

Phi-3.5-vision עוקף מודלים גדולים יותר כמו Claude-3.5 Sonnet ו-Gemini 1.5 Flash במשימות OCR, הבנת טבלאות וגרפים ומשווה בביצועים במשימות הסקת ידע חזותי כללית. תומך בקלט רב-מסגרתי, כלומר מבצע הסקה על מספר תמונות.


### Phi-3.5-MoE

***תערובת מומחים (Mixture of Experts, MoE)*** מאפשרת למודלים לעבור אימון עם הרבה פחות חישוב, מה שאומר שאפשר להגדיל משמעותית את גודל המודל או של המאגר עם אותו תקציב חישובי כמו מודל צפוף (dense). במיוחד, מודל MoE אמור להשיג את אותה איכות כמו המקביל הצפוף במהירות רבה יותר במהלך האימון.

Phi-3.5-MoE כולל 16 מודולי מומחים של 3.8 מיליארד פרמטרים. Phi-3.5-MoE עם רק 6.6 מיליארד פרמטרים פעילים משיג רמת הסקה, הבנת שפה ומתמטיקה דומה למודלים גדולים בהרבה.

ניתן להשתמש במודל ממשפחת Phi-3/3.5 בסביבות שונות. בניגוד ל-LLM, אפשר לפרוס Phi-3/3.5-mini או Phi-3/3.5-Vision במכשירי edge.

**Microsoft Foundry**

**NVIDIA NIM**

בנוסף לקטלוג מודלים מבוסס הענן של Microsoft Foundry, ניתן להשתמש גם ב-[NVIDIA NIM](https://developer.nvidia.com/nim?WT.mc_id=academic-105485-koreyst) להשלמת קריאות קשורות. ניתן לבקר ב-NVIDIA NIM להשלמת קריאות API למשפחת Phi-3/3.5. NVIDIA NIM (NVIDIA Inference Microservices) הוא סט של שירותי מיקרו-שירותים מהירי חיזוי שמטרתם לסייע למפתחים לפרוס מודלים של AI ביעילות ברחבי סביבות שונות, כולל עננים, מרכזי נתונים ותחנות עבודה.

הנה כמה תכונות מרכזיות של NVIDIA NIM:

- **קלות הפריסה:** NIM מאפשר פריסת מודלי AI בפקודה אחת, מה שמקל על אינטגרציה לזרימות עבודה קיימות.
- **ביצועים מותאמים:** משתמש במנועי חיזוי מותאמים מראש של NVIDIA, כמו TensorRT ו-TensorRT-LLM, להבטחת זמן תגובה נמוך וקצב העברה גבוה.

**Hugging Face Transformer**
Hugging Face Transformers היא ספרייה עוצמתית המיועדת לעיבוד שפה טבעית (NLP) ומשימות למידת מכונה אחרות. הנה כמה נקודות מפתח עליה:

1. **מודלים מאומנים מראש**: היא מספקת אלפי מודלים מאומנים מראש שניתן להשתמש בהם למשימות שונות כגון סיווג טקסט, זיהוי ישויות, מענה על שאלות, סיכום, תרגום ויצירת טקסט.

2. **אינטרופרביליות של מסגרות עבודה**: הספרייה תומכת במספר מסגרות למידה עמוקה, כולל PyTorch, TensorFlow, ו-JAX. זה מאפשר לאמן מודל במסגרת אחת ולהשתמש בו במסגרת אחרת.

3. **יכולות מולטימודליות**: בנוסף ל-NLP, Hugging Face Transformers תומכת גם במשימות בראייה ממוחשבת (כגון סיווג תמונות, זיהוי עצמים) ועיבוד אודיו (כגון זיהוי דיבור, סיווג אודיו).

4. **קלות שימוש**: הספרייה מציעה ממשקי API וכלים להורדה וכיוונון מדויק של מודלים, מה שהופך אותה לנגישה גם למתחילים וגם למומחים.

5. **קהילה ומשאבים**: ל-Hugging Face קהילה חיה ותיעוד מקיף, מדריכים והדרכות כדי לעזור למשתמשים להתחיל ולהפיק את המרב מהספרייה.

**ONNX Runtime ל-GenAI**

[ONNX Runtime](https://github.com/microsoft/onnxruntime-genai?WT.mc_id=academic-105485-koreyst) הוא מאיץ למידת מכונה חוצה פלטפורמות לאינפרנציה ואימון. ONNX Runtime ל-AI גנרטיבי (GENAI) הוא כלי עוצמתי שעוזר לך להריץ מודלי AI גנרטיביים ביעילות במגוון פלטפורמות.

## מהו ONNX Runtime?
ONNX Runtime הוא פרויקט קוד פתוח שמאפשר אינפרנציה ביצועים גבוהים של מודלי למידת מכונה. הוא תומך במודלים בפורמט Open Neural Network Exchange (ONNX), שהוא תקן לייצוג מודלי למידת מכונה. אינפרנציה ב-ONNX Runtime מאפשרת חוויות משתמש מהירות יותר ועלויות נמוכות, ותומכת במודלים ממסגרות למידה עמוקה כמו PyTorch ו-TensorFlow/Keras וכן בספריות למידת מכונה קלאסיות כמו scikit-learn, LightGBM, XGBoost ועוד. ONNX Runtime תואם לחומרה, דרייברים ומערכות הפעלה שונות, ומספק ביצועים מיטביים על ידי ניצול מאיצי חומרה יחד עם אופטימיזציות וטרנספורמציות גרפיות.

## מה זה AI גנרטיבי?
AI גנרטיבי מתייחס למערכות בינה מלאכותית שיכולות ליצור תוכן חדש, כגון טקסט, תמונות או מוזיקה, בהתבסס על הנתונים שבהם אומנו. דוגמאות כוללות מודלי שפה כמו GPT-3 ומודלים ליצירת תמונות כמו Stable Diffusion. ספריית ONNX Runtime ל-GenAI מספקת את לולאת ה-AI הגנרטיבי למודלי ONNX, כולל אינפרנציה עם ONNX Runtime, עיבוד לוגיטים, חיפוש ודגימה, וניהול מטמון KV.

## ONNX Runtime ל-GENAI
ONNX Runtime ל-GENAI מרחיב את יכולות ONNX Runtime לתמיכה במודלי AI גנרטיביים. הנה כמה תכונות מפתח:

- **תמיכה רחבה בפלטפורמות:** עובד על פלטפורמות שונות, כולל Windows, Linux, macOS, Android ו-iOS.
- **תמיכה במודלים:** תומך בהרבה מודלים גנרטיביים פופולריים, כגון LLaMA, GPT-Neo, BLOOM ועוד.
- **אופטימיזציית ביצועים:** כולל אופטימיזציות עבור מאיצי חומרה שונים כמו NVIDIA GPUs, AMD GPUs ועוד2.
- **קלות שימוש:** מספק ממשקי API להשתלבות קלה ביישומים, המאפשרים ליצור טקסט, תמונות ותוכן נוסף עם מעט קוד.
- משתמשים יכולים לקרוא למתודה generate() ברמה גבוהה, או להריץ כל איטרציה של המודל בלולאה, כשהיא מייצרת טוקן אחד בכל פעם, ובאופן אופציונלי מעדכנת פרמטרים בתוך הלולאה.
- ל-ONNX Runtime יש גם תמיכה בחיפוש greedy/beam ובדגימת TopP, TopK ליצירת רצפי טוקנים ועיבוד לוגיטים מובנה כגון עונשי חזרה. ניתן גם להוסיף ניקוד מותאם בקלות.

```Python
import onnxruntime_genai as og

model = og.Model('path_to_your_model.onnx')

tokenizer = og.Tokenizer(model)

input_text = "Hello, how are you?"

input_tokens = tokenizer.encode(input_text)

output_tokens = model.generate(input_tokens)

output_text = tokenizer.decode(output_tokens)

print(output_text) 
```
### הדגמה: שימוש ב-ONNX Runtime GenAI לקריאה ל-Phi-3.5-Vision


```python

import onnxruntime_genai as og

model_path = './Your Phi-3.5-vision-instruct ONNX Path'

img_path = './Your Image Path'

model = og.Model(model_path)

processor = model.create_multimodal_processor()

tokenizer_stream = processor.create_stream()

text = "Your Prompt"

prompt = "<|user|>\n"

prompt += "<|image_1|>\n"

prompt += f"{text}<|end|>\n"

prompt += "<|assistant|>\n"

image = og.Images.open(img_path)

inputs = processor(prompt, images=image)

params = og.GeneratorParams(model)

params.set_inputs(inputs)

params.set_search_options(max_length=3072)

generator = og.Generator(model, params)

while not generator.is_done():

    generator.compute_logits()
    
    generator.generate_next_token()

    new_token = generator.get_next_tokens()[0]
    
    output = tokenizer_stream.decode(new_token)
    
    print(tokenizer_stream.decode(new_token), end='', flush=True)

```
