# Участь у проекті

Цей проєкт вітає внески та пропозиції. Більшість внесків вимагають, щоб ви
погодилися з Угодою про ліцензію для учасників (Contributor License Agreement, CLA), яка стверджує, що ви маєте право,
і насправді надаєте нам права використовувати ваш внесок. Для деталей відвідайте
<https://cla.microsoft.com>.

> Важливо: при перекладі тексту в цьому репозиторії будь ласка, не використовуйте машинний переклад. Ми перевірятимемо переклади через спільноту, тому просимо братися за переклади лише мовами, якими ви володієте.

Коли ви надсилаєте запит на витягування (pull request), бот CLA автоматично визначить, чи потрібно вам
надати CLA і відповідним чином оформить PR (наприклад, міткою або коментарем). Просто дотримуйтесь
інструкцій бота. Це потрібно зробити лише один раз для всіх репозиторіїв, які використовують наш CLA.

## Загальні настанови для написання

- Переконайтеся, що всі ваші URL-адреси обгорнуті у квадратні дужки з наступними круглими дужками без додаткових пробілів навколо або всередині `[]()`.
- Переконайтеся, що будь-яке відносне посилання (наприклад, посилання на інші файли та папки в репозиторії) починається з `./`, що посилається на файл або папку в поточній робочій директорії, або з `../`, що посилається на файл або папку, розташовані у батьківській робочій директорії.
- Переконайтеся, що будь-яке відносне посилання (наприклад, посилання на інші файли та папки в репозиторії) має ідентифікатор відстеження (тобто `?` або `&`, а потім `wt.mc_id=` або `WT.mc_id=`) вкінці.
- Переконайтеся, що будь-який URL з наступних доменів _github.com, microsoft.com, visualstudio.com, aka.ms та azure.com_ має вкінці ідентифікатор відстеження (тобто `?` або `&`, а потім `wt.mc_id=` або `WT.mc_id=`).
- Переконайтеся, що ваші посилання не містять локаль конкретної країни (наприклад, `/en-us/` або `/en/`).
- Переконайтеся, що всі зображення зберігаються в папці `./images`.
- Переконайтеся, що імена зображень описові, використовуючи англійські символи, цифри та дефіси у назві файлу.

Коли ви надсилаєте pull request, запускатимуться чотири різні робочі процеси для перевірки вказаних правил.
Просто дотримуйтесь інструкцій, наведених тут, щоб пройти перевірки робочого процесу.

- [Перевірка битих відносних шляхів](#check-broken-relative-paths)
- [Перевірка відносних шляхів на наявність відстеження](#check-paths-have-tracking)
- [Перевірка URL на наявність відстеження](#check-urls-have-tracking)
- [Перевірка відсутності локалі в URL](#check-urls-dont-have-locale)

### Перевірка битих відносних шляхів

Цей робочий процес гарантує, що будь-який відносний шлях у ваших файлах працює.
Цей репозиторій розгорнуто на GitHub pages, тому ви маєте бути дуже уважними при введенні посилань, що зв’язують все разом, щоб уникнути наведення на неправильне місце.

Щоб переконатися, що ваші посилання працюють належним чином, просто використовуйте VS code для перевірки.

Наприклад, коли ви наводите курсор миші на будь-яке посилання у ваших файлах, вам запропонують перейти за посиланням, натиснувши **ctrl + клацання**

![Скріншот VS code із підказкою для переходу за посиланням](../../translated_images/uk/vscode-follow-link.85520ab6a1237adc.webp?WT.mc_id=academic-105485-koreyst "Скріншот підказки VS code для переходу за посиланням при наведенні курсора на посилання.")

Якщо ви клацнете по посиланню і воно не працює локально, то, безсумнівно, це спричинить помилку у робочому процесі і не працюватиме на GitHub.

Щоб виправити цю проблему, спробуйте набрати посилання за допомогою VS code.

Коли ви вводите `./` або `../`, VS code запропонує вибрати з доступних варіантів відповідно до вашого вводу.

![Скріншот VS code із вибором відносного шляху](../../translated_images/uk/vscode-select-relative-path.3804eb73c3a9e5f2.webp?WT.mc_id=academic-105485-koreyst "Скріншот підказки VS code для вибору відносного шляху зі списку.")

Перейдіть до потрібного файлу або папки, клацнувши по ньому, і ви будете впевнені, що ваш шлях не є битим.

Після того, як ви додасте правильний відносний шлях, збережіть і надішліть зміни в репозиторій, робочий процес запуститься повторно для перевірки змін.
Якщо ви пройдете перевірку, можете продовжувати.

### Перевірка відносних шляхів на наявність відстеження

Цей робочий процес перевіряє, що будь-який відносний шлях містить відстеження.
Цей репозиторій розгорнуто на GitHub pages, тому нам потрібно відслідковувати переміщення між різними файлами і папками.

Щоб переконатися в наявності відстеження у відносних шляхах, просто перевірте наявність такого тексту `?wt.mc_id=` в кінці шляху.
Якщо цей текст доданий до ваших відносних шляхів, ви пройдете цю перевірку.

Якщо ні, ви можете побачити таку помилку.

![Скріншот коментаря GitHub із пропущеним відстеженням у шляхах](../../translated_images/uk/github-check-paths-missing-tracking-comment.880d4afe03e898ff.webp?WT.mc_id=academic-105485-koreyst "Скріншот коментаря в GitHub, що показує відсутність відстеження у відносних шляхах")

Щоб виправити цю проблему, відкрийте файл і шлях, вказаний робочим процесом, і додайте ідентифікатор відстеження в кінець відносних шляхів.

Після додавання ідентифікатора збережіть і надішліть зміни, робочий процес перевірить їх повторно.
Якщо ви пройдете перевірку, можете продовжувати.

### Перевірка URL на наявність відстеження

Цей робочий процес перевіряє, що будь-яка веб-URL містить відстеження.
Цей репозиторій доступний усім, тому потрібно відслідковувати доступ, аби знати, звідки йде трафік.

Щоб переконатися, що у ваших URL є відстеження, просто перевірте наявність тексту `?wt.mc_id=` в кінці URL.
Якщо він доданий до ваших URL, ви пройдете цю перевірку.

Якщо ні, ви можете побачити таку помилку.

![Скріншот коментаря GitHub із пропущеним відстеженням у URL](../../translated_images/uk/github-check-urls-missing-tracking-comment.1bd00d20b24a1e2e.webp?WT.mc_id=academic-105485-koreyst "Скріншот коментаря в GitHub, що показує відсутність відстеження у URL")

Щоб виправити цю проблему, відкрийте файл і шлях, вказаний робочим процесом, і додайте ідентифікатор відстеження в кінець URL.

Після додавання ідентифікатора збережіть і надішліть зміни, робочий процес перевірить їх повторно.
Якщо ви пройдете перевірку, можете продовжувати.

### Перевірка відсутності локалі в URL

Цей робочий процес гарантує, що в будь-якому веб-URL відсутня локаль конкретної країни.
Цей репозиторій доступний людям у всьому світі, тому важливо не включати локаль вашої країни в URL.

Щоб переконатися, що у ваших URL немає локалі країни, перевірте наявність тексту `/en-us/` або `/en/` чи будь-якої іншої мовної локалі у будь-якому місці URL.
Якщо її немає у ваших URL, ви пройдете цю перевірку.

Якщо ні, ви можете побачити таку помилку.

![Скріншот коментаря GitHub про додану локаль країни у URL](../../translated_images/uk/github-check-country-locale-comment.2f4fe93228161dee.webp?WT.mc_id=academic-105485-koreyst "Скріншот коментаря в GitHub, що показує додану локаль країни у URL")

Щоб виправити цю проблему, відкрийте файл та шлях, вказаний робочим процесом, і видаліть локаль країни з URL.

Після видалення локалі збережіть і надішліть зміни, робочий процес перевірить їх повторно.
Якщо ви пройдете перевірку, можете продовжувати.
