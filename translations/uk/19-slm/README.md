# Вступ до малих мовних моделей для генеративного ШІ для початківців
Генеративний ШІ — це захоплююча галузь штучного інтелекту, яка зосереджена на створенні систем, здатних генерувати новий контент. Цей контент може варіюватися від тексту та зображень до музики й навіть цілих віртуальних середовищ. Одним із найцікавіших застосувань генеративного ШІ є область мовних моделей.

## Що таке малі мовні моделі?

Мала мовна модель (SLM) — це зменшена версія великої мовної моделі (LLM), що використовує багато архітектурних принципів і методів LLM, але має значно менші обчислювальні вимоги.

SLM є підмножиною мовних моделей, призначених для генерації тексту, схожого на людський. На відміну від своїх більших аналогів, як-от GPT-4, SLM є більш компактними та ефективними, що робить їх ідеальними для застосувань із обмеженими обчислювальними ресурсами. Незважаючи на менший розмір, вони все ж здатні виконувати різноманітні завдання. Зазвичай SLM створюють шляхом стиснення або дистиляції LLM з метою збереження значної частини функціональності та лінгвістичних можливостей оригінальної моделі. Це зменшення розміру моделі знижує загальну складність, роблячи SLM ефективнішими як у використанні пам’яті, так і в обчислювальних потребах. Незважаючи на ці оптимізації, SLM можуть виконувати широкий спектр завдань обробки природної мови (NLP):

- Генерація тексту: створення зв’язних та контекстно релевантних речень або абзаців.
- Завершення тексту: передбачення та доповнення речень на основі заданого запиту.
- Переклад: конвертація тексту з однієї мови на іншу.
- Резюмування: скорочення довгих текстів у коротші, більш зрозумілі резюме.

Хоча з деякими компромісами в продуктивності чи глибині розуміння порівняно з їх більшими аналогами.

## Як працюють малі мовні моделі?
SLM навчаються на величезних масивах текстових даних. Під час тренування вони вивчають патерни та структури мови, що дозволяє їм генерувати текст, який є граматично правильним та контекстно доречним. Процес навчання включає:

- Збір даних: збір великих наборів текстових даних з різних джерел.
- Попередня обробка: очищення та організація даних для підготовки їх до навчання.
- Навчання: використання алгоритмів машинного навчання для навчання моделі розумінню та генерації тексту.
- Тонке налаштування: коригування моделі для покращення її продуктивності в конкретних завданнях.

Розробка SLM відповідає зростаючій потребі у моделях, які можна запускати в умовах обмежених ресурсів, таких як мобільні пристрої або платформи периферійних обчислень, де повноцінні LLM можуть бути непрактичними через великі вимоги до ресурсів. Зосереджуючись на ефективності, SLM забезпечують баланс між продуктивністю та доступністю, що дає змогу ширшому застосуванню у різних сферах.

## Відмінності між великими мовними моделями (LLM) і малими мовними моделями (SLM)

Як LLM, так і SLM базуються на основних принципах ймовірнісного машинного навчання, дотримуючись схожих підходів в архітектурі, методах навчання, процесах генерації даних і методах оцінювання моделей. Однак кілька ключових факторів відрізняють ці два типи моделей.

## Застосування малих мовних моделей

SLM мають широке застосування, зокрема:

- Чатботи: забезпечення підтримки клієнтів та взаємодія з користувачами в розмовному форматі.
- Створення контенту: допомога письменникам у генерації ідей або навіть написанні статей.
- Освіта: допомога студентам із письмовими завданнями або вивченням нових мов.
- Доступність: створення інструментів для людей з інвалідністю, таких як системи перетворення тексту в мову.

**Розмір**
  
Головна відмінність між LLM і SLM полягає у масштабі моделей. LLM, як-от ChatGPT (GPT-4), можуть мати орієнтовно 1,76 трильйона параметрів, тоді як відкриті SLM, наприклад Mistral 7B, створені з значно меншою кількістю параметрів — приблизно 7 мільярдів. Ця різниця переважно обумовлена відмінностями в архітектурі та процесах навчання моделей. Наприклад, ChatGPT використовує механізм самоуваги в рамці енкодер-декодер, а Mistral 7B застосовує ковзну увагу, що дозволяє ефективніше навчатися у моделей, що містять тільки декодер. Ця архітектурна різниця суттєво впливає на складність і продуктивність моделей.

**Розуміння**

SLM зазвичай оптимізовані для виконання в межах конкретних доменів, що робить їх високоспеціалізованими, але потенційно обмеженими в здатності забезпечувати широке контекстне розуміння в багатьох галузях знань. Водночас LLM прагнуть імітувати інтелект, подібний до людського, на більш широкому рівні. Навчені на великих і різноманітних наборах даних, LLM розраховані на успішне виконання завдань у різних сферах, пропонуючи більшу універсальність і адаптивність. Відповідно, LLM більше підходять для широкого спектра завдань, таких як обробка природної мови та програмування.

**Обчислення**

Навчання та впровадження LLM — це ресурсомісткі процеси, що часто вимагають значної обчислювальної інфраструктури, включаючи великі GPU-кластери. Наприклад, навчання моделі, як-от ChatGPT з нуля, може вимагати тисячі GPU протягом тривалого часу. Натомість SLM із меншою кількістю параметрів доступніші за потребою в обчислювальних ресурсах. Моделі, як-от Mistral 7B, можуть навчатись і запускатись на локальних машинах із помірними GPU, хоча навчання все ще потребує кількох годин на кількох GPU.

**Упередженість**

Упередженість є відомою проблемою LLM, що в основному виникає через природу навчальних даних. Ці моделі часто покладаються на сирі, відкрито доступні дані з інтернету, які можуть недооцінювати або неправильним чином відображати певні групи, вводити помилкове маркування або відображати мовні упередження, зумовлені діалектом, географічними варіаціями та граматичними правилами. Крім того, складність архітектури LLM може ненавмисно посилювати упередження, які можуть залишатися непоміченими без ретельного тонкого налаштування. Натомість SLM, навчені на більш обмежених і спеціалізованих доменних наборах даних, мають меншу схильність до таких упереджень, хоч і не є зовсім захищеними від них.

**Інференція**

Менший розмір SLM дає їм суттєву перевагу в швидкості інференції, дозволяючи ефективно генерувати вихідні дані на локальному обладнанні без необхідності великої паралельної обробки. У протилежність цьому, LLM через свій розмір і складність часто вимагають значних паралельних обчислювальних ресурсів для досягнення прийнятного часу відповіді. Більша кількість одночасних користувачів ще більше уповільнює час відповіді LLM, особливо при масштабованому впровадженні.

Підсумовуючи, хоча LLM і SLM мають спільну основу у машинному навчанні, вони суттєво відрізняються за розміром моделей, вимогами до ресурсів, глибиною контекстного розуміння, схильністю до упереджень і швидкістю інференції. Ці відмінності відображають їх відповідну придатність для різних випадків використання: LLM більш універсальні, але ресурсоємні, а SLM пропонують більш ефективне виконання завдань у певних доменах із зниженими обчислювальними витратами.

## Представлення сімейства Phi-3 / Phi-3.5

Сімейство Phi-3 / 3.5 орієнтоване здебільшого на сценарії застосування у тексті, зорі та агентських (MoE) застосунках:

### Phi-3 / 3.5 Instruct

Головним чином для генерації тексту, завершення чатів і вилучення інформації з контенту тощо.

**Phi-3-mini**

Модель із 3,8 млрд параметрів доступна на Microsoft Foundry, Hugging Face та Ollama. Моделі Phi-3 суттєво перевершують мовні моделі однакового і більшого розміру у ключових бенчмарках (див. наведені нижче показники, де вищі числа означають кращі результати). Phi-3-mini перевершує моделі у два рази більші за розмірами, а Phi-3-small і Phi-3-medium — більші моделі, зокрема GPT-3.5.

**Phi-3-small & medium**

Маючи всього 7 млрд параметрів, Phi-3-small випереджає GPT-3.5T за багатьма мовними, логічними, кодинговими та математичними бенчмарками.

Модель Phi-3-medium із 14 млрд параметрів продовжує цю тенденцію та перевершує Gemini 1.0 Pro.

**Phi-3.5-mini**

Можна вважати його оновленням Phi-3-mini. Попри те, що параметри залишились без змін, покращено здатність підтримувати кілька мов (підтримка 20+ мов: арабська, китайська, чеська, данська, нідерландська, англійська, фінська, французька, німецька, іврит, угорська, італійська, японська, корейська, норвезька, польська, португальська, російська, іспанська, шведська, тайська, турецька, українська) та додано посилену підтримку довгих контекстів.

Phi-3.5-mini з 3,8 млрд параметрів перевершує мовні моделі одного розміру та знаходиться на рівні моделей удвічі більшого розміру.

### Phi-3 / 3.5 Vision

Модель Instruct у Phi-3/3.5 — це здатність Phi до розуміння, а Vision дає Phi «очі» для розуміння світу.


**Phi-3-Vision**

Phi-3-vision, маючи лише 4,2 млрд параметрів, продовжує цю тенденцію й перевершує більші моделі, такі як Claude-3 Haiku і Gemini 1.0 Pro V у загальних завданнях візуального міркування, OCR (оптичне розпізнавання символів) та аналізі таблиць і діаграм.


**Phi-3.5-Vision**

Phi-3.5-Vision також є оновленням Phi-3-Vision, додаючи підтримку багатьох зображень одночасно. Можна вважати це вдосконаленням зору: тепер ви можете бачити не лише картинки, а й відео.

Phi-3.5-vision перевершує більші моделі, такі як Claude-3.5 Sonnet і Gemini 1.5 Flash у завданнях OCR, розумінні таблиць і діаграм, а також відповідає рівню в загальних завданнях візуального знання. Підтримує багатокадровий ввід, тобто виконує міркування на основі кількох вхідних зображень.


### Phi-3.5-MoE

***Mixture of Experts (MoE)*** дозволяє попередньо навчати моделі з набагато меншими обчислювальними затратами, що означає можливість масштабувати модель або розмір набору даних суттєво збільшуючи при цьому бюджет на обчислення у порівнянні з густими моделями. Зокрема, MoE модель повинна досягати якості, аналогічної густій моделі, значно швидше під час попереднього навчання.

Phi-3.5-MoE містить 16 модулів експертів по 3,8 млрд параметрів кожен. Phi-3.5-MoE із лише 6,6 млрд активних параметрів досягає подібного рівня у міркуванні, розумінні мови та математиці, як і значно більші моделі.

Ми можемо використовувати модель сімейства Phi-3/3.5 залежно від сценаріїв. На відміну від LLM, ви можете запускати Phi-3/3.5-mini або Phi-3/3.5-Vision на периферійних пристроях.

**NVIDIA NIM**

Окрім хмарного каталогу Microsoft Foundry Models, ви також можете використовувати [NVIDIA NIM](https://developer.nvidia.com/nim?WT.mc_id=academic-105485-koreyst) для виконання відповідних викликів. Ви можете відвідати NVIDIA NIM, щоб здійснювати API виклики для сімейства Phi-3/3.5. NVIDIA NIM (NVIDIA Inference Microservices) — це набір прискорених inference мікросервісів, розроблених для ефективного розгортання ШІ-моделей у різних середовищах, включно з хмарами, центрами обробки даних і робочими станціями.

Ось кілька ключових особливостей NVIDIA NIM:

- **Легкість розгортання:** NIM дозволяє розгортати моделі ШІ однією командою, що робить його простим для інтеграції у існуючі робочі процеси.
- **Оптимізована продуктивність:** Він використовує попередньо оптимізовані інференс-движки NVIDIA, такі як TensorRT та TensorRT-LLM, щоб забезпечити низьку затримку та високу пропускну здатність.
- **Масштабованість:** NIM підтримує автоскейлінг у Kubernetes, що дозволяє ефективно обробляти змінні навантаження.
- **Безпека та контроль:** Організації можуть зберігати контроль над своїми даними та додатками, розміщуючи мікросервіси NIM на власній керованій інфраструктурі.
- **Стандартні API:** NIM надає галузеві стандартизовані API, що полегшує створення та інтеграцію ШІ-додатків, таких як чатботи, ШІ-асистенти тощо.

**Hugging Face Transformer**
Hugging Face Transformers — це потужна бібліотека, розроблена для обробки природньої мови (NLP) та інших задач машинного навчання. Ось кілька ключових моментів про неї:

1. **Попередньо навчені моделі**: Вона надає тисячі попередньо навчених моделей для різних завдань, таких як класифікація тексту, розпізнавання іменованих сутностей, відповіді на питання, резюмування, переклад і генерація тексту.

2. **Інтероперабельність фреймворків**: Бібліотека підтримує кілька фреймворків глибокого навчання, включно з PyTorch, TensorFlow і JAX. Це дає змогу навчати модель у одному фреймворку і використовувати її в іншому.

3. **Мультимодальні можливості**: Окрім NLP, Hugging Face Transformers підтримує задачі комп’ютерного зору (наприклад, класифікація зображень, виявлення об’єктів) і обробки аудіо (наприклад, розпізнавання мови, класифікація аудіо).

4. **Легкість використання:** Бібліотека надає API та інструменти для простого завантаження та донавчання моделей, що робить її доступною і для початківців, і для експертів.

5. **Спільнота та ресурси:** Hugging Face має активну спільноту та обширну документацію, навчальні посібники й керівництва, що допомагають користувачам розпочати роботу і максимально ефективно використовувати бібліотеку.

**ONNX Runtime для GenAI**

[ONNX Runtime](https://github.com/microsoft/onnxruntime-genai?WT.mc_id=academic-105485-koreyst) — кросплатформовий прискорювач інференсу та навчання моделей машинного навчання. ONNX Runtime для Generative AI (GENAI) — це потужний інструмент, який допомагає ефективно запускати генеративні ШІ-моделі на різних платформах.

## Що таке ONNX Runtime?
ONNX Runtime — це проект з відкритим кодом, що забезпечує високопродуктивний інференс моделей машинного навчання. Він підтримує моделі у форматі Open Neural Network Exchange (ONNX), який є стандартом представлення моделей машинного навчання. Інференс ONNX Runtime може забезпечити швидший користувацький досвід і знизити витрати, підтримуючи моделі з фреймворків глибокого навчання, таких як PyTorch і TensorFlow/Keras, а також класичні бібліотеки машинного навчання, такі як scikit-learn, LightGBM, XGBoost тощо. ONNX Runtime сумісний з різним обладнанням, драйверами та операційними системами і забезпечує оптимальну продуктивність завдяки використанню апаратних прискорювачів там, де це можливо, поряд із оптимізаціями графа та трансформаціями.

## Що таке генеративний ШІ?
Генеративний ШІ стосується систем ШІ, які можуть створювати новий контент, такий як текст, зображення чи музика, на основі даних, на яких вони були навчені. Прикладами є мовні моделі, як GPT-3, і моделі генерації зображень, як Stable Diffusion. Бібліотека ONNX Runtime для GenAI забезпечує цикл генеративного ШІ для ONNX-моделей, включно з інференсом за допомогою ONNX Runtime, обробкою логітів, пошуком і семплінгом, а також управлінням кешем KV.

## ONNX Runtime для GENAI
ONNX Runtime для GENAI розширює можливості ONNX Runtime, підтримуючи генеративні AI-моделі. Ось кілька ключових функцій:

- **Широка підтримка платформ:** Працює на різних платформах, включно з Windows, Linux, macOS, Android і iOS.
- **Підтримка моделей:** Підтримує багато популярних генеративних моделей, таких як LLaMA, GPT-Neo, BLOOM та інші.
- **Оптимізація продуктивності:** Включає оптимізації для різних апаратних прискорювачів, таких як GPU NVIDIA, GPU AMD та інші.
- **Легкість використання:** Надає API для легкої інтеграції в додатки, дозволяючи генерувати текст, зображення та інший контент з мінімальним кодом.
- Користувачі можуть викликати метод generate() високого рівня або запускати кожну ітерацію моделі у циклі, генеруючи по одному токену за раз і, за бажанням, оновлюючи параметри генерації всередині циклу.
- ONNX Runtime також підтримує жадібний/beam пошук та семплінг TopP, TopK для генерації послідовностей токенів, а також вбудовану обробку логітів, як-от штрафи за повторення. Ви також можете легко додати власну оцінку.

### Запустіть модель: Ось простий приклад на Python:
```Python
import onnxruntime_genai as og

model = og.Model('path_to_your_model.onnx')

tokenizer = og.Tokenizer(model)

input_text = "Hello, how are you?"

input_tokens = tokenizer.encode(input_text)

output_tokens = model.generate(input_tokens)

output_text = tokenizer.decode(output_tokens)

print(output_text) 
```
### Демонстрація: Використання ONNX Runtime GenAI для виклику Phi-3.5-Vision


```python

import onnxruntime_genai as og

model_path = './Your Phi-3.5-vision-instruct ONNX Path'

img_path = './Your Image Path'

model = og.Model(model_path)

processor = model.create_multimodal_processor()

tokenizer_stream = processor.create_stream()

text = "Your Prompt"

prompt = "<|user|>\n"

prompt += "<|image_1|>\n"

prompt += f"{text}<|end|>\n"

prompt += "<|assistant|>\n"

image = og.Images.open(img_path)

inputs = processor(prompt, images=image)

params = og.GeneratorParams(model)

params.set_inputs(inputs)

params.set_search_options(max_length=3072)

generator = og.Generator(model, params)

while not generator.is_done():

    generator.compute_logits()
    
    generator.generate_next_token()

    new_token = generator.get_next_tokens()[0]
    
    output = tokenizer_stream.decode(new_token)
    
    print(tokenizer_stream.decode(new_token), end='', flush=True)

```
