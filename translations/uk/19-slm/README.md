# Вступ до малих мовних моделей для генеративного ШІ для початківців
Генеративний ШІ — це захоплююча галузь штучного інтелекту, що зосереджується на створенні систем, здатних генерувати новий контент. Цей контент може варіюватися від тексту та зображень до музики та навіть цілих віртуальних середовищ. Одним із найцікавіших застосувань генеративного ШІ є область мовних моделей.

## Що таке малі мовні моделі?

Мала мовна модель (SLM) представляє собою зменшену версію великої мовної моделі (LLM), яка використовує багато архітектурних принципів та технік LLM, водночас має значно зменшене обчислювальне навантаження.

SLM — це підмножина мовних моделей, розроблених для генерації тексту, схожого на людський. На відміну від своїх більших аналогів, таких як GPT-4, SLM є більш компактними та ефективними, що робить їх ідеальними для застосувань із обмеженими обчислювальними ресурсами. Незважаючи на менший розмір, вони все ще можуть виконувати різноманітні завдання. Зазвичай SLM створюють шляхом стиснення або дистиляції LLM, прагнучи зберегти значну частину функціональності та мовних здібностей оригінальної моделі. Зменшення розміру моделі знижує загальну складність, роблячи SLM більш ефективними як з точки зору використання пам’яті, так і обчислювальних вимог. Попри ці оптимізації, SLM все ще можуть виконувати широкий спектр завдань обробки природної мови (NLP):

- Генерація тексту: створення зв’язних і контекстуально релевантних речень або абзаців.
- Завершення тексту: передбачення та доповнення речень на основі заданого підказки.
- Переклад: конвертація тексту з однієї мови на іншу.
- Резюмування: скорочення довгих текстів до коротших, легших для сприйняття резюме.

Звичайно, з певними компромісами у продуктивності або глибині розуміння у порівнянні з їх більшими аналогами.

## Як працюють малі мовні моделі?
SLM навчаються на величезних обсягах текстових даних. Під час навчання вони вивчають закономірності та структури мови, що дозволяє генерувати текст, який є граматично правильним і контекстуально відповідним. Процес навчання включає:

- Збір даних: отримання великих наборів текстів із різних джерел.
- Попередня обробка: очищення та організація даних для придатності до навчання.
- Навчання: використання алгоритмів машинного навчання для навчання моделі розуміти та генерувати текст.
- Тонке налаштування: коригування моделі для поліпшення її роботи у конкретних завданнях.

Розробка SLM відповідає зростаючій потребі в моделях, які можна застосовувати у середовищах із обмеженими ресурсами, таких як мобільні пристрої або платформі edge computing, де повноцінні LLM можуть бути непрактичними через великі вимоги до ресурсів. Зосереджуючись на ефективності, SLM знаходять баланс між продуктивністю та доступністю, забезпечуючи ширше застосування у різних сферах.

## Відмінності між великими мовними моделями (LLM) і малими мовними моделями (SLM)

І LLM, і SLM базуються на фундаментальних принципах ймовірнісного машинного навчання, мають подібні підходи в архітектурі, методах навчання, процесах генерації даних та техніках оцінювання моделей. Проте кілька ключових факторів відрізняють ці два типи моделей.

## Застосування малих мовних моделей

SLM мають широкий спектр застосувань, включно з:

- Чатботи: надання підтримки клієнтам та взаємодія з користувачами у форматі діалогу.
- Створення контенту: допомога письменникам у генеруванні ідей або навіть чернеток цілих статей.
- Освіта: допомога студентам у написанні робіт чи вивченні нових мов.
- Доступність: створення інструментів для людей з інвалідністю, наприклад систем текст-в-мову.

**Розмір**
  
Основною відмінністю між LLM і SLM є масштаб моделей. LLM, такі як ChatGPT (GPT-4), можуть містити приблизно 1,76 трильйона параметрів, тоді як відкриті SLM, такі як Mistral 7B, мають значно меншу кількість параметрів — близько 7 мільярдів. Це розходження пояснюється насамперед різницею в архітектурі моделі та процесах навчання. Наприклад, ChatGPT використовує механізм самоуваги в рамках енкодер-декодерної структури, тоді як Mistral 7B застосовує увагу зі зсувним вікном, що дозволяє ефективніше навчати модель тільки-декодер. Ця архітектурна відмінність має значний вплив на складність і продуктивність моделей.

**Розуміння**

SLM зазвичай оптимізовані для продуктивності у певних доменах, що робить їх високо спеціалізованими, але потенційно обмеженими у здатності надавати широкий контекстуальний аналіз у різних сферах знань. На противагу цьому, LLM прагнуть імітувати інтелект, подібний до людського, на більш комплексному рівні. Навчені на великих, різноманітних наборах даних, LLM добре працюють у багатьох сферах, забезпечуючи більшу універсальність і адаптивність. Тому LLM більше підходять для ширшого кола завдань, таких як обробка природної мови та програмування.

**Обчислювальні ресурси**

Навчання і розгортання LLM є ресурсомісткими процесами, які часто вимагають значної обчислювальної інфраструктури, включно з великими кластерами GPU. Наприклад, навчання моделі на кшталт ChatGPT з нуля може потребувати тисячі GPU протягом тривалого часу. На противагу цьому, SLM, завдяки меншій кількості параметрів, є більш доступними за обчислювальними ресурсами. Моделі на зразок Mistral 7B можна тренувати і запускати на локальних комп’ютерах із помірними GPU можливостями, хоча навчання все одно вимагає кількох годин на кількох GPU.

**Упередження**

Упередження є відомою проблемою LLM, переважно через природу тренувальних даних. Ці моделі часто покладаються на сирі, відкрито доступні дані з інтернету, які можуть недопредставляти або спотворювати певні групи, містити помилкові позначки або відображати мовні упередження, пов’язані з діалектом, географічними відмінностями та граматичними правилами. До того ж складність архітектури LLM може непередбачено посилювати упередження, що іноді залишається непоміченим без ретельного тонкого налаштування. Натомість SLM, будучи навчені на більш обмежених, доменно-специфічних наборах даних, за своєю природою менш вразливі до таких упереджень, хоча і не є повністю захищеними від них.

**Висновки**

Менший розмір SLM дає їм значну перевагу в швидкості висновку, дозволяючи ефективно генерувати результати на локальному обладнанні без потреби у великому паралельному обчисленні. У порівнянні, LLM через свій розмір і складність часто вимагають значних паралельних обчислювальних ресурсів для досягнення прийнятного часу відповіді. Наявність одночасних користувачів додатково уповільнює час відповіді LLM, особливо при масштабному розгортанні.

Підсумовуючи, хоча і LLM, і SLM спираються на основи машинного навчання, вони значно відрізняються за розміром моделі, вимогами до ресурсів, контекстуальним розумінням, схильністю до упереджень і швидкістю висновку. Ці відмінності відображають їх придатність до різних випадків використання: LLM є більш універсальними, але ресурсомісткими, а SLM пропонують більш доменно-специфічну ефективність із меншими обчислювальними вимогами.

## Ознайомлення з сімейством Phi-3 / Phi-3.5

Сімейство Phi-3 / 3.5 головним чином орієнтоване на текстові, візуальні та агентські (MoE) сценарії застосування:

### Phi-3 / 3.5 Instruct

Головним чином для генерації тексту, завершення чату, вилучення інформації з контенту тощо.

**Phi-3-mini**

Мовна модель на 3,8 млрд параметрів доступна на Microsoft Foundry, Hugging Face і Ollama. Моделі Phi-3 значно перевершують мовні моделі такого ж або більшого розміру за ключовими бенчмарками (див. нижче цифри — вищі кращі). Phi-3-mini перевершує моделі вдвічі більшого розміру, а Phi-3-small та Phi-3-medium — більші моделі, включно з GPT-3.5.

**Phi-3-small & medium**

З усього 7 млрд параметрів, Phi-3-small переважає GPT-3.5T за різними мовними, логічними, кодувальними та математичними тестами.

Phi-3-medium із 14 млрд параметрів продовжує цю тенденцію й перевершує Gemini 1.0 Pro.

**Phi-3.5-mini**

Можна вважати його оновленням Phi-3-mini. Хоча кількість параметрів не змінилася, покращено підтримку кількох мов (понад 20 мов: арабська, китайська, чеська, данська, нідерландська, англійська, фінська, французька, німецька, іврит, угорська, італійська, японська, корейська, норвезька, польська, португальська, російська, іспанська, шведська, тайська, турецька, українська) і додано потужнішу підтримку довгого контексту.

Phi-3.5-mini з 3,8 млрд параметрів перевершує мовні моделі такого ж розміру і на рівні з моделями вдвічі більшого розміру.

### Phi-3 / 3.5 Vision

Модель Instruct Phi-3/3.5 можна розглядати як здатність Phi розуміти, а Vision дає Phi "очі", щоб розуміти світ.


**Phi-3-Vision**

Phi-3-vision, з усього 4,2 млрд параметрів, продовжує цю тенденцію і перевершує більші моделі, такі як Claude-3 Haiku та Gemini 1.0 Pro V, у завданнях загального візуального мислення, OCR, а також розумінні таблиць і діаграм.


**Phi-3.5-Vision**

Phi-3.5-Vision також є оновленням Phi-3-Vision, додає підтримку кількох зображень. Можна вважати це поліпшенням зору — можна бачити не лише картинки, а й відео.

Phi-3.5-vision перевершує більші моделі, такі як Claude-3.5 Sonnet і Gemini 1.5 Flash, у завданнях OCR, розумінні таблиць і діаграм, і відповідає їм у завданнях загального візуального мислення. Підтримує мультифреймовий вхід, тобто виконує мислення на основі кількох вхідних зображень.


### Phi-3.5-MoE

***Mixture of Experts (MoE)*** дозволяє моделі бути попередньо навченими з набагато меншими обчислювальними витратами, що означає, що ви можете значно масштабувати розмір моделі або набору даних, маючи той самий обчислювальний бюджет, що й для щільної моделі. Зокрема, модель MoE повинна досягати такої самої якості, як і її щільний аналог, набагато швидше під час попереднього навчання.

Phi-3.5-MoE складається з 16 модулів експертів по 3,8 млрд параметрів. Phi-3.5-MoE з усього 6,6 млрд активних параметрів досягає рівня мислення, розуміння мови та математики, як значно більші моделі.

Ми можемо використовувати моделі сімейства Phi-3/3.5 для різних сценаріїв. На відміну від LLM, можна розгорнути Phi-3/3.5-mini або Phi-3/3.5-Vision на периферійних пристроях (edge devices).

### Запуск Phi-3/3.5 локально
Інференс щодо Phi-3 або будь-якої мовної моделі, як GPT-3, означає процес генерації відповідей чи прогнозів на основі поданого вводу. Коли ви надаєте запит або питання Phi-3, модель використовує свою навчальну нейронну мережу для виведення найбільш ймовірної та релевантної відповіді, аналізуючи патерни та взаємозв’язки у навчальних даних.

**Hugging Face Transformer**
Hugging Face Transformers — це потужна бібліотека, розроблена для обробки природної мови (NLP) та інших задач машинного навчання. Основні моменти про неї:

1. **Попередньо навчени моделі**: Вона пропонує тисячі попередньо навчених моделей для різних задач, таких як класифікація тексту, розпізнавання іменованих сутностей, відповідь на запитання, сумаризація, переклад і генерація тексту.

2. **Інтероперабельність фреймворків**: Бібліотека підтримує декілька фреймворків глибинного навчання, зокрема PyTorch, TensorFlow і JAX. Це дозволяє тренувати модель у одному фреймворку та використовувати її в іншому.

3. **Мультимодальні можливості**: Крім NLP, Hugging Face Transformers підтримує завдання комп’ютерного зору (наприклад, класифікація зображень, виявлення об’єктів) і аудіообробки (наприклад, розпізнавання мовлення, класифікація аудіо).

4. **Легкість використання**: Бібліотека пропонує API і інструменти для простого завантаження та тонкого налаштування моделей, роблячи її доступною як для початківців, так і для експертів.

5. **Спільнота та ресурси**: Hugging Face має активну спільноту та велику документацію, навчальні матеріали та посібники, які допомагають користувачам почати роботу та максимально ефективно використовувати бібліотеку.

**ONNX Runtime для GenAI**

[ONNX Runtime](https://github.com/microsoft/onnxruntime-genai?WT.mc_id=academic-105485-koreyst) — це кросплатформенний прискорювач інференсу та тренування моделей машинного навчання. ONNX Runtime для Generative AI (GENAI) — це потужний інструмент, що допомагає ефективно запускати генеративні AI-моделі на різних платформах.

## Що таке ONNX Runtime?
ONNX Runtime — це проект з відкритим кодом, який забезпечує високопродуктивний інференс моделей машинного навчання. Він підтримує моделі у форматі Open Neural Network Exchange (ONNX), який є стандартом для подання моделей машинного навчання. ONNX Runtime інференс може забезпечити швидший досвід користувача і зменшення витрат, підтримуючи моделі з фреймворків глибинного навчання, таких як PyTorch і TensorFlow/Keras, а також класичних бібліотек машинного навчання, як scikit-learn, LightGBM, XGBoost тощо. ONNX Runtime сумісний з різним апаратним забезпеченням, драйверами та операційними системами, і надає оптимальну продуктивність, використовуючи апаратні прискорювачі там, де це можливо, поряд із оптимізаціями та трансформаціями графів.

## Що таке Generative AI?
Генеративний AI відноситься до систем штучного інтелекту, які можуть генерувати новий контент, такий як тексти, зображення або музику, на основі даних, на яких вони були натреновані. Прикладами є мовні моделі, як GPT-3, і моделі генерації зображень, як Stable Diffusion. ONNX Runtime для GenAI надає цикл генеративного AI для моделей ONNX, включаючи інференс з ONNX Runtime, обробку логітів, пошук і семплювання, а також керування кешем KV.

## ONNX Runtime для GENAI
ONNX Runtime для GENAI розширює можливості ONNX Runtime для підтримки генеративних AI-моделей. Ось деякі ключові особливості:

- **Широка підтримка платформ:** Працює на різних платформах, включно з Windows, Linux, macOS, Android і iOS.
- **Підтримка моделей:** Підтримує багато популярних генеративних AI-моделей, таких як LLaMA, GPT-Neo, BLOOM та інші.
- **Оптимізація продуктивності:** Включає оптимізації для різних апаратних прискорювачів, як NVIDIA GPU, AMD GPU тощо.
- **Легкість використання:** Надає API для простої інтеграції в застосунки, дозволяючи генерувати текст, зображення та інший контент з мінімумом коду.
- Користувачі можуть викликати високорівневий метод generate() або запускати кожну ітерацію моделі в циклі, генеруючи по одному токену та за потреби оновлюючи параметри генерації всередині циклу.
- ONNX runtime також підтримує жадібний/променевий пошук (greedy/beam search) та семплювання TopP, TopK для генерації послідовностей токенів, а також вбудовану обробку логітів, як наприклад штрафи за повтори. Ви також можете легко додавати власне оцінювання.

### Запустіть модель: Ось простий приклад на Python:
```Python
import onnxruntime_genai as og

model = og.Model('path_to_your_model.onnx')

tokenizer = og.Tokenizer(model)

input_text = "Hello, how are you?"

input_tokens = tokenizer.encode(input_text)

output_tokens = model.generate(input_tokens)

output_text = tokenizer.decode(output_tokens)

print(output_text) 
```
### Демонстрація: Використання ONNX Runtime GenAI для виклику Phi-3.5-Vision


```python

import onnxruntime_genai as og

model_path = './Your Phi-3.5-vision-instruct ONNX Path'

img_path = './Your Image Path'

model = og.Model(model_path)

processor = model.create_multimodal_processor()

tokenizer_stream = processor.create_stream()

text = "Your Prompt"

prompt = "<|user|>\n"

prompt += "<|image_1|>\n"

prompt += f"{text}<|end|>\n"

prompt += "<|assistant|>\n"

image = og.Images.open(img_path)

inputs = processor(prompt, images=image)

params = og.GeneratorParams(model)

params.set_inputs(inputs)

params.set_search_options(max_length=3072)

generator = og.Generator(model, params)

while not generator.is_done():

    generator.compute_logits()
    
    generator.generate_next_token()

    new_token = generator.get_next_tokens()[0]
    
    output = tokenizer_stream.decode(new_token)
    
    print(tokenizer_stream.decode(new_token), end='', flush=True)

```
