## Генерація з покращеним пошуком (RAG)

Чатбот на основі LLM обробляє запити користувачів для створення відповідей. Він спроектований бути інтерактивним і спілкуватися з користувачами на широкий спектр тем. Однак його відповіді обмежені контекстом і базовими тренувальними даними. Наприклад, знання GPT-4 охоплюють дату до вересня 2021 року, тобто він не знає про події після цього періоду. Крім того, дані, використані для навчання LLM, виключають конфіденційну інформацію, таку як особисті нотатки або інструкції з продукту компанії.

### Як працюють RAG (Retrieval Augmented Generation)

![малюнок, що показує, як працюють RAG](../../../translated_images/uk/how-rag-works.f5d0ff63942bd3a6.webp?WT.mc_id=academic-105485-koreyst)

Припустимо, ви хочете розгорнути чатбота, який створює тести з ваших нотаток, вам потрібен зв’язок із базою знань. Ось тут на допомогу приходить RAG. RAG працює наступним чином:

- **База знань:** перед пошуком ці документи потрібно завантажити та обробити, зазвичай розбиваючи великі документи на менші частини, перетворюючи їх у текстові ембеддинги та зберігаючи у базі даних.

- **Запит користувача:** користувач ставить питання

- **Пошук:** коли користувач ставить питання, модель ембеддингу отримує релевантну інформацію з бази знань для надання додаткового контексту, який буде включено у запит.

- **Покращена генерація:** LLM покращує свою відповідь на основі отриманих даних. Це дозволяє згенерувати відповідь не тільки на основі попередньо натренованих даних, а й релевантної інформації з доданого контексту. Отримані дані використовуються для доповнення відповідей LLM. Потім LLM повертає відповідь на питання користувача.

![Діаграма, що показує архітектуру RAG](../../../translated_images/uk/encoder-decode.f2658c25d0eadee2.webp?WT.mc_id=academic-105485-koreyst)

RAG поєднує механізм пошуку (retriever) із генератором: запит перетворюється у вектор, порівнюється з індексом документів для пошуку релевантних текстових фрагментів, які потім подаються як контекст LLM, що генерує відповідь. Пошукач і генератор можуть використовувати різні моделі; RAG не потребує трансформера з енкодером-декодером.

Два підходи до реалізації RAG за запропонованою статтею: [Retrieval-Augmented Generation for Knowledge intensive NLP (natural language processing software) Tasks](https://arxiv.org/pdf/2005.11401.pdf?WT.mc_id=academic-105485-koreyst):

- **_RAG-Sequence_**: використання отриманих документів для прогнозування найкращої відповіді на запит користувача

- **RAG-Token**: використання документів для генерації наступного токена, потім отримання їх заново для відповіді на запит користувача

### Чому варто використовувати RAG? 

- **Насиченість інформацією:** забезпечує відповіді текстом, що є актуальними і оновленими. Це покращує продуктивність у завданнях, що залежать від конкретної сфери, через доступ до внутрішньої бази знань.

- Зменшує вигадки, використовуючи **перевірені дані** у базі знань для надання контексту запитам користувачів.

- Це **економічно вигідно**, оскільки дешевше за точне налаштування LLM.

## Створення бази знань

Наш застосунок базується на наших особистих даних, тобто уроці про нейронні мережі з курсу "Штучний інтелект для початківців".

### Векторні бази даних

Векторна база даних, на відміну від традиційних баз, — це спеціалізована база даних, призначена для зберігання, керування та пошуку векторних вбудовувань. Вона зберігає чисельні уявлення документів. Розбивання даних на чисельні ембеддинги полегшує нашій системі ШІ розуміння та обробку даних.

Оскільки LLM мають обмеження на кількість вхідних токенів, ми ділимо документи на частини перед створенням ембеддингів. Коли користувач ставить питання, ембеддинги, найбільш подібні до запиту, визначають релевантні текстові частини, які повертаються з запитом. Розбиття також зменшує кількість токенів, що передаються у LLM, отже може знизити вартість.

Деякі популярні векторні бази даних включають Azure Cosmos DB, Clarifyai, Pinecone, Chromadb, ScaNN, Qdrant та DeepLake. Ви можете створити модель Azure Cosmos DB за допомогою Azure CLI з такою командою:

### Від тексту до ембеддингів

Перед тим, як зберігати наші дані, їх потрібно перетворити у векторні ембеддинги для збереження у базі. Якщо ви працюєте з великими документами або довгими текстами, ви можете розбити їх на частини відповідно до очікуваних запитів. Розбиття можна виконувати на рівні речень або абзаців. Оскільки зміст частини залежить від навколишніх слів, можна додати додатковий контекст, наприклад, заголовок документа або текст перед чи після частини. Розбивання даних можна зробити так:

```python
def split_text(text, max_length, min_length):
    words = text.split()
    chunks = []
    current_chunk = []

    for word in words:
        current_chunk.append(word)
        if len(' '.join(current_chunk)) < max_length and len(' '.join(current_chunk)) > min_length:
            chunks.append(' '.join(current_chunk))
            current_chunk = []

    # If the last chunk didn't reach the minimum length, add it anyway
    if current_chunk:
        chunks.append(' '.join(current_chunk))

    return chunks
```

Після розбиття ми можемо вбудувати наш текст за допомогою різних моделей ембеддингів. Серед моделей, які можна використовувати: word2vec, ada-002 від OpenAI, Azure Computer Vision та багато інших. Вибір моделі залежатиме від мови, типу контенту (текст/зображення/аудіо), розміру вхідних даних, які вона може обробити, і довжини вихідного ембеддингу.

## Пошук і векторний пошук

Коли користувач ставить питання, пошуковик перетворює його у вектор за допомогою енкодера запитів, потім шукає у нашому індексі документів релевантні вектори, пов’язані з введенням. Після цього обидва вектори — і вхідний, і з документів — перетворюються назад у текст і передаються у LLM.

### Пошук

Пошук відбувається, коли система швидко знаходить документи з індексу, які відповідають критеріям. Мета пошуку — отримати документи, які будуть використані для створення контексту і прив’язки LLM до ваших даних.

Існує кілька способів пошуку в нашій базі даних, такі як:

- **Пошук за ключовими словами** — використовується для текстового пошуку

- **Векторний пошук** — перетворює документи з тексту у векторні уявлення за допомогою моделей ембеддингів, дозволяючи виконувати **семантичний пошук** за значенням слів. Пошук здійснюється серед документів, чиї векторні уявлення найближчі до запиту користувача.

- **Гібридний** — комбінація пошуку за ключовими словами та векторного пошуку.

Проблема пошуку виникає, коли у базі немає схожої відповіді на запит — тоді система повертає найкращу інформацію, яку вона може знайти, проте ви можете застосовувати стратегії, наприклад, встановити максимальну відстань релевантності або використовувати гібридний пошук, комбінуючи ключові слова та вектори. У цьому уроці ми використовуватимемо гібридний пошук, поєднання векторного і ключового пошуку. Ми збережемо наші дані у датафреймі з колонками, що містять частини тексту та ембеддинги.

### Векторна схожість

Пошуковик шукатиме у базі знань ембеддинги, які близькі один до одного — найближчих сусідів, оскільки вони відображають схожі тексти. У цьому сценарії, коли користувач надсилає запит, він спочатку вбудовується і потім співставляється з подібними ембеддингами. Найпоширенішою мірою схожості векторів є косинусна схожість, яка базується на куті між двома векторами.

Інші метрики для вимірювання схожості — евклідова відстань, що є прямою лінією між кінцями векторів, та скалярний добуток, який вимірює суму добутків відповідних елементів у двох векторах.

### Індекс пошуку

При здійсненні пошуку нам потрібно будувати індекс пошуку для нашої бази знань перед виконанням пошуку. Індекс зберігатиме наші ембеддинги та швидко знаходитиме найбільш схожі частини навіть у великій базі даних. Ми можемо створити індекс локально за допомогою:

```python
from sklearn.neighbors import NearestNeighbors

embeddings = flattened_df['embeddings'].to_list()

# Create the search index
nbrs = NearestNeighbors(n_neighbors=5, algorithm='ball_tree').fit(embeddings)

# To query the index, you can use the kneighbors method
distances, indices = nbrs.kneighbors(embeddings)
```

### Пересортування результатів (Re-ranking)

Після того, як ви запитали базу, можливо, потрібно відсортувати результати за релевантністю — від найбільш релевантних. ЛЛМ для пересортування використовує машинне навчання, щоб покращити релевантність результатів пошуку, впорядковуючи їх від найрелевантніших. Використовуючи Azure AI Search, пересортування виконується автоматично за допомогою семантичного пересортувальника. Приклад роботи пересортування з найближчими сусідами:

```python
# Find the most similar documents
distances, indices = nbrs.kneighbors([query_vector])

# Print the three most similar documents with their distance to the question
for distance, index in zip(distances[0][:3], indices[0][:3]):
    print(flattened_df['chunks'].iloc[index])
    print(flattened_df['path'].iloc[index])
    print(distance)
```

## Об’єднуємо все разом

Останній крок — додати наш LLM у процес, щоб отримувати відповіді, основані на наших даних. Ми можемо реалізувати це так:

```python
user_input = "what is a perceptron?"

def chatbot(user_input):
    # Convert the question to a query vector
    query_vector = create_embeddings(user_input)

    # Find the most similar documents
    distances, indices = nbrs.kneighbors([query_vector])

    # add documents to query  to provide context
    history = []
    for index in indices[0]:
        history.append(flattened_df['chunks'].iloc[index])

    # combine the history and the user input
    history.append(user_input)

    # create a message object
    messages=[
        {"role": "system", "content": "You are an AI assistant that helps with AI questions."},
        {"role": "user", "content": "\n\n".join(history) }
    ]

    # use the Responses API to generate a response
    response = client.responses.create(
        model="gpt-5-mini",
        max_output_tokens=800,
        input=messages,
        store=False,
    )

    return response.output_text

chatbot(user_input)
```

## Сфери застосування RAG і векторних баз даних

Існує багато різних випадків, де RAG може покращити ваш додаток, наприклад:

- Питання й відповіді: прив’язка даних компанії до чату, який можуть використовувати співробітники для запитань.

- Рекомендаційні системи: створення системи, що підбирає найбільш схожі значення, наприклад, фільми, ресторани тощо.

- Чатбот-сервіси: збереження історії чатів і персоналізація розмов на основі даних користувача.

- Пошук зображень на основі векторних ембеддингів, корисний для розпізнавання зображень і виявлення аномалій.
