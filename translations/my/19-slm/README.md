# စတင်ပါရန် လူငယ်များအတွက် Generative AI အတွက် အသေးစားဘာသာစကားမော်ဒယ်များအကြောင်း နိဒါန်း
Generative AI သည် စနစ်အသစ်များကို ဖန်တီးနိုင်သော စနစ်များကို ဖန်တီးရာတွင် အာရုံစိုက်သော စိတ်ဝင်စားဖွယ် အတုအယောင်ကိရိယာတစ်ခုဖြစ်ပြီး၊ ၎င်းသည် စာသား၊ ပုံရိပ်၊ သီချင်းအပါအဝင် အကြောင်းအရာ အသစ်များ ရေးဆွဲနိုင်သော စနစ်များ ဖြစ်သည်။ Generative AI ၏ အလွန်စိတ်ဝင်စားဖွယ် အသုံးပြုမှုတစ်ခုမှာ ဘာသာစကား မော်ဒယ်များ နယ်ပယ်တွင် ဖြစ်သည်။

## အသေးစားဘာသာစကားမော်ဒယ်များ ဆိုတာဘာလဲ?

အသေးစားဘာသာစကားမော်ဒယ် (SLM) သည် အကြီးစား ဘာသာစကားမော်ဒယ် (LLM) တွေရဲ့ မူကြမ်းသဘော အဆောက်အဦးများနှင့်နည်းစနစ်များကို အသုံးချပြီးလည်း ကွန်ပျူတာ ကွဲပြားမှု လျော့နည်းသည့် မော်ဒယ်တစ်မျိုးဖြစ်သည်။

SLM များသည် လူ့ဘာသာစကားကို ညီကွေ့စွာဖန်တီးပေးနိုင်သော ဘာသာစကားမော်ဒယ်အစုဖြစ်သည်။ GPT-4 ကဲ့သို့ အကြီးစား မော်ဒယ်များနှင့် မတူဘဲ SLM များသည် ပိုမိုသေးငယ်ပြီး ထိရောက်မှုကောင်းမွန်သည်၊ ထိုကြောင့် စနစ်ရင်းမြစ် ကန့်သတ်မှုရှိသည့် ပတ်ဝန်းကျင်များတွင် အသုံးပြုနိုင်ရန် သင့်လျော်သည်။ မော်ဒယ်၏ အရွယ်အစား သေးသည်ကိုဖြစ်စေ၊ သူတို့သည် စာသား ဆန်ဆန် ရေးသားမှု၊ စာအုပ်ပြည့်အတည်ပြုမှုများကဲ့သို့သော အများအပြားအလုပ်များ ပြုလုပ်နိုင်သည်။ ယေဘုယျအားဖြင့် SLM များကို LLM များအတွက် compress သို့မဟုတ် distill လုပ်ခြင်းဖြင့် ပြုလုပ်ပြီး မူရင်းမော်ဒယ်၏ လုပ်ဆောင်ချက်များနှင့် ဘာသာစကားစွမ်းရည်များ အများစုကို ထိန်းသိမ်းရန် ကြိုးပမ်းသည်။ ဒီလျော့နည်းမှုကြောင့် မော်ဒယ်၏ စုစုပေါင်းရှုပ်ထွေးမှု လျော့သွားပြီး၊ ဒါဟာ ဂေဟာသတိပေးမှုနဲ့ ကွန်ပျူတာလိုအပ်ချက်များနှင့် ပတ်သက်လို့ ထိရောက်မှု ပိုများစေပါတယ်။ ထိုသို့ တိုးတက်မှုများရှိသောနောက်လည်း SLM များသည် သဘာဝဘာသာစကား တိုက်တွန်းခြင်း (NLP) အလုပ်များစွာ ပြုလုပ်နိုင်သည်။

- စာသား ဖန်တီးခြင်း: သက်ဆိုင်ရာပြီးပြတ်သော ဝေါဟာရနဲ့ စာကြောင်းသို့မဟုတ် ပုဒ်မများ ဖန်တီးခြင်း။
- စာသား ပြည့်စုံခြင်း: ပိုမိုထားသော စာကြောင်းများကို ခန့်မှန်းပြီး ပြည့်စုံစွာ အပြီးသတ်ပေးခြင်း။
- ဘာသာပြန်ခြင်း: တစ်ဘာသာစကားမှ နောက်တစ်ဘာသာစကားသို့ စာသား ကိုပြောင်းလဲခြင်း။
- အကျဉ်းချုပ်ခြင်း: ကြီးမားသော အကြောင်းအရာများကို ပုတီးလေးပြီး ဆက်နွယ်သော အကျဉ်းချုပ်များ ဖန်တီးခြင်း။

ထိုအချိန် အလားအလာများတွင် ပိုမိုကြီးမားသော မော်ဒယ်များနှင့် နှိုင်းယှဉ်ပါက စွမ်းဆောင်ရည် သို့မဟုတ် နက်နဲသိမြင်မှုတွင် တချို့ စွန့်ပစ်မှုများ ဖြစ်ပေါ်နိုင်သည်။

## အသေးစားဘာသာစကားမော်ဒယ်များ ဘယ်လို လုပ်ဆောင်ကြသလဲ?
SLM များကို စာသား ဒေတာ များစွာနှင့် သင်ကြားပေးသည်။ သင်ကြားစဉ်တွင် ဘာသာစကား၏ ပုံစံများနှင့် ဖွဲ့စည်းမှုများကို သင်ယူကာ သဒ္ဒါဝင်သည့်နှင့် ရိုးရှင်းသည့် စာသားများ ဖန်တီးနိုင်ရန် တတ်မြောက်လာသည်။ သင်ကြားမှု လုပ်ငန်းစဉ်တွင် အောက်ပါ အချက်များ ပါဝင်သည်-

- ဒေတာ စုဆောင်းခြင်း: အကြောင်းအရာ စာသား များကို အမျိုးမျိုးသော အရင်းအမြစ်များမှ စုဆောင်းခြင်း။
- ကြိုတင် စစ်ဆေးခြင်း: သင်ကြားရန် သင့်တော်သော စနစ်ဖြင့် ဒေတာများကို သန့်ရှင်းတည်းဖြတ် စီမံခြင်း။
- သင်ကြားခြင်း: မော်ဒယ်အား စာသား နားလည်ခြင်းနှင့် ဖန်တီးနိုင်ရန် စက်ရုပ်သင်ယူနည်းများ အသုံးပြု၍ သင်ကြားခြင်း။
- အဆင့်မြှင့်တင်ခြင်း: သတ်မှတ်ထားသော အလုပ်များတွင် စွမ်းဆောင်ရည် တိုးတက်အောင် မော်ဒယ်ကို ပြင်ဆင်ခြင်း။

SLM များထွက်ရှိလာခြင်းသည် အပြည့်အစုံ LLM များကို အသုံးပြုရန် မဖြစ်နိုင်သည့် မိုဘိုင်း စက်ပစ္စည်းများ သို့မဟုတ် edge computing ပလက်ဖောင်းများကဲ့သို့ အရင်းအမြစ်ကန့်သတ်ခံရသော ပတ်ဝန်းကျင်များတွင် မော်ဒယ်များအသုံးပြုနိုင်ရန် လိုအပ်ချက်တိုးနေလို့ ဖြစ်သည်။ ထိရောက်မှုကို ဦးစားပေး၍ SLM များသည် စွမ်းဆောင်ရည်နဲ့ လက်လီဝယ်ယူမှုအကျိုးအမြတ်တို့ကို ထိန်းညှိနိုင်ပြီး နယ်ပယ်အမျိုးမျိုးတွင် အသုံးချနိုင်ခြင်း ပို၍ ကျယ်ပြန့်စေသည်။

## သင်ယူရမည့် ရည်ရွယ်ချက်များ

ဒီသင်ခန်းစာတွင် SLM ကို နားလည်မှု ပေးပြီး Microsoft Phi-3 နှင့်ပေါင်းစပ်ကာ စာသားအကြောင်းအရာ၊ မြင်ကွင်း နှင့် MoE တွင် အခြေအနေ အမျိုးမျိုးသင်ယူပါမည်။

သင်ခန်းစာပြီးဆုံးသောအခါတွင် အောက်ပါမေးခွန်းများကို ဖြေဆိုနိုင်ရမည် ဖြစ်သည်-

- SLM ဆိုတာဘာလဲ?
- SLM နဲ့ LLM တွေကြား有什么ကြာခြားချက်ရှိသလဲ?
- Microsoft Phi-3/3.5 မိသားစု ဆိုတာဘာလဲ?
- Microsoft Phi-3/3.5 မိသားစုနဲ့ inference ကို ဘယ်လို လုပ်မလဲ?

အသင့်ဖြစ်ပါသလား? စတင်ကြပါစို့။

## အကြီးစားဘာသာစကားမော်ဒယ်များ (LLMs) နှင့် အသေးစားဘာသာစကားမော်ဒယ်များ (SLMs) ကြားက ကွဲပြားချက်များ

LLMs နှင့် SLMs နှစ်မျိုးစလုံးသည် အခြေခံ နယ်ပယ်များဖြင့် probabilities စက်ရုပ်သင်ကြားနည်းဖြင့် တည်ဆောက်ပြီး၊ ဆောက်လုပ်ပုံ၊ သင်ကြားမှု နည်းလမ်းများ၊ ဒေတာ ဖန်တီးခြင်း လုပ်ငန်းစဉ်များနှင့် မော်ဒယ် ဖော်သိမှုနည်းလမ်းများတွင် ဆင်တူပုံစံဖြင့် လုပ်ဆောင်သည်။ သို့သော် သတ်မှတ်ချက်အချို့က ဒီနှစ် မော်ဒယ် များကို ခွဲခြားစေသည်။

## အသေးစားဘာသာစကားမော်ဒယ်များ၏ အသုံးချမှုများ

SLM များတွင် အောက်ပါအသုံးချမှုများ ပါဝင်သည်။

- Chatbots: ဖောက်သည်များကို အကորအခဲပေးရန် နှင့် အသုံးပြုသူများနှင့် စကားပြော ဆက်ဆံရန်။
- အကြောင်းအရာ ဖန်တီးခြင်း: စာရေးသူများကို အကြံဉာဏ်များဖြင့် အကူအညီပေးခြင်း သို့မဟုတ် ဆောင်းပါးများ စာကြမ်းရေးခြင်း။
- ပညာရေး: ကျောင်းသားများက ရေးသားခြင်း အလုပ်များ သို့မဟုတ် ဘာသာအသစ်များ သင်ယူနိုင်ရန် အကူအညီပေးခြင်း။
- လက်လံခန်းမှတဆင့် အသုံးပြုသူများ: မတတ်နိုင်သူများအတွက် စာသားမှ အသံသို့စနစ်များ ဖန်တီးခြင်း။

**အရွယ်အစား**
  
LLMs နဲ့ SLMs ကြား အဓိကကွဲပြားချက် တစ်ခုမှာ မော်ဒယ်အရွယ်အစားဖြစ်သည်။ ChatGPT (GPT-4) ကဲ့သို့သော LLMs တွင် ခန့်မှန်းချက်အားဖြင့် 1.76 စာရင်းပြည့် ပရမီတာများ ပါဝင်နိုင်သော်လည်း Mistral 7B ကဲ့သို့သော ဖွင့်လင်း အရင်းအမြစ် SLM များမှာ ပရမီတာ သိန်း ၇ ဘီလီယံ ဝန်းကျင်သာ ပါရှိသည်။ ၎င်းကွဲပြားမှုသည် မော်ဒယ်၏ ဖန်တီးပုံ နှင့် သင်ကြားမှု လုပ်ငန်းစဉ်များ၏ ကွဲပြားချက်များမှ ဖြစ်သည်။ ဥပမာအားဖြင့် ChatGPT သည် encoder-decoder ဖွဲ့စည်းပုံအတွင်း self-attention စနစ်ကို အသုံးပြုသော်လည်း Mistral 7B သည် decoder only မော်ဒယ်ဖြစ်ပေမယ့် sliding window attention ကို အသုံးပြုကာ ထိရောက်စွာ သင်ကြားနိုင်စေသည်။ ဒီဖွဲ့စည်းပုံကွဲပြားမှုက မော်ဒယ်၏ ရှုပ်ထွေးမှုနှင့် စွမ်းဆောင်ရည်တွေမှာ ထိရောက်မှု မှီခိုနိုင်စေသည်။

**နားလည်မှု**

SLM များသည် ပိုမိုအထူးပြု ပိုင်းများအတွင်း ထိရောက်မှုအတွက် တိုက်ရိုက် တိုးတက်အောင်ပြုလုပ်ထားသောကြောင့်၊ နယ်ပယ်အမျိုးမျိုးတွင် ကျယ်ပြန့်သည့် ဘာသာရပ်နားလည်မှု ပေးနိုင်မှု ကန့်သတ်ခြင်းရှိတတ်သည်။ LLMs သည် မြန်မာဘာသာများစွာဖြင့် သင်ကြား၍ လူ့အသိပညာနှင့် ရိုက်နှိပ်မှုရှိသော ပိုမိုကျယ်ပြန့်သော လုပ်ဆောင်မှုများသို့ မော်ဒယ်တစ်ခုလုံးဖြစ်စေလိုသည်။ ဒေတာ များစွာနှင့် မတူညီသော အကြောင်းအရာများဆီမှ သင်ကြားခဲ့သောကြောင့် LLMs သည် နယ်ပယ်အမျိုးမျိုးများတွင် အကောင်းဆုံးလုပ်ဆောင်နိုင်ပြီး ချေးတင်ရန်စွမ်းဆောင်မှု အမျိုးမျိုးရှိသည်။ ထို့ကြောင့် LLM များသည် နောက်ဆက်တွဲ လုပ်ငန်းများဖြစ်သော သဘာဝ ဘာသာစကားဆိုင်ရာ မူလမှုများနှင့် ပရိုဂရမ်ရေးဆွဲမှုများကဲ့သို့သော တိုးတက်မှုများမှာ သက်ဆိုင်မှု ပိုရှိသည်။

**ကွန်ပျူတာ စွမ်းဆောင်ရည်**

LLM မော်ဒယ်များကို သင်ကြားခြင်းနှင့် မော်ဒယ် အသုံးပြုခြင်းသည် အလွန်ကြီးမားသော ကွန်ပျူတာ အရင်းအမြစ်များ လိုအပ်ပြီး ကြီးမားသော GPU ကလပ်တာများ လိုအပ်သည်။ ဥပမာအားဖြင့် ChatGPT ကဲ့သို့ မော်ဒယ်တစ်ခုကို အစမှ စတင် သင်ကြားရန် GPU တစ်သိန်းကျော် သုံးစွဲရမည့် ကြာရှည်သည့် လုပ်ငန်းစဉ်များ လိုသည်။ အခြားတစ်ဖက်တွင် SLM များသည် အရွယ်အစား သေးငယ်ပြီး ကွန်ပျူတာမြို့နယ် အရင်းအမြစ်များ နည်းသော်လည်း ဝင်ရောက်နိုင်သော ကြောင့် ဒေသိယစက်များပေါ်တွင် GPU ထောက်ပံ့မှု ရွေးချယ်ထားသည့် စက်များမှ သင်ကြားနှင့် စစ်ဆေးနိုင်သည်၊ ထိုသို့ သင်ကြားမှုသည့် နည်းလမ်းဖြင့် များစွာသော GPU များဖြင့် ညာထောင့်ကို မလိုအပ်ပေ။

**အလွဲသုံးသပ်ချက်**

LLM မျာ၌ အလွဲသုံးသပ်ချက်သည် သင့်လျော်သောပြဿနာဖြစ်ပြီး သင်ကြားမှုအတွက် အသုံးပြုသော ဒေတာရင်းမြစ်များတွေ့ရှိမှုမှ ဖြစ်သည်။ ဤမော်ဒယ်များသည် အင်တာနက်မှ မူလ ဒေတာများကို ဆန္ဒပြ၍ ယူကြသောကြောင့် အချို့သောအုပ်စုများကို မလုံလောက်စွာသည့်သို့ဖြစ်စေနိုင်သလို၊ မှားယွင်းသော အမှတ်အသားပြုခြင်းများ ဖြစ်ပေါ်စေနိုင်သည်။ ဗျည်းဖြင့် စကားပြော နေရာ၊ ဒေသခံအသံ နှင့် သဒ္ဒါအစီအစဉ်အသစ်များဖြင့် ဖြစ်သော ဘာသာစကား အလွဲအချော်များပါသလည်းဖြစ်သည်။ ထို့အပြင် LLM များ၏ ခပ်သိမ်းဖွဲ့စည်းမှု ရှုပ်ထွေးမှုများက အလွဲသုံးသပ်မှုကို မထိန်းချုပ်နိုင်ဘဲ ကြီးထွားစေနိုင်သည်၊ ထို့ကြောင့် အလေးပြုခြင်း မရှိလျှင် တွင်ရောက်တွန်းတောက် ထွက်လာနိုင်သည်။ အခြားတစ်ဖက်တွင် SLM များသည် ဧရိယာအရ ကိုးကားထားသော ဒေတာများ ဖြင့် သင်ကြားထားသောကြောင့် အရှက်မြင့်မှု ပိုမိုနည်းသည်၊ သို့သော် အလွဲများအတိုင်းမပြီးသေးပါ။

**Inference**

SLM များ၏ ဆေးမျက်နှာပြင်တွင် အရွယ်အစားသေးမှုကြောင့် local hardware ပေါ်တွင် ထုတ်လွှင့်မှု ပြုလုပ်ရာတွင် အလွန်မြန်ဆန်သည့်အားသာချက် ရှိသည်၊ ဤဟာအတွက် ပိုမိုချိတ်ဆက်မှု ဒေတာတင်ပြရန် မလိုအပ်ဘဲ ပြုလုပ်နိုင်သည်။ ယှဉ်ပြိုင်ပြီး LLM များသည် အရွယ်အစားကြီးမှုနှင့် ရှုပ်ထွေးမှုကြောင့် ထုတ်လွှင့်ချိန်မှာ parallel computing ပိုကြီးမားမှုကို တောင်းဆိုင်သည်။ အသုံးပြုသူကျယ်ပြန့်မှု များသော်လည်း LLM များ၏ တုံ့ပြန်မှု အချိန်နှုန်း ကို ဆန့်ကျင်တားဆီးစေသည့်အချက် ဖြစ်သည်။

အကျဉ်းချုပ်အားဖြင့် LLMs နှင့် SLMs နှစ်မျိုးစလုံးမှာ စက်ရုပ်သင်ယူမှု နယ်ပယ်တွင် အခြေခံ အဆောက်အအုံများကို မျှတစွာ အကျုံးဝင်ကြသော်လည်း မော်ဒယ်အရွယ်အစား၊ အရင်းအမြစ် လိုအပ်ချက်၊ နားလည်မှု၊ အလွဲသုံးသပ်မှု ဖွံ့ဖြိုးတိုးတက်မှုနှင့် ထုတ်လွှင့်မှု အချိန်တန်မှုစသည်ဖြင့် ကြီးထွားသောကွဲပြားမှုများ ရှိသည်။ ၎င်းကွဲပြားမှုများသည် အသုံးပြုမှု အမျိုးမျိုးအတွက် ထိပ်သီးသင့်လျော်မှုကို ပြသပြီး LLMs များသည် ပိုမိုကျယ်ပြန့်သော်လည်း အရင်းအမြစ်များ အလွန်လိုအပ်သည်၊ SLMs များက ပြီးပြည့်စုံရန် လျော့နည်းသော ကွန်ပျူတာလိုအပ်ချက်များဖြင့် နယ်ပယ်အထူးပြု ထိရောက်မှု ပေးနိုင်သည်။

***မှတ်ချက်- ဒီသင်ခန်းစာတွင် Microsoft Phi-3 / 3.5 ကို နမူနာအဖြစ် အသုံးပြု၍ SLM များကို မိတ်ဆက်ပါမည်။***

3.8B parameter ရှိသော Phi-3.5-mini သည် အရွယ်အစားတူ မော်ဒယ်များထက် ပိုကောင်းပြီး နှစ်ဆအရွယ်မော်ဒယ်များနှင့် အသင့်တန်း ဆင်တူသည်။

Phi-3/3.5 ၏ Instruct မော်ဒယ်ကို Phi ၏ နားလည်မှု စွမ်းအင်ဟုယူနိုင်ပြီး Vision သည် Phi အမြင်ကို ကမ္ဘာနားလည်ရန် ပေးသည်။

Phi-3-vision သည် 4.2B parameters ဖြင့် ဆက်လက်ပြီး Claude-3 Haiku နှင့် Gemini 1.0 Pro V ကဲ့သို့ ပုံမှန် မြင်ကွင်း သဘောတရား ရှာဖွေရေး၊ OCR နှင့် ဇယား သဘောပေါက်မှု လုပ်ငန်းများတွင် ပိုမိုကောင်းမွန်သည်။


**Phi-3.5-Vision**

Phi-3.5-Vision သည် Phi-3-Vision ၏ ညှိနှိုင်းတိုးတက်မှုဖြစ်ပြီး အမြင်အများအတွက် ပံ့ပိုးမှု ပေါင်းထည့်သည်။ ရှုမြင်ရန် တစ်ပုံပင်သာမက ဗွီဒီယို များနှင့်လည်း ဆက်စပ်သည်။

Phi-3.5-vision သည် Claude-3.5 Sonnet နှင့် Gemini 1.5 Flash ကဲ့သို့ ပိုမိုကြီးမားသော မော်ဒယ်များထက် OCR၊ ဇယား နှင့် ပြဇယား နားလည်မှု အလုပ်များတွင် ပိုမိုကောင်းမွန်ပြီး၊ ပုံမှန် မြင်ကွင်း အသိပညာ နားလည်မှု လုပ်ငန်းများတွင် တန်းတူသောစွမ်းဆောင်ရည် ရှိသည်။ ကြာရှည် ပုံစံ ပေးပို့မှုများကို ထောက်ပံ့သည်၊ များစွာသော ပုံများပါဝင်သည့် Input တွင် စိတ်ခေါ်စွမ်းဆောင်နိုင်သည်။


### Phi-3.5-MoE

***Mixture of Experts (MoE)*** မှ စွမ်းဆောင်ရည် သာမာန် တွေထက် လျော့နည်းစွာ ကြေးစိုင် အသုံးပြု၍ မော်ဒယ် သို့မဟုတ် ဒေတာအရွယ်အစားကို အလွန်တိုးမြှင့်နိုင်ရန် ခွင့်ပြုသည်။ အထူးသဖြင့် MoE မော်ဒယ်များသည် Dense Model ဖြစ်သော မော်ဒယ်နှင့် ယှဉ်တွဲသင်ကြားမှု အရည်အသွေး ကို ပိုမိုအရှိန်မြန်စေသည်။

Phi-3.5-MoE သည် 16x3.8B ထူးချွန်သမား မော်ဂျူးများ ပါဝင်သည်။ Phi-3.5-MoE သည် 6.6B လှုပ်ရှားသည့် parameter များသာ ပါရှိပြီး ပိုမိုကြီးမားသော မော်ဒယ်များနှင့်တူညီသည့် အာရုံစူးစိုက်မှု၊ ဘာသာစကား နားလည်မှုနှင့် သင်္ချာမှု တန်းတူ အောင် စွမ်းဆောင်နိုင်သည်။

အသုံးအဆောင် ဘာသာရပ်အမျိုးမျိုးအရ Phi-3/3.5 မိသားစု မော်ဒယ်များကို အသုံးပြုနိုင်သည်။ LLM များဆီမှ မတူဘဲ Phi-3/3.5-mini သို့မဟုတ် Phi-3/3.5-Vision များကို edge devices ပေါ်တွင် တပ်ဆင်အသုံးပြုနိုင်သည်။

**NVIDIA NIM**

cloud-based Microsoft Foundry Models အညွှန်းအပြင် [NVIDIA NIM](https://developer.nvidia.com/nim?WT.mc_id=academic-105485-koreyst) ကိုလည်း အသုံးပြု၍ သက်ဆိုင်ရာ ခေါ်ယူမှုများ ပြုလုပ်နိုင်သည်။ NVIDIA NIM (NVIDIA Inference Microservices) သည် developer များအား မတူညီသော ပတ်ဝန်းကျင်များ၌ AI မော်ဒယ်များ အဆင်ပြေစွာ တပ်ဆင်အသုံးပြုခြင်း အတွက် ဖြည့်စွက်အမြန် inference microservices အစုအဝေးဖြစ်သည်။ ၎င်းမှာ cloud များ၊ data center များနှင့် workstation များတွင် အသုံးပြုရန် ရည်ရွယ်သည်။

NVIDIA NIM ၏ အဓိက အင်္ဂါရပ်များမှာ-

- **တပ်ဆင်ရလွယ်ကူမှု:** NIM သည် AI မော်ဒယ်များကို တစ်ချက်တည်းသော command ဖြင့် တပ်ဆင်နိုင်စေပြီး ရှိပြီးသား လုပ်ငန်းစဉ်များနှင့် ပေါင်းစည်းနိုင်ရန် စနစ်တကျ ဖြစ်သည်။
- **စွမ်းဆောင်ရည် မာန်မာန်မှု:** TensorRT နှင့် TensorRT-LLM ကဲ့သို့ NVIDIA ၏ အကြိုတည်းနှိမ့် ခေါ်ယူ စက်များကို အသုံးပြုကာ စွမ်းဆောင်ရည် တောက်ပစေသည်။
- **အတိုင်းအတာချဲ့ထွင်နိုင်မှု:** NIM သည် Kubernetes တွင် autoscaling ကို ပံ့ပိုးကာ အလုပ်ရှုပ်မှု အမျိုးမျိုးကို ထိရောက်စွာ ကူညီနိုင်သည်။
- **လုံခြုံရေးနှင့် ထိန်းချုပ်မှု:** အဖွဲ့အစည်းများသည် NIM microservices ကို ကိုယ်ပိုင်စနစ်တစ်ခုအတွင်း ကိုယ်တိုင် ထိန်းချုပ်နိုင်သည်။
- **စံချိန်တော် API များ:** NIM သည် စက်မှုလုပ်ငန်းစံချိန် API များကို ပေးဆောင်ပြီး၊ chatbots၊ AI အကူအညီများနှင့် အခြား AI ဆိုင်ရာလျှောက်လွှာများကို တည်ဆောက်ရန်နှင့် ပေါင်းစည်းရန် အလွယ်တကူဖြစ်စေပါသည်။

NIM သည် NVIDIA AI Enterprise ၏ အစိတ်အပိုင်းဖြစ်ပြီး၊ AI မော်ဒယ်များကို တပ်ဆင်ခြင်းနှင့် လည်ပတ်မှု လွယ်ကူစေရန် ရည်ရွယ်ကာ NVIDIA GPU များတွင် ထိရောက်စွာ လည်ပတ်စေရန် အာမခံပေးပါသည်။

### Phi-3/3.5 ကို တိုင်းတာစမ်းသပ်ခြင်း
Phi-3 သို့မဟုတ် GPT-3 ကဲ့သို့သော ဘာသာစကားမော်ဒယ်တစ်ခုနှင့် ပတ်သက်သော Inference ဆိုသည်မှာ၊ ၎င်းထံမှ ရရှိသော input အပေါ် မူတည်၍ တုံ့ပြန်ချက်များ သို့မဟုတ် ခန့်မှန်းချက်များ ထုတ်ပေးခြင်းဖြစ်သည်။ သင်သည် Phi-3 သို့ prompt သို့မဟုတ် မေးခွန်းပေးသောအခါ၊ ၎င်းသည် သင်္ကေတများနှင့် ဆက်နွယ်မှုများကို လေ့လာခွင့်ရ neural network ကို အသုံးပြုပြီး အလားအလာရှိ နာမည်နှင့် သင့်လျော်သော တုံ့ပြန်ချက်ကို ခန့်မှန်းပေးသည်။

**Hugging Face Transformer**
Hugging Face Transformers သည် သဘာဝဘာသာစကား ကိုင်တွယ်မှု (NLP) နှင့် အခြား စက်လေ့လာမှု အလုပ်များအတွက် ဖန်တီးထားသော အင်အားကြီးသော စာကြည့်တိုက်တစ်ခုဖြစ်သည်။ ၎င်းအကြောင်း အချက်အချို့မှာ အောက်ပါအတိုင်းဖြစ်သည်။

1. **ကြိုတင်လေ့လာပြီး မော်ဒယ်များ**: စာသားခွဲခြားခြင်း၊ အမည်ရှိ အပိုင်းများသတ်မှတ်ခြင်း၊ မေးခွန်းဖြေရှင်းခြင်း၊ အနှစ်ချုပ်ရေးခြင်း၊ ဘာသာပြန်ခြင်း၊ စာသားဖန်တီးခြင်း စသည်တို့အတွက် အသုံးပြုနိုင်သော ကြိုတင်လေ့လာပြီး မော်ဒယ်များကို သန်းပေါင်းများစွာ ပေးဆောင်သည်။

2. **စနစ်တစ်ခုမှ တစ်ခုသို့ လုပ်ဆောင်နိုင်မှု**: စာကြည့်တိုက်သည် PyTorch၊ TensorFlow၊ JAX စသော နက်နဲသောလေ့လာမှု စနစ်များ အားလုံးကို ပံ့ပိုးပေးသည်။ ၎င်းဧပျိုကို သင်က framework တစ်ခုတွင် မော်ဒယ် လေ့လာသင်ယူပြီး အခြား framework တစ်ခုတွင် အသုံးပြုနိုင်ပါသည်။

3. **အမျိုးမျိုးသော မော်ဒယ်များကို ထောက်ပံ့မှု**: NLP အပြင် Hugging Face Transformers သည် ကွန်ပျူတာမြင်ကွင်း (ဉပမာ- ပုံခွဲခြားခြင်း၊ အရာဝတ္ထု တွေ့ရှိခြင်း) နှင့် အသံများ ရှင်းလင်းခြင်း (ဉပမာ- အသံမှတ်ခြင်း၊ အသံခွဲခြားခြင်း) ဖောက်ထွင်းထောက်ပံ့သည်။

4. **အသုံးပြုရ လွယ်ကူမှု**: စာကြည့်တိုက်သည် မော်ဒယ်များကို လွယ်ကူစွာ ဒေါင်းလုပ်ဆွဲရန်နှင့် ချိန်ညှိရန် API များနှင့် ကိရိယာများကို အသုံးပြုနိုင်စေရန် ပံ့ပိုးပေးသည်။

5. **အသိုင်းအဝိုင်းနှင့် ရင်းမြစ်များ**: Hugging Face သည် အသက်ဝင်သော အသိုင်းအဝိုင်းနှင့် ကျယ်ပြန့်သော စာရွက်စာတမ်းများ၊ တင်ခေါင်းများနှင့် လမ်းညွှန်များကို ပံ့ပိုးကူညီသည့် ပါဝင်သူများအတွက် ရရှိနိုင်သည်။

**ONNX Runtime for GenAI**

[ONNX Runtime](https://github.com/microsoft/onnxruntime-genai?WT.mc_id=academic-105485-koreyst) သည် cross-platform inference နှင့် လေ့လာသင်ယူမှု စက်လေ့လာမှု လျှင်မြန်စွာအလုပ်လုပ်စေသော ကိရိယာတစ်ခုဖြစ်သည်။ ONNX Runtime for Generative AI (GENAI) သည် မော်ဒယ်များကို platform မျိုးစုံပေါ်တွင် ထိရောက်စွာ လည်ပတ်စေသော စွမ်းအားကောင်းသော ကိရိယာဖြစ်သည်။

## ONNX Runtime ဆိုတာဘာလဲ?
ONNX Runtime သည် machine learning မော်ဒယ်များကို အမြန်ဆုံး inference ပြုလုပ်နိုင်စေသော ဖွင့်တောက်ထားသော ပရောဂျက်တစ်ခုဖြစ်သည်။ ၎င်းသည် Open Neural Network Exchange (ONNX) ဖော်မတ်ရှိ မော်ဒယ်များကို ပံ့ပိုးပြီး၊ PyTorch နှင့် TensorFlow/Keras ကဲ့သို့သော နက်နဲသောစက်လေ့လာမှု framework များနှင့် scikit-learn၊ LightGBM၊ XGBoost စသည့် ပုံမှန် machine learning စာကြည့်တိုက်များကိုလည်း ထောက်ပံ့သည်။ ONNX Runtime သည် hardware, driver, operating system မျိုးစုံနှင့် ကိုက်ညီကာ hardware accelerator များအား အသုံးပြုပြီး graph optimization နှင့် transform များပြုလုပ်ခြင်းအားဖြင့် ထိရောက်မှု အကောင်းဆုံးပေးနိုင်သည်။

## Generative AI ဆိုတာဘာလဲ?
Generative AI သည် သင်္ချာမော်ဒယ်များမှ လေ့လာသင်ယူထားသော ဒေတာများအပေါ် အခြေခံကာ စာသား၊ ပုံနှင့် ဂီတကဲ့သို့သော အကြောင်းအရာအသစ်များ ဖန်တီးနိုင်သော AI စနစ်များကို ဆိုလိုသည်။ ဥပမာများထဲတွင် GPT-3 ကဲ့သို့သော ဘာသာစကားမော်ဒယ်များနှင့် Stable Diffusion ကဲ့သို့သော ပုံဖန်တီးမော်ဒယ်များ ပါဝင်သည်။ ONNX Runtime for GenAI စာကြည့်တိုက်သည် ONNX မော်ဒယ်များအတွက် အလားအလာဖန်တီးမှုအကွ loops, inference, logits ကိစ္စများ၊ ရှာဖွေမှုနှင့် အမည့်ပုံ၊ KV cache စီမံခန့်ခွဲမှုနှင့်အတူ ပံ့ပိုးသည်။

## ONNX Runtime for GENAI
ONNX Runtime for GENAI သည် ONNX Runtime ၏ စွမ်းဆောင်ရည်များကို ဖြည့်စွက်ကာ generative AI မော်ဒယ်များအား ထောက်ပံ့ပေးသည်။ အဓိက လက္ခဏာအချို့မှာ အောက်ပါအတိုင်းဖြစ်သည်။

- **အထွေထွေ Platform Support:** Windows, Linux, macOS, Android၊ iOS စသည့် platform မျိုးစုံ၌ လုပ်ဆောင်သည်။
- **မော်ဒယ် ထောက်ပံ့မှု:** LLaMA, GPT-Neo, BLOOM နှင့် နာမည်ကျော် generative AI မော်ဒယ်များ ပါဝင်သည်။
- **စွမ်းဆောင်ရည် တိုးတက်မှု:** NVIDIA GPU, AMD GPU နှင့် အခြား hardware accelerators များအတွက် ညှိနှိုင်းမှုများ ပါသည်။
- **အသုံးပြုရလွယ်ကူမှု:** အလွယ်တကူ API များပေးပြီး ခန့်မှန်းစာသား၊ ပုံများနှင့် အခြား အကြောင်းအရာများကို လွယ်ကူစွာ ဖန်တီးပေးနိုင်သည်။
- အသုံးပြုသူသည် generate() နည်းလမ်းမြင့်ကို ခေါ်နိုင်ပြီး မော်ဒယ်တိုင်းအလုပ်လိုင်းကို loop ဖြင့် ဖော်ဆောင်၍ တစ်ခုချင်းသီးသန့် token များကို ဖန်တီးနိုင်သည်၊ ပြင်ဆင်ချက်များကို loop အတွင်း ပြောင်းလဲရန်လည်း ရနိုင်သည်။
- ONNX runtime တွင် greedy/beam search နှင့် TopP, TopK sampling ဖြင့် token စာရင်းများ ဖန်တီးခြင်းနှင့် ပြန်လည် ထပ်မံ ရေးသားခြင်း အပါအဝင် logits ထိန်းချုပ်မှုကို ထည့်သွင်းပေးထားသည်။ သင့်လိုအပ်ချက်အရ မိမိတိုင် မျှမှတ်ချက်များကိုလည်း လွယ်ကူစွာ ထည့်သွင်းနိုင်သည်။

ONNX Runtime for GENAI နှင့် စတင်လုပ်ဆောင်ရန်အနေဖြင့် အောက်ပါ လမ်းညွှန်များကို လိုက်နာနိုင်ပါသည်။

### ONNX Runtime ကို တပ်ဆင်ပါ:
```Python
pip install onnxruntime
```
### Generative AI Extensions ကိုတပ်ဆင်ပါ:
```Python
pip install onnxruntime-genai
```

### မော်ဒယ်တစ်ခု လည်ပတ်ခြင်း - Python မှာ ရိုးရိုး လေးနမူနာ:
```Python
import onnxruntime_genai as og

model = og.Model('path_to_your_model.onnx')

tokenizer = og.Tokenizer(model)

input_text = "Hello, how are you?"

input_tokens = tokenizer.encode(input_text)

output_tokens = model.generate(input_tokens)

output_text = tokenizer.decode(output_tokens)

print(output_text) 
```
### ပြသချက် - ONNX Runtime GenAI ကို အသုံးပြုပြီး Phi-3.5-Vision ကို ခေါ်ပါ။


```python

import onnxruntime_genai as og

model_path = './Your Phi-3.5-vision-instruct ONNX Path'

img_path = './Your Image Path'

model = og.Model(model_path)

processor = model.create_multimodal_processor()

tokenizer_stream = processor.create_stream()

text = "Your Prompt"

prompt = "<|user|>\n"

prompt += "<|image_1|>\n"

prompt += f"{text}<|end|>\n"

prompt += "<|assistant|>\n"

image = og.Images.open(img_path)

inputs = processor(prompt, images=image)

params = og.GeneratorParams(model)

params.set_inputs(inputs)

params.set_search_options(max_length=3072)

generator = og.Generator(model, params)

while not generator.is_done():

    generator.compute_logits()
    
    generator.generate_next_token()

    new_token = generator.get_next_tokens()[0]
    
    output = tokenizer_stream.decode(new_token)
    
    print(tokenizer_stream.decode(new_token), end='', flush=True)

```
