# ကူညီဆောင်ရွက်ခြင်း

ဒီပရောဂျက်သို့ ကူညီတောင်းဆိုမှုများနှင့် အကြံပြုချက်များကို ကြိုဆိုပါသည်။ မိမိကူညီထည့်သွင်းလိုသောအကြောင်းအရာများအတွက်
Contributor License Agreement (CLA) တစ်ရပ်အပေါ် သဘောတူကြောင်း သက်သေပြရန် လိုအပ်ပြီး၊
မိမိကူညီထည့်သွင်းသောအရာကို ကျွန်ုပ်တို့ အသုံးပြုခွင့်ရှိကြောင်း သက်သေပြရပါမည်။ အသေးစိတ်အချက်အလက်များအတွက်
<https://cla.microsoft.com> တွင် ကြည့်ရှုနိုင်ပါသည်။

> အရေးကြီးပါသည် - ဤ repository တွင် အကြောင်းအရာများ ဘာသာပြန်ရာတွင် စက်ဘာသာပြန်မှု မသုံးစွဲရန် သေချာစေရန် ကျေးဇူးပြုပါ။ ဘာသာပြန်မှုများကို အသိုင်းအဝိုင်းမှ စစ်ဆေးမည်ဖြစ်သောကြောင့် မိမိ ကျွမ်းကျင်သောဘာသာစကားများအတွက်သာ ဘာသာပြန်လှူဒါန်းပေးပါရန် တိုက်တွန်းအပ်ပါသည်။

Pull request တင်သည့်အခါ CLA-bot သည် မိမိ၏ CLA လိုအပ်မှုကို အလိုအလျောက်ဆုံးဖြတ်ပြီး PR ကို သင့်လျော်စွာ အမှတ်အသားပြုလုပ်ပေးမည် (ဥပမာ - အမှတ်အသား၊ မှတ်ချက်) ဖြစ်ပါသည်။ 
အဲဒီ bot ထံမှ ပြောပြချက်များကို လိုက်နာပေးရုံဖြင့်ဖြစ်ပြီး ကျွန်ုပ်တို့ CLA သုံးပြီးသော repository တိုင်းတွင် တစ်ကြိမ်တည်းသာ လုပ်ဆောင်ရမည် ဖြစ်ပါသည်။

အသေးစိတ်အချက်အလက်များအတွက် [Code of Conduct FAQ](https://opensource.microsoft.com/codeofconduct/faq/?WT.mc_id=academic-105485-koreyst) ကိုဖတ်ရှုပါ၊ သို့မဟုတ် [opencode@microsoft.com](mailto:opencode@microsoft.com) သို့ မေးမြန်းရန် သို့မဟုတ် မှတ်ချက်ပေးရန် ဆက်သွယ်နိုင်သည်။

## မေးခွန်း သို့မဟုတ် ပြဿနာရှိပါသလား။

GitHub တွင် ပထမဦးဆုံးပံ့ပိုးမှုဆိုင်ရာ မေးခွန်းများအတွက် issue မဖွင့်ရန် ကျေးဇူးပြုပါ။ GitHub list ကို ပုံစံအသစ် မတင်ဘဲ feature တောင်းဆိုခြင်းနှင့် bug report များအတွက်သာ အသုံးပြုရန် ဖြစ်ပါသည်။ ဤနည်းဖြင့် ကုတ်ကြောင်းမှ ပြဿနာများကို ထောက်လှမ်းစနစ်တကျ ဆောင်ရွက်နိုင်ပြီး အများပြည်သူဆွေးနွေးမှုကို တခြားသီးသန့်ထားနိုင်ပါသည်။

## စာလုံးလွဲ၊ ပြဿနာများ၊ Bugs နှင့် ကူညီထည့်သွင်းမှုများ

Generative AI for Beginners repository တွင် အပြောင်းအလဲတင်သွင်းချိန် အောက်ပါအကြံပြုချက်များကို လိုက်နာပေးပါရန် မေတ္တာရပ်ခံအပ်ပါသည်။

* ဖိုင်ပြင်ဆင်မှုများ ပြုလုပ်မည်ဖြစ်ပါက repository ကို မိမိ၏ အကောင့်သို့ မပြန်လည်ပေါင်းစပ်မီ မျှဝေပေးရန် သေချာစေရန်။
* အပြောင်းအရွှေ့များစုပေါင်း၍ တစ်ခုတည်းသော pull request သို့ မပေးပို့ကြရ။ ဥပမာအားဖြင့်၊ ဘာသာပြန်ချက်များကို ပိုင်းခြားထားသော PR များဖြင့် bug fix နှင့် စာတမ်းများအတွက် သီးခြားလိုက်ပါ
* သင်၏ pull request တွင် merge conflicts တွေ့ပါက၊ မိမိပြင်ဆင်မှုများပြုလုပ်မည်မီ local main ကို main repository မှ ရှိသည့်အရာနှင့် တူညီသော mirror အဖြစ် update လုပ်ထားရန် သေချာစေရန်
* ဘာသာပြန်စာသားတင်သည့်အခါ၊ ဘာသာပြန်ထားသော ဖိုင်များအားလုံးအတွက် PR တစ်ခုသာဖန်တီးပေးပါ၊ အပိုင်းအစလောက်စာဘာသာပြန်များကို လက်ခံမရပါ
* စာလုံးထိုးမှားခြင်း သို့မဟုတ် စာတမ်းအမှားများ အတွက် တစ်ခုသာသော PR တွင် သင့်တော်သည့်အခါ ပေါင်းစပ်ပြင်ဆင်နိုင်ပါသည်

## အယ်ဒီတာလုပ်ငန်းတာဝန်နှင့် တတိယပါတီထုတ်ကုန်များ

ဤသင်ရိုးညွှန်းတမ်းသည် Microsoft နည်းပညာများနှင့် vendor-neutral ကို ဖွင့်လှစ်စံချိန် များအပေါ် ဦးတည်ပြုထားသည်။ စီစဉ်ပေးသည့် အကြောင်းအရာများသည် ပညာရေးရည်ရွယ်ချက် ကြောင်းရှင်းရမည်ဖြစ်ပြီး တတိယပါတီ ရောင်းချပေးသည့် ကုမ္ပဏီ ထုတ်ကုန်သို့မဟုတ် ဝန်ဆောင်မှု၊ မော်ဒယ်မောင်းနှင်ကိရိယာ၊ SDK၊ MCP ဆာဗာ သို့မဟုတ် vendor-specific ပံ့ပိုးချက်တစ်ခုခုကို အဓိကရည်ရွယ်၍ မဖြစ်ရပါ။

ဖွင့်လှစ်မူရင်းဆော့ဖ်ဝဲများနှင့် တတိယပါတီ ဖက်ကူညီမှုများကို ဖွင့်လှစ်စံချိန် သို့မဟုတ် နှစ်ဖက်အလုပ်လုပ်နိုင်မှု အခြေအနေတစ်ခု အဖြစ် ရှင်းပြရာတွင် လိုအပ်ပါကသာ ရည်ညွှန်းနိုင်သည်၊ သာမာန်အားဖြင့် နေရာထားပြသည်၊ vendor ၏ ထုတ်ကုန် သို့မဟုတ် host လုပ်ထားသော အဆုံးအချက် များကို အလယ်မှာထား၍ မဟုတ်ရပါ။ သင်၏ ကမ်းလှမ်းချက်တွင် vendor-specific ထုတ်ကုန် သို့မဟုတ် ဝန်ဆောင်မှု ပါရှိပါက ပြဿနာတစ်ခုဖွင့်၍ မပေးမည့်မတိုင်မှီ သိမ်းဆည်းသူ၏ အတည်ပြုချက်ကို လိုက်နာရမည်။

အကျိုးဝင်သူများသည် မိမိတို့၏ ကမ်းလှမ်းချက်၌ ရည်ညွှန်းထားသည့် ထုတ်ကုန် သို့မဟုတ် ဝန်ဆောင်မှုနှင့်သက်ဆိုင်သော အလုပ်အကိုင်၊ ပိုင်ဆိုင်မှု၊ ပံ့ပိုးမှု သို့မဟုတ် အဖက် affiliation များအား ထုတ်ဖော်ပြသရမည်။ မပံ့ပိုးသော စျေးနှုန်း၊ လုပ်ဆောင်မှု၊ လုံခြုံရေး၊ ကိုယ်ရေးကိုယ်တာ များ သို့မဟုတ် နှိုင်းယှဉ်ချက်များ မထည့်သုံးရ။ အပြေးစမ်း ပြသနိုင်သော ဥပမာများမှာ သင်ယူသူဒေတာများကို ပျံ့နှံ့ပေးခြင်း သို့မဟုတ် ပြင်ပတတိယပါတီ ဝန်ဆောင်မှုမှတဆင့် အများပါဝင်လှုပ်ရှားမှုများကို မပေးခြင်းဖြစ်ရမည်။

## ရေးသားမှုအတွက် အထွေထွေ လမ်းညွှန်ချက်များ

- သင့် URL များအားလုံးကို အနိမ့်ဘောင်မှထင်ဟပ်ထားပြီး အနောက်ကျော၌ ဝိုင်းကွင်းထည့်သွင်းထားသည့် ဆောင်းပါးများနှင့် အချိုးသင့် ချင်း မရှိစေရန် သေချာစေရန်`[]()` ။ 
- စနစ်တကျပိုင်းတွင် relative link များ (ဥပမာ - repository ထဲရှိ အခြားဖိုင်များနှင့် ဖိုလဒါများသို့ ချိတ်ဆက်ရာ များ) တွင် လက်ရှိလုပ်ငန်း directory တွင်တည်ရှိသော ဖိုင် သို့မဟုတ် ဖိုလဒါကို ရည်ညွှန်းသော `./` ဖြင့် သို့မဟုတ် မိမိ၏ parent working directory တွင် တည်ရှိသော ဖိုင် သို့မဟုတ် ဖိုလဒါကို ရည်ညွှန်းသော `../` ဖြင့် စတင်ရန် သေချာစေရန်။
- စနစ်တကျပိုင်းတွင် relative link များတွင် (ဥပမာ - repository ထဲရှိ အခြားဖိုင်များနှင့် ဖိုလဒါများသို့ ချိတ်ဆက်ရာ များ) နောက်ဆုံးတွင် tracking ID ကို သေချာပါရှိရန် (ဥပမာ - `?` သို့မဟုတ် `&` ပြီးနောက် `wt.mc_id=` သို့မဟုတ် `WT.mc_id=`)။
- အောက်ပါ domain များဖြစ်သော _github.com, microsoft.com, visualstudio.com, aka.ms, နှင့် azure.com_ မှ URL များတွင် tracking ID (ဥပမာ - `?` သို့မဟုတ် `&` ပြီးနောက် `wt.mc_id=` သို့မဟုတ် `WT.mc_id=`) ပါရှိသည်ကို သေချာစေရန်။
- မိမိတင်တဲ့ links များတွင် နိုင်ငံအလိုက် locale မပါဝင်စေရန် သေချာပါစေ (ဥပမာ - `/en-us/` သို့မဟုတ် `/en/`)။
- ဓာတ်ပုံများအားလုံးကို `./images` ဖိုလဒါမှာ သိမ်းဆည်းထားရန် သေချာပါစေ။
- ဓာတ်ပုံများအားဖြင့် အမည်တပ်မည့်အခါအင်္ဂလိပ်အက္ခရာများ၊ နံပါတ်များနှင့် ကြောင်းခြားများကို အသုံးပြု၍ ပါရေးရန် သေချာပါစေ။

## GitHub Workflows

သင်သည် pull request တင်သည့်အခါ အောက်ပါ rules များကို အတည်ပြုရန် workflow လေးခုကို ဖွင့်လှစ်ပါလိမ့်မည်။
workflow စစ်ဆေးမှုများကို ဖြတ်သန်းနိုင်ရန် ဒီနေရာမှာ ပါရှိသော အညွှန်းများကို လိုက်နာလိုက်ပါ။

### Check Broken Relative Paths

ဤ workflow သည် မည်သည့် relative path မဆို သင်၏ဖိုင်များထဲမှာ ပုံမှန် လုပ်ဆောင်နိုင်မှု ရှိကြောင်း အာမခံပေးသည်။
ဒီ repository ကို GitHub pages တွင် တင်ထားသည့်အတွက် ချိတ်ဆက်မှုများစာသား မှားယွင်းခြင်းမဖြစ်စေရန် အလွန် ဦးစားပေးဖြစ်ရပါမည်။

မိမိ link များက တိကျမှန်ကန်စွာ လုပ်ဆောင်နေကြောင်း သေချာစေရန် VS code ကို အသုံးပြု၍ စစ်ဆေးပါ။

ဥပမာအားဖြင့် သင်၏ဖိုင်ထဲရှိ link များအပေါ် cursor ကို တင်သောအခါ **ctrl + click** ဖြင့် လမ်းကြောင်းကို လိုက်လံ ရွေးချယ်နိုင်သည်ကို ပြသပါမည်။
