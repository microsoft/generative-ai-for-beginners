# ရယူထည့်သွင်းထားသော မူလတန်းထုတ်လုပ်မှု (RAG) နှင့် ဗက်တာ ဒေတာဘေ့စ်များ

[![ရယူထည့်သွင်းထားသော မူလတန်းထုတ်လုပ်မှု (RAG) နှင့် ဗက်တာ ဒေတာဘေ့စ်များ](../../../translated_images/my/15-lesson-banner.ac49e59506175d4f.webp?WT.mc_id=academic-105485-koreyst)](https://youtu.be/4l8zhHUBeyI?si=BmvDmL1fnHtgQYkL)

ရှာဖွေရေး လျှောက်လွှာသင်ခန်းစာတွင် သင့်အချက်အလက်များကို ကြီးမားသောဘာသာစကား မော်ဒယ်များ (LLMs) ထဲသို့ ပေါင်းစပ်ပုံနည်းကို အတိုချုပ်သင်ယူခဲ့သည်။ ဒီသင်ခန်းစာတွင် သင့်အချက်အလက်များကို LLM လျှောက်လွှာမှာ အခြေပြုခြင်းသဘောတရားများ၊ အလုပ်လုပ်ပုံသဘောစဉ်နှင့် ဒေတာသိုလှောင်မှုနည်းလမ်းများ (embedding နှင့် စာသား နှစ်မျိုးစလုံး) ကို နက်နက်ရှိုင်းရှိုင်း လေ့လာသွားမှာ ဖြစ်သည်။

> **ဗွီဒီယို မကြာခင်ထွက်မည်**

## နိဒါန်း

ဒီသင်ခန်းစာမှာ ကျွန်ုပ်တို့မှာ အောက်ပါအရာတွေကိုဖုံးလွှမ်းသွားမှာဖြစ်သည် -

- RAG ကို မည်သည့်အရာဖြစ်ပြီး AI (အတုအယောင်ပညာရေး) မှာ ဘာကြောင့် အသုံးပြုသလဲ ဆိုတာ အကျဉ်းချုပ်မိတ်ဆက်ခြင်း။

- ဗက်တာ ဒေတာဘေ့စ်များ ဆိုတာဘာလဲ၊ ကျွန်ုပ်တို့လျှောက်လွှာအတွက် ဘယ်လိုတည်ဆောက်မလဲ ကိုနားလည်ခြင်း။

- RAG ကို လျှောက်လွှာထဲတွင် ပေါင်းစည်းအသုံးပြုနည်း အသုံးချမှုဥပမာ။

## သင်ယူမှတ်တမ်းများ

ဒီသင်ခန်းစာပြီးဆုံးတဲ့အခါ၊ သင်သည် အောက်ပါအရာများကို ပြောပြနိုင်မည်ဖြစ်သည် -

- ဒေတာ ရယူပြီး ပြင်ဆင်မှုအတွက် RAG ၏ အရေးပါမှုကိုရှင်းပြနိုင်မည်။

- RAG လျှောက်လွှာတည်ဆောက်ပြီး သင်၏ဒေတာဖြင့် LLM ကို အခြေပြုနိုင်မည်။

- LLM လျှောက်လွှာများတွင် RAG နှင့် ဗက်တာ ဒေတာဘေ့စ်များကို ထိရောက်စွာ ပေါင်းစပ်အသုံးပြုနိုင်မည်။

## ကျွန်ုပ်တို့၏ အခြေအနေ: ကျွန်ုပ်တို့၏ LLM များကို ကိုယ်ပိုင်ဒေတာဖြင့် တိုးတက်မွန်းတည့်စေခြင်း

ဒီသင်ခန်းစာအတွက် ကျွန်ုပ်တို့ ပညာရေး စတင်လုပ်ငန်းတွင်ကိုယ်ပိုင်မှတ်စုများထည့်သွင်းလိုသည်၊ ၎င်းက chatbot ကို အတော်အသိပညာများ ရယူနိုင်စေပါမည်။ ကျွန်ုပ်တို့၏မှတ်စုများဖြင့်၊ သင်ယူသူများသည် ပိုမိုကောင်းမွန်စွာ စာပေကိုလေ့လာနားလည်နိုင်ပြီး၊ မေးပွဲများအတွက် ထပ်မံသင်ကြားရန် ပို၍ အဆင်ပြေပါမည်။ ကျွန်ုပ်တို့၏အခြေအနေကို တည်ဆောက်ရန်အတွက် -

- `Azure OpenAI:` ကျွန်ုပ်တို့ chatbot ဖန်တီးရန် အသုံးပြုမည့် LLM

- `AI for beginners' lesson on Neural Networks` ကျွန်ုပ်တို့ LLM အတွက် အခြေပြုရန် ဒေတာ

- `Azure AI Search` နှင့် `Azure Cosmos DB:` ဒေတာသိုလှောင်ရန်နှင့် ရှာဖွေရေးနေရာဖန်တီးရန် ဗက်တာ ဒေတာဘေ့စ်

အသုံးပြုသူများသည် ကိုယ်ပိုင်မှတ်စုများမှ လေ့ကျင့်မေးခွန်းများနှင့် ပြန်လည်သတိပေးချိန်းများ တည်ဆောက်နိုင်ပြီး ထိုမှတ်စုများကို ကျစ်လစ်သော အကြောင်းအရာများအဖြစ် ချုပ်ဆိုနိုင်သည်။ စထိုက်အဆင့်အတန်းကိုစဖို့ RAG သည် ဘာဖြစ်ပြီး ကျွန်ုပ်တို့ဘယ်လိုအသုံးပြုမသလဲ ဟုပြန်ကြည့်ကြစို့။

## ရယူထည့်သွင်းထားသော မူလတန်းထုတ်လုပ်မှု (RAG)

LLM အားအခြေခံသော chatbot သည် အသုံးပြုသူက နောက်ခံထားသော မေးခွန်းများအပေါ် တုံ့ပြန်ချက်များကို အပြန်ဖြေရှင်းပေးသည်။ ၎င်းမှာ စကားပြောဆက်ဆံခြင်းဖြစ်ပြီး တစ်သက်တမ်းကြီး အကြောင်းအရာများ သို့ ဝင်ရောက်သွားပါသည်။ သို့သော် တုံ့ပြန်ချက်များမှာ ၎င်း၏သက်တမ်းကာလနှင့် ချဲ့ထွင်ထားသည့်ဒေတာ အတွင်းအကြောင်းအရာများအပြန်အလှန် ပြန်လည် ပေးစွမ်းသည်။ ဥပမာ၊ GPT-4 ၏ အသိပညာ ကာလမှ အတော်လေးနောက်ကျသွားပြီး စက်တင်ဘာ ၂၀၂၁ အထိ ဖြစ်ပေါ်ခဲသည့် ဖြစ်ရပ်များကို မသိပါ။ ထို့အပြင် LLM အသုံးပြု၍ 만든 ထောက်ခံရေးလေ့ကျင့်ချက်တွင် ကိုယ်ရေးအချက်အလက် စာတမ်းများ သို့မဟုတ် ကုမ္ပဏီ ပစ္စည်းလက်စွဲ စာအုပ်ကဲ့သို့ နှောင်နှင်းထားသော အချက်အလက်များ မပါဝင်ပါ။

### RAG (ရယူထည့်သွင်းထားသော မူလတန်းထုတ်လုပ်မှု) မည်သို့ လုပ်ဆောင်ကြသည်

![RAG လုပ်ဆောင်ပုံ ဖော်ပြချက်](../../../translated_images/my/how-rag-works.f5d0ff63942bd3a6.webp?WT.mc_id=academic-105485-koreyst)

သင်နိုင်ငံအပေါ်မှတ်စုများမှ မေးခွန်းများ တည်ဆောက်သည့် chatbot တစ်ခု ထည့်သွင်းလိုတယ်ဆိုပါစို့၊ နည်းပညာ အချက်အလက်ဖြစ်သော knowledge base နှင့် ချိတ်ဆက်ရန် လိုအပ်သည်။ ၎င်းမှာ RAG ထောက်ပံ့ပေးသောအခန်းကဏ္ဍ ဖြစ်ပါသည်။ RAG များ အောက်ပါအတိုင်း လည်ပတ်ပါသည် -

- **Knowledge base:** ရယူမတိုင်မီ ဤစာရွက်စာတမ်းများကို စုစည်းသင့်ပြီး ကြိုတင်ပြင်ဆင်ရမည်၊ အများအားဖြင့် စာရွက်စာတမ်းများကို အပိုင်းအသေးများ ခွဲခြားခြင်း၊ စာသား embedding သို့ ဘာသာပြန်ခြင်းနှင့် ဒေတာဘေ့စ်အတွင်း သိမ်းဆည်းခြင်းတို့ ပါဝင်သည်။

- **User Query:** အသုံးပြုသူက မေးခွန်းတစ်ခု မေးတယ်

- **Retrieval:** အသုံးပြုသူမေးခွန်းမေးသောအခါ embedding မော်ဒယ်က အချက်အလက်ကို knowledge base မှ ရှာဖွေလိုက်ပါသည်၊ ထပ်တိုး context ပေး၍ prompt ထဲထည့်ပေးမည်ဖြစ်သည်။

- **Augmented Generation:** LLM သည် ရရှိသောဒေတာအရ တုံ့ပြန်ချက်ကို တိုးတက်စေသည်။ ထိုအတိုင်းပြန်လည်ထုတ်ပေးမှုသည် ကြိုတင်သင်ကြားထားသည့် ဒေတာသာမက ထည့်သွင်းထားသော context မှ ပါရမီရှိသော အချက်အလက်ကိုလည်း အသုံးပြုသည်။ ပြန်လည်ရယူထားသော ဒေတာကို LLM ၏ တုံ့ပြန်ချက်များအတွက် ထောက်ပံ့သုံးစွဲသည်။ LLM သည် အသုံးပြုသူမေးခွန်းအတွက် တုံ့ပြန်ချက် အဖြေကို ပြန်ပေးပါသည်။

![RAG ဖန်တီးပုံ](../../../translated_images/my/encoder-decode.f2658c25d0eadee2.webp?WT.mc_id=academic-105485-koreyst)

RAG သည် retriever နှင့် generator တို့ပေါင်းစပ်ထားသည် - မေးခွန်းကို ဗက်တာသို့ ပြောင်းပြီး၊ စာရွက်စာတမ်း အညွှန်းနှင့် ကိုက်ညီသော အပိုင်းများကို ရှာဖွေကာ LLM သို့ context အဖြစ် ပေးသွင်းပြီး တုံ့ပြန်ချက်ထုတ်ပေးသည်။ retriever နှင့် generator တို့သည် မော်ဒယ်များ ကွဲပြားမှုရှိနိုင်ပြီး RAG သည် encoder-decoder transformer မလိုအပ်ပါ။

ထုတ်ပြန်ထားသော စာတမ်း [Retrieval-Augmented Generation for Knowledge intensive NLP (natural language processing software) Tasks](https://arxiv.org/pdf/2005.11401.pdf?WT.mc_id=academic-105485-koreyst) အရ RAG ကို ရှေ့ဆောင်တည်ဆောက်ရာတွင် ၂ မျိုးရှိသည်။

- **_RAG-Sequence_** retrieved စာရွက်စာတမ်းများဖြင့် အသုံးပြုသူမေးခွန်း၏ အကောင်းဆုံးဖြေကြားချက် ခန့်မှန်းခြင်း

- **RAG-Token:** စာရွက်စာတမ်းများဖြင့် နောက်တစ်ခုသော token ကို ဖန်တီးပြီး ထို့နောက် အသုံးပြုသူမေးခွန်းဖြေရှင်းရန် ပြန်လည်ရယူခြင်း

### ဘာကြောင့် RAG များအသုံးပြုသလဲ?

- **အချက်အလက်ထောက်ပံ့မှုများပြည့်စုံမှု:** စာသားတုံ့ပြန်ချက်များသည် နောက်ဆုံးရသတင်းအချက်အလက် အသစ်များနှင့် ကိုက်ညီမှုရှိပြီး၊ အထူးခွာရာ အလုပ်များအတွက် တိုးတက်မှုရရှိစေသည်။

- အသုံးပြုသူမေးခွန်းများအတွက် အချက်အလက်များကို **အတည်ပြုနိုင်သော ဒေတာ** အဖြစ် သုံးပြီး မတိကျမှုများ လျော့နည်းစေသည်။

- LLM ကို fine-tune ပြုလုပ်ခြင်းနှင့်နှိုင်းယှဉ်၍ **စီးပွားထိရောက်မှုရှိသည်**

## knowledge base ဖန်တီးခြင်း

ကျွန်ုပ်တို့၏လျှောက်လှာသည် ကိုယ်ပိုင်ဒေတာတွေပေါ်တွင်း အခြေခံထားပါသည်၊ ဥပမာအားဖြင့် AI for Beginners သင်ခန်းစာမှ Neural Network သင်ခန်းစာဖြစ်သည်။

### ဗက်တာ ဒေတာဘေ့စ်များ

ဗက်တာ ဒေတာဘေ့စ်သည် ဆင်တူ ဒေတာဘေ့စ်များနှင့်မတူပဲ၊ embedded vector များကို သိမ်းဆည်း စီမံ၍ ရှာဖွေရန် ပြုလုပ်ထားသည့် အထူးကဏ္ဍဖြစ်သည်။ စာရွက်စာတမ်းများ၏ နံပါတ်တန်းဖော်ပြမှုများကို သိမ်းဆည်းထားသည်။ ဒေတာကို နံပါတ်ဖော်ပြခြင်းဖြင့် AI စနစ်အတွက် ပိုမိုနားလည်စေပြီး အသုံးပြုရ လွယ်ကူစေသည်။

LLM မှ input token အရေအတွက် ကန့်သတ်ချက် ရှိသည်ကြောင့်၊ စာရွက်စာတမ်းများကို အပိုင်းခွဲပြီး ထည့်သွင်းသည်။ အသုံးပြုသူမေးခွန်းတစ်ခုရှိလျှင်၊ embedding တွေထဲမှ ထိပ်တန်းနှီးနွယ်မှုရှိသောများကို ရွေးကောက်ပြီး စာပိုင်းများကို ပြန်လည်ပေးသည်။ chunking က token အရေအတွက်ကို လျော့ကာ LLM သုံးစရိတ် လျော့နည်းစေသည်။

### စာသားမှ embeddings သို့

ဒေတာကို သိမ်းမည်မပြုမီ၊ ဒေတာကို ဗက်တာ embeddings သို့ ပြောင်းရန် လိုအပ်သည်။ ကြီးမားသောစာရွက်စာတမ်းများ သို့မဟုတ် ရှည်လျားသော စာသားများဖြစ်လျှင် မေးခွန်းမျှော်မှန်းချက်အရ အပိုင်းခွဲနိုင်သည်။ အပိုင်းခွဲခြင်းကို ဝေါဟာရအဆင့်သို့မဟုတ် စာပိုဒ်အဆင့်၌ လုပ်နိုင်သည်။ အပိုင်းများ၏ သဘောတရားက ဝေါဟာရများ၏ လှည့်ပတ်လည်အသည်းအသန်မှ ဆင်းသက်လာသည့်ကြောင့်၊ အပိုင်းတစ်ခုသို့ အခြား context များထည့်နိုင်ပါသည်၊ ဥပမာ စာရွက်စာတမ်းခေါင်းစဉ်ထည့်ခြင်း သို့မဟုတ် အပိုင်းမတိုင်မီ သို့မဟုတ် အပိုင်းနောက်ပိုင်း စာသား ထည့်သွင်းနိုင်သည်။ ဒေတာအပိုင်းခွဲခြင်းကို အောက်ပါအတိုင်းလုပ်နိုင်သည် -

```python
def split_text(text, max_length, min_length):
    words = text.split()
    chunks = []
    current_chunk = []

    for word in words:
        current_chunk.append(word)
        if len(' '.join(current_chunk)) < max_length and len(' '.join(current_chunk)) > min_length:
            chunks.append(' '.join(current_chunk))
            current_chunk = []

    # If the last chunk didn't reach the minimum length, add it anyway
    if current_chunk:
        chunks.append(' '.join(current_chunk))

    return chunks
```

အပိုင်းခွဲပြီးနောက်၊ ကွဲပြားသော embedding မော်ဒယ်များဖြင့် စာသားကို embed လုပ်နိုင်သည်။ သင်အသုံးပြုနိုင်သည့် မော်ဒယ်များမှာ word2vec, OpenAI ရဲ့ ada-002, Azure Computer Vision စသဖြစ်ပါသည်။ မော်ဒယ်ရွေးချယ်မှုမှာ သင်အသုံးပြုမည့် ဘာသာစကားများ၊ ပါဝင်သောအကြောင်းအရာအမျိုးအစား (စာသား/ပုံ/အသံ)၊ input အရွယ်အစားနှင့် output embedding ၏ အရှည်တိုင်းတာမှုအပေါ် မူတည်ပါသည်။

OpenAI ရဲ့ `text-embedding-ada-002` မော်ဒယ်ဖြင့် embed လုပ်ထားသော စာသားဥပမာမှာ -

## ရယူခြင်းနှင့် ဗက်တာရှာဖွေရေး

အသုံးပြုသူ မေးခွန်းမေးလျှင် retriever သည် query encoder ဖြင့် ဗက်တာသို့ ပြောင်းပြီး ပေါင်းထားသော စာရွက်စာတမ်း ရှာဖွေသည့် အညွှန်းထဲမှ input နှင့် ဆက်စပ်သော ဗက်တာများ ရှာပါသည်။ပြီးလျှင် မူရင်း input ဗက်တာနှင့် စာရွက်စာတမ်းဗက်တာများကို စာသားသို့ ပြောင်း၍ LLM ကိုပေးသည်။

### ရယူခြင်း

ရယူခြင်းသည် စနစ်၏ ရည်ရွယ်ချက်သည် ရှာဖွေရေး ကြီးကြပ်မှုစံသတ်မှတ်ချက်ဖြင့် စာရွက်စာတမ်းများအား လျင်မြန်စွာ ရှာဖွေခြင်းဖြစ်သည်။ Retriever ၏ ရည်ရွယ်ချက်မှာ ကိုယ့်ဒေတာဖြင့် LLM ကို အခြေပြုစေနိုင်သော context အနေဖြင့် အသုံးပြုရန်စာရွက်စာတမ်းများ ရှာဖွေပါသည်။

ကျွန်ုပ်တို့၏ဒေတာဘေ့စ်အတွင်း ရှာဖွေရေးကို အောက်ပါနည်းလမ်းများဖြင့် လုပ်နိုင်သည် -

- **Keyword ရှာဖွေရေး** - စာသားရှာဖွေရေးအတွက် အသုံးပြုသည်

- **ဗက်တာ ရှာဖွေရေး** - စာရွက်စာတမ်းများကို embedding မော်ဒယ်များဖြင့် ဗက်တာများသို့ ပြောင်းပြီး အဓိပ္ပာယ်အရ semantic search လုပ်ရန် ခွင့်ပြုသည်။ ရှာဖွေမှုသည် အသုံးပြုသူမေးခွန်းနှင့် နီးကပ်ဆုံးသော ဗက်တာကို ရှာဖွေခြင်းဖြစ်သည်။

- **အာဟာရပေါင်းစပ်** - keyword နှင့် vector ရှာဖွေရေး တို့ပေါင်းစပ်မှု။

ရယူရာတွင် စိန်ခေါ်မှုတစ်ခုမှာ ဒေတာဘေ့စ်တွင် မေးခွန်းနှင့် ဆင်တူသော တုံ့ပြန်ချက် မရှိဘဲဖြစ်လျှင် စနစ်သည် ထိပ်တန်းအချက်အလက်ကို ပြန်ပေးမည်ဖြစ်သည်။ သင်ရှာဖွေမှုအကွာအဝေးကို သတ်မှတ်ခြင်း သို့မဟုတ် keyword နှင့် vector ရှာဖွေရေး ပေါင်းစပ်မှုဖြင့် အသုံးပြုနိုင်သည်။ ဒီသင်ခန်းစာတွင် ကျွန်ုပ်တို့သည် vector နှင့် keyword ရှာဖွေရေး ပေါင်းစပ်မှုကို အသုံးပြုမည်ဖြစ်ပြီး ဒေတာကို dataframe တွင် ခွဲခြားထားသော အပိုင်းများနှင့် embeddings ကိုထည့်သွင်းထားမည်။

### ဗက်တာ ဆင်တူမှု

Retriever သည် knowledge database ထဲမှ နီးစပ်မှုရှိသော embedding များအား ရှာဖွေလိုက်ပါသည် - အနီးဆုံး အိမ်နီးချင်းများ။ ဒီအခြေအနေမှာ အသုံးပြုသူမေးခွန်းကို အရင်ဆုံး embedding ပြုလုပ်ပြီး ဆင်တူမှုရှိသော embedding များနှင့် ကိုက်ညီစေသည်။ ဗက်တာ ဆင်တူမှုတိုင်းတာရာတွင် လူကြိုက်သော အတိုင်းအတာမှာ cosine similarity ဖြစ်ပြီး ဗက်တာ နှစ်ခုအကြား ထောင့်အပေါ် အခြေခံသည်။

တခြားတိုင်းတာမှုများမှာ Euclidean distance ဖြစ်ပြီး ၎င်းသည် vector အစွန်းနှစ်ခုအကြား တန်းတန်းလမ်းကြောင်းတစ်ခု ဖြစ်သည်။ dot product သည် vector နှစ်ခုတွင် ကိုက်ညီတဲ့ အချက်အလက်များ၏ ထုတ်ကုန်များ စုစုပေါင်းကို တိုင်းတာသည်။

### ရှာဖွေရေး အညွှန်း

ရယူခြင်း လုပ်ဆောင်ရာတွင် knowledge base အတွက် ရှာဖွေရေး အညွှန်းကို ဖန်တီးရမည်။ အညွှန်းသည်  embedding များကို သိမ်းဆည်းထားပြီး ကြီးမားသော ဒေတာဘေ့စ်တွင်ပါ ပိုမိုဆင်တူသော စာပိုင်းများကို မြန်ဆန်စွာ ရှာဖွေနိုင်သည်။ ကျွန်ုပ်တို့၏ အညွှန်းကို ဒေသတွင်းတွင် ဖန်တီးနိုင်သည်။

```python
from sklearn.neighbors import NearestNeighbors

embeddings = flattened_df['embeddings'].to_list()

# Create the search index
nbrs = NearestNeighbors(n_neighbors=5, algorithm='ball_tree').fit(embeddings)

# To query the index, you can use the kneighbors method
distances, indices = nbrs.kneighbors(embeddings)
```

### ပြန်လည် အဆင့်ခွဲခြင်း

ဒေတာဘေ့စ်ကို မေးခွန်းမေးပြီးနောက်ရလဒ်များကို အကောင်းဆုံး မပြုမိအောင် စီမံရန်လိုနိုင်သည်။ ပြန်လည် အဆင့်ခွဲခြင်း LLM သည် စိစစ်မှုကိုတိုးတက်အောင် Machine Learning အသုံးပြုပြီး ရှာဖွေမှု ရလဒ်များကို အဆင့်လိုက် စီသည်။ Azure AI Search အသုံးပြုမှုတွင် semantic reranker ဖြင့် အလိုအလြောကျ ပြုလုပ်သည်။ အနီးဆုံး အိမ်နီးချင်းများ အသုံးပြုကာ ပြန်လည်အဆင့်ခွဲခြင်း ဖော်ပြချက်။ 

```python
# Find the most similar documents
distances, indices = nbrs.kneighbors([query_vector])

# Print the three most similar documents with their distance to the question
for distance, index in zip(distances[0][:3], indices[0][:3]):
```

- စကားပုံချောမွေ့မှု - ဖြေချက်သည် သဒ္ဒါတကျ ဖြစ်ပါသလား ဆိုတာ

## RAG (ရယူထည့်သွင်းထားသော မူလတန်းထုတ်လုပ်မှု) နှင့် ဗက်တာဒေတာဘေ့စ် အသုံးပြုမှု များ

RAG သည် သင့်လျှောက်လွှာများကို တိုးတက်အောင် ပြုလုပ်နိုင်သည့် အသုံးပြုမှုများ အများအပြားရှိသည်၊ ဥပမာ -

- မေးခွန်းပြန်ဖြေခြင်း: ကိုယ်ပိုင်ကုမ္ပဏီဒေတာကို chatbot တစ်ခုတွင် အခြေပြု၍ ဝန်ထမ်းများ မေးခွန်းများ မေးနိုင်စေရန် အသုံးပြုခြင်း။

- အကြံပြုမှုစနစ်များ: မုချ၊ စားသောက်ဆိုင်၊ တခြား ပစ္စည်းများအကြောင်း အများဆုံးဆင်တူသော အချက်အလက်များနှင့် ကိုက်ညီမှု ရှာဖွေရန်စနစ်တစ်ခု ဖန်တီးခြင်း။

- Chatbot ဝန်ဆောင်မှုများ: ချတ်စ် မှတ်တမ်းများကို သိမ်းဆည်းပြီး အသုံးပြုသူဒေတာအပေါ် အခြေခံကာ ဆွေးနွေးပုံကို ကိုယ်ပိုင်ပြုလုပ်နိုင်သည်။

- ဗက်တာ embedding အခြေခံ၍ ပုံများကို ရှာဖွေခြင်း၊ ပုံသိမှတ်ခြင်းနှင့် မတူကွဲပြားမှု ကြားသိမှု အတွက် အသုံးဝင်သည်။

## အနှစ်ချုပ်

ကျွန်ုပ်တို့ RAG ၏ အခြေခံအချက်များကို LLM အတွက် ဒေတာထည့်သွင်းခြင်း၊ အသုံးပြုသူမေးခွန်း နှင့် ထုတ်လွှင့်ပုံတို့အပါအဝင် ဖော်ပြခဲ့သည်။ RAG ဖန်တီးမှုကို လွယ်ကူစေရန် Semantic Kernel, LangChain သို့မဟုတ် AutoGen ကဲ့သို့သော framework များကို အသုံးပြုနိုင်သည်။

## အလုပ်တာဝန်

RAG ကို ဆက်လက်လေ့လာရန်အတွက် သင်လုပ်ဆောင်နိုင်သည် -

- သင်နှစ်သက်သည့် framework ဖြင့် အလှဆင်ထားသော front-end တည်ဆောက်ခြင်း

- LangChain သို့မဟုတ် Semantic Kernel တစ်ခုခုကို အသုံးပြု၍ သင်၏ လျှောက်လွှာကို ထပ်မံဖန်တီးခြင်း

သင်ခန်းစာ အဆုံးသတ်ခြင်းနှင့် ကျေးဇူးတင်ပါသည် 👏

## သင်ယူခြင်းသည် ဒီနေရာမှာ မရပ်ပါ၊ ခရီးတစ်ခုကို ဆက်လက်သွားပါ

ဒီသင်ခန်းစာပြီးဆုံးပြီးနောက်၊ ကျွန်တော်တို့ရဲ့ [Generative AI Learning collection](https://aka.ms/genai-collection?WT.mc_id=academic-105485-koreyst) ကို သွားကြည့်ပြီး Generative AI သိပ္ပံကို ပိုမိုတိုးတက်အောင် ဆက်လက်လေ့လာလိုက်ပါ!
